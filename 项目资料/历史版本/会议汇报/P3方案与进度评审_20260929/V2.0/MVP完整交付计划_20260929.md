# P3 MVP 完整交付计划

编制日期：2026-09-28；评审日期：2026-09-29。状态：**建议细化排期，待团队确认**。范围以 PRD V1.3 为基线；正式评审和签收尚未完成。

## 目标和时间基线

MVP 面向应用/Agent/P4 交付可独立运行的记忆服务，完成保存、当前使用、长期化、跨会话召回、事实维护、内部基础调度、租户隔离及恢复。包含 P0 FR01—15、FR17—18。FR16 预测预热在后续 P1。

PRD §13 的原计划：MVP 为 2026-09-01 至 12-01，11-14 前推进独立能力，11-15 起真实集成。下列细分日期为建议日历窗口，未折算为人员工日，国庆假期、A 开发人选和外部依赖可用时间需评审落实。十月开始接口预联调与模型评测准备，11-15 为正式联合集成节点。

MVP 不扩建独立 Web 管理端、RBAC、身份或审计平台。当前新增监测前端作为已有代码增量如实展示，必要诊断能力随服务交付。Final 的正式纳管、全量交付和 72h 长稳在后续阶段，本计划仅包含 MVP 约定环境所需的部署与运行交接。

## 当前起点

2026-09-28 源码核对：HEAD `74f71bc` 已包含统一持续服务，工作区另有监测、任务/Trace 目录等修改。本地 Remember、Recall、RF 和 Operate 已整合。真实 HTTP、SQLite、文件缓存、BGE 及故障恢复的证据引用 2026-09-26 报告。本次未重跑测试，新增监测代码未据本次静态核对判为验收通过。

仍需独立完成：真实 LLM 质量、P2/Milvus 与身份集成、约定实际物理调整、模型/性能/24h 长稳、部署及整体数据恢复、业务 UAT 与交接。

## 数值目标与测量口径

| 验收项 | PRD目标 | 必须固定的测量条件 |
|---|---|---|
| 当前记忆核心读写 | P99 < 10ms | P3接收有效请求到返回结果；负载/并发/硬件/冷热比；不混同完整Context延迟 |
| 语义计算 | ≥2000条有效内容/秒 | 模型、硬件、输入长度、批次、实际完成数量；缓存命中不能代替计算 |
| 压缩 | ≥5倍且质量通过 | 同批原始与压缩正文真实保存字节；关键事实/数字/否定/条件/冲突；失败样本保留 |
| 基础调度规则 | 正确率100%，错误降层0 | 已明确规则、负载、容量；调度真实效果另外读回核对 |
| MVP长稳 | 连续≥24h | 候选版本和真实依赖固定；正确性/隔离/错误/积压/资源/未决操作连续记录 |
| 内容/检索质量 | 按共同确认的标注和判定规则 | 标注集版本、冲突/更正/删除/长文和负样本；未定义项在功能验收前确认 |

这些指标尚未验收。若测量条件或实现能力与目标存在差距，提交差距、改进工作量及影响日期；指标变更须通过明确范围决议并同步 PRD/验收，不能默认为豁免。

## 真实执行范围决议

PRD 把基础调度、自动执行和反馈列为 P0，现有 DEC-SCOPE-01 对生产物理分层的具体范围仍待联合确认。当前本地真实文件缓存是已验证起点。阶段一应确定 P2/P1 的目标介质、允许动作、精确读取、原操作查询、恢复约束与交付日期。未取得范围变更批准前，本计划保留真实执行和结果确认要求。

## UAT 与退出条件

按现有 UAT-01—08 执行跨会话记忆、更正删除、故障恢复、冲突/长度、隔离、后台动作、部署交接和约定 P2 三态用例。UAT 在 G4 后开展，用真实候选环境和同版本数据，不能由 Mock 演示代替。

退出：约定必验场景全部通过；P0/P1 阻断缺陷清零并复验；质量和性能目标通过；P2/P3 一般问题由业务方明确接受条件和修复期；部署、备份、回滚、监测和支持交接完成；业务方签收。这里缺陷 P0/P1 的严重度与功能 FR16 的 P1 优先级不是同一含义。

## 责任与关键路径

沿用 7 人安排：陈凯负责架构/RF规则及组织验收；A开发待确定；B杨鹏通、C沈佳隆；测试与P2对接分别为肖宇、赵旭东、谭旭梁。P3内部接口由相关开发协作，陈凯协调。RF具体编码由陈凯逐项指定唯一实现人。

还需落实：P2对象/向量/关系/执行联系人、真实模型环境、身份提供方及撤权窗口、部署负责人、首批应用/P4接入方与业务验收代表。P2自身能力交付由P2方负责，P3侧适配由对应开发负责，对接人跟踪至关闭。

关键路径：人员和范围/契约明确 → P0独立能力与真实依赖就绪 → 联合闭环 → 系统指标与24h长稳 → UAT签收与交付。真实依赖预联调、样本标注和运维准备可以提前并行。依赖延期必须同步修改受影响交付日期及验收范围，不能用本地替身结果关闭。

## 最终交付包

1. 可运行候选/发布版本：源码、构建、依赖锁定、配置与模型指纹、部署数据约定。
2. 应用接入与使用说明：写入、长文状态、召回、权限、异常、更正删除及连续示例。
3. 验收证据：功能/集成/安全/模型质量/性能/24h报告、缺陷与复验、证据环境。
4. 运维材料：启动、健康、诊断、告警处理、备份恢复、升级回滚和支持接手。
5. 业务签收：真实UAT、遗留问题接受条件、运行交接人与日期。
