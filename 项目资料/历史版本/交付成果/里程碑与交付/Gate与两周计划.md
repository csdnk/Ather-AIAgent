## 两周安排（10个工作单元，待团队排入日历）

| 单元 | 输出与责任角色 | 验证 / 依赖 |
|---|---|---|
| W01 目标边界 | 产品/项目审查目标一页纸和DEC-SCOPE-01 | 完成六个目标问题，列清尚未批准范围 |
| W02 需求原型 | P2/P3分别走查Mock和FR→Epic | 关键Epic可定位输入/输出/失败；预测明确P1 |
| W03 架构决策 | 架构角色审查总图、主ADR及数据归属 | 抽问选择理由、备选、代价；准备G1/G2材料 |
| W04 接口冻结 | P2/P3/P1明确Provider能力与远程入口 | 精确版本、ready、删除、Unknown、授权和路由契约 |
| W05 真实演示接入 | RF/接入角色为新Host接薄HTTP及演示适配 | TC-P3-23；服务结果和Mock模式清晰区分 |
| W06 记忆产品缺口 | B/A拆分文档、真实提取、压缩、冲突/tokenizer开发 | TC-P3-18~22，给出可运行最小垂直切片和余量，不承诺两天完成全量 |
| W07 P2执行验证 | P2补运行工具链、部署和三态用例 | P2-01~03；图远程入口缺口需先解决 |
| W08 集成异常 | RF/P2/P3完成首条真实保存召回及故障演示 | INT-01；动作按范围决议覆盖P2-04 |
| W09 测试验收 | 测试/交付更新TCR、缺陷、性能质量与UAT计划 | 实测/模拟/未运行分开；剩余指标与环境列出 |
| W10 联合预审 | 项目角色统一12页汇报并随机抽查Epic/ADR | 汇报15分钟，记录G1/G2结论及G3以后剩余计划 |

前四项的文档草案及结构本次已补齐；联合Review与W05以后的工程/验收工作按实际证据推进。两周目标是可讲清、可评审、可验证的体系，不承诺两周完成生产全部代码和性能。

## 发布与运行必备项

固定版本与配置；密钥注入及授权验证；数据迁移/备份恢复；部署/回滚步骤；日志和告警；资源/依赖健康；已知缺陷；支持与故障接手角色；UAT签收。现在这些属于待实施和待演练事项，不能把此清单本身当作已准备就绪。
