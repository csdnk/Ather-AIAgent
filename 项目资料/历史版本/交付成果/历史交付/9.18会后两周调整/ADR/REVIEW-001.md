# REVIEW-001 以两个服务入口组织产品与演示

- 状态：Proposed，待联合评审
- 日期：2026-09-18
- 需求：FR01、FR08、FR15
- 对应演示：S01、S06
- 来源：S1 §4.1–4.4、§5.1、§8.7；已有 ADR-0001、0004
- 评审责任：见文末责任角色；具体姓名与评审结论尚未指定

本记录为本次评审包内的建议，不覆盖已有 ADR，也不将建议标记为已获批准。

## 背景与问题

P3 没有独立管理端，但接入团队仍需评审保存、召回和异常响应。旧材料出现 Web 运维页和三模块操作入口，容易扩大交付范围。

## 建议决策

对外保留 Remember 与统一 Recall 两类业务入口，更正、删除、任务和结果查询作为配套操作。Operate 自动运行。演示页是 P4/调用方替身和受控内部观察工具，不作为新增产品后台；切换模拟时钟或故障也不是产品业务接口。

## 方案比较

| 方案 | 取舍依据 |
| --- | --- |
| 建设完整管理后台 | 增加账号、导航、审批等非本期范围，分散两周评审重点。 |
| 只交静态架构图 | 无法讨论连续操作、错误响应和状态变化。 |
| 采用接入方替身与有状态 Mock | 能演示产品行为，同时保持服务交付边界；本次建议。 |

## 代价与影响

需要同时维护业务可见结果和内部诊断两种视图，并明确其授权边界。演示页面不能被当作生产认证或管理系统。

## 验证方式

从接入面可以完成保存、召回、更正、删除和查询；没有业务调度按钮。仅发生存储变化也产生调度观察记录。

## 待确认事项与责任

产品与接入 Owner 确认最终 SDK/协议封装及对外 DTO；架构评审时确定。
