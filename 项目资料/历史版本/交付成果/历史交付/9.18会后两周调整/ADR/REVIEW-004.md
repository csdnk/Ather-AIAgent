# REVIEW-004 更正和逻辑删除优先约束所有使用路径

- 状态：Proposed，待联合评审
- 日期：2026-09-18
- 需求：FR04、FR05、FR11、FR17
- 对应演示：S02、S05、S06
- 来源：S1 FR05/07/11/17、§12.1–12.3；已有 ADR-0003；S5
- 评审责任：见文末责任角色；具体姓名与评审结论尚未指定

本记录为本次评审包内的建议，不覆盖已有 ADR，也不将建议标记为已获批准。

## 背景与问题

旧向量、历史 Context 和迟到的后台操作可能使已更正或删除内容再次出现。物理清理又通常不能即时完成。

## 建议决策

同一记忆以期望版本进行显式更新，旧版退出默认资格，新版重新准备投影。删除先记录 tombstone 并阻断新的交付，再跟踪对象、投影及副本清理。异步任务与调度回执核对当前版本和删除状态，不能复活失效对象。历史上下文不可绕过检查重新下载。

## 方案比较

| 方案 | 取舍依据 |
| --- | --- |
| 直接覆盖正文并沿用旧投影 | 候选版本与正文可能错配，难以追责。 |
| 全部副本清理后才算删除生效 | 扩大等待时间和暴露窗口。 |
| 版本化事实与立即逻辑阻断 | 隔离前台安全与后台清理；本次建议。 |

## 代价与影响

需要维护版本、引用和清理证据。当前 Mock 只处理显式选中的 memory 及其版本，不声称能自动发现其他来源的等价事实；不能撤回已返回客户端的文本。

## 验证方式

更正后旧版不交付；旧期望版本更新被拒；删除后新召回为空、历史重放被阻断、迟到动作不激活对象。实际验收增加在途写屏障和清理重扫。

## 待确认事项与责任

B/A/P2 Owner 明确按 memory 或 source_event 删除的级联范围，以及备份、日志、共享原文保留策略；生产接入前确定。
