# REVIEW-005 基础调度自动执行并以观察结果收敛

- 状态：Proposed，待联合评审
- 日期：2026-09-18
- 需求：FR12、FR13、FR14
- 对应演示：S06
- 来源：S1 §6.5、FR12–14、§12.5–12.6；S6；已有 ADR-0005
- 评审责任：见文末责任角色；具体姓名与评审结论尚未指定

本记录为本次评审包内的建议，不覆盖已有 ADR，也不将建议标记为已获批准。

## 背景与问题

旧文档的“输出建议”不足以满足新 PRD 的自动执行闭环。受理回执或响应丢失均不能说明真实状态；记忆类型也不等于物理层级。

## 建议决策

存储和召回轨迹共同驱动后台基础算法。P3 以 Representation 为决策单位，经 Provider 解析为不透明执行目标，由 P2/P1 或约定 Executor 执行物理操作。保留原动作 ID 与版本、路由绑定，受理后继续查询。只有目标内容正确且可读才确认完成；未知保持核对，不盲目创建冲突动作。

## 方案比较

| 方案 | 取舍依据 |
| --- | --- |
| P3 只显示调度建议 | 不满足 FR14 的本期自动执行要求。 |
| P3 直接实现底层搬运 | 侵入 P2/P1 数据面职责。 |
| P3 决策和跟踪，Provider 执行并给证据 | 边界清晰且可核验；本次建议。 |

## 代价与影响

需要能力发现、目标映射、幂等、代际校验和真实读取证据。Mock 的两次交付温→热仅为可解释样例，不是正式算法，也不代表命中率或时延收益。

## 验证方式

仅写入也有算法判断；召回后自动生成动作。回执丢失时显示 Unknown，核对原动作不增加动作数，确认后新召回显示新层级。生产追加失败、并发更正、容量约束和真实迁移测试。

## 待确认事项与责任

C/P2/P1 明确执行 Owner、支持层级、规则阈值、结果查询和读取证明；真实联调前完成。
