# REVIEW-007 可信身份限定每一次操作和后台处理

- 状态：Proposed，待联合评审
- 日期：2026-09-18
- 需求：FR15、FR17、FR18
- 对应演示：S09
- 来源：S1 §3.3、FR15、§8.2、§11；已有 ADR-0004
- 评审责任：见文末责任角色；具体姓名与评审结论尚未指定

本记录为本次评审包内的建议，不覆盖已有 ADR，也不将建议标记为已获批准。

## 背景与问题

客户端提供 tenant_id 或知道对象 ID 不构成授权；同租户 Agent 也不能默认互读。后台处理与历史结果重放同样可能越权。

## 建议决策

服务从有效凭证或经验证上游身份取得可信范围，请求只能在已授权范围内选择。读、写、更正、删除和查询分别校验；后台任务保持原范围并复核当前授权。模拟界面使用固定凭证替身，修改请求范围会被拒绝，生产必须由服务端执行同类规则。

## 方案比较

| 方案 | 取舍依据 |
| --- | --- |
| 信任请求体的 tenant_id | 调用方可伪造范围。 |
| 新增独立 RBAC 后台 | 超出本期产品范围。 |
| 消费可信身份并进行资源级授权 | 覆盖服务边界且无需新平台；本次建议。 |

## 代价与影响

需定义凭证吊销、授权 epoch 和共享边界。浏览器端固定对象只能说明规则，不提供真实安全隔离，任何人可修改脚本。

## 验证方式

跨租户和同租户未授权 Agent 请求均被拒绝，无正文或存在性泄露。生产追加直接请求、后台任务、撤权、历史结果和日志脱敏测试。

## 待确认事项与责任

接入/安全与 A/B/RF Owner 明确凭证格式、共享资源规则和授权变更传播；接入验收前确定。
