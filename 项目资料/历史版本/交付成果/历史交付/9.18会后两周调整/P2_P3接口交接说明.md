# P2 P3 接口交接说明

日期：2026-09-18。状态：Proposed。本文描述逻辑能力与评审样例，不修改已经记录的 P2 proto，不将浏览器响应直接视为真实 RPC Schema。

## 交接能力与缺口

| P3 需要的逻辑能力 | 当前 P2 文档依据 | 必须另外核对的语义 | 不满足时 |
| --- | --- | --- | --- |
| 保存并回读准确对象 | ObjectService PutObject / HeadObject / GetObject | 持久完成边界、精确版本、内容摘要及读取身份 | 不报告可靠保存或 Ready |
| 建立表示并确认可查询 | VectorService InsertVector / SearchVector | 模型表示身份、全部分块、版本绑定、查询可见性 | 保留已保存事实，长期未就绪 |
| 带授权范围检索 | SearchVector 及相关筛选能力 | tenant/agent/task 过滤是否由 Provider 可靠执行，错误与缺失如何表达 | 阻断不安全路径，不能用客户端后过滤声称已满足隔离 |
| 读取来源关系 | GraphService CreateNode / CreateEdge / Traverse；FusionService | 关系引用与正文版本的一致性、查询边界和截断语义 | 不声称存在未验证的完整证据链 |
| 解析并执行调整 | SegmentControlService 内省、Freeze/Unfreeze、OnMigrateComplete/Failed | Representation 到实际目标的映射、执行 Owner、支持层级与权限 | 保持或暂缓，不构造可执行动作 |
| 核对未知结果 | ListSegments 扩展字段、migration_id、expected_route_epoch | 原动作查询、目标代际、当前路由、准确正文可读及回执重放 | 保持 Unknown，不用重试上限改成 Failed |
| 删除与在途写隔离 | DeleteVectors / DeleteObject | 删除范围、在途写屏障、重复清扫和物理清理证据 | 逻辑阻断维持；物理完成状态不能冒报 |

以上 RPC 名称来自 [P2 API 文档](../../../../../AgentJYS-main/engine/docs/P2_AetherEngine_API接口文档_v0.1.md)。当前真实字段支持、错误返回及实现行为需要 P2 Owner 提供实际请求/响应和验证结果。P3 内部共享事务和最终提交机制还依赖公共可靠性设计，不能仅靠 P2 RPC 补齐。

## 身份与版本字段各自负责什么

| 字段 | 保护对象 |
| --- | --- |
| tenant / agent / task scope | 已验证的资源访问范围；请求体本身不是凭证 |
| memory_id + memory_version | 业务记忆及其当前内容版本 |
| representation_id / model identity | 被计算、查询或调度的具体表示 |
| object_ref / content checksum | 准确正文或分块的引用与内容绑定 |
| mapping_generation | 逻辑到 Provider 映射自身的版本 |
| target_generation | Provider 目标当前驻留或内容的代际 |
| route_epoch | 物理路由或切换版本 |
| operation_id / migration_id | 原操作身份、幂等与结果查询 |

这些字段不自动存在于每个实际 RPC 中。Adapter 要明确逐字段映射、派生来源以及无法提供的保证，不应把所有字段收拢为一个 generation。

## 建议的逻辑请求与结果样例

以下均为评审 DTO，使用逻辑操作名而非虚构已经上线的 URL。正式 Schema 由双方确认。

```json
{
  "operation": "Remember",
  "trusted_context": {"tenant": "tenant-a", "agent": "project-assistant", "task": "aether-pilot"},
  "idempotency_key": "request-001",
  "content": "本阶段预算上限为20万元。",
  "source_ref": "meeting-0918"
}
```

可信上下文由服务端验证层注入。调用方可提出范围选择，但不能自行设置 trusted_context 获得授权。

```json
{
  "operation_id": "op-001",
  "memory_ref": {"id": "mem-001", "version": 1},
  "save_state": "saved",
  "processing_state": "pending",
  "long_term_ready": false
}
```

saved 需要内容及关联事实的可靠保存证据。仅收到外部队列或底层受理回执时，返回 accepted，不填 saved。当前 Mock 的对象在内存中即时模拟保存，因此显示 saved 时同时标注模拟。

```json
{
  "operation": "Recall",
  "query": "当前预算是多少？",
  "source_selection": ["working", "long_term"],
  "budget": {"unit": "tokens", "limit": 1024, "tokenizer_profile": "TO_BE_AGREED"}
}
```

```json
{
  "outcome": "degraded",
  "selected_sources": ["working", "long_term"],
  "missing_sources": [{"source": "long_term", "reason": "provider_unavailable"}],
  "items": [{"memory_id": "mem-001", "version": 2, "content": "本阶段预算上限为15万元。", "source_ref": "correction-002"}]
}
```

正式预算单位是待约定 tokenizer 下的 tokens；本地 Mock 使用字符预算，页面已明确区分。排序、来源选择和候选数量不是事实正确性的证明。

```json
{
  "operation": "QueryOriginalAction",
  "action_id": "act-001",
  "representation_id": "mem-001:canonical:v2",
  "memory_version": 2,
  "expected_route_epoch": 7,
  "observation": {
    "state": "unknown",
    "reason": "acknowledgement_lost",
    "target_read_verified": false
  }
}
```

未知结果继续查询原操作与准确目标；未完成核验前，不能用“已发送”“已接受”或乐观的目标层级表示成功。原操作发现目标已到达且准确正文可读后，还需复核 Memory 和执行目标版本仍有效。

## 与演示对应的契约验证建议

1. 同键同载荷返回原处理；同键不同载荷明确冲突，不覆盖原事实。
2. 投影失败不删除原文；查询命中必须绑定正确正文及当前版本。
3. 来源故障与正常空区分；全部超预算不可用，冲突信息不得截断。
4. 显式更正用期望版本；旧结果、旧索引及迟到任务不能重新交付旧值。
5. 删除先阻断，清理另行查询；并发最终提交及在途写屏障必须真实复验。
6. 未知执行保持原 ID，不新建冲突动作；状态观察与实际读取相符。
7. 请求体伪造范围、同租户未授权 Agent、后台旧授权均不得越权。

每个真实 Provider 需提供环境、版本、输入、输出、错误与恢复记录。Mock 只能检验这里定义的行为，不能替代 Provider 契约测试。
