## 阅读边界

- Remember 按内容与规则选择加工，不要求每条数据依次经过长文、稳定事实和压缩。当前有效 Working 无需等待长期加工。
- Recall 从 B 取得准确正文和关系；候选阶段、最终提交及原结果重取都核验资格。原结果未完成时只返回阶段，不执行“旧结果正文核验”。冲突成员无法完整表达时排除整组并说明缺失；所有组超长为不可用，不是正常空。
- 恢复先查原结果是否已提交；已提交走原结果核验，未提交才判断依赖、期限、处理权与安全继续条件。到期或无法继续时返回真实失败和可采取动作，不能无限续跑。
- Operate 同时消费存储与召回轨迹。受理不等于完成，未知查询原动作，成功必须核对目标可读性及当前资格。目标生效与旧副本清理分开记录。
- RF 提供机制，领域决定业务恢复；日志和 Trace 帮助定位，正式状态与执行证据决定结论。云身份不替代业务租户授权。

## 框架与实现细节

LangMem 用于 Remember 候选提取；LlamaIndex 的分层检索、融合和后处理作为 Recall 设计参考；Kubernetes Controller 模式作为 Operate 当前状态对账参考。RRF、final_guard、租约、CAS 是实现选择，不是 PRD 指定的产品或方法名。

共享 Embedding 为正文和问题提供同一模型空间的编码；可采用既有 BGE / FastEmbed / ONNX Runtime 适配。可选 CrossEncoder 负责排序，tokenizer 计算包含正文、引用和说明的完整长度。RF 采用统一事务、Outbox/Inbox、持久任务和日志机制；OTel/W3C 是追踪接入参考。Azure VM 到 AKS 的演进必须另行验证身份、持久化、并发领取和备份恢复。

RRF 是排名融合：图中两个列表使用 `1/(60+名次)` 加分，名次从1开始；参数60是示例。read/packed是访问阶段，当前策略只给成功read去重计热，packed不重复计热。PRD要求阶段可区分且不重复计数，并未规定唯一热度公式。

## 实现差距与验收

已有基础不等于全部目标已实现。长文、Semantic、压缩质量、多成员冲突组、Recall持久恢复、真实P2执行、云身份与集中观测仍需按[当前实现登记](../../../../../交付成果/开发协作/01_当前实现与待办.md)逐项开发和验证。指标执行暂缓，不删除 PRD 产品要求。

本次只整合图和说明。四张图检查了文字宽度、元素引用、直角连接及不穿过非目标节点；未修改业务代码、PRD或宣称运行验收通过。
