# P2/P3 关系与接口说明
> 适用场景：P3 阶段方案评审、P2/P3 接口对齐、项目经理分派接口 owner。  
> 核心目标：用最少内容说清楚 P2 和 P3 的分工、数据流、接口和待确认事项。

---

## 1. 一句话关系

**P2 是数据引擎层，负责把对象、向量、图和 Segment 存好、查好、状态暴露好；P3 是语义层与调度决策层，负责把 Agent/RAG 数据语义化、记忆化，并根据语义价值和资源状态输出调度建议。**

简单说：

- **P2 管数据和状态**：对象、向量、图、Segment、索引、查询、内省、回调。
- **P3 管语义和决策**：Embedding、记忆、Context Pack、调度判断、调度建议。
- **P3 不实现 P2 的引擎**，P2 不做 P3 的语义价值判断。

---

## 2. 职责边界

| 事项 | P2 负责 | P3 负责 |
|---|---|---|
| 原始数据保存 | 保存对象、chunk、metadata | 判断哪些内容需要进入语义/记忆链路 |
| 向量能力 | 保存向量、建索引、ANN/Hybrid 检索 | B1 生成 embedding 并写入 P2 |
| 图能力 | 保存节点、边、属性，提供图查询/融合查询 | B2/B3 消费图关系用于追溯、召回、预取 |
| Segment 状态 | 暴露 Segment 列表、大小、索引、访问计数、状态 | B3 使用 Segment 状态做调度判断 |
| 记忆管理 | 提供底层对象/向量/图保存与查询能力 | B2 管理 Working/Episodic/Semantic Memory |
| 调度决策 | 不做语义调度策略 | B3 输出 Promote/Demote/Pin/Prefetch/Evict/Keep 建议 |
| 物理迁移 | 配合 P1/P2 执行组件完成执行和回调 | 不直接搬数据，只输出动作/建议 |
| 执行反馈 | 返回状态、耗时、错误码、资源变化 | 接收反馈，记录日志，调整策略状态 |

## 3. P2 给 P3 什么

| P2 输出能力                        | 给 P3 哪个模块    | 用途                           |
| ------------------------------ | ------------ | ---------------------------- |
| 对象数据 / ObjectMeta              | B1 / B2 / B3 | 原文追溯、记忆保存、调度对象建模             |
| 向量写入接口                         | B1           | 保存 B1 生成的 embedding          |
| ANN / Hybrid 检索接口              | B2           | 支撑历史记忆召回和 Context Pack 构建    |
| 图查询 / 子图 / 融合查询结果              | B2 / B3      | 支撑证据链追溯、关联召回、预取判断            |
| Segment 内省接口                   | B3           | 获取 Segment 状态、大小、索引、访问统计     |
| Segment 控制 / 迁移回调              | B3           | 支撑 Freeze、Unfreeze、迁移完成/失败反馈 |
| status / error_code / trace_id | B1 / B2 / B3 | 支撑联调、排障和验收追踪                 |

## 4. P3 给 P2 什么

| P3 输出内容 | 来自哪个模块 | 给 P2 哪个能力 | 用途 |
|---|---|---|---|
| embedding + metadata + source_id | B1 | P2-E1 向量引擎 | 向量落地和后续检索 |
| 记忆原文 / 摘要 / metadata | B2 | P2-E2 对象引擎 | 记忆持久化和来源追溯 |
| memory embedding | B1/B2 | P2-E1 向量引擎 | 跨会话记忆召回 |
| 记忆关系 / RAG 证据链 / Trace 关系 | B2 | P2-E3 图引擎 | 图关系追溯和关联召回 |
| Segment 调度建议 | B3 | P2 SegmentControl | 支撑分层调度闭环 |
| Freeze / Unfreeze 请求或建议 | B3 | P2 SegmentControl | 迁移前后的引擎侧状态控制 |
| 调度动作原因 / priority / trace_id | B3 | P2 / 监控 | 解释调度来源和追踪执行结果 |

## 5. 三条核心数据流

### 5.1 B1 → P2：Embedding 写入流

```text
P4 / Agent / RAG 输入
→ B1 做 chunk + embedding + metadata/source_id 绑定
→ P2-E1 保存向量
→ P2 返回写入状态、vector_ref、trace_id
```

重点：**B1 只生成语义向量，P2-E1 才是向量引擎。**

---

### 5.2 B2 ↔ P2：记忆保存与召回流

```text
B2 写入记忆
→ P2-E2 保存记忆原文/摘要/metadata
→ P2-E1 保存 memory embedding
→ P2-E3 可选保存 session-task-rag-evidence-memory 关系

Agent 推理前
→ B2 调用 P2-E1/E2/E3 召回相关内容
→ B2 生成 Context Pack 返回 P4/Agent
```

重点：**P2 负责查得出来，B2 负责组织成 Agent 可用上下文。**

---

### 5.3 B3 ↔ P2：Segment 调度闭环

```text
P2 暴露对象/Segment/图状态
→ B3 结合 memory signal 和资源状态做 Heuristic 判断
→ B3 输出 Promote/Demote/Pin/Prefetch/Evict/Keep 建议
→ P1/P2 执行或模拟执行
→ P2 返回执行反馈、状态变化、错误码、trace_id
```

重点：**B3 不直接搬数据；P1/P2 执行，P2 返回状态与回调。**

## 7. MVP 最小接口清单

12 月 1 日前，P2/P3 至少需要对齐以下接口：

| 编号 | 接口 | 方向 | 用途 | 优先级 |
|---|---|---|---|---|
| IF-01 | 对象/原文/metadata 获取 | P2 → P3 | B1/B2 追溯原始内容 | P0 |
| IF-02 | Embedding 写入 | P3-B1 → P2-E1 | 向量落地 | P0 |
| IF-03 | 向量检索 | P2-E1 → P3-B2 | 记忆召回 | P0 |
| IF-04 | 记忆对象保存/更新/删除 | P3-B2 → P2-E2 | 记忆持久化 | P0 |
| IF-05 | Segment 内省 | P2 → P3-B3 | 调度状态输入 | P0 |
| IF-06 | 调度动作建议 | P3-B3 → P1/P2 | 输出 Promote/Demote/Pin 等 | P0 |
| IF-07 | 执行反馈 | P1/P2 → P3-B3 | 闭环反馈 | P0 |
| IF-08 | 图关系写入/查询 | P3/P4/P2 ↔ P2-E3 | 关系追溯与预取 | P1 |
| IF-09 | trace_id / error_code 规范 | P2/P3/监控 | 联调排障 | P0 |

## 8. 当前最需要确认的问题

| 问题 | 影响 |
|---|---|
| P2 向量写入接口何时可用？ | 决定 B1 是否真实写入 P2 |
| P2 是否保存 chunk 明文，还是只保存 object 引用？ | 影响 B2 Context Pack 构建 |
| source_id、chunk_id、memory_id、object_id 是否统一？ | 影响全链路追溯 |
| P2 向量检索是否支持 tenant/user/agent/status 过滤？ | 影响 B2 安全召回 |
| Segment 内省字段有哪些？ | 影响 B3 调度对象建模 |
| 调度动作是建议式还是执行式？ | 影响 B3 与 P1/P2 边界 |
| 图引擎当前阶段是否提供最小关系图？ | 影响 B2 追溯和 B3 预取演示 |
| P1/P2 执行反馈字段是什么？ | 影响调度闭环和评审材料 |
| trace_id、error_code 是否统一？ | 影响联调排障 |
| 12 月 1 日 MVP 是否允许部分接口 mock？ | 影响交付风险 |
