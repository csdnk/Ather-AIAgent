我们是 A：负责 Recall 最终上下文的端到端正确性、SemanticEmbeddingCapability，以及 VectorProjectionPort 的写入、查证、删除和 ProviderResult。

B 决定 Memory/chunk、版本、生命周期、正文映射、语义/冲突策略、投影构建编排及 ProjectionState。C 决定调层、预热、释放与策略效果。P2 提供实际存储和索引事实。RF 提供共享身份、持久化和事件基础机制。

因此，A 生成 Passage 向量后先交 B；B 批准投影后再调用 A 的写机制。A 的 READY 只表示有证据的机制完成，B 仍需执行 Ready Guard。在线 Recall 不负责补写索引或重新预热。

## 2. 两条需要实现的流程

### Recall 在线读流程

```text
请求与可信授权证据
  → 校验、scope_union_v1 选路、准入及幂等绑定
  → Query Embedding（working_only 跳过）
  → Working / 长期向量候选发现
  → B 候选事实与资格核验
  → B 正式映射 → 内联正文 / 可选 Prewarm / 正式存储读取及校验
  → 内容身份去重、来源排名融合、B 语义与冲突策略
  → 全部已加载可组装候选最终复核、整组预算与完整渲染计数
  → ContextPack + 终态 + 最小 Trace + 已发生事件 Outbox 可靠提交
  → 交付，并按真实时点分别记录发出、接收和模型使用
```

- 两类来源都适用则 combined，仅 Working 则 working_only，仅长期则 long_term_only；客户端不传模式。明确非法或越权的 session/task 不能丢掉后继续查询。
- 模式受理前确定，受理后不因服务故障或缓存状态改变。Working 是独立来源；Prewarm 是正文加速路径。
- 先完成 Query 阶段，再进入候选发现；发现阶段的 Working 和向量搜索可以并发。
- 同键请求附着同一执行；各阶段共享原 deadline，读取前预占次数和字节。崩溃不能重新获得预算。
- 最终复核覆盖替补候选；不同版本正文不能在原候选上悄悄替换。
- 四终态为 COMPLETE_AVAILABLE、COMPLETE_EMPTY、DEGRADED_AVAILABLE、FAILED_UNAVAILABLE。故障零条不算正常空，正常预算裁剪不自动降级，提交未知时不发布正文或业务终态。

### Embedding 与向量投影流程

```text
B 准备获批片段 → A Passage 推理 → 合法向量与模型/输入绑定交 B
B 批准目标 → A 保存投影请求和稳定操作身份 → P2 写入
  → 查询原操作 / 核验准确目标与索引事实
  → A 保存 ProviderResult → B Ready Guard → B 更新领域状态

Recall Query → 同一共享能力的 Query 推理 → 已验证向量 → 向量搜索
```

Query 不写长期索引，纯 Embedding 不自动分块或写库。模型、预处理、usage、输入摘要与检索空间须显式绑定。Query/Passage 需要独立队列与执行资源；按 usage 分 batch 本身不等于资源隔离。

投影目标绑定租户、Provider、检索空间以及 `memory_id/chunk_id/memory_version/model_version/projection_schema_version` 五元组。响应丢失先查原操作，普通 not_found 不证明未产生效果。同五元组 rebuild 当前明确拒绝；删除完成还须证明旧写不会复活。

## 3. 现有源码入口与差异

目前主调用链是：

```text
api/routers/context.py
  → MemoryRuntime.build_context
  → application/services.py::BuildContextUseCase
  → memory/retrieval/service.py::ContextRetrievalService
  → sources.py 中的多个 RecallSource
  → pipeline.py::RecallPipeline
  → augment_context 组装 ContextPack
```

[Composition Root](../../../AgentJYS-main/src/aether_agent_memory/bootstrap/container.py) 当前注册 Working、Episodic、Semantic、Long Document、Context Catalog 五个适配来源。新设计的 working/long_term 是业务覆盖模型，不能直接将五个适配来源的数量当作新来源状态。Catalog 中 Resource/Skill/Session 的既有行为需要保留兼容边界，不能未经过 Memory 资格契约就混入新 Recall。

| 流程 | 当前源码依据 | 实现差异与处理方向 |
|---|---|---|
| 请求与选路 | [context/models.py](../../../AgentJYS-main/src/aether_agent_memory/context/models.py)、[application/services.py](../../../AgentJYS-main/src/aether_agent_memory/application/services.py)、[application/scope.py](../../../AgentJYS-main/src/aether_agent_memory/application/scope.py) | 当前 ContextRequest 要求 session_id，max_tokens 有默认值；BuildContext 要求 session scope。新契约须支持无当前会话的授权长期检索、显式预算和内部选路。现有 scope 字段一致性检查不能代替可信授权证据 |
| 状态与幂等 | [retrieval/service.py](../../../AgentJYS-main/src/aether_agent_memory/memory/retrieval/service.py) | 当前主流程没有设计中的 RecallExecution、Checkpoint、读取账本与最终提交恢复对象。需要持久化状态推进，不能只新增一个状态字符串 |

| 候选发现 | [retrieval/sources.py](../../../AgentJYS-main/src/aether_agent_memory/memory/retrieval/sources.py)、[retrieval/models.py](../../../AgentJYS-main/src/aether_agent_memory/memory/retrieval/models.py) | 已有来源适配、部分结果和异常收集。需补两类来源的完成证据、稳定引用与有界范围；不能仅由返回列表推导完整 |

| 提交与观察 | [retrieval/service.py](../../../AgentJYS-main/src/aether_agent_memory/memory/retrieval/service.py)、[application/services.py](../../../AgentJYS-main/src/aether_agent_memory/application/services.py) | 当前 Trace 保存异常被吞掉，选中 memory_id 生成简化 AccessTrace。新流程须区分诊断日志与可靠业务证据，原子提交结果/终态/最小 Trace/Outbox，交付后的事件另按实际发生记录 |
| 共享 Embedding | [b1/models.py](../../../AgentJYS-main/src/aether_agent_memory/b1/models.py)、[b1/pipeline.py](../../../AgentJYS-main/src/aether_agent_memory/b1/pipeline.py)、[b1/sidecar_client.py](../../../AgentJYS-main/src/aether_agent_memory/b1/sidecar_client.py) | 已有推理后端、Query/Passage 调用与数值检查；旧 EmbeddingPipeline 同时分块、推理和 sink.upsert，不能直接当新纯向量能力。需增显式模型/输入契约、可靠执行绑定、结果复用与唯一重试协调 |
| 推理隔离 | [b1/batching.py](../../../AgentJYS-main/src/aether_agent_memory/b1/batching.py)、[b1/sidecar.py](../../../AgentJYS-main/src/aether_agent_memory/b1/sidecar.py) | 当前按 input_type 与长度分 batch，但 Sidecar 使用一个动态调度器。需补 Query/Passage 独立准入、队列和执行额度，再测混合负载 |

当前 [P2 proto](../../../AgentJYS-main/engine/proto/aether_engine.proto) 的 VectorService 有 InsertVector、DeleteVectors、SearchVector；没有设计所需的按原操作键查证或准确向量目标 readiness 查询。已有对象 Get/Range/Head 不自动证明版本绑定和受限接收能力。具体适配以[与 P2 对接文档](运行时详细设计_V0.1/召回与P2接口对接需求_V0.1.md)和 AL 签收为准。

## 4. 按流程推进的开发批次

| 批次 | 可交付代码范围 | 验证重点 |
|---|---|---|
| 0：本地契约和测试基座 | Recall/Embedding/Projection DTO、错误枚举、配置约束、typed Ports；有状态 Provider 与持久化测试替身 | 原字段/版本与主设计一致；测试替身明确标识；业务层不出现 if mock |
| 1：受理与执行 | scope_union_v1、可信授权输入、过滤规范化、准入、幂等指纹、十三态、CAS/租约/Checkpoint；预留读取账本与提交身份 | 三种模式、非法模式字段、显式越权、不适用类型、同键冲突/并发、配置变化后原绑定不变 |
| 2：共享 Embedding 与 Query 阶段 | usage/model/source_hash/space 绑定、向量验证、独立队列与执行额度、已完成结果复用、共享执行协调；Recall 固定附着绑定 | Query/Passage 不串用；NaN/Inf/零向量/错维度/错模型拒绝；回包丢失重启不倍增推理 |
| 3：候选发现 | WorkingRead 与消费向量的 VectorSearch 适配、SourceReadResult、VectorCandidateSet、来源快照 | 完整空/partial/故障分开；长期失败仍保留原 combined；未发现直接收尾也有两份真实来源记录 |
| 4：资格与加载 | B 事实读取、正式映射、独立校验、可选 Prewarm 回退、读取账本与字节预占 | 未授权不加载；旧版本不偷换；缓存失败正式回退成功不降级；并发及崩溃不突破总字节预算 |
| 5：排序与装配 | 内容身份去重、稳定代表、RRF、B 策略、冲突原子组、模板/tokenizer、全候选最终复核 | 重复不放大；交换完成顺序不改变代表；替补无最终证据不得入包；整包 token 不超限 |
| 6：可靠提交与交付 | 四终态判定、原子最终提交、提交未知查证、过期隔离、Outbox、同键重放与分期清理 | 故障空不报正常空；提交未确认不发正文；迟到成功不能覆盖已隔离代际；P-16=0 仍保留必要绑定 |
| 7：投影写机制交付 | 五元组目标、操作幂等、状态查询、ProviderResult、删除屏障、更新与重建拒绝 | 元数据证据引用变化不改变语义摘要；缺完成证据不 READY；删除不复活；同目标 rebuild 不调用 P2 |
| 8：集成及验收 | 新旧入口映射、正式 Adapter、访问事件映射、可选归因与生产指标 | L2 替身契约与 L3 真实联调分别出证据；混合负载与隔离负载分别测量 |

批次按依赖推进，不表示写机制必须等在线 Recall 全部完成：批次 0 同时定义 SemanticEmbeddingCapability、VectorProjectionPort 和有状态向量模拟器，满足 A 工作包第一批要求；共享契约稳定后，投影机制可以提前交付 B。Recall 主流程仍按八阶段逐段实现。

读取预算与可靠提交属于第一批架构约束，不能在最后才给现有列表流水线补装饰性状态。后续批次逐步实现其行为，首个可交付闭环也必须经过安全复核与可靠提交。

## 5. 首个编码增量的具体范围

建议先实现批次 0/1：独立的新请求 DTO、SourceSelection、配置校验、错误码、状态转换与测试 Ports；用稳定授权快照验证自动选路，并定义原子受理/附着接口。

推荐在现有包内按能力分区：


这些是建议路径，目前未创建。新 Recall 内部对象与旧 ContextRequest/RecallCandidate/ContextPack 明确区分，通过适配层接入现有 Facade。旧 Northbound v1、Catalog 行为和 B 的领域投影执行器需要兼容测试，不直接全局改名或扩大 A 的所有权。
