# 召回与调度优化接口对接需求 V0.1（Operate，精简版）

更新：2026-09-07。维护方：Recall；对接方：Operate / C。B 指 Remember，RF 指 Runtime Foundation。本文件整理双方的可读事实、访问记录和核验结果；未确认的接口保证、责任和证据集中维护在[跨模块待确认事项](跨模块待确认事项_V0.1.md#4-operate--c)。

下列编号是能力与信息需求，不是要求新增 6 个 API。实际读取/订阅/报告通道由相应 Owner 用既有契约确认；问题全部待确认，联调场景全部待执行。

## 1. 双向接口与信息交接

| 对接项 | 方向与能力 | 需要交接的内容 | 责任与适用范围 |
|---|---|---|---|
| RC-01 | C/B/Provider → Recall：预热表示与读取约定 | Recall 使用 B 已批准的内容引用、版本、范围和授权；需确认可用热副本表示、与 Working 的隔离、失效/miss 与权威回退语义 | B 确认内容资格与读取契约，C 确认预热生命周期，Provider 提供字节。经内容加载适配链读取，不直读 Redis key；对应 IF-05 |
| RC-02 | C/Provider → Recall 旁路任务：成功动作与关联证据 | Recall 指明待核验动作/表示范围；需要成功证据、目标 Memory/表示版本、实际副本/来源、完成后 generation 或等价唯一关联证明及有效时间 | C 拥有动作事实，Provider 拥有物理观察，Memory 事实仍归 B；只读已有证据，不新增 C 证据对象；对应 IF-11 |
| RC-03 | C/Provider → Recall：释放、更新和失效观察 | 需从已确认读取/证据通道辨认并发 Release、版本变化、过期或更高 generation；Recall 隔离旧副本并在剩余预算内回退 | C/Provider 确认既有并发行为；Recall 不设置 C 的 TTL、租约或 Release 前置条件；确认 Provider 是否已内部回退，避免重复回退 |
| RC-04 | RF/C → Recall 旁路任务：遥测完整性证据 | 需知道必要事件是否到齐、覆盖范围、空洞、迟到和时间可信度，用于本地窗口评估 | 使用原 Owner 的已有证据；不要求创建 VerificationWindow 对象，不定义 RF/C 水位、保存期或消费状态 |
| RC-05 | Recall → RF → C：访问事实 | Recall 按真实时点提供候选、校验、加载、选择、Context 发出与请求结果，及可追溯的 Memory/表示/版本、时间和关联证据 | Recall 本地观察按获批 AccessTraceCapability 契约映射；Schema/Ingest 归 RF，C 消费；不直写 C 内部存储或新建同步回调；对应 IF-10 |
| RC-06 | Recall → C：预热使用核验记录 | 提供可追溯的加载/Context 命中、不可验证原因、证据覆盖与评估版本；有实际调用方证据时才报告模型请求使用 | PlacementVerificationRecord 及事实核验说明由 Recall 维护，具体交付方式待确认；C 汇总结果开展策略效果评估，Recall 不回写 C 的 TierAction 或 Plan |

既有双向关系的依据：[Operate 总流程](../../operate流程/AetherStore_P3_Operate_Optimize_Overall_Flow_V1.0.md) 第 5.2 节明确 Recall→共享 Trace Store→C；[Recall 验证设计](召回流程详细设计_V0.1.md#53-向-operate-提供预热使用证据a-04)列出反向证据需求与本地核验产出。RC-01～RC-04 的具体获取方式及 RC-06 的报告交付仍须确认，不当作已经实现的服务。

## 2. 责任与处理边界

模式由 Recall 按[主设计 3.1](召回流程详细设计_V0.1.md#31-校验请求并选路)内部决定；C 不参与该决策，也不需要提供模式判别接口。Prewarm 的有无、命中或释放都不改变 Working/长期必需来源；对 C 仍只交付已确认契约允许的真实访问事实，不把内部 SourceSelection 自动扩成共享事件字段。

- 不调用 C 的调层控制 Port，不在在线 Recall 链路等待 C 完成 Promote/Prefetch/Release。Recall 不把 C 的调度决策作为自身请求的前置条件；可选预热/归因不可用时仍可使用可信权威正文。
- Prewarm 仅用于 B 已认可的同版本正文或 Artifact，不把 Working key 当热副本，也不把向量搜索命中算作正文加载命中。缓存失败但权威回退成功不自动降级；归因证据不足不等于正文不可用。
- Prewarm/正式回退统一使用主设计 3.5.1 的调用前预占账本；内部回退须在整次获准响应上限内，不触发第二次重复回退。实际字节未知时预算按预留全额扣费，但访问统计保持未知，不能把保守扣费当作 C 的真实流量或成本；剩余字节不足以保障首次正式回退时跳过可选 Prewarm。
- 不用 desired_tier、同一 Memory 或时间接近证明动作命中。关联必须有相符租户、Memory/表示版本、实际副本与有效窗口；使用完成后的 generation 或原契约认可的等价关联，不盲目要求等于执行前 generation。多动作不能重复认领同一次读取。
- RC-05 只发送真实观察：已加载不等于已选中，已选中不等于已发出；已发出不保证实际调用方已接收，实际模型使用需要实际调用方证据。空结果不伪造 Memory ID，超时不伪造成 miss，本地 observation_type 不冒充 RF 共享枚举。
- Recall 负责本地可靠记录、Outbox 和按原契约补发；RF 接收确认不等于 C 已消费。C 自行确认消费、去重与热度口径；不能把 Recall 多阶段事件的 true 标志直接相加来推断访问次数。
- RC-06 的充分正向 Context 命中可先确认；未完整闭窗、缺覆盖证据时不能下否定结论或计作 miss，C 用于策略评估的正式比率只取完整闭窗样本并报告覆盖率。迟到证据产生新评估版本，不覆盖历史结论。动作尚未成功或不属正文/Artifact 范围时不进入本版成功预热样本。
- C 决定热度、阈值、防抖、放置计划和动作，并负责策略命中率、成本与延迟收益的评估；Recall 提供使用事实和关联核验说明，不单凭命中关联宣称调层造成性能改善。预算与时间容差只引用[参数目录](召回流程详细设计_V0.1.md#参数目录)，不是向 C 单方面下达生产 SLO。

## 4. 联调验收要点

以下是待执行要求，不是已完成测试。只验证 Recall 的消费/生产行为及双方确认的交接，不借此定义或测试替代 C 的调度算法。

| 场景编号 | 场景与验收要点 | 对接项 |
|---|---|---|
| RCT-01 | 授权、内容/Memory 版本或表示不符的热副本不可输出；Working 与 Prewarm 不混用，也不跳过 B 校验 | RC-01 |
| RCT-02 | miss/失效后权威回退成功不自动降级；Provider 已内部回退时不重复回退或伪称预热命中 | RC-01、RC-03 |
| RCT-03 | 读取期间 Release、过期或 generation 变化；旧副本隔离，必要时回退，不由 Recall 触发调层补救 | RC-03 |
| RCT-04 | 成功动作的同版本实际副本唯一命中才可关联；旧版本、来源不明或多个动作难以唯一分配时不可归因 | RC-02 |
| RCT-05 | 只检索、只加载、只选择、已发出及无实际调用方回执分别核对；不虚构 Context 发出或实际模型使用，未知不当 false | RC-05 |
| RCT-06 | Outbox 重启、重复、乱序、积压和补发保留稳定身份；RF 已接收但 C 尚未消费时，不伪造消费成功 | RC-05 |
| RCT-07 | 窗口未结束或存在空洞时不判未命中；充分正向证据可先确认，但未完整闭窗不进入正式比率 | RC-04、RC-06 |
| RCT-08 | 新迟到证据生成新评估版本；报告能追溯原证据和未知原因，不覆盖历史或改写 C 状态，不把相关性当因果改善 | RC-02、RC-06 |
| RCT-09 | Prewarm 断流、释放或崩溃后未知接收量：额度保守扣费，真实字节统计保持未知；正式回退另占额度，成功回退不因缓存故障降级 | RC-01、RC-03、RC-05 |
