# 召回数据定义 V0.1

更新：2026-09-07。维护方：Recall。定位：当前 Recall 设计范围内的规范化数据字典，作为后续逐接口对接的输入基线；不是外部接口已确认稿，也不是数据库实现或生产就绪证明。

## 阅读入口：按流程查找对象

**第 1～18 章定义 Recall 对象，第 19～25 章补充 Embedding 与向量投影机制对象，一章定义一个主要对象。** 先看该章的用途、产生时点和上下游，再看字段、嵌套结构、约束与保存方式。对象已有的完整示例紧接本章；公共字段和复用类型保留引用，统一在[附录 A](#types)维护。

先定义“Recall 内部需要保存和判断什么”，再据此向外部 Owner 提出信息需求。本文定义 A 自有的 Recall 请求与结果，以及 Embedding 和向量投影机制的规范化请求、执行与 ProviderResult。Memory、Working、ProjectionState、内容映射、TierAction、P2 原始响应、共享 AccessTrace 和实际调用方回执仍由原 Owner 定义；规范化字段不要求对方返回同名字段。

单一维护位置：

- **字段、类型、必填/可空、主键和引用：本文各对象章节及附录 A。**
- 流程、排序/预算、失败/降级、事件时点和归因规则：[召回流程详细设计](召回流程详细设计_V0.1.md)；完整执行状态机仍只在[总流程第 2.2 节](../AetherStore_P3_Recall_Overall_Flow_V1.0.md)。
- 数值阈值仍只在[参数目录](召回流程详细设计_V0.1.md#参数目录)，本文不复制第二套默认值。
- 外部确认状态只在[跨模块待确认事项](跨模块待确认事项_V0.1.md)。对接文档消费本地字段定义，不据此宣称 Provider 已支持草案。

字段表中的“必填”表示 Recall **内部记录必须具备该字段**，不表示调用方必须传入。尤其是 retrieval_mode、source_selection 和 allowed_sources，均由 Recall 内部生成，外部请求不传。字段填不出来时，按可空条件和失败规则处理，不能伪造数据，也不能把不可验证的候选继续装入 Context。

## 1. RecallRequest：Recall 内部标准请求

### 1.1 用途与流转

| 项目 | 定义 |
|---|---|
| 用途 | 保存受理后、已经完成授权范围规范化与内部选路的标准请求，作为本次执行固定的输入。 |
| 产生时点 | 入口格式、授权与准入通过后创建；运行期请求校验阶段继续检查绑定和最新权限。 |
| 输入依据 | 调用方提供的 Query、范围、现有筛选、预算和幂等键，以及已验证的身份、授权和固定 Recall 策略。 |
| 外部输入边界 | 调用方和 P4 不提供 retrieval_mode、source_selection 或 allowed_sources；Recall 核验范围、权限与类型筛选后自行生成这些值。 |
| 后续使用 | [RecallRequestIndex](#request-index) 与 [RecallExecution](#recall-execution) 固定引用它；后续向量、来源读取、装配及重放均以此为准。 |
| 主键 / 唯一约束 | tenant_id + recall_id；request_ref 为同租户受控别名。 |

**本章定义 Recall 在服务端构造的内部对象。** 外部调用方经 P4 转交 Query、范围、现有筛选与预算等原始输入；Recall 按[详细设计 3.1](召回流程详细设计_V0.1.md#31-校验请求并选路)核验授权并决定模式，再把输入与计算结果保存为 RecallRequest。新入口收到客户端传入 retrieval_mode、source_selection 或 allowed_sources（含筛选内同名字段）时，按已有规则返回 REQUEST_INVALID。

<!-- recall-type: RecallRequest; base: OnlineHeader; kind: record -->
### 1.2 字段定义（Recall 内部记录）

**公共字段：** 继承 [OnlineHeader](#online-header)，包含 `schema_version`、`tenant_id`、`created_at`、`recall_id`、`request_id`、`trace_id`。这些字段在内部记录中同样必填；下表的“必填”只检查 Recall 构造完成后的记录，字段由谁提供以“来源 / 定义”为准。

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| request_ref | Id | 是 | 本地标准请求的受控引用 | 与 RequestIndex、Execution 指向一致 |
| query | string | 是 | 校验后的非空 Query | 不超过 P-01；不做隐式语义改写，规范化方式固定在 policy |
| retrieval_mode | RetrievalMode | 是 | **Recall 内部计算，外部不传**；对已授权且符合范围、类型约束的适用来源取并集后生成 | 与 source_selection 的 eligible 来源一一对应；执行中不变；客户端传入则拒绝 |
| source_selection | SourceSelection | 是 | **Recall 内部生成，外部不传**；保存本次来源选择理由 | 同时绑定授权证据、scope、筛选与策略；禁止客户端赋值 |
| scope | Scope | 是 | 认证/授权求交后的范围 | 不能因来源不可用扩大范围 |
| principal_ref | Id | 是 | 可重验的调用身份引用 | 不保存认证 token |
| authorization_ref | EvidenceRef | 是 | 本次已验证授权的受控证明 | 重放/发出前仍需复核，不等于永久授权 |
| idempotency_key | Id | 是 | 上游幂等键 | 只在 tenant + principal + scope 内唯一 |
| request_fingerprint | Hash | 是 | A 对执行语义的规范化摘要 | 输入集合见本节下文；不包含自身 |
| deadline_at | Timestamp | 是 | 上游期限与 P-02 上限取较早值 | 已过期拒绝；重启和重试不延长 |
| token_budget | uint | 是 | 上游明确给出的预算 | 0 < token_budget <= P-03 |
| tokenizer_id | Id | 是 | 已认可的精确计数器 | 与实际注入方式匹配，未知组合拒绝 |
| tokenizer_version | Version | 是 | 固定 tokenizer 版本 | 不随默认模型更新漂移 |
| template_version | Version | 是 | 固定的上下文注入模板版本 | AL-P403 需确认实际模板 |
| retrieval_constraints | RetrievalConstraints | 是 | Recall 规范化外部类型/时间筛选，选路后内部派生 allowed_sources；外部不传 allowed_sources | 类型保存筛选意图，各分支只用其适用部分；不能扩大 scope 或在执行中改来源 |
| retrieval_space_ref | ContractRef? | 是 | 本次长期检索空间及模型绑定的只读引用 | working_only 为 null；其他模式必须有值，消费既有批准配置 |
| policy_version | Version | 是 | 服务固定的 Recall 参数、类型展开及选路算法版本 | 本次示例为 design-v0.1-source-union-v1；整次执行及同键重放沿用该版 |

### 1.3 嵌套结构与公共类型

本对象专属的嵌套结构在本节完整定义：[SourceSelection](#source-selection)。它们继承父记录的租户与 schema 上下文，不增加独立记录的公共头。

本章复用的公共结构：[Scope](#scope)、[RetrievalConstraints](#retrieval-constraints)、[Hash](#hash)。字段中的标量、枚举及 Ref / EvidenceRef / ProtectedRef 等引用语义见[附录 A.1](#scalar-types)。引用仅保存受控标识，不递归嵌入目标记录。

<!-- recall-type: SourceSelection; base: none; kind: value -->
#### SourceSelection：Recall 内部选路依据

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| strategy | Version | 是 | Recall 固定的选路算法标识，本版 scope_union_v1 | 与父请求 policy_version 绑定；调用方不能选择或覆盖 |
| working_eligibility | SourceEligibility | 是 | 当前会话/任务、授权及类型约束的本地判定 | 按无当前范围 → 未授权 → 类型排除 → eligible 的优先级；no_current_scope 仅在两个 ID 均 null 时成立 |
| long_term_eligibility | SourceEligibility | 是 | 长期范围读取授权及类型约束的本地判定 | 按未授权 → 类型排除 → eligible 的优先级；不能使用 no_current_scope |

这是 RecallRequest 内嵌值，不新增记录表或外部事实对象。依据来自父请求已验证的 scope、authorization_ref、retrieval_constraints 和 policy_version；不能仅靠此本地枚举证明授权。授权未知/显式范围非法时受理前拒绝，不伪造 not_authorized。eligible 来源取并集后必须与 retrieval_mode 和 allowed_sources 一致；没有 eligible 不产生受理后的 RecallRequest。策略不读实时服务健康，也不根据 Query 文本猜测来源。

### 1.4 约束与保存

fingerprint 对 query、scope、retrieval_mode、source_selection、retrieval_constraints、token_budget、tokenizer_id、tokenizer_version、template_version、retrieval_space_ref、policy_version 计算；不含 request_id、trace_id、created_at、deadline_at、request_ref、authorization_ref 或凭证。principal_ref 已由幂等唯一键限定；新授权证明的引用 ID 不应制造语义冲突，真实权限仍必须重新验证。

同键重试先按租户/身份/Scope 定位旧执行，使用旧 policy_version 规范化这次显式 Query、筛选和预算，并保留旧模式、source_selection、模板/模型空间绑定再比较 fingerprint；不能用新默认策略重选或覆盖变更输入。新增权限不扩大原模式，撤销原来源权限则安全拒绝，不缩成单来源重放。策略升级影响新键新执行，不追溯改写旧结果。

此前的自动选路调整将 RecallRequest 升级到 recall-request-0.2。本次为执行账本、来源记录和最终复核补齐必填字段，新的 Recall 独立记录使用 recall-data-0.2；请求版本仍为 recall-request-0.2，共享外部 Schema 不变。旧记录不能靠补零账本、默认来源或猜测提交状态自动迁移；只有受控旧版读取/复核可用时才重放，否则 REPLAY_REVALIDATION_REQUIRED。不得用新请求重写旧执行或重新取得已消耗额度。

RecallRequest 是受理后的本地对象；格式/授权/准入已拒绝的原始输入不为凑字段而虚构一条执行。运行中的 Request Validation 仍可检查绑定、一致性和最新权限；请求级拒绝与已受理后的失败区分见 A-02。

**保存与引用。** 保存为 request_ref 可恢复定位的受控请求载荷，与请求索引和首次 Execution 一致提交；Query 不进入索引或普通日志。保留、删除及幂等键重用遵循已确认规则，不能承诺永久可重放。

## 2. RecallRequestIndex：幂等绑定

### 2.1 用途与流转

| 项目 | 定义 |
|---|---|
| 用途 | 将同一租户、身份、范围内的幂等键绑定到首次请求与执行，用于判断重试应复用还是拒绝。 |
| 产生时点 | 首次受理时与标准请求、Execution 一致建立；同键重试先查询既有绑定。 |
| 输入依据 | [RecallRequest](#recall-request) 的身份、规范化 Scope、幂等键和请求语义摘要。 |
| 后续使用 | 通过 request_ref 定位 [RecallRequest](#recall-request)，通过 recall_id 定位 [RecallExecution](#recall-execution)。 |
| 主键 / 唯一约束 | tenant_id + principal_ref + scope_digest + idempotency_key。Hash 按完整规范值参与唯一比较。 |

<!-- recall-type: RecallRequestIndex; base: RecordHeader; kind: record -->
### 2.2 字段定义

**公共字段：** 继承 [RecordHeader](#record-header)，包含 `schema_version`、`tenant_id`、`created_at`。这些字段同样必填；下表定义本对象专有字段。

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| principal_ref | Id | 是 | 首次受理的身份引用 | 与请求一致 |
| scope_digest | Hash | 是 | 对完整规范化 Scope 的摘要 | 唯一键比较完整摘要值及算法，不跨 scope 复用 |
| idempotency_key | Id | 是 | 首次受理的幂等键 | 不覆盖旧绑定 |
| request_fingerprint | Hash | 是 | 请求语义摘要 | 与 RecallRequest 相等 |
| recall_id | Id | 是 | 首次受理创建的执行 | 与请求/执行一致 |
| request_ref | Ref<RecallRequest> | 是 | 不可变标准请求引用 | 与执行建立同一可靠提交边界 |

### 2.3 嵌套结构与公共类型

本对象没有专属嵌套结构。

本章复用的公共结构：[Hash](#hash)。字段中的标量、枚举及 Ref / EvidenceRef / ProtectedRef 等引用语义见[附录 A.1](#scalar-types)。引用仅保存受控标识，不递归嵌入目标记录。

### 2.4 约束与保存

索引只存绑定，不存 Query 正文；其保留由关联 Execution.retention.metadata_retain_until 和未解决恢复状态控制，不能直接套用 P-16。正文清除后仍保留原 fingerprint、策略/规范化绑定及结果不可重放标记；同键不能视为新请求。正常窗口结束后的键重用仍须按 AL-P401、AL-B06、AL-RF02 确认，确认前不自动开放旧键重用，不单方面承诺永久幂等。

**保存与引用。** 逻辑集合为 recall_request_index。首次绑定可靠提交后不被同键不同 fingerprint 的请求覆盖；索引随执行的最小元数据清理，不随正文删除。完整规则见附录 B.3。

| payload_state | string | 是 | retained 或 cleared | 清除后不得把同键当新执行 |
| payload_cleared_at | Timestamp? | 是 | 敏感载荷实际清除时间 | cleared 必填；retained 为 null |

保留控制可在终态后独立 CAS 更新，不改变终态/原摘要。运行中、提交未知或 attention_required 不按普通 TTL 删除最小绑定；法定/授权删除优先清正文，元数据按获准最小标记处理。分类型规则见附录 B.3。

### 3.4 约束与保存

租约字段补齐防旧执行者迟到写入的约束，不规定 RF 如何实现锁。终态后 state、result_ref/digest、业务结论和 completed_at 固定；last_event_sequence 等投递记账仍可 CAS 增长，不能借此改写原结果。清除敏感载荷不回退终态。

**保存与引用。** 逻辑集合为 recall_execution，持久化且允许 CAS 更新。运行中不得因普通 TTL 丢失；终态正文按 P-16，执行/幂等/提交标记按 RecallRetention 和附录 B.3 保留。每次推进先确认阶段输出和本阶段调用账本可靠落地；最终提交之前 source_result_refs 必须闭合为两来源。

## 4. RecallCheckpoint：可靠阶段输出

### 4.1 用途与流转

| 项目 | 定义 |
|---|---|
| 用途 | 把某次阶段尝试已经可靠保存的输出、输入绑定和版本固定下来，供恢复和下一阶段使用。 |
| 产生时点 | 各 RUNNING 阶段确认输出时形成，早于 Execution 对应阶段的 CAS 推进；贯穿全流程。 |

### 4.4 约束与保存

同一阶段不同已证明输出不得覆盖旧快照；Execution 只引用本次合法推进采用的一份。工作来源仅返回引用时，证据和受控载荷必须在后续处理期可读；失效则重新验证或安全失败，不从断裂引用跳过校验。

**保存与引用。** 逻辑集合为 recall_checkpoint；检查点与其受控输出不可变。输出及摘要先可靠落地，再允许推进；终态后的正文载荷按 P-16 清除，恢复所需检查点元数据按 RecallRetention 保留，不能只保存进程内地址。

### 4.5 阶段输出对照

本表只为已有八个阶段绑定数据类型，不另立执行状态机。集合可以为空，但跳过、已确认空与失败必须在相应结果和 StageTrace 中区分。

| 既有阶段 | 可靠输出 / 受控引用 | 不能据此声称 |
|---|---|---|
| RUNNING_REQUEST_VALIDATION | RecallRequest 引用及 StageTrace 中的校验说明 | 已永久授权 |
| RUNNING_QUERY_EMBEDDING | QueryEmbeddingResult；working_only 以 StageTrace 说明跳过 | Passage 写入或 Projection Ready |
| RUNNING_VECTOR_SEARCH | 两份 SourceReadResult，长期分支适用时关联 VectorCandidateSet | Memory 已有效或正文可用 |
| RUNNING_CANDIDATE_VALIDATION | 各发现候选的 CandidateValidationResult | accepted 就是正文已加载 |
| RUNNING_CANONICAL_LOAD | ContentLoadResult，以及内容可信的 RecallCandidate | 已通过最终发出前复核 |
| RUNNING_RANKING | RankedRecallCandidates | 已实际进入 Context |
| RUNNING_CONTEXT_ASSEMBLY | RecallBudgetGroup、FinalValidationBatch 和 ContextPack 准备稿 | 准备稿已提交、已发出或被实际调用方使用 |
| RUNNING_TRACE_FINALIZATION | 提前失败时补齐的 SourceReadResult；与终态一致提交的 ContextPack、RecallTrace 和本地 Outbox | 已执行跳过的发现阶段、RF 已 Ack、C 已消费或实际调用方已接收 |

准备稿可先分配稳定引用和拟议结果，但不能凭本地字段发布终态。只有实际一致提交证明成立，才可作为正式结果交付。

### 8.4 约束与保存

**保存与引用。** 作为候选校验阶段检查点输出保存，保留实际读取的证据版本和检查时点；后续内容加载失败不覆盖初次 accepted 事实。

### 15.4 约束与保存

| observation_type | bytes 的唯一口径 | latency_ms 的唯一区间 |
|---|---|---|

| ContextSelected | null，避免重复计算已加载正文 | null；整包组装耗时在阶段 span |
| ContextEmitted | null，传输整包 byte 只在 delivery 级技术记录统计，不复制到每条 item | null；传输耗时在 delivery 级技术记录 |
| RecallCompleted | null；实际流量/保守扣费从唯一调用账本分开统计 | 同一可验证单调时钟下从受理到最终可靠提交的耗时，包含排队/恢复；跨重启无法可靠还原时 null |

加载失败没有成功加载事件，接收残留字节、失败及重试时长留在调用账本/技术 span。只在操作确实耗时为零或确实读到零字节时填 0；未知或不适用用 null。trace_delivery_lag 是本地 Outbox 首次可靠保存到本地收到并可靠保存 IngestAck 的可验证间隔，不能拿远端时钟直接相减；跨重启无法证明时报告未知。

**保存与引用。** 不可变事件载荷与 Outbox 投递进度绑定，受控引用解析；原事实、event_id、序号和摘要在重投时保持不变。必须删除的内容不因尚未 Ack 而继续保留或投递。

| provider_ref | ExternalId | 是 | 固定目标 Provider | 恢复不切换 Provider 盲写 |
| retrieval_space_ref | ContractRef | 是 | 固定目标检索空间 | 必须与向量兼容并获授权 |

| request_fingerprint | Hash | 是 | 固定请求语义摘要 | 范围见 21.4；同键不同摘要拒绝 |

### 21.3 嵌套结构与公共类型

#### ProjectionIdentity：原工作包的投影五元组

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| memory_id | ExternalId | 是 | B 的 Memory 身份 | 不生成新 Memory |
| chunk_id | ExternalId | 是 | B 的片段身份 | A 不接管切分规则 |
| memory_version | Version | 是 | B 本次构建/删除版本 | 与内容映射相符 |
| model_version | Version | 是 | 本次投影模型版本 | upsert 与向量实际版本相符 |
| projection_schema_version | Version | 是 | B/A 已对齐的投影 Schema | 不等于 Embedding 输出 Schema 或本地记录 Schema |

#### ProjectionPayload：一个准确目标的写入内容

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| embedding_result_ref | Ref<SemanticEmbeddingResult> | 是 | A 已验证的 Passage 结果 | 同租户、usage=Passage，模型/空间匹配 |
| representation_id | ExternalId | 是 | B 批准的投影表示关联 | 与 B 元数据契约一致 |
| content_ref | ExternalId | 是 | B 的正式内容引用 | 不把向量存储地址当正文地址 |
| content_version | Version | 是 | 本次正文版本 | 不能用新正文解释旧向量 |
| approved_range | ByteRange | 是 | B 本次片段的准确原字节范围 | 有范围与输入转换证据 |

| metadata_hash | Hash | 是 | 只对 scope、memory_type、occurred_at 的 JCS + UTF-8 字节做 SHA-256 | 排除 owner_metadata_evidence_ref、向量及原文；byte_encoding=jcs-utf8、range=null |

#### ProjectionMetadata：需要随向量保存的检索属性

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| scope | Scope | 是 | B 授权的该片段范围快照 | tenant 与请求一致；不能仅靠调用者 tenant 猜测可检索范围 |
| memory_type | ExternalLabel | 是 | B 确认的长期 Memory 类型 | 本版仅 Episodic / Semantic；不把 Working 直接写为长期投影 |
| occurred_at | Timestamp? | 是 | B 的业务发生时间 | 未知为 null，不能填本次写入时间；时间过滤缺事实时不得伪称支持 |
| owner_metadata_evidence_ref | EvidenceRef | 是 | Scope、类型、时间等源事实依据 | 不由 A 推断生命周期、衰减或冲突事实 |

P2 的实际存储载荷由本请求的 ProjectionIdentity、目标租户/空间、SemanticEmbeddingResult 的向量/模型/维度/Schema/摘要、ProjectionPayload 的正文/表示/范围，以及 ProjectionMetadata 的过滤属性共同组成。上述内容全部绑定同一准确目标；A 不上传未批准的原文或认证 token。

metadata_hash 的唯一计算输入为 `JCS({scope, memory_type, occurred_at})`，scope 所有维度按附录 A 出现，未知时间显式为 null。owner_metadata_evidence_ref 只定位批准依据，不参加语义摘要；引用变更后仍核验新证据支持相同三项值及当前授权。若任一语义值变化，必须改变摘要并按同键冲突处理；不得为了复用旧键删掉真实变化。P2 外发 metadata 正是这三项，因此对同一规范语义视图可重算相同摘要，外部属性编码差异须由适配还原后计算。

### 21.4 约束与保存

target_digest = SHA-256(JCS({tenant_id, provider_ref, retrieval_space_ref, identity}))。operation_key 在此基础上加入 operation_kind；因此写入与删除不互相冒充重试。摘要使用公共 Hash 规范，不截短或按字符串拼接。

request_fingerprint 的 JCS 对象固定包含 fingerprint_schema="projection-request-fingerprint-0.2"、tenant_id、provider_ref、retrieval_space_ref、identity、operation_kind；upsert 另包含 build_intent="initial_or_retry"、实际 model_binding、source_hash、input_binding_digest、vector_hash、representation_id、content_ref、content_version、approved_range、metadata_hash，delete 不包含这些 upsert 字段。上述 Hash 按完整规范结构参与计算。随机请求 ID、trace、瞬时授权/证据引用、等待期限及受控向量结果引用不进入摘要；重试沿用已绑定策略并重验权限。只更换证据或向量结果的受控引用且实际语义/向量不变可复用；content_ref 等明确参与计算的正式内容定位值改变则冲突，不能把它当作可忽略的引用。

本次摘要语义使用 projection-data-0.2。已有 0.1 请求/操作不得原地重算摘要或换键重写：能按原契约解释时只查询/重放原绑定，无法解释则拒绝并要求受控迁移；相同物理目标的旧幂等/退役标记仍生效。本文是开发基线，未假定存在可直接覆盖的历史生产数据。

不可变请求及 SemanticEmbeddingResult 作为受控载荷与操作初次创建一致绑定，不为每个载荷单建领域表。upsert 只处理完整单向量；多 chunk 分别建操作。build_intent=rebuild 在本版关闭；同目标普通重试复用已 settled 的原结果，不证明当前目标仍存在。新的合法构建代际及同版本重建统一见[待确认事项第 7 章](跨模块待确认事项_V0.1.md#7-同版本投影重建必须一起确认的决策)；不能通过新 attempt 或伪造版本绕过原绑定/退役屏障。

逻辑集合 projection_result。结果和操作最新引用在同一可靠边界确认后才可被 B 查询；V0.1 使用 submit/query 补取，不新增共享事件或强制回调。P2 原始证据、A 机制结论与 B 的领域 Ready 三者各自保留来源，B 的最终判断不写回本结果。

## 25. SemanticEmbeddingExecution：推理次数与结果恢复

### 25.1 用途与流转

| 项目 | 定义 |
|---|---|
| 用途 | 保存单次共享向量化调用的有界执行进度，不改写规范化请求。 |
| 产生时点 | 请求通过准入后、推理前，与请求引用一致保存。 |
| 输入依据 | SemanticEmbeddingRequest 与固定 EM 配置。 |
| 后续使用 | 重启后沿原 deadline/次数恢复；成功后关联 SemanticEmbeddingResult。 |
| 主键 / 唯一约束 | tenant_id + embedding_request_id；tenant_id + caller_ref + caller_request_ref 另唯一定位同一次调用。 |

### 25.2 字段定义

**公共字段：** 继承 RecordHeader，schema_version=embedding-data-0.1。

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| embedding_request_id | Id | 是 | 原共享请求标识 | 与 request_ref 一致 |
| request_ref | Ref<SemanticEmbeddingRequest> | 是 | 固定输入请求 | 同键换输入/usage/模型拒绝 |
| caller_ref | Id | 是 | 原调用身份 | 重取结果仍验证当前权限 |
| caller_request_ref | ExternalId | 是 | 原调用关联 | 不跨调用方复用幂等绑定 |
| state | EmbeddingExecutionState | 是 | queued/running/succeeded/failed | 不是 Recall 或 P2 机制状态 |
| attempts_reserved | uint | 是 | 推理前可靠占用次数 | 初始 0；批内每条请求各占一次；重启不归零 |
| deadline_at | Timestamp | 是 | 原执行截止 | 等于原请求 deadline_at，重放不延期 |
| execution_policy_ref | ContractRef | 是 | 原 EM 配置 | 沿用原重试/队列规则 |
| result_ref | Ref<SemanticEmbeddingResult>? | 是 | 已保存的可信结果 | succeeded 必须非 null，其他状态 null |
| error_code | EmbeddingErrorCode? | 是 | 最终推理/输入错误 | failed 必填；其他状态 null |
| lease_owner | Id? | 是 | 当前推理协调者 | 与 lease_until、lease_token 同有值 |
| lease_until | Timestamp? | 是 | 本次推进租约 | 失租回调不能写结果 |
| lease_token | Id? | 是 | 防旧推进者写入令牌 | 重新领取时变化 |
| state_version | uint | 是 | CAS 版本 | 更新时校验并递增 |

### 25.3 嵌套结构与公共类型

复用公共引用与时间类型，不定义 B Task。请求中的输入和模型是不可变事实，执行记录只改变本次推理进度。

### 25.4 约束与保存

逻辑集合 embedding_execution，请求及结果是关联的受控载荷。同一调用重试按 tenant_id + caller_ref + caller_request_ref 找到原绑定，再按原模型/策略核验输入语义；queued/running 只附着原执行，succeeded 取回原结果，failed 返回原失败，不新建推理。新增权限不扩大原输入范围。共享协调者独占 EM-04 推理重试；Recall 的 P-08 只控制附着/结果补取传输次数，不能将两者相乘。V0.1 不合并不同调用的在途计算；不同合法调用才有独立执行额度。

推理前以 CAS 递增 attempts_reserved，再执行；崩溃的未完成尝试仍占次数。原 deadline/次数允许时可重新执行纯推理，否则明确失败。结果及 result_ref/state 一致保存后才返回成功；批内各条独立提交，不使失败条目错位。数据清除后复用引用必须明确失效，不伪造仍可读取。生命周期、清除与最小合法幂等标记按 AL-RF05 确认。

## 附录 B. 跨对象一致性、存储与清除

各对象自己的保存方式已经写入对应章节的“约束与保存”；本附录集中说明 Recall 的七个逻辑集合及共享推理/投影机制的四个逻辑集合和提交边界。阶段输出类型已集中到 [RecallCheckpoint](#checkpoint)，评估去重与修订规则已放入对应评估对象章节。

### B.1 逻辑集合总览

| 逻辑集合 | 主键 / 唯一约束 | 记录 / 关联 | 生命周期 |
|---|---|---|---|
| recall_request_index | tenant_id + principal_ref + scope_digest + idempotency_key | RecallRequestIndex，关联受控 RecallRequest | 与执行创建一致提交；受保留/删除约束 |
| recall_execution | tenant_id + recall_id | RecallExecution，含读取账本、提交恢复、保留控制及唯一结果引用 | 运行中不静默 TTL；最小元数据按 RecallRetention，正文按 P-16 |
| recall_checkpoint | tenant_id + recall_id + stage + output_digest | RecallCheckpoint 及受控阶段载荷；checkpoint_ref 另唯一定位 | 输出先落地；载荷与恢复元数据分期清理 |
| recall_result | tenant_id + pack_id + pack_version；tenant_id + recall_id 唯一 | ContextPack 与同边界提交的 RecallTrace | 结果不可变；删除可使内容不可再重放 |
| recall_access_outbox | tenant_id + event_id；tenant_id + recall_id + event_sequence 唯一 | OutboxEntry 及不可变 RecallAccessObservation | 未 Ack 不静默 TTL；容量不足拒绝新准入 |
| recall_context_use_assessment | tenant_id + assessment_id + assessment_version | ContextUseAssessment，指向现有 Pack/item 和回执证据 | 可选旁路，实验期按 P-16；不阻塞在线结果 |
| recall_placement_verification | tenant_id + verification_id + evaluation_version | PlacementVerificationRecord，保留历史评估版本 | 可选旁路，实验期按 P-16；长窗口另确认 |
| embedding_execution | tenant_id + embedding_request_id；tenant_id + caller_ref + caller_request_ref 唯一 | SemanticEmbeddingExecution，关联受控请求/结果 | 原 deadline 与重试预算不重置；按 AL-RF05 清理 |
| projection_target | tenant_id + target_digest；target_binding_id 唯一 | ProjectionTargetBinding，含本机制退役屏障 | 覆盖写重放/迟到窗口，删除规则按 AL-RF05/AL-B08 |
| projection_operation | tenant_id + operation_id；tenant_id + operation_key 唯一 | VectorProjectionOperation，关联不可变请求与向量载荷 | 未解决操作不按在线 P-16 静默删除 |
| projection_result | tenant_id + operation_id + observation_version；result_id 唯一 | 不可变 ProviderResult 与受控原始证据 | 保留恢复及 B 取回所需版本，敏感删除另按已签收规则 |

复合键中的 Hash 使用固定算法/编码后的完整规范值，不截短摘要；生产数据库的列类型、索引形式、加密和事务机制由 Recall 与 RF 按 AL-RF02 落实，本文不选数据库产品或新增 P2 Port。

request_ref、checkpoint_ref、embedding_result_ref、set_ref、source_result_ref、validation_ref、content_result_ref、ranked_ref、trace_ref 由受控载荷/元数据映射解析；不能只保存无法恢复的进程内地址。Execution.result_ref 对应唯一的 tenant_id + pack_id + pack_version。事件载荷、编码报文和 Query/向量/内容也走同一受控引用机制，不因此创建新的领域事实表。

### B.2 跨对象的提交与恢复关系

1. 请求索引、标准请求受控载荷与首次 Execution 建立一致绑定；同键不同 fingerprint 拒绝，不覆盖旧请求。
2. 每次在线调用先在 Execution 原子保存意图、次数和字节预占，后保存结算与受控结果；阶段输出、其摘要与 checkpoint 落地后才能 CAS 推进。每个引用可恢复且同租户，重启不清零额度。
3. 终态、Pack、最小 Trace、两来源结果引用、截至该时点的 ContextSelected/RecallCompleted Outbox 一致提交；按 commit_id/generation 唯一绑定。未知提交先查证，截止后只能原子隔离旧提交并失败收尾；未证明成功不发内容。
4. 实际交付后才能追加 ContextEmitted；其崩溃缺口按真实证据补齐，不能预写未来事实。
5. 相同事实重投复用 event_id；重复评估复用输入摘要与规则绑定，迟到证据建立新版本，保留 supersedes_version 链。
6. 来源版本和授权失效后，即使本地对象结构完整也不能直接重放。原结果不改写，重新验证失败则拒绝重放；需要重新搜索时创建新执行。

共享机制另有三条提交约束：Embedding 请求、执行与调用幂等绑定先保存，推理次数在调用前占用，成功结果与执行结果引用一致保存；投影目标、请求、操作及删除退役标记一致建立；每次 P2 调用意图/次数先保存，ProviderResult 与最新操作引用一致更新。未知提交先查本地记录，再依据原操作查 P2，不跨服务假定事务。

这些是 A 的数据一致性要求，不是声称 RF 已支持某种分布式事务。

### B.3 保存、隐私与删除

Query、向量、正文、rendered_context、证据载荷和能够反推它们的摘要只进入受控存储，不进入普通日志。对外字段投影不能暴露内部存储地址、跨租户信息或未授权对象的存在性。

P-16 是 Recall 实验期保留基线，不改变 B 的 Memory 生命周期、Working TTL 或 C 的缓存 TTL。运行中执行需要可恢复；未 Ack 事件不能无声丢弃。删除/撤销规则按 AL-B06、AL-RF02 执行并优先于普通保留计划：清除被要求删除的敏感载荷、禁止旧结果重放，按已确认审计规则保留最小合法标记；不以“事件还没 Ack”为由继续保留或投递必须删除的内容。

| 数据类别 | 当前可实现的保留/清除规则 | P-16=0 时 |
|---|---|---|
| 可重放载荷：Query、正文、向量、rendered_context、含内容的阶段载荷 | 终态后至 payload_retain_until；删除/撤权可提前清除，引用标为不可读 | 立即禁止后续正文重放；当前在线首次交付仍先确认提交，交付结束即清除受控快照，不能等下一次重试再删 |
| 执行与检查点最小元数据：模式、策略绑定、状态、账本、已采用引用和清除标记 | 至少至 metadata_retain_until；未知提交/attention_required 继续保留必要恢复标记，未确认合法清理前不自动删 | 不随正文清零；终态与原预算保持 |
| 幂等索引与请求最小语义绑定 | 与执行最小元数据同清理边界；保留原 fingerprint、规范化策略及已清除标记，敏感摘要同样受控 | 同键仍定位原执行；正文已清除返回 REPLAY_REVALIDATION_REQUIRED，不新建执行 |
| 最终提交证明与旧写隔离标记 | 与执行最小元数据同清理边界，覆盖全部在途/迟到提交；未知结果不能仅因恢复额度耗尽删除 | 保留唯一结果身份和防旧提交依据 |

metadata_retain_until 初始为首次受理时间 + P-22；终态时原子更新为它与 payload_retain_until 的较晚值。该时间是允许评估清理的最早时间，不是未知记录的自动删除时间。清除正文不擦除最小绑定，不重新开放旧键。无法保留完整请求时只保留获准的规范化/摘要绑定；不能安全比较新同键输入时拒绝重放，不猜测等价。共享 Embedding/投影、未 Ack Outbox 与旁路评估仍遵守各自章节的生命周期，不直接套用本表的正文 TTL。

冻结结果只冻结结论与版本，不保证正文永久可读。证据或内容已清除时，引用解析必须明确失败，不能声称结果仍可完整复现。
