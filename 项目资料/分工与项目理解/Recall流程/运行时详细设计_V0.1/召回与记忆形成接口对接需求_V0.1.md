# 召回与记忆形成接口对接需求 V0.1（Remember，精简版）

更新：2026-09-07。维护方：Recall 负责人（A）；对接方：Remember / B。本文整理 B 提供的读取能力、Recall 的访问事实，以及 A 负责建设并向 B 提供的 Embedding 与向量投影写入机制；不定义 B 的对象、字段、状态、存储或阈值。

下列编号是对接需求编号，不是新增 API。各能力由对应 Provider（A 或 B）提供实际接口、方法和契约版本；字段与协议由原 Owner 维护。Embedding 由 A 建设；消费映射及尚未确认的输入输出、保证、责任集中维护在[《跨模块待确认事项》](跨模块待确认事项_V0.1.md#2-remember--b)。下列联调场景仍为待执行要求。

## 1. 双向接口与信息交接

| 对接项 | 方向与能力 | 需要交接的内容 | 责任与适用范围 |
|---|---|---|---|
| RB-01 | Recall ↔ B：当前 Working 读取 | Recall 提供已授权的当前 session/task、Scope 和有界读取需求；B 提供当前候选、正文或合法引用、版本/TTL 与完成范围证据 | 沿用 B 认可的 Working Read；working_only、combined 必需，不要求 Projection Ready；对应 IF-02 |
| RB-02 | Recall ↔ B：候选事实查询及发出前复核 | Recall 提供准确候选身份；最终复核覆盖全部已加载可组装候选及替补。B 逐项提供当前 Memory/version、Type、状态、权限/Scope、TTL、证据及有效窗口；重放另做只读复核 | MemoryReadCapability；初查与最终复核不同，分批上限和窗口待签收；对应 IF-03 |
| RB-03 | Recall ↔ B/内容 Provider：正式内容映射与加载 | Recall 提供获准的 Memory/版本及所需范围；B 提供正式表示、内容引用、版本/范围和期望完整性依据，Provider 提供真实字节与读取结果 | CanonicalLoadCapability，经 ContentStorePort / OBJ-001；映射和契约归 B，物理正文归 Provider；对应 IF-04 |
| RB-04 | B → Recall：语义、冲突与证据策略 | Recall 指明需处理的已校验候选；消费 B 已有质量/衰减、冲突成员、证据与策略版本，确认可用回退语义 | 可随既有 MemoryRead/语义能力提供，不要求独立接口、评分系数或新外部对象；最终排序与 Context 组装归 Recall |
| RB-05 | B/原向量能力 Owner → Recall：长期可读与模型兼容事实 | Recall 提供候选 Projection 引用和 Query 模型空间；取得可读版本、ProjectionState 与模型/Schema 兼容证据 | B 确认领域可读事实，原向量能力 Owner 提供模型契约；只用于长期读取，不接管构建、写入或恢复 |
| RB-06 | B 经确认通道 → Recall：删除、过期与版本失效通知 | Recall 消费 B 的权威失效事实，清理自身派生缓存/历史 Context 内容并限制重放；保留与删除机制同 RF 对齐 | 通知/补发形式由 B、RF 确认；异步清理不能替代每次访问复核，不由 Recall 设置 B 的 TTL 或生命周期 |
| RB-07 | Recall → RF；供 B 使用访问事实的路径待确认 | Recall 已有候选、加载、Context 发出与请求结果等本地观察，可按获批 RF 契约映射为 AccessTrace；B 明确需要哪些证据及用途 | B 的 AccessTrace 消费链路尚未确认；不得把本地观察表直接当共享 Schema，确认前不新增 B 订阅或直连回调 |
| RB-08 | A 的 Embedding 模块 → B：Passage 正文向量化 | B 提供固定调用身份、文本/片段、usage=Passage、model_contract、source_hash 和 timeout；A 返回真实向量及模型/输入绑定。网络或 Task 重试使用原 caller_request_ref 附着原执行/补取结果 | A 独占 EM-04 推理重试，B 不以换 attempt 重获推理额度；生成成功不等于投影 Ready |
| RB-09 | B ↔ A VectorProjectionPort：投影 upsert/delete/query 与机制结果 | B 提供写/删授权、五元组、正式内容和检索元数据；upsert 关联已验证 Passage 结果。A 调 P2 并返回 operation_id、ProviderResult 和完成/未知证据 | A 提供机制，P2 负责物理存储/索引，B 负责构建编排、Ready Guard、版本切换与旧目标清理；超时先查，不以机制 READY 直接改 ProjectionState |

RB-07 的依据与限制：[Remember V2](../../remeber流程/2026-09-03-201608-remember-V2.0.md) 第 2.9、2.10 节提出使用可信 AccessTrace 作为衰减/价值或 MemorySignal 的证据；但[冻结 Work Map](../../总设计/AetherStore_P3_Work_Map_V0.4.1.md) 第 4.1 节目前明确的 Consumer 是 C。此处只登记 AL-B07，请 B、RF 与原架构确认方对齐，不宣称冻结契约已经允许 B 消费。

## 2. 责任与处理边界

模式由 Recall 按[主设计 3.1](召回流程详细设计_V0.1.md#31-校验请求并选路)内部决定；B 不需要新增模式判别能力。B 仍只定义 Working/长期类型、当前性和读取事实；Recall 结合已确认授权与现有类型筛选决定启用哪些分支。当前 session/task 的有效归属、各来源读取权限须由原授权 Owner 的证据支撑，不能把 B/授权服务超时当作“无当前会话”或“长期不适用”。

- working_only 不生成 Query 向量、不调用长期检索；combined 仍需长期分支。B 返回零条且所需范围已完整确认才可认定来源为空；超时、版本或权限未知不是空。
- Recall 不直读 B 的内部 Redis key，不回写 Memory 或 ProjectionState。B 确认无效的候选与事实未知的候选分开处理；不拿新正文匹配旧 Projection，不用 Provider READY 代替 B 的领域 Ready。
- 正文及 Prewarm 都由 Recall 使用 B 提供的授权、版本与完整性依据完成校验。Working 已内联提供可信正文时无需重复下载；发出前复核失败不能重放旧 Context，也不声称跨服务线性一致。
- Working 内联正文在发现调用前即占正文上限；后续本地校验不重复扣字节。B 的范围/响应必须能受限，超限、断流及未知接收量按主设计 3.5.1 处理。最终复核输入集合含替补，返回缺项按 unverifiable 处理，不用初次资格证据补齐。
- Recall 使用 B 的语义策略，不定义冲突真值或衰减算法；冲突成员、策略或证据不足时按[主设计规则](召回流程详细设计_V0.1.md#4-结果故障与恢复a-02)处理，不能静默挑一方作为真值。
- RB-07 确认接入后，Recall 只提供访问事实；由 B 决定是否及如何进入衰减、价值或 MemorySignal。检索命中、已加载、已选中、已发出不是同一事实；实际模型使用需要实际调用方证据，无回执为未知，不伪造使用。RF 接收确认不等于 B 已消费，Recall 在线请求不等待 B 更新衰减或 Signal。
- A 同时负责 Recall Runtime、Embedding 共享模块和向量投影写入机制。RB-08 是我们向 B 提供的向量化能力；Query 是 Recall 对同一模块的内部调用。Embedding 输出到向量及模型/输入绑定事实为止，Projection Build 编排由 B 负责，向量写机制见主设计第二章及 RB-09。ContextPack 仍交付上游调用方（可经 P4 转交），不在本文新增面向 B 的 ContextPack 服务；也不把 B→C 的 MemorySignal 当作 Recall 产出。
- 在线 Recall 读取调用受剩余 deadline、授权范围和[参数目录](召回流程详细设计_V0.1.md#参数目录)约束；实验配置不是给 B 的生产 SLO。外部能力未确认时不启用相应真实路径，RB-07 未确认不阻塞已有安全读路径。

- RB-09 使用独立 VP 额度与恢复窗口，不套用在线 Recall token/读取预算。同目标同动作重试复用原操作；同键换载荷拒绝。B 指定五元组、版本与空间，A 不自动按 memory_id 覆盖旧向量。
- B 的删除指令必须指定准确目标；A 先保留退役屏障，再调用 P2 并核验迟到写入不会复活。A 的 VectorProjectionRequest 使用 build_intent 区分 initial_or_retry 与 rebuild，delete 为 null；本版明确 rebuild 返回 PROJECTION_REBUILD_UNSUPPORTED 且不调 P2。新 task/attempt 不改变五元组操作键；普通重复调用仍返回原操作及历史结果，不能以旧 READY 证明缺失对象已修复。同版本重建方案单列在[待确认事项第 7 章](跨模块待确认事项_V0.1.md#7-同版本投影重建必须一起确认的决策)。
- A 使用 submit/query 返回已保存的 ProviderResult，B 可重复取回；不要求新建回调或共享事件。B 仍校验当前 Memory、正文、模型、维度、Schema 与可查询性，旧版本 READY 只是一条历史机制事实。

## 3. 请 Remember 确认并提供

请 B 提供对应的现有方法/契约版本、脱敏输入输出及故障样例、权限/版本语义、批量与服务限制；有缺口时说明原 Owner 与确认步骤，不由 Recall 补写 B 的 API。

RB-08 由 A 先提供 Embedding 契约、样例和使用限制，B 确认输入准备、模型空间绑定及消费映射；不要求 B 实现 Embedding。完整流程见[主设计第二章](召回流程详细设计_V0.1.md#2-embedding-与向量投影写入怎么实现)，本地字段见《召回数据定义》第 19～25 章；功能见[主设计 5.4](召回流程详细设计_V0.1.md#54-构建并提供-embedding-共享模块)。

## 4. 联调验收要点

以下是待执行要求，不是已完成测试。涉及 RB-07 的消费验证只在相关契约获确认后执行；契约未确认时只检查边界与不开通行为。

| 场景编号 | 场景与验收要点 | 对接项 |
|---|---|---|
| RBT-01 | working_only 的可信当前正文不要求 Projection、不多余检索/下载；明确完整空与超时/partial 分开处理 | RB-01 |
| RBT-02 | 初查通过后发生删除、版本变化或撤权；最终复核与重放不得输出旧内容，事实未知不伪称已删除 | RB-02 |
| RBT-03 | Projection 未 Ready、旧版本命中或模型空间不兼容；不混用新正文与旧向量，不由 Recall 改 Ready | RB-05 |
| RBT-04 | 映射不存在、hash/范围不符或 head/get 跨版本；不输出未经验证的正文，不把字节不存在当 Memory 已删除 | RB-03 |
| RBT-05 | 冲突成员不全、策略不可用或预算容不下完整冲突组；按主设计隔离/降级或整组处理，不静默只留一方 | RB-04 |
| RBT-06 | 删除通知迟到、重复、乱序或清理尚未完成；当前授权/版本复核仍生效，派生清理不修改 B 主事实 | RB-06、RB-02 |
| RBT-07 | 获批通道中的访问事件重复、乱序或补发；Recall 保留稳定身份与真实阶段，接收确认不冒充 B 消费或语义更新成功 | RB-07 |
| RBT-08 | 只有加载/选择证据、尚无发出/实际调用方使用证据时，不伪造实际使用；B 消费契约未确认时不新增链路，已有安全 Recall 继续 | RB-07 |
| RBT-09 | B 的 Passage 与 Recall 的 Query 使用同一共享模块，在兼容模型空间中返回合法真实向量和可追溯版本/维度；不要求 B 感知推理后端，也不由 Embedding 修改 ProjectionState | RB-08 |
| RBT-10 | 文本、chunk、usage 或模型版本变化时重新计算；符合契约条件时才复用。超时、不兼容或非法向量明确失败，不用模拟向量或旧结果冒充成功 | RB-08 |
| RBT-11 | Passage 向量与 B 指定片段/版本/空间准确关联；Query 不建库；A 只返回机制结果，B 通过 Ready Guard 才置 Ready | RB-08、RB-09 |
| RBT-12 | 同键重投、首次响应丢失、PENDING/UNKNOWN、B 任务重启均查询同一 operation_id；不另起有副作用路径 | RB-09 |
| RBT-13 | V3 READY 迟到时 Memory 已是 V4，B 不采用旧版本；新旧目标独立，只有 B 决定切换和清理 | RB-09 |
| RBT-14 | 精确删除与旧 upsert 在途竞态、退役标记保留和重建请求；无 P2 屏障/完成证据不宣称删除完成，多 chunk 逐项汇总 | RB-09 |
| RBT-15 | 首选 A 最终失效，已加载替补 B 只有在本轮独立复核通过时才能进入 Context；缺项、未知或证据过期则隔离，最终 E/P 从复核后的组计算 | RB-02、RB-04 |
