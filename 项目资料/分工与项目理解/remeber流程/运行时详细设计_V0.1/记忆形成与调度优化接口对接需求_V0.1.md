# 记忆形成与调度优化接口对接需求 V0.1（Operate）

整理日期：2026-09-07。维护方：Remember（B）；对接方：Operate（C）。B 提供真实 Memory 变化与内容资格，C 消费并负责热度、驻留计划、预热和 TierAction。本文不定义 C 的对象字段、热度权重、动作状态机或物理实现。

下列为既有能力的信息需求，不是新增 API。确认状态只回填[主设计第 7 章](记忆形成流程详细设计_V0.1.md#alignment-c)，B 本地字段见[数据定义](记忆形成数据定义_V0.1.md#signal)。问题全部待确认，验收场景全部待执行。

## 1. 双向接口与信息交接

| 对接项 | 方向与能力 | 需要交接的内容 | 责任与适用范围 |
|---|---|---|---|
| BC-01 | B → C：MemorySignalCapability | 稳定 signal_id/version、来源 Memory/state 版本、类型/生命周期、importance、Scope 摘要、变化时间/原因/策略、获准使用证据 | B 拥有事实载荷，C 消费；对应 BI-08，不是 Recall 的 ContextPack |
| BC-02 | C → B：消费 Ack/查询证据 | 事件身份、载荷绑定、消费范围、持久确认时点与结果；错误版本、重复/部分接收明确 | C 拥有消费事实，B 维护 SignalDelivery；不以 RF/Broker Ack 代替 |
| BC-03 | B → C：表示资格与失效约束 | 精确 Memory/表示/内容版本、业务有效期、可读范围、删除/更正屏障、来源撤销、受控保留与替代关系 | B 确认什么可用；C 据此限制新旧动作，不能用 Pin 恢复资格 |
| BC-04 | C/Provider → B：相关失效/清理处理证据 | 目标表示、当前 generation、动作/清理关联、处理范围、未决残留与真实完成证明 | C 管 Prewarm/动作，Provider 管物理结果；B 只收敛自身失效交接，不接管调层 |
| BC-05 | B/C ↔ RF/Infra：隔离与资源约束 | Working 独立资源、后台/Prewarm 配额边界、压力/健康观察及来源时间 | B 保护当前 Working，C 控制预热资源；不共同写一个热度事实 |
| BC-06 | B → RF → C：B 实际观察 | 本地事实提交、Working 真实读取、内部处理与清理等按获准 Schema 映射 | B Producer、RF Schema/Ingest、C Consumer；内部 IO 不自动当 useful access |

AccessTrace 与 MemorySignal 分开：前者记录真实访问/运行阶段，后者交接已确认事实/价值变化。B 获准消费 A AccessTrace 仍需主设计 AL-RF04，不因本表向 C 输出事件就自动获得反向消费权限。

## 2. 责任与处理边界

- Signal 在事实创建、分类/生命周期、版本或投影变化时产生，不是最后一次全局成功通知。历史载荷保持不变；新变化生成新事件，重发复用原身份。
- 传输至少一次，消费必须去重；Pending、Submitted、Succeeded 分别表示本地保存、发送/受理、C 匹配持久消费。C 已生成 Action 不等于当前 Signal Ack 已证明，Action Succeeded 更不代替 Memory 状态。
- C 以来源 state_version 和删除/版本屏障避免旧 Active/使用事件覆盖新失效。失效事件不得被简单“只保留最新一条”合并掉；如用快照补齐，明确 snapshot 与事件水位。
- B 的逻辑读屏障不等待 C 清理；C 消费删除后仍须约束在途 Prefetch/Promote/Pin，处理迟到副作用。B 不直接写 C 的 Prewarm Redis 或 TierAction 数据库。
- B 管 Working 业务资格和释放条件；C 管 Prewarm 驻留。长期内容进入热副本不会因此变 Working，Working 释放也不因此使 Memory Deleted。C 不能通过驱逐 Working 解决自身预热容量压力。
- 按 PRD 正式功能验收中的两个独立 Redis 实例准备资源；早期共享基础设施表述由 AL-RF03 统一。独立 namespace 不能被单方面宣布已满足两实例验收。
- 使用字段无证据为 unknown/null，不能把加载、选择、发出、实际模型请求使用合并成一个 true。统计窗口不完整不能默认零使用，内部重建/探针也不能强化热度。
- C 不可用时 Memory 与基础读取继续，Signal 有界补发/告警；但 B 若未可靠保存事件待办，就不能声称已完成交接。Outbox 与事实提交关系按主设计 2.2/2.7。
