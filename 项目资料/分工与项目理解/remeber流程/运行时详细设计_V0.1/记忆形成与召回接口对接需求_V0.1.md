# 记忆形成与召回接口对接需求 V0.1（Recall 与 A 共享能力）

整理日期：2026-09-07。维护方：Remember（B）；对接方：Recall（A）及 A 负责的 Embedding/向量机制。本文区分 B 向 A 提供的读取事实与 A 向 B 提供的写入机制；不把两种方向合并为“共同负责”。

编号是能力和信息交接需求，不是新增 API。外部字段、方法和契约版本由所属 Owner 提供；本地字段见[数据定义](记忆形成数据定义_V0.1.md)，确认状态只回填[主设计第 7 章](记忆形成流程详细设计_V0.1.md#alignment)。所有问题均待确认，场景均为待执行验收要求。

## 1. 双向接口与信息交接

| 对接项 | 方向与既有能力 | 需要交接的内容 | 责任与适用范围 |
|---|---|---|---|
| RA-01 | B → A：WorkingRead | A 给已授权当前 Session/业务任务、Scope、筛选与有界数量；B 返回当前 Memory/版本、正文或合法引用、有效期/TTL 区别及完成范围 | B 定当前性，A 决定检索模式和最终 Context；对应 Recall RB-01、BI-09 |
| RA-02 | B → A：MemoryReadCapability | A 给候选原始引用/版本及校验目的；B 返回当前事实、生命周期、类型、Scope、资格版本和已知排除/不可核验结论 | 支持初查、发出前及重放前复核；不让 A 直读 B 内部 key；对应 Recall RB-02/05 |
| RA-03 | B → A/内容 Provider：CanonicalLoadCapability | B 给获准表示、精确内容版本/范围、权威期望摘要和来源；Provider 返回真实字节及完成证明 | B 管映射/资格，Provider 管物理正文，A 验证后使用；对应 Recall RB-03、OBJ-001 |
| RA-04 | B → A：语义与冲突策略 | Type、importance/confidence/stability、衰减输入和策略、冲突完整成员/证据、允许的回退与评价时间 | B 定义语义规则，A 执行排序、预算和冲突呈现；对应 Recall RB-04 |
| RA-05 | B → A：版本、删除与失效事实 | Memory/状态版本、失效范围、时间、原因、tombstone 与补发身份；A 返回接收/处理范围证据 | A 清理自身派生缓存/历史 Context，当前访问仍复核；对应 Recall RB-06 |
| RA-06 | A → B：SemanticEmbeddingCapability | B 给 Passage 文本/片段、source_hash、model_contract、usage、timeout；A 给实际向量、模型/空间、维度、dtype、Schema、输入绑定与错误 | A 实现共享模块；B 不实现推理/ANN；对应 Recall RB-08、BI-06 |
| RA-07 | A → B：VectorProjectionPort / VEC-001 | B 给固定 manifest、五元组及完整输入指纹、向量、metadata、目标资源；A 给逐项 ProviderResult、操作/对象/版本、查询与删除证据 | A 机制，B 编排/Ready Guard；不因 Provider READY 自动置领域 Ready；对应 BI-07 |
| RA-08 | A → RF；B 消费路径待批准 | A 提实际检索、加载、选择、Context 发出等观察；实际模型使用需调用方证据；B 仅在获准范围内评估使用 | Work Map 当前 Consumer=C，B 不自动新增订阅；对应 Recall RB-07、BI-10 |

RA-07 虽未作为在线 Recall 对接表的一项业务读取能力，仍是 A 原工作包明确的共享机制责任；它属于 Remember 的写路径，不让 Recall 在线 Query 承担投影构建。RA-06/07 的机制实现与 A 的 Recall Runtime 结果责任分别交付。

## 2. 责任与处理边界

- Working 不要求 Projection Ready；长期候选必须对应当前有效版本和 Ready 集合。B 提供事实，A 负责选择 working_only/long_term_only/combined 及最终完整/降级/失败结果，B 不要求上游传检索模式。
- B 返回完整零条必须有本次边界完成证据；读取超时、权限未知、版本不明和 partial 不能包装成“没有记忆”。一次查询 complete 不代表后续正文、授权和发出前复核也已通过。
- A 不在旧候选上悄悄替换新正文；Memory、Content、Projection、Provider generation 的版本含义独立。A 发出前复核失败时不得重放旧 Context。跨服务一致性窗口由双方确认，不凭本地快照承诺全局线性一致。
- Original/Artifact 的 byte range、编码和摘要覆盖必须相符。整对象 checksum 不证明任意子串；head v1/get v2 不组成合法读取证据。Prewarm 只能缓存 B 已批准的表示，不能变成第三个记忆来源。
- A 负责 Passage/Query 模型空间兼容和真实向量；B 负责输入选择、主事实、manifest、Task、ProjectionState。分块机制归属须明确，不能让两边各自分块后只比较总数。
- 同一五元组内 source、Artifact、分块/预处理或空间变化必须能区分为新输入身份。Provider 状态未知先查询原操作，批次成功不得掩盖缺 chunk；只有 B 在完整证据与 CAS 通过后发布 Ready。
- Model/Schema 升级只影响相关投影；访问计数或排序衰减变化不自动重做向量，更不能把 Memory 旧版自动 Superseded。
- RA-08 未批准时关闭 B 新消费路径；获准后也须区分 loaded、selected、emitted 与 model_request_used。无实际回执为未知，RF 摄取 Ack 不等于 B 已消费或更新价值成功。
- 子调用继承剩余 deadline，长操作按 B Task 预算执行。A 的 SDK 与 B 的任务重试需统一主要 Owner，不能层层自动重试相乘。限额由双方 Profile 确认，不把 Recall 的实验参数直接套成 Remember 配额。

## 4. 联调验收要点

| 场景编号 | 场景与验收要点 | 对接项 |
|---|---|---|
| RAT-01 | Working 当前可信内容不等待 Embedding/Projection；完整空、partial 与不可用分别返回 | RA-01 |

| RAT-03 | 旧向量命中、新正文已更新；不拼接不同版本，不由 A 回写 B Ready | RA-02、RA-07 |

| RAT-05 | 冲突成员缺失或策略不可用；不静默选一方，不由 B 代写 ContextPack 状态 | RA-04 |
| RAT-06 | 同维不同模型空间、非法向量、usage/source_hash 错；不写投影、不复用错结果 | RA-06 |

| RAT-08 | Artifact/分块改变而五元组没变；输入身份仍能区分，旧结果不能覆盖 | RA-06、RA-07 |
| RAT-09 | 内联转 Task、租约丢失/旧回调、模型升级与更正；当前版本与成功历史保持一致 | RA-07 |
| RAT-10 | B 消费权限未确认时不启用 RA-08；获准后重复/迟到事件不重复强化 | RA-08 |
