# 记忆形成与 P2 接口对接需求 V0.1

整理日期：2026-09-07。维护方：Remember（B）；对接方：P2 / 实际 Content、Vector Provider，A 负责向量 Port 适配。本文按 Remember 运行阶段提出物理证据需求，不定义 P2 引擎、索引、复制、WAL 或迁移实现。

编号是对接需求，不是新增接口路径。沿用 ContentStorePort（OBJ-001，B）与 VectorProjectionPort（VEC-001，A）。P2 提供实际 SDK/RPC/HTTP 方法、版本与限制；B 不绕过 A 直接维护向量机制。问题全部待确认，场景全部待执行。确认状态只回填[主设计 7.4](记忆形成流程详细设计_V0.1.md#alignment-p2)及关联 RF/A 项。

## 2. 调用方式与责任边界

**正文先证明，主事实再确认。** 大正文写入与 B 状态提交不假设分布式事务；先登记操作，再写精确对象、确认必要证明，最后提交 Memory 与映射。E2 已写而 B 未确认时保留候选孤儿，不立即删除。短 Working 可按 W1 在事务库保存可靠快照，不强制每条同步调用 E2。

**未知先查询。** 网络 timeout 不等于未执行；一次 HEAD 404 在可见性窗口内不证明未写。Provider 若不支持稳定操作查询，应给出等价的不可变对象/幂等/可见性证明；没有可恢复证据时，该真实写入路线不能宣称具备安全自动重试。

**版本与摘要分别核对。** memory_version、content_version、object_version、Provider generation 不要求字符串相等，但必须通过映射可追溯。可变 latest、裸 URL、未知语义 ETag、全对象 hash 不能替代精确版本/片段证明。head/get 跨版本必须失败或显式重新获取，不能拼凑成功。

**机制成功与领域 Ready 分开。** A 负责向量机制与结果适配，B 负责当前 Memory/输入完整性/Ready Guard。批次成功、对象总数、Pod Healthy、索引已建立均不能单独证明全部目标可 Recall；必须精确覆盖 manifest。Query Search 属于 A 在线读路径，B 仅提出构建后的可见性证明需求，不接管 Recall。

**重试有一个主要 Owner。** B 管业务任务与预算，A/Provider 管一次机制调用及内部执行；双方声明 SDK 自动重试次数、可重试错误和查询边界。前台 deadline 不能被每次子调用重置，后台沿 Task deadline 和租约执行。

**删除证明明确层次。** B 先建立逻辑读屏障，经相应 Port 清理；当前版本不可见不等于所有历史字节擦除，取消操作不证明在途写停止。共享引用、保留期、软删、异步索引和备份恢复限制必须说明；B 不得扩大到未授权对象。

**物理 Provider 保持边界。** E2 对实际字节负责，E1 对向量对象和可见性负责；B 的事实/版本、Task、Semantic 质量和 Signal 不交给 P2 决定。WAL、复制、Fencing 内核、ANN 与分片实现由 Provider 选择，P3 只验证可见结果和调用合同。

正式集成使用 integrated_p2 的真实 E1/E2。Simulator 和历史 Milvus Profile 分别记录，不把其成功迁移成真实 P2 已就绪。部署/指标 Profile 待 AL-RF03/05，具体接口承诺不得沿用历史计划日期。

| BP2Q-04 | 向量集合：逐项结果和 ProviderResult 怎样映射；完整 manifest、输入指纹、模型空间与部分写如何关联 | BP2-05 | AL-A02、AL-P203 |
