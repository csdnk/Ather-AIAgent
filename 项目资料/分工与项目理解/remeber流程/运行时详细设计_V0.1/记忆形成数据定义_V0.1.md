# 记忆形成数据定义 V0.1

整理日期：2026-09-07。维护范围：Remember（B）。本文定义本地设计需要保存和判断的数据，作为实现与接口评审的输入；不是已部署 Schema、已签收外部报文或数据库选型。流程、原因码、参数与 AL 状态只在[流程详细设计](记忆形成流程详细设计_V0.1.md)维护。

<a id="catalog"></a>
## 1. 范围、阅读方式与对象关系

Memory 主事实、生命周期、内容映射、Task、Artifact 资格、ProjectionState、Signal 属于 B；A 的向量、ProviderResult，P2 的物理版本/持久化，C 的动作/驻留，以及 RF 的共享遥测保持原权威。本地字段可以保存它们的受控引用与校验结论，不能把本地副本改名为外部权威。

每张字段表一行一个字段；所有独立记录继承 RecordHeader，可变记录再继承 MutableFields。默认字段必须出现；`?` 只表示可取 null，不能以缺字段替代未知。嵌入值不另建表。记录拆成多少表、索引和服务由存储 Profile 决定。

### 1.1 独立记录目录

| 记录 | 身份（均含 tenant_id） | 写入与保存性质 |
|---|---|---|
| RememberRequest | request_ref | 规范化请求，受控不可变 |
| RememberOperation | operation_id；idempotency_scope + idempotency_key 唯一 | 准入、幂等、事实提交与可靠接管，条件更新 |
| ContentWriteIntent | content_operation_id | 调用正文写入前登记，查询/恢复进度可变 |
| ContentBinding | content_binding_id | 精确版本内容映射，不原地换正文 |
| MemoryRecord | memory_id | 当前业务指针、类型/生命周期及资格，条件更新 |
| MemoryVersion | memory_id + memory_version | 内容、来源及证据修订，不可变 |
| MemoryVersionState | memory_id + memory_version | 每个版本的生命周期与替代关系，条件更新 |
| StageCheckpoint | checkpoint_id | 某次阶段/目标已确认输出，不可变 |
| LifecycleEvaluation | evaluation_id | 一次分类/巩固/到期判断，不可变 |
| SemanticCandidate | candidate_id | 候选内容/证据固定，评估进度可变 |
| EvidenceLink | evidence_link_id | 来源和结论依赖关系，撤销资格可追踪 |
| ConflictGroup | conflict_group_id | 版本化完整冲突成员与允许处理策略 |
| WorkingMaterialization | working_representation_id | 当前副本与物理观察，条件更新 |
| WorkingReadResult | working_read_id | 一次范围读取结果，不可变 |
| AsyncTask | async_task_id | B 后台任务，目标固定、状态条件更新 |
| TaskDispatchOutbox | dispatch_id | 同一任务派发轮次的可靠待办 |
| CompressionArtifact | artifact_id | 指定输入的实际输出及质量，不可变；资格变化由新评估/绑定控制 |
| ProjectionSet | projection_set_id | 构建输入固定，五态与当前证明条件更新 |
| ChunkManifest | manifest_id | 精确预期分块集合，不可变 |
| ProjectionItem | projection_set_id + chunk_id | 逐项机制观察与证明，条件更新 |
| ReadyProof | ready_proof_id | 某次 Guard 的完整证据，不可变 |
| MemoryReadSnapshot | memory_snapshot_id | 一次受控资格复核快照，不可变 |
| MemorySignal | signal_id + signal_version | 不可变业务事件 |
| SignalDelivery | signal_id + signal_version | 投递、重试和匹配 Ack，可变 |
| RememberObservation | event_id | B 实际观察的不可变事件，不是 RF 共享 Schema |
| UsageAssessment | assessment_id | 获准使用证据的去重/资格评估，不可变 |
| ReconciliationRecord | reconciliation_id | 对账观察、决策和复核，分轮记录 |
| CleanupRecord | cleanup_id | 具体表示清理及未知结果，条件更新 |
| AuditCorrection | correction_id | 误报事实的追加纠正，不擦除原历史 |
| RememberResponse | response_id | 一次响应快照，不可变；重试可生成新快照 |

### 1.2 关系与流转

```text
RememberRequest → RememberOperation → ContentWriteIntent → ContentBinding
                                  → MemoryRecord ↔ MemoryVersion
                                      ├─ LifecycleEvaluation / SemanticCandidate / EvidenceLink
                                      ├─ WorkingMaterialization → WorkingReadResult
                                      └─ CompressionArtifact → ChunkManifest → ProjectionSet
                                                               └─ ProjectionItem → ReadyProof
MemoryRecord / 正式表示 → MemoryReadSnapshot → Recall
后续目标 → AsyncTask → TaskDispatchOutbox → Worker → StageCheckpoint
已提交变化 → MemorySignal → SignalDelivery → C 的匹配消费 Ack
B 的实际观察 → RememberObservation → RF 既有契约
获准的使用证据 → UsageAssessment → 策略输入（不改原观察）
未决项 → ReconciliationRecord → 补登记 / 新恢复 Task / CleanupRecord
误报事实 → AuditCorrection（原记录保留）
```

版本指针和反向依赖均需可查。MemoryVersion 保存不可变内容，MemoryVersionState 保存该版本的当前资格及历史引用；MemoryRecord 的类型/状态是当前版本的查询快照，必须与所指版本状态同事务或经可证明屏障更新。旧版 Superseded/Deleted 不能只靠 current_memory_version 推断。MemorySignal 不是正文表示；AsyncTask 的目标可以是 Memory、Candidate、Artifact、ProjectionSet、Signal 或 Cleanup，Task 自身不参与记忆检索。

## 2. 类型与公共约定

### 2.1 标量、引用与枚举

| 类型 | 本地约定 |
|---|---|
| Id / Version | 非空不透明字符串；Version 只做相等或契约认可的比较，不按字典序推断新旧 |
| Timestamp | UTC RFC3339，固定毫秒和 Z；业务发生与观察时间分开 |
| UInt | 非负安全整数，最大 9007199254740991；字节、计数和毫秒不接受负数或小数 |
| Number | 有限 JSON 数值；NaN/Infinity 不合法 |
| Bool / String | JSON 布尔/字符串；空串只在字段明确允许时使用 |
| T? | 字段存在，可为 null；表示未知/不适用，不能默认为 false、0 或空集合 |
| List<T> | 有序数组；无元素为 []；要求集合时去重 |
| Ref<T> | 本地 Id，按 tenant_id 解析为指定类型并检查访问权限 |
| ProtectedRef | 受控载荷/证据存储引用；不是公开 URL、凭据或内部 Redis key |
| EvidenceRef | 原始观察/提交证据的受控引用，附来源契约、时间和身份绑定 |
| ContractRef | 已登记契约/策略/Profile 及版本的受控引用；不能只存未版本化名称 |
| ProviderRef | 来自外部契约的不透明对象/操作/资源引用；保留原类型和适配证据 |
| MemoryType | Working、Episodic、Semantic；null 仅允许内部 classification_status=pending |
| MemoryStatus | Active、Archived、Superseded、Expired、Deleted |
| TaskState | Pending、Running、Succeeded、Retryable、Failed、Cancelled、Expired |
| ProjectionState | Pending、Building、Ready、Failed、Stale；不新增 Unknown/Retryable |
| ProviderStatus | ACCEPTED、PENDING、READY、FAILED、UNKNOWN；本地无损适配观察 |
| SignalState | Pending、Submitted、Succeeded、Retryable、Failed |
| Availability | available、unavailable、not_applicable；不可验证不是“已知 unavailable” |
| Coverage | complete、partial、unavailable；完整仅指本次授权边界和数量范围 |
| Stage | s1_validate、s2_fact、s3_lifecycle、s4_working_task、s5_artifact、s6_projection、s7_signal、s8_reconcile |
| RequiredOutput | fact、working、artifact、long_term；signal Ack 默认不属于同步目标 |
| ResponseStatus | Success、Accepted、Partial、Failed；语义见流程 3.1，不新增 Memory 总状态 |
| ReasonCode | 仅取流程 3.2 的 RM_ 原因码；原始 Provider 错误另保存 |

`task_id` 在外部报文如不可改名，适配时明确其语义：Scope 中的业务任务映射 business_task_id，B 后台任务映射 async_task_id，P2 Task 映射 ProviderRef，不能相互查询或混用。

## 3. 请求、主事实和阶段输出

<!-- remember-type: RememberRequest; base: RecordHeader; kind: record -->
### 3.1 RememberRequest

| 字段 | 类型 | 必填 | 来源 / 定义 | 校验 |
|---|---|---|---|---|
| request_ref | Id | 是 | 规范请求身份 | 不等于每次网络 request_id |
| request_id | Id | 是 | 首次请求关联 | 重试不覆盖首次值 |
| trace_id | Id | 是 | 首次调用链 | 后台沿因果关联，不复用为业务 ID |
| operation_kind | String | 是 | create、correct、explicit_remember、lifecycle_event | 删除管理操作另验明确权限和范围 |
| scope | Scope | 是 | 规范授权范围 | 嵌套 tenant 一致 |
| input_ref | ProtectedRef | 是 | 原内容或受管理外部输入说明 | 不把秘密/凭据直接写进普通记录 |
| input_fingerprint | Hash | 是 | 语义规范化指纹 | coverage=normalized_request；排除 trace/deadline |
| normalization_ref | ContractRef | 是 | 规范化和摘要规则版本 | 同键重试用原规则比较 |
| source_event_ref | ProtectedRef | 是 | source、source_event、主体及来源证据 | 可追溯，不能只存模型结论 |
| occurred_at | Timestamp | 是 | 原业务发生时间 | 与 created_at 分开 |
| target | MemoryRef? | 是 | 更正/重判目标 | create 可空；更正必须明确目标 |
| hints_ref | ProtectedRef? | 是 | 调用方分类/重要度 Hint | 只作建议，不授予权限 |
| required_outputs | List<RequiredOutput> | 是 | 本次承诺目标 | 非空、去重，必含 fact；由实际 API 合同规范化 |
| request_deadline | Timestamp | 是 | 本次在线截止 | 后台 deadline 独立 |
| profile_ref | ContractRef | 是 | 存储/执行/资源 Profile | 固定调用解释边界 |

| WorkingMaterialization | B 资格，Redis 物理 | Working 独立实例 | W1 从可靠来源重建；用途/替代与保护条件满足才条件释放 |
| Prewarm | C 驻留，B 内容资格，Provider 物理 | C 独立资源 | C 管释放；B 提失效，不能直接当 Working 操作 |
| Task/operation/checkpoint/Outbox | B 事实，RF/Infra 持久机制 | B 状态库或可靠等价边界 | 执行通道不作唯一来源；未决项和删除事件不能提前清理 |
| MemorySignal | B 不可变事件，C 消费事实 | B Outbox + 已确认通道 | 可原样重放；当前快照不能恢复丢失历史事件 |
| 观察/审计/对账 | B 本地事实，RF 共享 Schema | 受控持久存储 | 保存窗口与删除范围经确认；普通 OTel 采样不替代业务证明 |

### 8.2 必须守住的提交和恢复关系

| 关系 | 约束 |
|---|---|
| 请求 → 操作 | 幂等唯一键与指纹绑定原子生效；再次调用先重授权 |
| 正文 → 主事实 | L1 外部正文先证实，B 再提交映射；W1 小文随事务落地 |
| 内部 Active → 对外发布 | 分类可以有内部检查点；Type 发布和读取屏障完成前不可暴露成功 |
| 主事实 → 待办 | 事实变化与不可变待办同事务/等价桥接；未可靠接管不能 Accepted |
| Task → Broker | 先 Task/DispatchOutbox；重复消息不创建第二个业务目标 |
| 输入 → Projection | 完整指纹和 manifest 固定；每个 item 是该集合的一员 |
| ReadyProof → Ready | 先可靠保存证明，再 CAS 切状态/当前集合；过期执行者无权发布 |
| 生命周期 → 清理 | 先读屏障、版本和失效待办，再做物理清理；未知不解除屏障 |
| Signal → Ack | 载荷身份/摘要不变；只认 C 匹配持久消费证明 |
| 历史成功 → 后来损坏 | 保存真实历史，目标先失效，新 Task 修复；误报另追加审计 |

所有必需引用既验证存在，也验证 tenant、类型、内容版本、资格状态和输入身份。循环关联使用预分配稳定 ID，不将对象全文互相嵌套或把自身 hash 纳入摘要。孤儿/未决项有独立扫描路径，不能依赖进程内列表。

### 8.3 保存、隐私与删除

普通 Log/Metric/Trace 不写凭据、完整向量和敏感正文；高基数 ID 留结构化 Trace，指标只保聚合标签。受控 payload、来源证据和旧版本仍受原 Scope 及删除/保留政策约束。Unknown、null 和缺失覆盖不能为节省存储被归零。

删除覆盖 MemoryVersion、正文/Artifact/向量/Working、受影响 Candidate/Semantic、A 派生缓存/历史 Context、C 热副本及事件/训练使用关系；实际清除责任由相应 Owner 承担，B 保存交接和清理证据。共享引用、保留期、全版本删除与备份水位见 AL-B05/AL-P204/AL-RF05。物理残留与普通可读资格严格分开。

## 9. 从本地字段反推外部信息需求

| 本地需要核验的事实 | 外部提供者与对接项 | 不向外部强加的实现 |
|---|---|---|
| Scope、授权、request/trace、正式响应 | RF/Auth/上游；AL-RF01 | 不要求 P4 决定 Memory Type |
| commit_evidence、CAS、租约/fencing、恢复水位 | RF/Infra；AL-B01/AL-RF02/05 | 不默认 P2 Catalog 做 B 状态库 |
| 精确正文版本、Hash、durable/readable、负查询 | Content Provider；AL-P201/202 | 不猜 ETag 算法、不要求新建同名字段 |
| generation、TTL、当前版本、读范围完成性 | Redis/B；AL-B06/AL-RF03 | 不把内部 key 公开给 A |
| source_hash、模型/space、维度、逐项结果 | A/P2；AL-A01/02/AL-P203 | B 不实现 ANN/Embedding，也不代写 ProviderResult |

外部原始报文可用不同命名；适配必须保留原始契约版本与无损证据。缺字段时按 null/错误与不启用规则处理，不能编造值使表面 Schema 校验通过。
