## 3. 对接差异和 A 侧处理

| 索引 | 差异/新增信息 | 本轮 A 侧设计 | 原对接位置 |
|---|---|---|---|
| RD-01 | 原 README 把 A 的 AL 台账写成全项目唯一；B 新设计另有独立 AL | 明确 A:AL 与 B:AL 命名空间；不合并同号、不代改签收状态 | A 待确认事项；B 主设计第七章 |
| RD-02 | SRF RecallExecution 汇总态与 A 十三态不同；ContextPack 状态还混有交付维度 | 保留领域原态；共享只读投影带映射版本；CREATED/Cancelled/交付状态不擅自补齐 | A:AL-RF02/RF03 |
| RD-03 | SRF 为 retrieved/validated/loaded/selected/used_in_context；C 为 search_hit 等另一组名称 | 在 A 侧做版本化候选映射；实际传输采用确认 Schema，不改 C 或 SRF 枚举 | A:AL-RF03/C03 |
| RD-04 | A ContextSelected 是最终复核/预算后的待提交条目，SRF selected 允许中途选择；内联 Working 不一定有外部 Provider | 保留 A 原时点和 source/证据；缺 Provider 不编造；请求完成事件不塞进逐 Memory 访问事件 | A:AL-RF03/C03 |
| RD-05 | 新 Remember 设计区分业务有效期、Working 用途期限、缓存 TTL，并有 W1 可靠来源 | A 只消费资格事实和已批准回退；不因 Redis miss 判删除，不直读 B 的数据库 | A:AL-B01/B03；B:AL-B06/RF03 |
| RD-06 | B 固定 manifest 和完整输入指纹，五元组不足以区别 Artifact/分块变化；A 同版本 rebuild 暂不支持 | 校验完整身份和逐项证据；未支持重建仍拒绝，不用新键绕过；不单方定义新代际 | A:AL-B08/P206/P207；B:AL-A01/A02 |
| RD-07 | B RA-08 提出消费访问事实，但现有消费边界未批准变更 | 只保留 A→RF 的已约定输出；不新增 B 消费通道 | A:AL-B07；B:AL-RF04 |
| RD-08 | P2 逻辑 DTO 含筛选/版本/证据，实际 proto 未提供全部字段或保证 | 显式协议映射及能力缺口；不把请求回显、普通 get 或本地后过滤包装为已满足保证 | A:AL-P202/P203/RF04 |
| RD-09 | SRF 公共恢复/状态能力有规范，但不等于 A 需要的最终原子隔离已经实现 | A 表达 Guard、唯一提交、预算与恢复规则并做替身测试；真实原子性等 RF 联调证明 | A:AL-RF02/RF04/RF05 |
| RD-10 | C 动作标签、Provider 物理结果与实际读取路径属于不同证据 | 可选归因只用准确副本/版本和证据，不直接信任 Submitted/Succeeded 标签证明使用；不改 C 状态机 | A:AL-C02/C04/P204 |

这些条目说明设计采用方式与阻塞范围，不代替原 Owner 的确认。外部能力只能部分满足时，只启用已被证据覆盖的适配路径；不会以“较新文档覆盖旧文档”为理由单方面更改责任或原契约。

## 4. 本次可以确定与仍需对接的内容

**我们可以直接确定并实施：** Recall 目录、阶段处理器、输入输出引用、单一状态推进、原身份/预算绑定、错误与缺口分类、排序/组装规则、Consumer Port、测试替身和故障用例。D1 可据此开始。

**仍需按原台账对接：** B 当前事实/映射的实际协议与样例；RF 原子提交/隔离和事件 Schema；P2 搜索隔离/精确读取/写删证明；C 访问阶段映射及可选预热证据。这些是接口落地与能力核验，不意味着要推翻三个流程或让我们重写其他组。

本版不安排 B/C/SRF/P2 的内部开发顺序，不给其新增负责人，不修改其交付物。后续若存在无法兼容的外部变化，先说明影响并调整 A 的适配设计；涉及双方契约变更的仍回到原对接事项处理。
