## 2. 开发批次

### D0：冻结我们下一批的本地接口和测试样例

交付：01 的 StageContext/StageOutcome 及处理器约束；02 的依赖映射表；下一批需要的正常、拒绝、未知、失租、预算不足样例。优先覆盖授权、执行存储、共享 Embedding，再准备 Working/复核/内容映射的消费样例。

这里“冻结”只指 A 内部实现基线，不是三组共同签收。外部契约未确认时保留显式适配缺口，测试替身只模拟约定输入输出。样例由我们准备以便对接，不替对方宣布已支持。

退出条件：下一批每个本地接口都有输入/输出、错误/未知行为、调用预算、状态写入位置及可执行用例。无需等待所有外部实现完成。

### D1：请求复核与 Query 统一执行

**下一次代码开发就做这一批。**

1. 在 Recall 内增加阶段交接值对象与应用编排入口，复用已有记录类型，不另造一套请求/执行模型。
2. 实现请求复核处理器：读取原绑定，复核当前权限和证据，拒绝原范围被更改；成功保存真实复核检查点。
3. 把 query.py 的向量准备/结果验证逻辑迁入阶段处理器；取消其独立直接推进状态路径。若保留原实验入口，只能委托统一编排，不维持双写。
4. 在调用前保存 Query 共享身份、次数/预算意图；失租、重入和超时只查询/附着原执行，实际推理重试仍归共享模块。
5. 实现 Working-only 跳过、long_term_only 失败转收尾、combined Query 失败记长期缺口后进入 Working 发现的阶段交接。此批停在候选发现入口，不生成假候选或 Context。
6. 所有调用使用原期限并预留最终复核/收尾时间；状态保存和推进均使用有效 Guard 与返回的新版本。加入可注入时钟和可控故障测试替身。

D1 若先做到收尾准备/恢复边界而尚无最终提交实现，对外只能报告执行进度/暂不可用，不能伪造 FAILED_UNAVAILABLE 已持久化。完整最终提交随后在 D2 交付。

退出条件：一个执行只有一个状态推进者；所有模式与失败分支有真实检查点；重复调用不创建新推理身份；失租/旧版本不能写回；原受理行为无回归。

### D2：Working-only 完整业务链路

交付 Working 发现 → 初查 → 内联/引用正文验证 → 排序 → 最终复核及预算 → 唯一最终提交 → 交付事实。

- 用 B 契约适配或明确测试替身实现有界 Working 读取，区分 complete/partial/unavailable。
- 实现全部候选及替补最终复核、原子冲突组、整包真实 token 计数；缺少 B 语义时不编造默认成功。
- 一起交付最小账本、阶段事实 Outbox 和最终提交/查询/隔离边界。可靠性是本批完成条件，不留到整条链路完成后再补。
- 返回四终态及其正确空/非空包；未知提交不发布结果。交付事件在真实发送后产生。
- 本地示例覆盖合法 Working、完整空、来源故障、撤权、全部组超预算、提交回包丢失。

退出条件分开记录：**替身闭环通过**表示 A 规则成立；**真实端到端通过**还需 B/RF 能力及当前契约证据。只有前者时不声称一次真实 Remember 写入已经可端到端召回。

### D3：长期与 combined 链路

- 接受已证明范围隔离、过滤、模型空间和完成语义的 P2 搜索结果；保留稳定引用和来源排名。
- 核验 B 的当前长期可读事实与精确内容映射；实现有界字节读取、范围/版本/hash 校验及失败记账。
- 复用 D2 的核验、排序、预算和提交；增加跨来源去重、来源并行发现、缺口合并和成功回退处理。
- 三种模式共用结果分类，不因 Query 失败把 combined 改成 working_only，不以完整空掩盖长期缺口。

退出条件：三模式正确，旧向量/新正文不混用，Provider 部分/未知事实可解释，可靠返回有证据。真实 P2 功能不足时只保留测试环境路径，不用本地后过滤冒充 Provider 授权隔离。

### D4：恢复、事件适配与可选读取

- 用 RF 正式能力验证跨进程租约、原子预算、未知提交、防迟到写和重启恢复；把结果与替身测试分开记录。
- 按确认 Schema 接入 AccessTrace，验证本地事实/RF 摄取/C 消费确认的区别；不修改 C 的消费器或状态机来配合 A。
- 实现 A 自有派生内容的失效处理、分期清理和只读安全重放；P-16=0、过期、撤权均有明确行为。
- 仅在相关契约具备时加入 Prewarm 读取/回退和动作归因。它不阻塞基础 Recall 的排序、Context 和正式正文路径。

退出条件：真实故障注入可证明恢复与不重复副作用；未验证的外部能力仍列出缺口，不以整体“完成”覆盖。

### S：既定共享能力的独立工作包

Passage 输入适配与向量机制可在不等待 Recall 排序完成的情况下推进，但本次不是给 B 安排编排任务。

我们准备 B 可消费的 Embedding 正常/异常样例和模型空间契约；实现投影操作绑定、逐项 ProviderResult、原操作查询、准确目标核验、删除屏障与未知恢复。接受 B 已批准的 manifest，不自行分块或发布领域 Ready。

同五元组换 Artifact/分块以及 repair/rebuild 相关身份/代际尚未确认，保持明确不支持；不能用新任务键代替对接解决。其余已经具备输入与机制契约的路径可独立实现。

退出条件：每项输入/目标/结果可追溯，五态无假成功，缺 chunk 和迟到旧写被正确处理。B 的集合 Ready 是否成立以其提供的领域结果为准，不作为我们擅自实现的状态。
