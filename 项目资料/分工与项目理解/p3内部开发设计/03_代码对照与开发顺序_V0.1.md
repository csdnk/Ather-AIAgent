## 2. 下一批先做什么

### 批次 D0：接口基线与样例对齐

这是当前文档工作的后续评审动作，不要求等待所有人完成实现。

1. A 自查 RIF-01～06：原请求、状态 Owner、幂等身份、模型空间、deadline 和检查点是否一致。
2. 与 B 优先对齐 RB-01/02/03/08/09：Working Read、候选复核、正式正文映射、Passage 输入批准、投影结果消费；先提供方法/契约版本及正常、空、部分、未知样例。
3. 与 RF 优先对齐 AL-RF01/02/04/05；最终提交需要的事务与查询边界尽早明确，不能到末期才发现存储无法表达。
4. 与 P2 对齐逻辑 DTO 到真实接口的字段和错误映射；与 C/RF 对齐 AccessTrace 的摄取、消费和去重语义。可选 Prewarm 后置。
5. 差异及签收证据回写原 AL 台账；本目录接口说明按签收版本引用。

**D0 退出条件：** 接下来要使用的边界有提供方、版本、输入/输出样例和失败规则。其余未确认接口明确隔离，不阻断无依赖的内部实现，也不启用未经确认的真实路径。

### 批次 D1：执行复核与 Query 接入

**目标：** 同一已受理执行进入 Query 阶段并形成可恢复的阶段输出。

- 增加请求复核阶段处理器：读原绑定、重新授权、保存复核输出；授权未知或撤销停止相应执行路径。
- 将现有 Query 实验实现迁到执行存储 Port，消除直接改状态的第二套推进路径。保留原调用身份；重启/重试只附着同一共享推理执行。
- Working-only 保存“跳过推理”的检查点；long_term_only 核验向量后准备搜索；combined 记录 Query 失败造成的长期缺口，在预算允许时继续 Working。
- 使用原 deadline，并扣除最终复核/收尾预留；把调用开始前的预算与尝试记账接入已有模型。
- 用测试替身完成状态/错误分支，用原生 ONNX 作为额外集成验证。不要用真实模型测试代替幂等/失租测试。

**D1 退出条件：** 对应契约测试通过；旧 lease 无法写检查点；重复调用不新建推理身份；没有 Context 假结果；一个执行只有一个状态推进 Owner。

### 批次 D2：Working-only 的完整输出链路

**目标：** 一次记忆写入后，可以经已确认的 B 读接口返回可信 Context。

- 实现 Working 候选发现、来源覆盖和正文预算；接初次资格核验。
- 对内联/引用正文采用同样版本与完整性要求；实现基本排序、token 预算及出处保留。
- 实现最终复核、终态判定及 RIF-13 最小可靠提交；源码层先用 RF 测试替身验证，真实端到端验收需实际 B/RF 能力。
- 新增返回执行引用/结果的应用层入口，并映射到双方确认的接入契约。未完成协议评审前不擅自替换冻结 HTTP v1。

**D2 退出条件：** 完整有结果、可信空集、部分有结果、撤权/TTL 到期/预算装不下及提交未知等情形得到正确结果；提交未确认时不输出 Context。

Working-only 不调用向量模型和 P2 搜索，但仍沿用十三态及跳过检查点。状态名 `RUNNING_VECTOR_SEARCH` 的分支处理需按原状态机解释，不能为了实现方便私增或跳过状态。

### 批次 D3：长期候选、正文与 combined

- 接 P2SearchInput/Result 的真实适配或经认可的模拟接口，完成授权筛选、候选上限和 complete/partial 消费。
- 接 B 的长期领域 Ready、版本/模型空间核验及正式内容映射，完成有界正文读取。
- 复用 D2 的候选核验、排序、预算、最终复核和可靠提交，增加跨来源合并与缺口归并。
- 校验 Query 与 Passage 的模型和预处理空间一致；新原生模型配置不能未经核验复用历史投影空间。

**D3 退出条件：** 三种模式均能完成；来源故障与内容缺失不会伪装成完整空；只有准确版本、范围和证据通过的正文进入 Context。

### 并行工作包 VP：向 Remember 提供投影机制

这也是 A 的职责，可与 D1～D3 按人力并行。其推进不要求 Recall 排序/Context 全部完成。

1. 完成共享 Embedding 的 Passage 输入批准适配、结果获取和契约样例。
2. 实现投影请求原子绑定、提交/查询与机制结果保存。
3. 接 P2 upsert、query_operation、get_projection、delete 的实际适配与证据核验。
4. 实现未知结果查证、删除与旧写屏障；未冻结的同版本 rebuild 按当前设计拒绝。
5. B 消费结果并独立执行 Ready Guard；在 B 当前版本校验失败时不置 Ready。

**VP 退出条件：** ProviderResult 五态都有可测试路径；丢回包不重复写；旧 READY 不替代当前存在性；B 不需要了解后端推理或 P2 私有细节。

### 批次 D4：可靠恢复与 Operate 联调

基础提交/Outbox 在 D2 已需要实现；D4 是补齐完整恢复和真实基础设施验收，不是把可靠性全部拖到最后。

- 接 RF 正式存储/摄取，验证进程崩溃、租约接管、提交未知、额度不重置和内容分期清理。
- 接 C 的 AccessTrace 消费、去重、迟到事件和使用事实解释；验证 RF Ack 与消费 Ack 的不同含义。
- 按已确认契约接可选 Prewarm 与动作使用归因；没有充分证据的样本保持未知。
- Operate 完成 Signal/Trace→Plan→Action→Feedback→Reconciliation 的独立闭环；真实迁移效果由 P2 的实际层级证据确认。

## 4. 每个接口的开发完成标准

1. 契约与实现签名一致；适配映射能追到提供方契约版本。
2. 正常、空、部分、拒绝、未知及额度耗尽都有确定行为和测试。
3. 该保留的原身份/版本/预算没有被重试重置；有副作用的未知先查询。
4. 阶段输出可核验，并通过检查点/租约/CAS推进；不在辅助函数内偷偷写另一个状态 Owner。
5. 真实外部能力未验证时，交付说明明确“规则测试通过/真实联调未完成”。
6. 对外契约变化先更新说明与契约测试，再改双方适配；不要求先完成整个 Recall 再集中返工。
