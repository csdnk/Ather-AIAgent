## 本轮发现并修复的问题

1. Keycloak 26.8 对 introspection 增加 audience 检查。为 `platform-bff` 加入明确 audience 映射，保留严格令牌校验。修复前相关 BFF 用例拒绝访问，修复后通过。
2. Keycloak 默认不保留未注册的自定义资料属性。已注册仅身份管理员可读写的测试所有权属性，并读回核对权限，避免靠浏览器可编辑字段判断账号归属。
3. 为旧测试账号补属性时，Keycloak PUT 会清空未提交的姓名、邮箱。已改为保留完整既有资料再更新属性，并读回比较关键字段。受影响的 8 个隔离测试账号已按原 realm/初始化记录恢复；后续真实登录及 seed 回归通过。未涉及生产账号或 P3 数据。
4. 账号创建成功但本地回执缺失，以及回执 JSON 截断，会阻止重跑。已增加可信服务端 marker 恢复，损坏文件留存副本，回执通过同目录临时文件、flush/fsync、原子 replace 写入。
5. PostgreSQL 集成测试现于任何连接及 DDL/DML 前执行与导入器一致的隔离目标校验。
6. 本机启动检查改用 IPv4 回环，避免 `localhost` 的 IPv6 连接延迟导致误报；PID 归属校验统一比较 UTC 时间刻度，兼容 PowerShell 自动解析 JSON 日期。

## 当前环境与验收限制

新增身份目录使用**本机独立 PostgreSQL**，没有写入 Azure/P3 业务数据库。Keycloak、Budibase、目录库、BFF 均是隔离本机服务。现有 P3 的历史 Azure 验证结果见前一阶段报告，本轮没有重新运行或扩大那些结论。

BFF 的内存会话重启后失效，访问令牌到期需重新登录；这是一套兼容性验证入口。生产 HTTPS、跨实例持久化会话及完整生命周期仍需实现。

当前目录账号的 `identity_only` 只代表认证与目录数据已准备；管理修改的 `pending` 表示外部同步尚未完成。启用、角色分配、账号归属迁移、完整租户 CRUD 需要后续同步任务和读回，当前不会绕过这些条件放行。

6 个聊天场景仅是输入与预期，尚未执行 Remember/Recall/LLM。普通用户私有记忆隔离、跨会话召回、真实模型回复和原 operation/job 恢复仍需后续端到端验收。
