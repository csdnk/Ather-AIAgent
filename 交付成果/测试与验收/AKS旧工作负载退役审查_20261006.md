## 另外发现的 3 个临时 Pod

这三个 Pod 没有 ownerReferences，不受 Deployment、ReplicaSet 或 Job 管理，也没有挂载 PVC。均已终止，可以在保留必要日志和状态证据后删除 Pod 对象。

| Pod | Pod phase / reason | 容器终止状态 |
|---|---|---|
| `p3-interface-relay-20261003-03` | Failed / DeadlineExceeded | Error，退出码 137 |
| `p3-local-live-relay-20261003-01` | Failed / DeadlineExceeded | Error，退出码 137 |
| `p3-storage-validation-20261003-01` | Failed / DeadlineExceeded | Completed，退出码 0 |

第三项在 `kubectl get pods` 的 STATUS 列显示 Completed，但 Pod 原始 phase 为 Failed；容器完成不等于该历史验证整体验收通过。此处只依据其已经终止、无控制器和无持久卷判定对象清理条件。

删除这些对象主要减少列表残留；它们当前没有运行中的业务容器。临时 emptyDir 和日志不能作为持久备份，清理前应保存仍需追溯的证据。

## 旧 P3 为什么需要退役步骤

| 项目 | 旧 `p3` | 当前 `aether-agent-p3` |
|---|---|---|
| 配置文件 | `/deployment/service.yaml` | `/work/service.yaml` |
| profile | local | development |
| storage_mode | 未配置 | azure |
| PVC | `p3-data`，20 Gi | `aether-agent-p3`，5 Gi |
| Temporal endpoint | `temporal:7233` | `temporal:7233` |
| Temporal namespace | `default` | `aether-agent-20261005` |
| deployment_id | `aks-p3-demo` | `aether-agent-20261005` |

旧命名空间检查时有 1 个运行中工作流：`p3/aks-p3-demo/periodic`，类型 `P3PeriodicWorkflow`。这是周期调度工作流，不能直接等同于“有用户对话未完成”，但它证明旧后台尚未退役。新命名空间同一时刻也有 1 个运行中工作流。

旧卷 `/deployment/state` 中仍有 `p3.db`、`p3.logs.db`、WAL、正文文件、输入与缓存回执。仅数据库文件就有约 44 MB 状态库和 604 MB 日志库。本次只读检查文件元数据，没有证明这些历史资料可丢弃，也没有做数据迁移。

当前平台运行配置明确为 `http://aether-agent-p3.aether-p3-demo.svc.cluster.local:8080`。网关 ConfigMap 与当前源码均将 `/openapi.json` 指向新 P3；旧 `p3:8080` 的可见网关引用位于已经停服的 `web-nginx`。本次未做全网流量观测，不能排除未登记的外部客户端直接访问旧 Service。

## 建议执行顺序、风险与回退

1. 第一批仅处理旧 Web 对象及 3 个终止临时 Pod：执行前重新核对状态、专属配置引用和资源版本，保留可恢复资源定义及必要日志；不连带删除其他命名空间或卷。
2. 单独退役旧 P3：确认不再承接旧测试/客户端；对 SQLite 与正文等做一致性备份或经验证的卷快照；制定旧周期工作流停止方案，核实不会自动续建；再将 Deployment 缩容至零观察。验证新平台登录、对话、P3 保存/召回和 Temporal 后，才清理旧 Deployment/Service。
3. 如不再使用本机数据库转发工具，单独退役中继并更新连接说明。瞬间没有连接只支持“当前空闲”，不足以证明工具已经废弃。
4. 旧 P3 缩容观察失败时，恢复原配置和副本，并按工作流退役方案恢复调度；不得将旧数据写入新平台库。旧 Web 可从保留配置重建，但恢复公网路由属于另一个有影响的变更。

必须保留的 PVC：`aether-agent-p3`、`aether-budibase-data`、`aether-platform-database`、`aether-platform-release`、`p3-data`、`public-web-caddy-data`、`temporal-data`。本次没有审查通过任何卷删除。

实际收益：删除零副本 Web 与 3 个终止 Pod 不会减少运行中的业务 Pod；旧 P3 和中继若分别完成退役，最多减少 2 个当前运行 Pod。AKS 节点和磁盘费用不一定随 Pod 数量下降，需要另核对节点与磁盘计费。
