## 重要失败与处理

1. 预发布真实 HTTP 路由测试发现健康路径被 308 重定向覆盖。改为显式顺序路由并关闭自动重定向；修复后健康 200、首页 308 均通过，自动证书仍启用。
2. 首次 Linux 启动报 `exec /usr/bin/caddy: operation not permitted`。官方镜像二进制带 `cap_net_bind_service=ep`，与容器 `drop ALL` 冲突。独立 Linux Job 复现原二进制失败、复制后成功；增加非 root init 将相同二进制复制到 emptyDir 去除文件能力，应用只读挂载。保持原权限限制，代理随后 Ready，临时 Job 已清理。
3. 本机 Azure CLI 多次管理请求发生 SSL EOF。镜像通过已存在代理成功导入；公网 IP 使用已登录 CLI 获取的短期凭据调用支持的 ARM API 创建，先查后建，未关闭证书验证，未持久改代理设置。
4. 首次 TLS-ALPN 证书挑战连接超时，Caddy 自动转用 HTTP-01 完成校验并取得正式证书。最终公网 HTTPS 和公共证书校验均通过；持续续期仍需运行期验证。
