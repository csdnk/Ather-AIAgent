日期：2026-09-30。范围：本地源码接入与工程验证。完整 Python 回归 1513 项通过，独立审查的三个有效问题已修复并纳入本轮回归；迁移增量已安全合入原项目，合入后 Web 检查通过。Docker 因镜像仓库网络阻断未通过，Azure 与真实外部依赖不属于本地通过结论，不能作为生产验收签收。

## 1. 实现范围

统一 P3 的 Remember 接纳/文档/更正、后台加工、Working 与长期 Recall、Operate、事件投递、周期和缓存维护已接入 Temporal。原 RF 在线 claim、sweep、run_once、事件调度和旧周期入口已退役。普通读取、身份重载、进程探针仍由服务直接执行。

业务事务、权限与版本守卫、幂等键、不可变输入、完成凭据、分块检查点和业务 Outbox/Inbox 保留。Temporal 负责执行历史、任务投递、计时器与恢复编排；不能替代数据库恢复、P2 运维或操作系统进程重启。

首版为一个 P3 进程承载 API 与 SDK Workers，独占业务目录，连接独立 Temporal Server。SDK 1.33.0、CLI 1.9.1（内置 Server 1.32.0）、Python 3.13.15；CLI 开发服务器不等同于生产 Temporal 集群。

## 4. 升级、迁移与回退

当前执行计划版本保持 `plan_version=1`；未知版本在计划读取和阶段绑定校验中拒绝。离线重放使用由真实 Server 生成的 17-event 脱敏历史，只改 Worker identity，无业务正文或凭据。兼容例为不改变历史命令的 query 扩展；不兼容例把原 Activity 改为 Timer。

普通任务计划不变。审查整改接通周期控制唤醒后，新增实际兼容标记 `p3-periodic-control-wake-v1`，旧历史仍保持原计时器行为；保存由整改前提交 9e643bb 实现生成的 21-event 真实周期历史，并已用当前实现重放通过。今后改变活动顺序、分支或周期计划时，必须保留旧版本分支或迁移 Worker，并对保存历史执行重放门禁；不能仅修改版本号后让旧任务执行新步骤。

切换已有目录须停止旧服务和自动重启，运行 `migrate_temporal.py inspect`，处理阻断项后显式 `apply`。本轮没有自动操作用户运行中的业务数据。迁移保留原 ID、输入、预算与截止时间；缺少未知动作原始证据时拒绝切换。

切换后不能直接启动旧 RF 程序接管同目录。回退须停止新服务，由相应负责人按已核对的业务状态和 Temporal 历史制定方案；不能通过删除后端标记或重置 operation ID 绕过。

## 5. 重要失败与整改

- Operate 两个评估可能在准备和提交之间登记不同动作。已用固定交错顺序复现：两个 prepare 均先于 submit 时原断言失败。准备阶段现同事务保存 `generated` 动作和任务引用；首次提交原子转为 `submitted`，其余调用核对同 ID。定向 8 项通过，效果计数为 1。
- 运行验证器曾因 Windows 深路径达到 261 字符而无法创建正文临时文件。已缩短验证器证据目录，不改业务内容或隐藏失败；短路径真实进程门禁 6 项通过。实际部署仍须选择系统支持的路径长度。
- Docker 在基础镜像鉴权网络阶段失败，未通过改变全局代理或跳过构建来标记成功。
- PR 发布时 CI 发现 `IncidentRecord.reason_code` 对应 Schema 漏同步；已补齐生成文件，`generate_schemas.py --check` 从失败恢复为 131 个 Schema 全部一致。发布文件核对另补齐监测回归所依赖的同版对话验证脚本；该脚本复用已通过完整回归的版本，不更改业务执行逻辑。

独立审查整改：

| 项目 | 用户可见问题 | 修复与验证 |
|---|---|---|
| R1 / P1 | 人工恢复原来只更新业务记录，未向原 Workflow 发控制信号 | 接通恢复、取消、周期控制及进度查询；权限、revision、原绑定、OperationRecord 与控制意图同事务；ACK 丢失重复转交原 ID。真实 HTTP→SDK signal 测试通过；闭链明确失败；事务回滚和转交前撤权通过 |
| R2 / P1 | 旧周期 run 的历史清理后，仍活跃原链可能无法重新连接 | 从持久原链 ID、计划摘要、类型、队列验证当前后继；6 个边界用例和真实 Continue-As-New 测试通过。NOT_FOUND 是传输故障注入，未声称真实等待保留期到期 |
| R3 / P2，按影响列 Important | Task 已结束而 Recall、恢复操作、修复事件或投递仍显示等待 | 集中幂等终态投影覆盖 Activity 直接收尾、预算/截止、撤权/版本失败与周期技术终态核对；8 个定向用例通过，不更改 unknown 效果、不伪造独立核验成功 |

其他已复现回归：Recall 的空 pending-index 结果不再冻结成候选终态；basic/generation 两路径均复现后通过。组件测试的批量 drain 明确等待 60 秒，生产 deadline/预算不变；按用户要求，测试收敛等待统一为 60 秒，覆盖 10 秒 heartbeat；旧周期 API 的退役测试先等公开 readiness 就绪。全套每次失败均保留原始证据，最后结果单列于 E03。

测试等待约定（用户确认）：就绪、Workflow 完成、事件到达、批次收敛和子进程恢复的等待上限为 60 秒。故障注入的短 Activity timeout、重试间隔、HTTP 短等待及并发隔离断言保持测试所需设置；这些用于制造或判定故障，并非收敛等待。周期唤醒另断言原 Timer 被取消，不能用自然到期冒充控制有效。
