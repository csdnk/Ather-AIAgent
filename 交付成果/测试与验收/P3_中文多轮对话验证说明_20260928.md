# P3 中文多轮对话验证

日期：2026-09-28。脚本：[dialogue_demo.py](../../AgentJYS-main/scripts/p3/dialogue_demo.py)。

## 验证的场景

以出差助手为例，把自然中文用户话语发给当前运行的统一 P3 服务。脚本不会另建数据库，也不在客户端保存答案后伪装成召回结果。保存与查询分别经 Remember、Recall，后台长期化和 Operate 由正在运行的服务自动执行。

| 步骤 | 用户话语 / 应用动作 | 检查的真实结果 |
|---|---|---|
| 1 | 我的饮品偏好是无糖咖啡。 | 服务确认持久保存 |
| 2 | 我下周三去上海出差，住在虹桥附近。 | 服务确认持久保存另一轮陈述 |
| 3 | 我的饮品偏好是什么？ | 本会话 Working 召回包含无糖咖啡 |
| 4 | 我下周三去哪里出差？ | 本会话召回包含上海 |
| 5 | 结束会话 A，提交长期化 | 等待真实后台任务完成 |
| 6 | 新会话 B：我的饮品偏好是什么？ | 只发送问题，从 long_term 召回无糖咖啡 |
| 7 | 新会话 B：我下周三去哪里出差？ | 长期召回包含上海和虹桥 |
| 8 | 更正我的饮品偏好：我现在改喝无糖红茶。 | 明确纠错更新版本；旧召回结果重取返回预期 HTTP 410 |
| 9 | 再确认一下，我的饮品偏好是什么？ | 返回无糖红茶，不返回旧偏好；同一记忆版本递增 |
| 10 | 用另一个业务范围查询 | 不串入本次测试记忆 |
| 11 | 检查后台任务和监测记录 | 当前范围任务完成；Operate 已消费读写事件；三流程日志可查询 |

每次运行生成唯一 `dialogue_...` 业务范围。会话 A/B 属于同一个测试用户、同一个业务范围；新会话查询不携带旧聊天历史，也不限制旧会话 ID。P3 不创建聊天会话对象，A/B 是脚本中上层应用的会话标记。这个检查证明跨会话读取同一用户的长期记忆，不等同于跨租户权限验收。

## 在监控里逐轮查看

1. 自动刷新选择“每 5 秒”。脚本成功输出的 `tasks` 列出本次任务，复制完整 `task_id` 到“后台任务”查询。
2. `traces` 中的 `dialogue_steps` 对应中文对话步骤；复制旁边的 `trace_id` 到“链路追踪”，查看瀑布图和节点记录。
3. 多轮请求会产生多条 Trace。保存请求的 Trace 可能还包含其后台 Remember/Operate 节点。超过一页时继续加载日志。
4. 短任务可能在两次采样之间完成，因此总览积压数为 0 不代表未运行。查看持久任务和 Trace 明细。
5. 旧结果 HTTP 410 是纠错用例期望的失效响应；不能把这条预期失败节点等同于整个测试失败。

本地实测：默认参数执行完成，退出码 0，12 项检查通过。业务范围 `dialogue_0acca8ba2e8e4a499e37f9e8a077c8fa` 的 27 个任务均 succeeded，查询到 12 条业务 Trace、1989 条保留节点记录。这是该次完成时的快照，周期任务后续可能增加记录。错误凭据另行验证返回 HTTP 401；脚本 Ruff 检查通过。

这是中文对话场景下的真实记忆链路验证。当前本地实例使用 lexical 检索及原文加工基线，没有配置聊天大模型；输出明确标为“P3 实际召回”，不是模型生成的回答。保存、查询、明确纠错的接口路由由预设上层应用给出，不证明系统已能自动理解任意意图或自动判定纠错。词法召回可能带回多条上下文，本用例不宣称精确排序或同义改写质量。

此用例检查自然对话触发的 Operate 任务，不人为循环 16 次读取来触发 hot，也不声称已观察到热度阈值升级。需要专门验证 hot 放置时继续使用 `monitor_demo.py`。日志只覆盖当前保留范围；故障恢复、生产长稳及真实模型质量仍需单独验收。
