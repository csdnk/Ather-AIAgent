CP2-04 的真实 HTTP 场景逐项断言：

1. 保存成功；同一 operation_id 重复提交返回原 job 和原结果。
2. 后台投影 ready 后检索到保存正文；另一租户无法读取该记忆。
3. P3 正文和输入没有本地权威文件副本，对象经真实 P2 回读。
4. 关闭并重建 P3 服务，原任务结果、原 Recall 结果仍可读取。
5. 同一记忆更正到 v2 后旧 Recall 失效，新检索返回更正正文。
6. 删除后新检索为空、旧结果失效；轮询原清理任务直至 succeeded。
7. 另一条仍有效的 Working 记忆保留相同原正文并继续可检索。

## 3. 本轮修正

| 问题 | 修正及验证 |
|---|---|
| 能力目录读取已移除的 Ceph 配置，返回 500 | 改为报告实际装配的对象 provider；区分 p2_grpc、local_reference、其他 P2 provider，并明确 production_ready=false |
| 中断恢复测试重启时更换加工组件类型 | 测试保留原组件类型，仅解除外部阻塞；继续验证恢复，不放宽冻结组件身份校验 |
| 将搜索未命中误认作向量不存在 | 未命中保持 unknown；删除完成依赖 P2 明确回执与 P3 持久确认记录 |
| 删除前没有投影记录时缺少防迟到写入记录 | 先记录删除意图，再调用 P2；后续投影拒绝重建该目标 |
| P2 删除回执数量和重复搜索行未严格验证 | 拒绝数量不匹配；重复向量 ID 不能作为投影成功证据 |
| 单位向量 inner_product 模型空间被误拒绝 | 接受单位向量下与 cosine 的数学等价；检查单位长度，保持原模型空间标识 |
| 另一条记忆拥有相同正文导致删除任务永远等待 | 缓存按目标 Memory、作用域、版本判断清理；另一条有效记忆的相同正文副本保留 |
| 较短请求截止时间没有约束远端等待 | 收窄可信上下文，调用前后复核截止时间，并限制异步等待。过期请求不写意图；等待超时保留原意图，按原投影检查，不重复插入 |
| 查询中共享授权撤销仍能得到 verified | P2 返回后再次检查目标记忆读取权限，撤权则拒绝返回确认结果 |
| 普通搜索接受重复 ID 或超过 top_k 的回执 | 拒绝违反条数和唯一性约束的回执；并发重复投影与删除后迟到写入有专项测试 |
| 更正/删除使尚未提交的 Operate 动作进入 unknown/attention_required | 未提交动作持久化为 cancelled，原工作流完成收尾且不调用执行器。已提交未知动作保留原 ID 查询，取得确定结果后再收尾 |
| 缓存接口抽取后使用文本读取自动转换 CRLF | 完整性检查和缓存读取改为原始字节解码；保留换行并拒绝非法 UTF-8 |
| 旧的修复回执丢失测试未传新增授权上下文 | 故障注入传递原上下文，实际完成持久修复后再丢失回执，断言只执行一次并通过读取验证恢复 |

保留的失败记录：原 74 项回归曾有 4 失败、2 跳过；4 个具体失败已有针对性复验通过，未将原始结果覆盖成全绿。本轮完整 HTTP 验证还实际发现并修复了度量兼容和缓存清理问题。补充测试首先复现了 7 项向量消费失败、2 项 Operate 更正/删除失败及 2 项缓存 CRLF 失败，最终均纳入 CP2-08 通过。中间回归另发现旧故障注入签名不匹配，并纠正了“远端已查询确认的删除动作仍应保持未知”的测试预期；保留原失败及纠正依据。固定调度顺序的更正/删除专项测试已确认原 action_id、未提交取消、零执行器调用和原工作流收尾；已提交未知动作仍按原 ID 回查。原生模型跳过项不计入通过。

## 4. 正式 P2 接入需求

以下是 P3 需要消费和验证的能力，由 P2 负责人确认实际接口与实现；不在本次 P3 工作中改写 P2 引擎或决定其数据库方案。

| 能力需求 | P3 消费验收要求 |
|---|---|
| 原子元数据/权限/任务/事件操作 | CAS、幂等键、事务提交、Outbox/Inbox、撤权竞态、分页一致性；成功或不确定提交可按原操作查询 |
| 对象存储 | 真实 Ceph 写入/回读；不可变写入语义、范围、hash、权限、版本、删除与保留策略，以及原请求重放边界 |
| 向量存储 | 真实 Milvus 投影和搜索；scope、模型空间、来源、版本过滤；精确投影查询、原操作查询、完整/部分结果语义 |
| 缓存与放置 | 真实 Redis 及 P2 层级存储；读取、配额、TTL、放置观察、repair/purge、原动作回查；失效版本无法被迟到动作恢复 |
| 环境与安全 | 开发/测试/生产逻辑空间隔离，TLS/身份授权，端点和能力版本；故障明确报告，禁止自动切换参考后端 |
| 调用方运行登记与恢复 | P4 request/scenario/scope、步骤意图、operation/job 和结果关联需持久化；原子创建、冲突检查、版本/所有权栅栏和原操作查询。P3/P4 已通过既有事务接口实现登记消费，参考元数据下完成运行恢复及回执丢失保护通过，见 FG-29—33；正式 P2 仍需确认/提供事务与原操作查询。普通 Object Put/Get 不等于跨实例 CAS |

当前 P2 仍缺少精确向量读取和原操作查询。返回元数据与自查询相似度的核对不能替代独立的底层向量精确证明。当前删除回执只证明持久查询墓碑生效，不能声称物理擦除。向量截止时间和共享授权撤销已完成 P3 消费端受控专项验证；正式 P2/生产身份下的相同行为、Segment 迁移回调、跨进程动作协调及多实例故障仍需真实环境验证。

## 5. 后续切换与迁移准入

优先将正式 P2 的差异限定在配置和消费 adapter，保持业务契约与 Temporal 编排语义；这仍需要兼容性回归，不能提前承诺只改一个地址就完成迁移。

1. P2 明确能力版本、逻辑命名空间、权限和后端契约，P3 实现并验证正式消费 adapter。
2. 以同一批业务场景跑通 P3→正式 P2→PG/Redis/Milvus/Ceph；逐项留真实依赖证据。
3. 盘点原数据、删除标记、来源/版本/授权及所有未终结任务，确认需要迁移的范围。
4. 建立备份与明确切换水位，保留 Memory ID、operation_id、job/workflow 身份、input hash、scope、auth_epoch、fence。未知作用先回查原操作。
5. 导入权威数据并核对 hash/版本/删除状态，重建派生投影，验证幂等；显式升级 provider binding，禁止绕过旧绑定。
6. 恢复原任务并复验保存、检索、更正、删除与恢复；最后切流，准备单边写入的回滚方案。
7. 完成正式模型质量、身份、AKS/生产 Temporal、故障恢复、灾备和长稳验收后，才交付可上线版本。

正式 P2 的事务与缓存 adapter 尚未具备，因此 production_p2 配置会在启动前拒绝进入服务。现有参考组件的最终替换目标保持有效；本报告不批准生产发布。
