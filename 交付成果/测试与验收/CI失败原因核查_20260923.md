# GitHub CI 失败原因核查

核查日期：2026-09-23。提交：`de006e1c12ff339a99147b4dea7dee4d2691db18`（PR #4 合并结果）。

## 结论

截图中的四项失败已取得远端日志。失败点为测试依赖、类型检查依赖/声明和 Rust 格式检查；这些日志没有证明 Recall 算法或模型推理输出错误，但阻断了对应远端验证。不能用本地 664 项通过替代远端全量工程验收。

本轮只核查原因和影响，没有修改工作流或业务代码，也没有重跑远端任务。

## 已确认的失败

| 检查 | 直接原因与结果 | 历史归属 |
|---|---|---|
| p3-native-embedding / adapter | requirements-native.txt 未安装 pytest-asyncio；新增异步测试报告 `async def functions are not natively supported`。实际 6 failed、12 passed | 新增异步测试后没有同步该分项 CI 依赖，是本轮遗漏；此前相同分项通过 |
| p3-flows / flows | 测试收集因 `No module named 'fastapi'` 中断，两处收集错误；类型检查因 FastAPI/Uvicorn 缺失及连带的未类型化装饰器错误失败，共 23 条 | 之前的 e3835d3 已有相同依赖问题（当时 21 条类型错误）；本轮新路由/测试增加了受影响位置 |
| ci / python | Ruff 成功；Mypy 发现 5 条错误：p2.generated 缺少类型声明/py.typed、sentence_transformers 缺失、两处 tokenizers 缺失、types-PyYAML 缺失。随后 Pytest 被跳过 | 基线 5340a30 的远端日志中已有相同 5 条错误 |
| ci / rust | `cargo fmt --all -- --check` 发现格式差异（导入顺序、空白和注释对齐等），退出 1；随后 Cargo test 被跳过 | 基线 5340a30 已有同类格式失败，本轮未修改 Rust 代码 |

流程分项中的 RF 回归、契约回归和示例仍通过；独立 p3-foundation、p3-contracts 工作流成功。通过项不能替代失败或未执行的检查。

## 另发现的协作工作流问题

`.github/workflows/p3-collaboration.yml` 对同一提交也有失败记录。GitHub CLI 提示可能是工作流文件问题，Actions API 返回 `total_count: 0`、`jobs: []`，没有任务日志。

因此，远端协作门禁没有实际启动测试。工作流中 job 级 env 使用 `runner.temp` 是需要校验的可疑配置点；详细配置校验注释仍因 Checks API 权限不足无法读取，不能把该怀疑写成已由远端日志确认的根因。该工作流在基线提交上也已失败。

## 影响与修复方向

- 本地完整协作门禁 664 项通过和此前真实 BGE/SQLite/TCP HTTP 功能验证仍是有效的本地证据；本次远端失败没有覆盖或撤销它们。
- 当前不能声明远端全量 CI、Rust 测试或全仓 Python 测试通过。没有执行的测试不计为通过。
- 原生分项需要补齐异步测试插件；流程分项应使用覆盖实际 HTTP/运行依赖的安装清单。
- 全仓 Python 工作流需要处理可选依赖、生成模块和类型声明边界，而不是直接关闭严格检查。
- Rust 应先修复格式，再实际执行 cargo test；格式失败本身不足以判断 Rust 功能是否正确。
- 协作工作流需要先修复启动配置，再在 GitHub 干净环境运行。修复依赖或格式后可能暴露后续测试问题，不能预先承诺仅改依赖就全部通过。
