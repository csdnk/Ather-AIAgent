## 5. 重要失败与修复记录

1. 原独立审查发现 Temporal schema 脚本把密码作为 awk regex、AKS runner 查询失败仍报成功/summary 早于 cleanup、async PG 元数据阻塞循环、Redis 配额只影响报告不约束所有准入、Temporal server-only 镜像缺探针 CLI。分别改为字面脱敏与保留退出码、UID 保护且最终确认 cleanup、ContextVar 有界线程池、Lua 原子 `min(service capacity, scope quota)`、使用实际 Server+CLI 镜像摘要模板。独立审查原快照判定未 ready-to-merge，修复与最终证据以本报告为准。
2. 新独立 Milvus 集合为空时，旧 P4 组件夹具在业务前被 readiness 拒绝。测试-only startup 使用真实 `prepare()` 创建自己的集合后进入原 lifespan；没有修改生产探针或伪造健康。旧 5 个失败及两次受控中断记录保留，9 项定点回归 GREEN。
3. launcher 的前一次 `review-final-05` 16 passed/6 failed，漏上传 deploy；source archive 加入 deploy 后 `review-final-06` 22 passed，最终清理确认。前一失败不改写为通过。
4. 旧 6 GiB Pod 模型叠跑出现 OOM，后续最终回归与模型测试串行并在已核对额度内执行。transport/中断/OOM 不计通过。
5. 候选恢复曾把已持久化 30 秒周期改为 60 秒，触发计划绑定拒绝与 readyz 503；仅恢复自己的原 30 秒配置后 Worker/原回执恢复。不同间隔不是同一环境重启的有效验证；开发指南已写明。
6. 早期候选 Recall 有 `EXECUTION_INTERRUPTED`，保留原操作记录，没有更换 operation ID 重发写入；后续 Working/长期召回及原结果读取按独立意图验证。
7. 最后复核补齐健康 HTTP 末端 PG offload 后，`full-final-reviewed-11` 被精确 SIGINT 以换最终源码；451 passed、退出 2 的该次中断不算完整通过。此前 `full-serial-final-10` 771 passed/5 failed、退出 2 的结果也不与定点结果累加。

8. 最终镜像 `aether-p3:cleanup-20261004-03` 的一次新保存操作 `final_save_e471ab5e93b841af9388e445d24d8db1` 对应 job `95a43f8d68384e78de62cb04f8d73ffca435616392deb4641eddb4f2314c7709`。原 POST 返回 REQUEST_IN_PROGRESS；只轮询该原 job，未重发。最终 result 返回 400 EXECUTION_INTERRUPTED，任务 attention_required、query_attempt=6、effect_status=unknown；Working/长期新业务后续步骤没有执行。Temporal 原历史显示 commit/admit_cache 多次 30 秒 StartToClose 和 10 秒 heartbeat 超时。虽然已有提交/receipt 相关记录，仍不能判定整个命令成功。只读同库 SELECT 1 经 relay 75–82 ms、AKS 直连约 1 ms；尚未证明唯一根因。下一步须在独立环境检查元数据锁/线程等待与阶段预算，再最小修复并验证原意图恢复；不能只加 HTTP request_timeout，也不能换 operation ID 重写相同意图。失败证据已保存后，仅本任务测试数据按授权回收。

## 6. 清理后的本机入口与 Azure 部署步骤

完整可执行指南见 [P3 Azure 开发环境与 AI 配置指南](../部署运行/P3_Azure开发环境与AI配置指南_20261004.md)。开发者应从本次 PR 的获核验提交创建个人分支，所有环境/密钥/模型/日志保存在仓库外。

本机启动顺序：个人 Python 3.13 外部 venv → 安装项目依赖和生成 protobuf → 准备 BGE/分词器与个人身份 → 领取并核验 PG/Redis/Milvus/Ceph 权限与 CA → 启动个人 development Temporal 或连接已批准正式 Temporal → 初始化空外部 deployment → check-config → 注入六项 AETHER 密钥并 serve → readyz/Worker/业务/原结果验证。

```powershell
# 在 AgentJYS-main，变量按开发指南设为个人外部路径。
& $P3Python -B -m aether_agent_memory check-config --config (Join-Path $P3Work 'deployment/service.yaml')
& $P3Python -B (Join-Path $P3Work 'start-p3.py')
# 在另一个终端检查个人端口，然后执行有唯一数据范围的业务冒烟。
Invoke-RestMethod http://127.0.0.1:18090/p3/readyz
& $P3Python -B scripts/p3/smoke_service.py --url http://127.0.0.1:18090 --credential-file (Join-Path $P3Work 'private/credential') --timeout 180
```

Azure 顺序：个人 az login 与订阅 → 独有 kubeconfig/RBAC → 分配个人 namespace/数据库/对象范围/Temporal/PVC/网络 → 构建 P3 与 Server+CLI 镜像并推 ACR、固定 digest → 生成外部容器路径配置与 Secret/CA → 预检模板 → 仅在个人 namespace apply/rollout → port-forward/HTTPS 入口 → readyz/Worker/保存/长期化/召回/原结果/独立重启与恢复验收。正式生产切换另需角色、TLS 与停机安排。
