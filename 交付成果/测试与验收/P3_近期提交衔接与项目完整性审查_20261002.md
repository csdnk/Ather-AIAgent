## 3. 必须处理的衔接和运行缺口

### F-01：P4 文档故事与新版摘要规则不兼容（P1）

PR #14 的 `WorkingSummaries.needed()` 仅在解析后的 UTF-8 正文达到 `working_summary_min_bytes` 时要求摘要，默认阈值 65,536 字节；旧版还把所有文档强制视为需要摘要。

P4 的 `remember()` 仍以 `document is not None` 强制进入 `finish_summary()`，该方法要求恰好一个 `remember.summarize` 任务且版本增加 1。图书馆规则只有一小段文字，新版保存后没有摘要任务，P4 因而调用 `reject_scope()`，返回“返回引用不属于本轮或来源不一致，停止展示与后续操作”。这是摘要规则的衔接错误，不是本次发现了实际跨租户数据泄漏。

E-01 在真实 P3/P4 HTTP 适配及真实 Temporal Server 下复现了该失败。该故事目前不能完成文档保存后的查询演示。应由 P4 按实际任务和处理状态消费可选摘要，并保持原来源、版本和权限检查。

定位：[摘要判断](../../AgentJYS-main/src/aether_agent_memory/remember/basic/summaries.py)第 64 行；[P4 文档消费](../../AgentJYS-main/src/aether_p4_simulator/demo/execution.py)第 203、208、220、268 行。

### F-02：旧 Remember 任务检查点不能直接续跑（P1）

旧 `checkpoint_binding()` 绑定策略、模型空间和两个 tokenizer 身份；新版另加入任务种类、处理规则版本和相关 provider/model 身份。`BackgroundStages.handler()` 在执行任何后台阶段前要求保存的指纹与新计算值完全相同。

E-03 用隔离数据重建了旧版指纹格式，保持策略、模型空间和 tokenizer 一致，并保留旧队列类别。`project`、`cleanup`、`extract`、`distill`、`compress`、`summarize`、`revalidate` 七类未完成任务全部变为 `attention_required / VERSION_CONFLICT / no_effect`；同环境的新格式投影任务成功。该实验验证的是旧格式业务账本的拒绝行为，没有修改真实历史任务，也不是全量旧历史回放验收。

PG 迁移脚本复制原始记录，Temporal 迁移检查确认绑定存在，均未实现旧 Remember 指纹的版本兼容或转换。新版注释中的“storage-only tasks stay compatible”不足以说明升级前的投影/清理任务实际兼容。需要明确旧任务收尾、兼容执行或受控迁移方案，不能直接重写指纹让旧模型输出变成可信新输出。

定位：[新指纹](../../AgentJYS-main/src/aether_agent_memory/remember/basic/pipeline.py)第 1351 行；[阶段入口核查](../../AgentJYS-main/src/aether_agent_memory/remember/basic/temporal_background.py)第 40 行；[PG 原始记录迁移](../../AgentJYS-main/scripts/p3/migrate_remember_postgres.py)。

### F-04：用户要求的固定后端和三环境隔离尚未完整实现（P1）

当前配置仍保留 `local/production`、缺省 SQLite 和可选 lexical；没有设计中的 `schema_version: 2`、`development/integration/production` 配置模型及三份环境模板。production 的校验只要求非空 `milvus_uri`，E-04 证明文件路径也可通过，未限制为 Milvus Server；Redis 仍可省略。`check-config` 主要验证结构和身份，不验证真实外部依赖。

即使元数据切到 PG，`ThreeFlows` 仍无条件创建 `LocalCacheExecutor`，Operate 的动作、修复和副本状态使用 `executor.db`，hot/warm/cold 是本地文件，健康检查也要求这个 SQLite 文件。Temporal 请求输入和正文副本仍依赖本地目录。Redis 正文 key 只有 scope 指纹及正文 hash，没有环境前缀；同一 Redis 数据库中的同 scope、同 hash 会共用 key。因此单纯切换地址不能实现既定的完整环境隔离，PG 接入也不能自动支持多副本。

此项是与用户已选方案的实现差距，并不把本地测试夹具称为生产后端。开发、联调和正式环境需要统一固定后端实现，并隔离数据库、bucket、Redis key、Milvus collection 和 Temporal namespace/队列。

定位：[默认后端](../../AgentJYS-main/src/aether_agent_memory/runtime/flows/config.py)第 67～84 行；[无条件本地执行器](../../AgentJYS-main/src/aether_agent_memory/runtime/flows/host.py)第 202、234 行；[SQLite 执行记录](../../AgentJYS-main/src/aether_agent_memory/operate/basic/executor.py)第 67 行；[Redis key](../../AgentJYS-main/src/aether_agent_memory/remember/basic/content.py)第 50 行。

### F-05：Ceph 接入边界、PG 灾备及 Temporal 持久化仍需完成（P1）

新增 `CephP2` 是 P3 Python 内的真实 RGW/S3 adapter，提供不可变写、精确字节比较、整读 hash 和范围读取检查。它由 P3 直接读取 Ceph 凭据并访问 RGW。设计文件目前要求 P2 管理 Ceph、P3 消费正文契约；现有 Rust P2 仍装配 `LocalObjectEngine::new_with_sqlite`。因此应明确最终正文边界，并同步设计、运行说明和消费者，不能宣称“P2 Ceph 引擎已经完成”。

PG 模式下现有 `/p3/backups`、`/p3/restore-drills` 明确拒绝旧 SQLite 快照流程，只提示需要 `pg_dump/pg_restore`，尚无对应完整备份、离线恢复和业务复验闭环。PG 元数据迁移不迁移正文，也不迁移 Temporal Server 历史。当前 Compose 和同日 Azure 现场的 Temporal 仍运行 `start-dev` 与 SQLite 持久化；PG 版 Temporal 部署未落地。

既有 Ceph 的 AKS 网络路径、认证读写与响应丢失恢复，PG/Redis/Milvus Server 的真实联合验证，均未在本次执行。不能只根据资源已创建或健康探针通过判为业务接入完成。

定位：[Ceph adapter](../../AgentJYS-main/src/aether_agent_memory/remember/basic/ceph_p2.py)、[P3 直接装配](../../AgentJYS-main/src/aether_agent_memory/runtime/flows/application.py)第 110 行、[Rust P2 后端](../../AgentJYS-main/engine/services/ae-server/src/bin/ae-grpc.rs)第 33 行、[PG 备份与恢复拒绝](../../AgentJYS-main/src/aether_agent_memory/runtime/foundation/lifecycle.py)第 124、185 行。

### F-06：新状态提示未被 P4 完整消费，回归基线也有漂移（P2）

新版 `/processing` 增加 `recovery`、`candidate_rejections`、`rejected_candidate_count` 和任务 `terminal_reason`；capabilities 增加 metadata/telemetry 后端。当前 P4 adapter 忽略这些字段，解析兼容，但界面没有承接新的恢复提示及存储模式证据。

E-02 复现了 5 项已有失败。其中并发比较、摘要期间更正/删除三个用例在任务入队后替换 provider，被新增 provider 指纹校验提前拒绝，相关竞态并未实际执行；不能据这些断言失败断言删除守卫本身坏了。同事件补充用例仍假定相同 `event_key` 即可合并，已与新证据策略不一致；需要补真实上下文和验证器用例判断新业务行为。摘要 demo 则仍默认短文档一定有摘要，直接出现 `NoneType` 读取异常。

E-01 中“抽取中断后恢复”用例重启时从 `Interrupted` provider 换成默认 provider，其任务账本同样为 `VERSION_CONFLICT`。这说明固定 provider 重启和改变 provider 后恢复必须分开验证，不宜把所有恢复用例失败统称为 Temporal 故障。

定位：[P4 响应类型](../../AgentJYS-main/src/aether_p4_simulator/validation/models.py)第 27、53、70 行；[处理状态输出](../../AgentJYS-main/src/aether_agent_memory/remember/basic/pipeline.py)第 915 行；[摘要 demo](../../AgentJYS-main/scripts/p3/demo_remember_summary.py)第 198 行。
