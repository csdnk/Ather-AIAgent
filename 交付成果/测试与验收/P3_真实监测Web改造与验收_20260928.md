# P3 真实监测 Web 改造与本地验收

日期：2026-09-28。工作分支：`codex/p3-monitoring-web`，基线为已合并 PR #8 的 `c2e8c24`。本报告描述本次本地 Web 改造，不将上一轮远端 CI 结果作为本次验证。

## 交付结论

现有 Web 已切换为统一 P3 服务的真实监测工作空间，提供运行总览、服务与依赖、后台任务、链路追踪和异常事件五个页面。浏览器已经通过同源代理访问实际运行的 Python 服务、SQLite 任务和本地 Trace；没有使用前端 Mock 回退。

UI 借鉴 Grafana、Datadog 等监控平台的常见组织方式，采用深色侧边栏、紧凑状态卡、工作负载趋势、表格、详情抽屉及父子节点瀑布图。390 像素宽度下验证无页面横向溢出；明细表保留容器内滚动。

## 接线与行为

- 新增 `GET /p3/tasks`：权限过滤、状态筛选、身份与查询条件绑定的签名游标。目录仅返回元数据；资源授权不授予他人的整条 Trace。
- 新增 `GET /p3/traces`：按原发起身份及 home scope 限制，支持流程筛选、首次保留记录倒序及分页。默认展示包含业务节点的链路，内部维护 Trace 可单独查看。
- 复用健康、运行态、任务详情/进度、规范化节点日志及异常接口；监测页面不提供恢复、删除或权限修改按钮。
- Trace 按 span_id 组织父子关系，用终止节点的真实 elapsed_ms 绘制耗时；事务 committed 不被误当作节点 returned。日志缺失和未闭合均明确标注。
- 工作负载趋势只保留连接后的最近 60 次实际采样。断连留空，历史不补零；认证失败时不保留正常指标，健康证据过期显示未知。
- 凭据仅存在页面内存，不进入 URL、浏览器持久存储或构建产物；刷新、断开及切换身份会清除本页状态。
- Vite 开发代理与 Nginx 部署代理统一使用同源 `/p3`。Compose 加入 Web，默认宿主端口 3000；两处 CI 配置加入 Node 22 的 lint/test/build，监测后端用例加入三流程门禁。

## 使用

参见 [Web README](../../AgentJYS-main/web/README.md)。后端启动后，在 `AgentJYS-main/web` 执行 `npm ci`、`npm run dev`，访问 `http://127.0.0.1:5173`，输入具备诊断权限的部署凭据。测试预览使用项目外独立部署数据，不读取用户生产记忆。

## 尚未覆盖

本次交付是本地统一服务监测界面。尚未提供持久历史指标服务、跨实例汇总、CPU/内存或业务 QPS/P95 采集、告警通知、OTLP/Grafana/Jaeger、Azure 运维平台、权限管理和自动恢复控制台。任务目录基于当前本地 RF 存储扫描，大规模集群性能仍待验证。Trace 覆盖范围受保留策略影响，不能替代持久业务事实；本次没有将短时界面验证升级为长稳或产品验收。
