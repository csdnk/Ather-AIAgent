# Mock V1.3 模拟改造验收

日期：2026-09-20。范围：甲方产品行为评审原型，非真实业务系统验收。

**结论：已交付统一的V1.3状态化Mock，可用于展示三流程、租户授权、检测追踪及恢复过程。共12个专题、105个步骤；默认主线20步。** 正式产品、身份、模型、P2、性能和长稳验收不在本次通过范围内。

入口：[P3统一Mock](../原型Mock/index.html)。操作方法见[演示说明](../原型Mock/原型Mock设计与演示说明.md)，现场答法见[甲方评审指南](../里程碑与交付/甲方评审沟通指南_PRD_ADR_Mock.md)。

## 1 交付变化

| 原核查项 | 本次处理 |
|---|---|
| M01 基线不一致 | 页面、场景、文档与导出统一标记PRD V1.3；无V1.2当前基线 |
| M02 ADR映射不直接 | 使用主ADR D01—D08；每个场景、决策和FR互相定位，保持Proposed |
| M03 两套授权逻辑 | 核心、租户和后台使用同一状态模型；旧Context校验当前主体、租户、资源许可和版本 |
| M04 后台范围不明确 | 任务保存原主体、租户、配置版本；演示控制仅推进原任务，并不赋予业务权限 |
| M05 V1.3场景缺失 | 增加配置失败不部分开放、在途撤权、主体停用、外部撤销时间线、停用后的旧快照恢复 |
| M06 覆盖表过期 | FR01—FR18关联新版专题；预测单列后续P1，真实验证边界逐项标明 |
| 追踪与恢复展示不足 | 同一原请求trace关联加工、租约检测、恢复判定、重试和迟到提交拒绝；依赖、Task、Outbox、Action、配置记录可查看 |
| Operate异常不完整 | 增加相邻降层、容量暂缓、明确失败、证据丢失保持Unknown及停用后受控对账 |

旧租户和补充加工HTML保留为跳转入口，原双模型JS与旧样式在备份及引用检查后移出成品目录。未修改生产后端或PRD原件。

## 3 明确限制

- 模型候选、提纯、检索、排序、身份和P2执行都是确定性模拟。演示目的是评审可见行为；不是验证这些真实技术已接入。
- 预算使用字符模拟完整组装；真实系统按目标tokenizer计量。
- 恢复采用“当前授权及有效性屏障独立保留”的模拟假设。正式权威来源、备份与失联处置需要设计及真实故障测试；旧快照不能复活删除或被替代内容。
- 外部撤销采用30秒虚拟窗口，正式传播上限仍按PRD 14.2确认。
- 任务租约、有限恢复及副作用对账均为浏览器内状态变化，不构成真实进程/磁盘故障恢复保证。
- 导出JSON为模拟记录，主ADR仍为Proposed；MVP24小时、Final72小时等产品验收未在此执行。

## 4 推荐演示顺序

先走S01，随后展开S09授权、S11恢复、S06调度。对某个失败结果点击trace_id解释依据，再用“需求覆盖”和“架构决策”定位条款与设计理由。不要逐页朗读框架介绍。
