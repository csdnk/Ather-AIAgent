## 3. 本轮修正与回归

1. **Redis 异步阻塞。** `resources/observe/submit/query` 原先在事件循环上直接等待 PG；4 项真实 PG 调度测试分别先失败，再经完整同步操作移到 `asyncio.to_thread` 后通过，保留上下文与原授权检查。
2. **Operate 阶段阻塞。** prepare/submit/reconcile/commit 的 PG 阶段读写先复现调度回调无法执行，再改为使用捕获的 `StageContext` 工作线程；准备输入、策略判断、原意图预约独立移出事件循环。原 task/action ID、provider 绑定、提交护栏保留。合并缓存相关验证 **24 项通过**。
3. **部署启动参数。** VM Compose 和 AKS 模板改为 `temporal-server --config-file /runtime-config/production.yaml start`。tmpfs 完整挂载选项加引号，避免 YAML 拆成三个元素。
4. **现有 schema 续跑。** Job 使用独立名称 `p3-temporal-schema-upgrade-1-32-0`，`P3_SCHEMA_MODE=upgrade`，从现有 1.19/1.1 继续；本轮未部署执行受阻的升级。
5. **可重复恢复测试。** 新增真实 Azure/模型 HTTP 独立进程测试，覆盖原 job 恢复、更正、删除与再次重启。

证据 **AZ-M03**：相关 Operate 工作流/慢元数据回归 **14 通过，48.24 秒**。这些测试用真实测试 Temporal 和参考领域后端，作用是回归控制语义；不据此宣称正式 PG Temporal 通过。

证据 **AZ-M04**：扩展 P3 回归一次运行 **101 通过、1 失败，126.63 秒**；失败项最初缺测试依赖 `fakeredis`，补齐 `fakeredis[lua]` 的 Lua 依赖 `lupa` 后，该项独立补跑 **1 通过，5.09 秒**，附加诊断复跑亦通过。因此 102 个所选用例均有通过证据，**不是一次 102/102 全量通过运行**。

证据 **AZ-M05**：五个本轮 Python 文件 Ruff 检查/格式通过，三个源文件目标严格 Mypy 通过；`git diff --check` 通过；VM Compose 配置校验通过；VM/AKS Temporal 命令、tmpfs 和 upgrade Job 检查通过。测试覆盖真实热缓存及关键恢复路径，尚不等于所有异步模块的性能/负载验收。
