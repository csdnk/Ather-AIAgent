# 租户功能实现核查

日期：2026-09-19。范围：当前 AgentJYS-main 工作副本的 P3 新运行链、相关已有测试和本次补充探查。结论用于区分 PRD V1.3、ADR 目标与实际实现；本次未修改生产代码，也未连接 Azure 或真实 P2。

**结论：已实现租户范围、主体凭证、资源与操作授权、显式共享及部分撤权恢复机制。尚未实现 Entra 接入和独立业务租户生命周期；共享记忆的自动 Recall 还有实际缺口。**

## 本次运行结果

证据编号 TEN-CODE-20260919：重跑现有 foundation 和 flows 中与 identity、grant、tenant、isolation、read_only 相关的测试，**10 项通过，45 项未选入本次专题检查**。覆盖跨用户/租户查询拒绝、身份伪造与本地撤权、显式 Grant 撤销、租户任务压力隔离、三流程范围隔离和只读调用者。

首次运行因独立临时目录的父目录尚未建立而在测试准备阶段报错；目录就绪后重跑通过，未改业务代码。该首次记录与重跑记录分别保留，不计为产品功能失败，也没有删除原始证据。

证据编号 TEN-SHARE-20260919：另用真实本地 ThreeFlows、lexical 测试适配和临时库验证共享行为：

1. Alice 保存并完成长期投影；向同租户 Bob 授予该记忆的 READ Grant。
2. Bob 按 memory_id 读取成功。
3. Bob 使用默认长期 Recall 返回 **empty，0 个结果组**。
4. 撤销 Grant 后，Bob 按编号读取被拒绝。

这说明“有共享授权模型”不等于“共享记忆已能被完整检索”。当前测试的共享通过项主要验证授权机制，不能代替产品级共享 Recall 验收。

## 对应实现计划

1. 引入最小 Tenant 配置及稳定外部身份映射；接入 Entra 认证适配器，统一生成可信上下文。
2. 在请求、后台执行、最终提交和结果再取检查当前租户/主体/许可版本；设计停用、重启和旧配置恢复的行为。
3. 为 Recall 构造服务端允许访问的候选集合：本人范围加同租户有效共享资源；保持请求只能缩小范围，不能靠改写 home_scope 实现共享。
4. 对向量投影、正文和必要来源依赖分别检查授权，防止仅共享一条记忆就连带暴露整个来源；明确共享版本及撤销规则。
5. 在真实身份及 P2 环境执行 TC-TEN-01～08，尤其验证外部撤权传播和多路径隔离。
