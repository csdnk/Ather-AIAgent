# 主要接口清单

这是一份按模块查阅的清单；调用顺序仍看[公共底座流程](01_公共运行底座_对象与接口.md)和[业务流程](02_三个业务流程_对象与接口.md)。对象含义可查[主要业务对象设计](04_主要业务对象设计.md)。输入基线：`2ee5b0e`；接口名称以当前本地职责调整版本为准。

表中省略反复出现的可信上下文、事务等参数，只展示理解交接所需的业务输入输出；不是完整调用签名。**已有**指本地实现，**基础**指基础能力可运行，**待接**指契约已有但业务接入未完成。同一行合并用途接近的方法，不按行数统计接口数量。

## 1. RF：公共运行接口

| 接口及状态 | 谁调用 → 谁提供 | 交什么 → 得到什么 | 用在什么时候 |
|---|---|---|---|
| `IdentityPort.authenticate` · 已有 | 请求入口 → RF | 凭据 → Principal | 请求进入时确认身份 |
| `IdentityPort.authorize / revalidate` · 已有 | B/A/C → RF | 上下文、目标和权限，或上下文复核 → 允许继续，否则拒绝 | 读取、执行及提交前 |
| `UnitOfWork.transaction`、`Transaction.get / put_if_revision` · 已有 | B/A/C → RF | 记录引用、数据、预期修订 → 读取结果或新修订 | 关联数据一起提交；版本不符拒绝覆盖 |
| `TaskPort.enqueue` · 已有 | B/C及维护逻辑 → RF | TaskSpec → TaskRecord | 登记后台工作 |
| `TaskPort.claim / renew` · 已有 | Worker → RF | 执行者/类别，或任务与当前租约 → 任务及有效租约；无可领任务时返回空 | 领取及续租 |
| `TaskHandler.run / recover` · 基础 | RF → B/C或维护处理器 | TaskRecord → RunResult / RecoveryDecision | 实际做业务，或判断恢复方式 |
| `TaskPort.complete` · 已有 | 业务处理器 → RF | 当前任务、结果引用 → 完成状态随业务事务提交 | 业务结果已准备好时 |
| `EventPort.append / consume` · 已有 | 生产者/投递逻辑 → RF | EventEnvelope → 登记事件 / 去重并执行消费回调 | 把事实可靠交给另一模块 |
| `MonitoringPort.health / emit` · 已有 | 运行入口/节点 → RF | 上下文 → RuntimeHealthSnapshot；NodeLogRecord → 写日志 | 检查健康、记录节点行为 |
| `DiagnosticsPort.task / operation / related` · 已有 | 查询入口 → RF | 任务编号、操作编号或目标引用 → 状态/关联证据 | 查进度、排查异常 |
| `TaskPort.request_recovery` · 已有 | 授权恢复入口 → RF | RecoveryRequest → OperationRecord | 请求受控恢复，保留原操作关联 |

以下也是主要调用入口，属于当前运行服务，不在旧的 Protocol 方法统计内：

| 运行服务及状态 | 输入与结果 | 作用 |
|---|---|---|
| `tasks.progress.checkpoint / wait / read` · 已有 | 阶段/等待记录及当前任务 → 持久附件；按 task_id 读取附件 | 保存已提交阶段，安排下次检查 |
| `dispositions.observe / cycle / reconcile` · 已有 | 样本或当前运行上下文 → 异常登记、采样/对账、复验推进 | 规则触发维护；业务复验后才关闭异常 |
| `lifecycle.activate / backup / restore` · 已有 | 配置快照及预期版本，或备份/恢复编号 → 激活配置或 BackupManifest | 登记部署配置，备份及隔离恢复 |

处置运行前须注册采样器、维护处理器和独立复验回调。健康检查本身不执行维护。

## 2. B：保存、管理记忆，向 A/C 提供权威事实

投影写入、核验、删除与索引发布由 B 负责。当前写入接口已迁至 B 的 ProjectionPort / GenerationProjectionPort，搜索接口为 A 的 VectorSearchPort / GenerationSearchPort。旧组合接口只保留兼容，新服务注入已分开。

| 接口及状态 | 谁调用 → 谁提供 | 交什么 → 得到什么 | 作用 |
|---|---|---|---|
| `RememberPort.save / get` · 已有 | 用户入口 → B | RememberRequest → RememberReceipt；记忆编号 → MemorySnapshot | 保存和读取基础记忆 |
| `RememberPort.correct / lifecycle` · 已有 | 业务入口 → B | 记忆编号 + 更正/生命周期请求 → 回执或更新后快照 | 更正、归档、重新激活 |
| `RememberPort.delete / delete_source` · 已有 | 业务入口 → B | 记忆/来源编号 + DeleteRequest → DeleteReceipt | 先阻断使用，再跟踪清理 |
| `ExtractionPort.extract` · 基础 | B 加工器 → 提取适配器 | ExtractionRequest → ExtractionResult | 从原文形成候选事实；完整模型及决策仍有待办 |
| `ProjectionPort.project / inspect / delete` · 基础，职责已迁移 | B → 向量存储适配器 | 写入请求或原投影目标及操作编号 → ProjectionResult | B 组织写入、核验原操作或清除指定投影 |
| `GenerationProjectionPort.project / inspect` · 多块业务待接，职责已迁移 | B → 向量存储适配器 | ChunkProjectionRequest → ChunkProjectionResult | B 按精确索引批次写入和核验各块 |
| `MemoryReadPort.working / load` · 已有 | A → B | 范围与分页 / 精确 MemoryRef 列表 → MemoryReadBatch | 取当前内容或指定版本正文 |
| `MemoryReadPort.final_guard` · 已有 | A/C等 → B | 精确引用及用途 → EligibilityBatch | 最终确认是否仍有资格使用 |
| `MemoryFoundationPort.load_bodies` · 待接 | A → B | MemoryRef 列表 → FullBodyReadResult 列表 | 读取完整正文，并给出核验版本戳 |
| `MemoryFoundationPort.publish_projection` · 待接 | B 加工器 → B 发布逻辑 | ProjectionManifest + 预期修订 → MemoryRecord | 全部预期块核验后发布索引 |
| `MemoryFoundationPort.accept_handoff` · 待接 | C → B | ReferenceHandoff → ReferenceHandoffReceipt | 确认新正文地址及权威记录修订 |

文档获取/解析还有 `DocumentReaderPort.acquire / parse`，当前 basic 保存入口未接入；本清单不把它算成现成的文档导入能力。

## 3. A：检索、编码、组装上下文

| 接口及状态 | 谁调用 → 谁提供 | 交什么 → 得到什么 | 作用 |
|---|---|---|---|
| `RecallPort.recall` · 基础 | 用户入口 → A | RecallRequest → ContextPack | 完成当前基础召回流程 |
| `RecallPort.status / result` · 已有 | 查询入口 → A | recall_id → RecallRecord / ContextPack | 查进度或重新获取经核验的结果 |
| `EmbeddingPort.embed` · 已有 | B 或 A → A 侧共享编码能力 | EmbeddingRequest → EmbeddingResult | Passage 建库编码 / Query 查询编码 |
| `VectorSearchPort.search` · 基础 | A 的 Recall → 向量搜索适配器 | VectorSearchRequest → VectorSearchResult | 查询当前索引；写入及核验职责见 B 部分 |
| `GenerationSearchPort.search` · 待接 | A 的 Recall → 向量搜索适配器 | ChunkSearchRequest → ChunkSearchResult | 搜索带精确记忆版本、索引批次和指纹的块 |
| `MemoryCandidatePort.search` · 待接 | A 编排 → 候选服务 | MemorySearchRequest → MemorySearchResult | 块命中聚合为记忆候选，按记忆占 Top K |
| `ContextAssemblyPort.plan` · 待接 | A 编排 → 组包服务 | RecallPlanRequest → ContextAssemblyPlan | 读取正文、补关系、整组排序及预算选择 |
| `ContextAssemblyPort.commit` · 待接 | A 编排 → 组包服务 | ContextCommitRequest → 已提交结果的 RecordRef | 最终条件核验与事务提交 |

B 建库时调用 A 的 Embedding，不需要调用 RecallPort.recall；后续投影由 B 组织。A 为自己的 Recall 使用搜索接口。当前基础 Recall 已可用，不表示新增候选及组包接口已接通。

## 4. C：消费事实、决策、执行与清理

| 接口及状态 | 谁调用 → 谁提供 | 交什么 → 得到什么 | 作用 |
|---|---|---|---|
| `SchedulingPort.consume / decide` · 基础 | RF 投递/C 内部 → C | EventEnvelope → 更新视图；SchedulingInput → PlacementDecision | 用事实更新视图并做放置决策 |
| `SchedulingPort.execute / reconcile` · 基础 | C 编排 → C 动作服务 | ActionIntent / 原 action_id → ActionRecord | 执行动作及查原操作结果 |
| `ExecutorPort.submit / query` · 已有本地 | C → 执行器 | ActionIntent / action_id → ExecutionFeedback | 对存储执行实际动作及查询 |
| `ExecutorPort.verify_read` · 已有本地 | C → 执行器 | ActionIntent → ReadProof | 证明目标真的能读到正确内容 |
| `ExecutorPort.resources / observe` · 已有本地 | C → 执行器 | 当前上下文 / 记忆及表示编号 → ResourceSnapshot / PlacementObservation | 获取容量、实例及驻留事实 |
| `LifecycleCleanupPort.release_protection / cleanup` · 待接 | 生命周期协调逻辑 → C | 保护编号及修订 / CleanupRequest → ProtectionReference / CleanupReceipt | 受控释放保护，逐项清理并回执 |

## 5. 外部测试从哪里开始

`POST /p3/remember`、`POST /p3/recall` 是两条主要业务 HTTP 入口；`GET /p3/health`、`GET /p3/ready`、任务与日志查询用于观察结果。完整运行路由看[HTTP 接入说明](../04_实现状态与运行/08_RF运行服务与HTTP接入.md)。上面的内部方法不是每个都有独立 HTTP 地址，C 的调度也不是用户直接发起的一组公开调度 API。
