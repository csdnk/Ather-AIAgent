## 已实现模块与边界

代码统一位于 `src/aether_agent_memory/runtime/foundation/`。

| 文件 | 实现职责 | 接口归属 |
|---|---|---|
| storage.py | 复用SQLiteCapabilityStore的WAL/FULL及BEGIN IMMEDIATE事务；作用域/版本定位、CAS、删除修订墓碑、分页、提交前校验 | RF UnitOfWork / Transaction |
| identity.py | 凭证摘要映射、服务端Context、当前身份及epoch复核、显式同租户对象Grant、配置变更记录 | RF IdentityPort |
| tasks.py | 注册、幂等提交、领取、续租、截止、类别/范围/租户限额、Attempt、结果提交、启动/周期过期扫描、恢复和维护记录 | RF TaskPort；调用领域TaskHandler |
| events.py | 原子Outbox、每消费者Delivery、事务Inbox、有限投递、丢确认后的确认补齐 | RF EventPort |
| diagnostics.py | 授权任务/操作查询、关联追溯、尝试及恢复证据；基础health为占位，实际探针由flows.Health提供 | RF DiagnosticsPort |
| host.py / __main__.py | 装配、Worker循环、停止新领取、维护命令 | RF Host；当前无新HTTP服务 |
| sample.py | 工程输入、任务处理和事件消费者；验证机制如何接入 | 工程样例，不能作为B/A/C产品能力 |

实现复用现有 `runtime/capability_store.py`，没有修改其表或连接实现。新数据使用 `p3_rf_` 命名空间；示例默认使用单独数据库，旧业务不自动迁移。所有事务都由同一UnitOfWork传入，禁止嵌套事务；禁止持有事务进行网络调用或跨`await`等待。数据库及进程依赖单机本地持久磁盘，不能将共享卷SQLite当成多主机方案。

## 快速运行

要求Python 3.13，在仓库根目录执行。只需隔离依赖，不需启动旧应用或模型。

```text
python -m pip install -r scripts/p3/requirements.txt
python scripts/p3/demo_foundation.py --directory <新的运行目录>
```

脚本生成两租户各两用户的随机工程凭证，仅将摘要保存到数据库，明文保存在指定目录的`demo-credentials.json`供本地演示使用。输出包含task_id及证据路径，不打印凭证。该目录不可与已有演示复用，以免覆盖数据。应放在代码仓库外并限制文件访问。

正常输出为`mode=engineering_only`、`passed=true`，`evidence.json`中的task为`succeeded`、delivery为`acknowledged`。这仅证明工程输入、任务结果与事件收据；不证明真实记忆或向量已形成。

## 分进程运行及查询

本地开发先将仓库的`src`目录加入`PYTHONPATH`。PowerShell示例（在仓库根目录执行）：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$runDir = 'E:/p3-local-demo'
$demoKeys = Get-Content (Join-Path $runDir 'demo-credentials.json') -Raw | ConvertFrom-Json
$env:P3_API_KEY = $demoKeys.alice
python -m aether_agent_memory.runtime.foundation --db "$runDir/foundation.db" health
python -m aether_agent_memory.runtime.foundation --db "$runDir/foundation.db" worker
```

另一个终端配置相同的`PYTHONPATH`和`P3_API_KEY`后使用：

```text
python -m aether_agent_memory.runtime.foundation --db <数据库> submit --key <稳定请求键> --text-file <UTF-8文本文件>
python -m aether_agent_memory.runtime.foundation --db <数据库> status --task-id <返回的task_id>
python -m aether_agent_memory.runtime.foundation --db <数据库> trace --task-id <task_id>
python -m aether_agent_memory.runtime.foundation --db <数据库> worker --once
python -m aether_agent_memory.runtime.foundation --db <数据库> recover --task-id <task_id> --revision <当前revision> --operation-id <固定操作ID> --reason <原因>
```

Worker无需产品用户凭证：它是有数据库文件权限的可信部署进程，执行前仍复核任务原主体的身份和对象权限。`configure`同样属于可信部署操作，不是对外管理端点；操作系统文件权限是其控制边界。任务查询、追溯及人工恢复必须经过凭证认证。诊断权限并不自动赋予跨用户或跨租户访问。

部署方可使用`configure --identities <JSON文件>`配置自己的身份。JSON包含`identities`数组，每项为`credential_sha256`及契约`Principal`；可另提供`grants`数组。配置为完整替换，省略主体即撤销；身份、权限或凭证变化必须递增`auth_epoch`，旧配置不能恢复旧epoch。Grant变更立即按当前配置生效。没有角色系统或账户后台。

## 三流程如何接入

1. Host创建共享UnitOfWork、Identity、Tasks、Events、Diagnostics，并在启动时注册固定Handler和事件类型；业务代码不创建第二套队列。
2. 流程自己的Repository使用传入Transaction的`get/put_if_revision/remove_if_revision`。`put_if_revision(..., None)`仅首次创建；删除留下修订号防止旧写覆盖。Repository不得绕过授权或更新其他流程数据。
3. 输入记录先持久化；同事务调用`tasks.enqueue`和`events.append`。TaskSpec的输入指纹绑定实际已保存输入；生产方身份、任务Owner、scope和截止须匹配。
4. Handler在事务外计算/调用外部依赖；提交时先调用`tasks.guard`，读取当前领域版本、删除及授权，再写结果/事件并调用`tasks.complete`，一并提交。Handler返回`committed`不触发公共层自动写成功。
5. 事件消费者在传入事务内保存消费效果或后续Task；不得直接调用外部执行端。Inbox与效果原子提交，Delivery确认独立保存。注册消费者固定在Host配置中；新增订阅只影响新事件，历史回放必须另设计并授权。
6. recover重新读取事实，给出有限重做、查询原操作、终止或人工处理。外部动作意图与原action_id必须由业务在发送前持久化；不能等响应丢失后再生成。公共层保存返回的operation_id并拒绝恢复时更换它，但不替代领域动作日志。

完整可运行接入示例是`sample.py`。B/A/C各自实现领域资格，公共层不判断记忆内容、上下文选择或迁移是否正确。

## 恢复、续租与事件语义

- Worker领取和恢复领取都持久保存租约。启动与每次领取扫描过期工作，进程退出后无需内存检查点继续发现任务。
- 协作式异步Handler运行时自动续租；不得阻塞事件循环。调用方统一截止不会被续租延长。取消只停止本地等待，不能证明外部效果撤销。
- 领取后未知异常保守进入`recovery_wait/unknown`。recover证明无效果才能进入`retry_wait`；查询预算耗尽转`attention_required`，不伪装失败或成功。
- 原主体撤权后停止自动处理并保留未决；未来若需要专用只读对账身份，须单独定义授权，不自动借用维护权限。
- 完成依据当前租约token和当前有效期。续租增加revision但不替换token；原Handler仍可完成。手动恢复使用expected_revision，不能夺取有效租约或重置终态。提交前再检查租约时间，防止长事务过期提交。
- 同一事件ID绑定整个规范封套，Inbox按consumer_id+event_id去重。消费提交后丢ACK，重启会依据已提交Inbox补齐确认。投递尝试及恢复查询均有限次。
- required_outputs只校验输出存在，领域仍需核验内容和版本。原输入、身份、lease、事实版本等校验不是跨外部系统的原子事务。

配置读取[foundation profile](https://github.com/csdnk/Ather-AIAgent/blob/2ee5b0e6c20246af63821ae19daaf44314aa3686/AgentJYS-main/contracts/p3/profiles/foundation.yaml)；工程类别与三流程类别分别限流，运行中的scope及tenant限额也按类别计算，后台任务不占用在线类别名额。不建立性能指标门禁。当前表扫描适合单机基座验证，尚未承诺大规模调度效率、公平性或生产容量。

## 追溯与状态

Task、Attempt、Recovery、Outbox、Delivery、Inbox、Diagnostic、Maintenance及配置历史独立保存，通过ID关联。trace查询不返回输入或结果正文。Trace ID按W3C格式生成并持久传播，当前尚未连接OTel导出器或Application Insights。

foundation 的 health 仅是基础诊断占位，不执行实际数据库健康探针，业务能力显示 `unknown`。当前实际检测使用 `runtime.flows ... health`：已接数据库、日志、Embedding、向量、执行端、tokenizer、reranker等探针，并检查Worker心跳和未决工作，见[日志与健康检测](https://github.com/csdnk/Ather-AIAgent/blob/2ee5b0e6c20246af63821ae19daaf44314aa3686/AgentJYS-main/docs/p3/development/06_%E6%97%A5%E5%BF%97%E8%BF%BD%E8%B8%AA%E4%B8%8E%E5%81%A5%E5%BA%B7%E6%A3%80%E6%B5%8B.md)。集中告警、外部持续检测和指标平台尚未接通。
