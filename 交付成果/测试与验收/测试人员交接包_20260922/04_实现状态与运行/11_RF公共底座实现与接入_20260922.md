# RF公共底座实现与接入

日期：2026-09-22。本轮把公共对象接入了现有RF运行机制，业务代码位于AgentJYS-main。三流程的新业务接口与生产部署仍有各自待办。

## 现在可以运行什么

| 能力 | 本轮实现 |
|---|---|
| 统一日志 | 现有节点自动生成NodeLogRecord，保留旧格式兼容；新查询按主体和作用域返回p3/log/2 |
| 统一健康 | 真实探针形成RuntimeHealthSnapshot；检查证据有效期、授权代次和配置版本。旧健康接口读取同一份结果 |
| 任务附件 | 等待记录绑定当前租约并影响下一次调度；断点和阶段输出同事务保存；任务完成自动保存completed断点；Worker生成统一心跳 |
| 监测处置 | 注册信号、操作和规则，执行有界采样、连续次数判定、标签限制和冷却；通过原Tasks安排维护，独立业务复验后才关闭异常 |
| 配置与备份 | 条件激活部署配置快照并保留历史；SQLite在线备份；恢复到新数据库并核验完整性、记录指纹及一致性水位 |
| HTTP运行 | 鉴权后的健康、日志、任务、恢复、异常、配置、备份，以及现有Remember/Recall入口；后台执行同一个任务循环 |

代码与运行步骤见[仓库接入说明](<08_RF运行服务与HTTP接入.md>)。完整对象阅读入口仍是[框架讲解](<../02_流程与规则/09_P3完整框架对象与接口流程讲解_20260922.md>)和[完整字段与接口索引（按需查仓库）](https://github.com/csdnk/Ather-AIAgent/blob/2ee5b0e6c20246af63821ae19daaf44314aa3686/%E4%BA%A4%E4%BB%98%E6%88%90%E6%9E%9C/%E5%BC%80%E5%8F%91%E5%8D%8F%E4%BD%9C/10_P3%E5%85%A8%E9%87%8F%E5%AF%B9%E8%B1%A1%E4%B8%8E%E6%8E%A5%E5%8F%A3%E7%B4%A2%E5%BC%95_20260922.md)。

## 使用边界

- 监测引擎已经实现。部署装配时仍须注册实际采样器、维护TaskHandler和独立业务验证回调；不会默认重启所有依赖。未知结果保持原操作关联，不自动另建动作。
- 等待与中间阶段断点接口由B/C处理器按业务需要调用；completed断点和心跳已自动接入任务执行。底座不会代替B/C判断具体业务如何恢复。
- 配置快照记录已部署的提供方与策略；不等于自动热加载模型、切换数据库或注入密钥。
- 备份范围是RF SQLite数据库，包含其中的内联记忆、任务等记录；外部向量库、原件提供方、模型文件和独立日志库不在本次备份中。恢复只写新目录，不覆盖在线库。
- 全库备份及配置要求启动时显式授权的部署运维主体，普通租户的维护权限不自动获得全库访问权。
- HTTP已可本地运行；OTLP/云端采集、外部身份、生产数据库、多副本及Azure/AKS实际部署验收尚未完成。B/A/C的多块发布、完整正文组包、地址交接等新增业务接口仍待实现。
