### 真实模型证据

- Embedding：`BAAI/bge-small-zh-v1.5`，512 维；沿用已有模型文件与预处理绑定。
- 重排序：`BAAI/bge-reranker-base`，固定版本 `2cfc18c9415c912f9d8155881c133215df768a70`。实际验证使用该版本的本地下载目录，权重已按官方元数据核验 SHA-256。
- Tokenizer：`tiktoken_o200k_base`。样本上下文 `[1] 我喜欢无糖咖啡。`（含末尾换行）计数为 11 token，预算为 1024。
- 纠错后采用版本 2；获取原 ContextPack 返回失效；删除后的新查询为空。同租户另一用户未读到原用户记忆。
- 通过 `trace_id` 查询到持久 Recall 阶段，重排序状态为 `succeeded`；自动缓存执行为真实本地目录操作。

此样本验证链路能运行及结果约束，没有进行检索质量 benchmark，也没有据此推导性能或生产 SLA。

## 未通过真实运行验收的范围

1. **真实 Milvus**：适配器和故障测试已交付；真实集合创建、索引、服务中断、恢复与查询一致性尚未实测。拿到服务后使用 Milvus 配置运行专用验证入口。
2. **默认配置与启用方式**：默认本地入口保持重排序 disabled；完整模型链必须显式选 `configs/recall.rerank.local.json`。首次运行需要下载和预热模型。
3. **现有数据迁移**：不能把已有 SQLite 投影库直接指向空 Milvus。当前有绑定检查，但没有一键迁移工具。
4. **外部迟到写入**：版本与逻辑删除检查阻断旧记忆召回；跨库没有原子事务，永久物理清理仍需持续对账验证。
5. **产品其余能力**：Remember 仍为 LiteralExtraction 基线；本轮未完成真实 LangMem、生产存储分层、HTTP Host、Azure/AKS 或 72 小时稳定运行验收。
6. **下游模型预算**：当前实际按 o200k_base 计数；尚未指定下游大模型。更换模型须校准 tokenizer，并另留消息模板和回答预算。

## 复现入口

在仓库根目录、已安装 `scripts/p3/requirements-recall.txt` 的 Python 环境中执行：

```text
python scripts/p3/validate_flows.py
python scripts/p3/validate_recall.py --recall-config configs/recall.rerank.local.json
```

第一个命令覆盖流程、基础及契约验证；第二个验证真实本地模型链。原 Recall 回归及原生适配器分别由 `tests/unit/recall` 和 `scripts/p3/validate_native_flows.py` 验证。服务具备后，将第二个命令配置换为 `configs/recall.milvus.json` 并填写真实地址。

以上验证均使用隔离的测试业务库，不覆盖已有业务数据。模型缓存和原始报告按团队环境配置到独立工作区。
