# 单条测试用例模板

复制本文件，每条用例独立填写。用例设计状态和执行结果分开；必填项未确认时填写“待确认 + 问题编号”，不能留一个含糊的“正常”。

| 字段 | 填写内容 |
|---|---|
| 用例编号 / 标题 | TC-模块-序号 / 一个明确的行为 |
| 关联需求及版本 | PRD 版本、章节或 FR 编号；设计补充的文件与章节 |
| 模块 / 流程节点 | RF/B/A/C；对应图节点或文字步骤 |
| 测试层级 / 类型 | 契约/服务/HTTP/联调/端到端；正常/异常/边界/安全 |
| 优先级 | P0 核心数据与安全、P1 核心流程、P2 一般分支（建议分级，团队确认） |
| 适用代码 / 环境配置 | 提交 SHA、平台、数据库、模型/提供方、关键参数 |
| 实现状态 | 已实现 / 部分实现 / 待实现 |
| 用例设计状态 | 草稿 / 待确认 / 已评审 |
| 前置条件 | 账号与权限、已有数据、任务状态、依赖是否可用 |
| 输入数据 | 完整字段、具体取值、来源、测试数据编号；凭据用引用 |
| 调用入口 | HTTP 方法与路径，或准确服务方法；二者不要混写 |
| 观察入口 | 响应字段、任务/操作/异常记录、日志或只读数据库检查 |
| 故障注入 | 注入位置、操作方式、次数/时序；无则填无 |
| 等待与超时 | 轮询条件、最长等待、超时后记录什么；引用环境配置 |
| 清理与复位 | 本用例创建的测试数据、回调/规则、故障和配置的恢复方式 |
| 依赖 / 待确认项 | 问题编号及负责人；不受阻则填无 |
| 编写 / 评审人 | 姓名与日期 |

## 步骤与逐步预期

| 序号 | 操作及精确输入 | 预期响应/字段 | 预期持久状态与副作用 | 证据获取位置 |
|---|---|---|---|---|
| 1 | 待填写 | 待填写 | 待填写 | 待填写 |
| 2 | 待填写 | 待填写 | 待填写 | 待填写 |
| 3 | 待填写 | 待填写 | 待填写 | 待填写 |

不要只检查 HTTP 200；根据场景检查是否产生重复记录、越权泄露、错误状态或不应发生的外部动作。日志不能替代持久业务结果。

执行结果在《执行记录与缺陷模板》中记录。同一用例多次执行保留独立记录，不覆盖失败证据。
