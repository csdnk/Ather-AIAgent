# 执行记录与缺陷模板

## 用例执行台账

每次执行新增一行。结果使用“未执行 / 通过 / 失败 / 阻塞 / 不适用”；阻塞填写原因，不当作通过；不适用填写范围依据。

| 执行编号 | 用例编号 | 日期/执行人 | 代码 SHA / 环境编号 | 数据与配置版本 | 实际结果 | 判定 | 证据编号 | 缺陷/阻塞编号 |
|---|---|---|---|---|---|---|---|---|
| RUN-日期-001 | TC-模块-001 | 待填写 | 待填写 | 待填写 | 尚未执行 | 未执行 | — | — |

## 缺陷记录

| 字段 | 内容 |
|---|---|
| 缺陷编号与标题 | BUG-日期-序号；明确触发条件和错误行为 |
| 关联用例/需求 | 用例编号及 PRD/设计条款 |
| 严重程度/优先级 | 团队分级；分别描述影响和修复顺序 |
| 版本/环境/配置 | 代码 SHA、环境编号、提供方及模型配置 |
| 最小复现步骤 | 前置数据、调用、关键时序；不要写“偶尔异常” |
| 预期结果 | 引用确定的规则；若规则本身冲突，先登记需求问题 |
| 实际结果 | 状态码/状态字段、持久副作用、是否重复或越权 |
| 发生频率与影响范围 | 次数/总次数；单租户/多租户、数据/可用性影响 |
| 证据 | trace_id、operation_id、task_id、incident_id、脱敏日志编号；按场景选填 |
| 负责人/状态 | 待分配 / 修复中 / 待复测 / 已关闭 |
| 修复提交/复测 | 提交 SHA、回归范围、独立复测执行编号 |

原始日志、数据库和截图存隔离工作区；报告使用可追溯证据编号。不要把凭据、完整业务隐私或测试机器绝对敏感目录直接放进共享缺陷描述。
