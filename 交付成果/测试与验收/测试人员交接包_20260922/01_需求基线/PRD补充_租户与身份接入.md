# PRD 补充 租户与身份接入

编号：PRD-ADD-07。日期：2026-09-19。状态：已合入 [PRD V1.3](<AetherBrain_P3_PRD_租户补全版_V1.3.docx>)正文，仍待联合评审；本文件保留作条款追溯。对应原文第 3～5 章、FR15、第 8～9 章、第 11 章及第 14.2 节；关联 FR01、FR08、FR11、FR12、FR17、FR18。

本补充明确已有多租户和授权要求的产品含义。身份接入建议使用 Microsoft Entra ID，具体技术取舍见[主 ADR D07](<../02_流程与规则/ADR-P2P3-001_总体架构决策.md#d07>)。Azure 接入尚未实现或批准；正文合版已完成，原 V1.2 保留作历史对照。

## 1 租户是什么

租户是使用 P3 的一个组织或客户的数据与资源归属边界。一个租户内可以有多个应用、用户、Agent 和任务。记忆归属租户，并根据资源及操作授权限制使用。

Azure 身份目录与 P3 业务租户分别管理，由受控配置明确对应关系，不能仅凭外部目录名称或请求中的租户编号授予访问权。初期即使只接入一个业务租户，也应保留租户归属及校验，便于后续扩展。

## 2 用户和调用方应得到什么行为

| 条款 | 产品要求 | 可观察的结果 |
|---|---|---|
| TEN-01 可信接入 | 用户或应用通过有效身份接入，并属于已经开通的 P3 业务租户 | 有效且获授权的请求可以继续；身份无效或未绑定业务租户时拒绝 |
| TEN-02 归属确定 | 每次操作的租户由可信身份和已批准映射确定；调用方只能选择其已获授权的范围 | 修改请求租户编号不能读取或修改其他租户数据 |
| TEN-03 数据隔离 | 记忆、来源、派生内容、结果、任务和运行记录遵守同一边界 | 知道其他租户对象编号也不能读取其正文、任务或敏感元信息 |
| TEN-04 租户内授权 | 同租户的不同应用、用户和 Agent 不默认互通；共享需要明确资源和操作许可 | 私有内容不可越权获取；被授权共享的资源可按许可使用 |
| TEN-05 操作区分 | 读取、写入、更正、删除、结果查询分别授权 | 有读取权限不自动有更正或删除权限 |
| TEN-06 状态变化 | 业务租户停用、主体停用或本地授权撤销后，后续受影响操作按最新状态判定 | 新请求、旧结果再次获取及后台提交不会沿用已失效业务许可 |
| TEN-07 后台一致 | 加工、事件、调度继承原业务归属，并在实际读写或提交时复核 | 后台服务的高权限不扩大原请求的业务授权 |
| TEN-08 异常可解释 | 无法验证身份或确认权限时拒绝受影响操作，给出适合调用方处理的原因 | 不因身份服务异常而扩大权限；结果不泄露其他租户敏感信息 |

本地业务许可撤销与外部身份平台中的账户撤销是两个事件。外部变更的获知方式及最大生效时间需要在接入评审中确认，不能承诺所有已签发令牌立即失效。

## 3 接入与最小管理范围

业务使用者沿用公司认可的身份接入方式。P3 本期不新增登录页面、成员邀请、角色配置、计费或租户管理后台。

部署或接入人员通过受控配置维护最小信息：稳定业务租户编号、启用状态、获准身份来源及主体映射、资源和操作授权、配置版本。开通或停用属于受控配置操作，保留变更记录。配置恢复不得重新启用已失效授权。

展示名称变化不改变数据归属；停用先阻止受影响使用，不自动等于删除全部数据。租户注销后的保留、导出、删除及恢复规则需另行确认，不能由停用按钮或账户删除隐含触发。

## 4 Azure 与 P3 的产品责任

Azure 身份设施可以提供可信用户或应用身份，云资源身份和访问控制可以保护运行环境。P3 负责将身份映射到业务租户，并判断具体记忆及操作是否获准。P2 按联合契约执行租户范围约束，P3 对最终交付继续复核。

成功登录、持有有效令牌、可以访问某个云存储资源，均不足以单独证明有权读取某条 P3 记忆。正式接入说明应明确调用方如何取得有效凭证、如何选择允许范围，以及身份过期或业务权限不足时怎样处理。

## 5 场景与验收

以租户 A、租户 B 和租户 A 内两个 Agent 为固定场景：A1 保存私有预算；B1 不能读取；A2 未共享时不能读取，获明确读取授权后可以读取，但不能删除；授权撤销后 A2 不能再次获取旧结果，关联后台操作按当前许可处理。

现有 [S09](https://github.com/csdnk/Ather-AIAgent/blob/2ee5b0e6c20246af63821ae19daaf44314aa3686/%E4%BA%A4%E4%BB%98%E6%88%90%E6%9E%9C/%E5%8E%9F%E5%9E%8BMock/index.html#scenario=S09)可用于部分隔离规则评审。新增[租户专题 Mock](https://github.com/csdnk/Ather-AIAgent/blob/2ee5b0e6c20246af63821ae19daaf44314aa3686/%E4%BA%A4%E4%BB%98%E6%88%90%E6%9E%9C/%E5%8E%9F%E5%9E%8BMock/tenant.html)已模拟身份映射、未绑定身份、共享、停用和撤权；不能把模拟身份当作 Entra 验证。

测试及回归见[租户与身份接入测试方案](<../05_已有用例与验证/租户与身份接入测试及回归方案.md>)。验收同时需要真实身份接入证据、P3 业务授权结果、真实 P2 隔离验证，以及后台和历史结果的复核；当前本地隔离测试不能替代全部验收。

## 6 合版前需确认的事项

项目与接入方确认业务租户划分及首批范围；身份接入方确认身份来源和接入方式；P3 负责映射、共享、停用及业务授权；P2 确认服务端过滤和对象边界。共同确定外部撤权传播、配置变更生效、数据保留及恢复要求。
