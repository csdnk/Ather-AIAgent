# P3 Ceph 可用接口与 HTTP 联调核查

日期：2026-10-03。结论：现有 Ceph RGW 的 HTTP S3 接口可以用于功能联调，本次实测认证、文件列表、对象信息、完整读取、真实分段读取及条件读取均可用。当前账号是三个既有 bucket 的所有者，ACL 给该账号 FULL_CONTROL。基础对象写入、删除与条件写能力有指南所列 Ceph 20.2.4 的官方文档/源码依据，但本轮未执行写操作，不能标为真实写入验收通过。

本轮是用户要求“先看一下 Ceph 有哪些接口”的只读核查。没有执行指南里的部署、SSH、清盘或管理步骤，没有修改业务代码、云配置、bucket 策略或存储数据，也没有向新实施会话发送任务。

## HTTP 与项目配置

HTTP 和 HTTPS 都可以承载同一套 S3 操作；HTTPS 增加传输加密和服务身份校验，不会增加基础对象存储功能。实际可访问的入口为 `http://20.191.146.177:8080`，本轮请求使用 SigV4 认证。HTTP 不加密对象正文，签名认证不能替代加密。

当前代码中的 `remember/basic/ceph_p2.py::CephP2Config` 已允许 HTTP 和 HTTPS。P3 Azure 的 `runtime/storage/configuration.py::CephStorageConfiguration` 及 `runtime/storage/objects.py::CephObjects` 明确要求 HTTPS。因此，直接在现有 P3 Azure 配置里把 endpoint 改为这个 HTTP 地址会被拒绝。

若测试阶段选择直接使用 HTTP，需由继续实施会话增加显式的开发/测试环境配置，保留生产环境 HTTPS 检查。此处仅给出适配结论，本轮未放宽验证或修改配置。配置切换还要考虑 endpoint/bucket/namespace 的对象资源绑定；HTTP 测试空间与未来正式空间应清楚分离，不能随意重定向已开始的任务。

## P3 所需接口与实测范围

下列路径采用当前 SDK 使用的 path-style 寻址。每个请求须按 S3 协议签名，不能仅靠知道 URL 获得授权。

| 能力 | S3 操作与请求 | 对 P3 的用途 | 当前证据 |
|---|---|---|---|
| 列出 bucket | ListBuckets：`GET /` | 核对账号可见存储空间 | CG-07：HTTP 200，3 个 bucket |
| 检查 bucket | HeadBucket：`HEAD /{bucket}` | 接入检查 | CG-07：三个 bucket 均 200 |
| 列出文件 | ListObjectsV2：`GET /{bucket}?list-type=2` | 查看对象、受控盘点 | CG-08：三个 bucket 均 200，本轮最多列 3 个 key；两个各有一个 11 字节对象，一个为空 |
| 读取对象信息 | HeadObject：`HEAD /{bucket}/{key}` | 长度、ETag、用户元数据 | CG-09：HTTP 200 |
| 读取完整正文 | GetObject：`GET /{bucket}/{key}` | 正文与任务原始输入读回 | CG-10：一个 11 字节既有对象完整读取 200；未展示正文 |
| 分段读取 | GetObject + `Range: bytes=start-end` | 原文分页、受控读取 | CG-11：`bytes=2-5` 返回 206，4 字节与完整内容的对应切片一致，Content-Range 为 `bytes 2-5/11` |
| 条件读取 | GetObject + If-Match / If-None-Match | 按 ETag 验证版本、避免读错 | CG-12：匹配条件可读；相同 If-None-Match 返回 304；错误 If-Match 返回 412 PreconditionFailed |
| 不存在/越界处理 | Head/GetObject；Range | 业务错误映射 | CG-13：缺失对象返回 404，Get 错误代码 NoSuchKey；越界范围返回 416 InvalidRange |
| 写入对象 | PutObject：`PUT /{bucket}/{key}` | 保存正文、上传输入、恢复输入 | CG-14：官方文档支持；账号所有者 FULL_CONTROL 有权限依据，未实际写入 |
| 不覆盖已存在对象 | PutObject + `If-None-Match: *` | 不可变对象、重复请求及并发保护 | CG-14：20.2.4 源码解析并传递该条件；实际 412、并发和丢响应回查仍未测试 |
| 保存校验元数据 | PutObject + Content-MD5 / `x-amz-meta-sha256` | 上传完整性及正文摘要校验 | CG-14：官方文档支持 Content-MD5 与自定义元数据；新对象的写入/读回及坏摘要拒绝尚未测试 |
| 删除对象 | DeleteObject：`DELETE /{bucket}/{key}` | 物理清理与测试数据清理 | CG-14：官方文档支持；未删除任何现有或测试对象 |

P3 的已有适配方法为 `CephP2.put_object_sync`、`get_object_sync`、`read_range_sync`、`delete_object_sync`；外层 `CephObjects` 提供命名空间、不可变写读回及错误映射。数据接口已实现，但本报告不将 S3 SDK 的只读成功当作完整 P3 接入通过。

现有样本对象的用户元数据包含 blake3、md5，不含 P3 完整读取要求的 sha256。样本可通过 S3 读取，不能直接当作当前 P3 格式对象消费。用户已明确旧数据不导入，后续仅验证 P3 按自身格式写入的新对象。

## 其他可用能力

| 能力 | 接口 | 核查结果与限制 |
|---|---|---|
| bucket 位置 | GetBucketLocation | 三个 bucket 均 200，返回 default |
| ACL 权限查询 | GetBucketAcl、GetObjectAcl | 三个 bucket 查询均 200；认证账号与 bucket owner 一致，授予 FULL_CONTROL；对象 ACL 只读查询 200 |
| bucket 策略 | GetBucketPolicy、PutBucketPolicy | 读取均 200，返回空 JSON 对象；未设置或修改策略。ACL 不是完整实时写入验证 |
| 版本管理 | Get/PutBucketVersioning、ListObjectVersions | 版本配置查询均 200，当前三个 bucket 都未启用版本管理；未改变配置 |
| 生命周期 | Get/PutBucketLifecycleConfiguration | 查询返回 404 NoSuchLifecycleConfiguration，表示当前没有规则；官方功能表支持生命周期，未创建规则 |
| 标签 | Get/PutBucketTagging、Get/PutObjectTagging | bucket 标签查询返回 404 NoSuchTagSet，当前无标签；写标签未测试 |
| 浏览器跨域 | Get/PutBucketCors | 查询返回 404 NoSuchCORSConfiguration，当前没有规则；服务端 P3 调用 S3 不依赖浏览器 CORS |
| 大文件分片 | CreateMultipartUpload、UploadPart、CompleteMultipartUpload、AbortMultipartUpload、ListMultipartUploads | 官方支持；ListMultipartUploads 对三个 bucket 均 200，当前无未完成上传；分片写入未测试 |
| 服务端复制 | CopyObject | 官方支持，未复制对象 |
| 创建/删除 bucket | CreateBucket、DeleteBucket | 官方支持，具体限额与操作仍待验证；本轮未新建或删除 bucket |
| 管理 API | `GET /admin/info?format=json` 等 | CG-15：该只读 info 请求返回 403。S3 数据账号不能据此认为拥有集群、账号、配额管理权限 |

Ceph 兼容 S3 的基础数据模型，不代表与 AWS 全部服务能力完全等价；例如官方功能表将 bucket replication 标为部分支持，限于 zones。未核查的扩展能力不纳入 P3 当前能力声明。

指南还记录了 RBD 块存储与 CephFS 文件系统。这两条路线需要对应 CephX keyring、网络和客户端，不能用当前 S3 密钥直接挂载。本轮没有验证它们，P3 正文接口采用 RGW/S3 即可。

## 下一步可执行验证

在已授权的独立应用范围里使用唯一测试对象，验证：

1. 新对象写入，记录 Content-MD5 与 sha256 元数据，使用独立客户端完整读回。
2. 同 key 相同 bytes 幂等；同 key 不同 bytes 拒绝覆盖；并发条件写只有允许的内容被持久化。
3. 分段字节与信任的原始内容一致；丢失写响应后回查同 key，不能以更换 ID 重发代替恢复。
4. 删除自己创建的测试对象并回查不存在；不清理或覆盖既有对象。
5. 从实际 AKS 工作负载访问相同 endpoint；本轮证明本机路径可用，没有证明 AKS 出站路径、P3 装配、完整业务或灾备。

现有接口足以覆盖 P3 对 Ceph 的基础对象功能需求；仍未闭合的是实际写入/删除/条件写契约与当前 P3 的 HTTP 测试配置，以及后续生产传输与完整业务验收。本轮不因未知写入结果而宣布接口不支持，也不因官方支持而宣布实际验收通过。
