# Mock 与 PRD V1.3、主 ADR 一致性核查

后续状态：本报告记录改造前发现，保留作为历史证据。2026-09-20已交付新版统一Mock，修正情况与验证结论见[模拟改造验收](Mock_V1.3模拟改造验收_20260920.md)，不再把下文缺口列表作为当前页面状态。

日期：2026-09-20。结论：**部分符合。主要业务方向和已有引导场景可用于局部行为评审；尚不能称为完整对齐 V1.3 的评审原型。** 本次是核查，不修改 Mock 行为，也不代填产品验收。

## 1 核查依据和方法

- 产品依据：[PRD V1.3《租户补全版》](../PRD版本/AetherBrain_P3_PRD_租户补全版_V1.3.docx)，重点核对 FR15、8.2、12.8，以及三流程、恢复和结果交付要求。
- 技术依据：[主 ADR](../ADR版本/ADR-P2P3-001_总体架构决策.md)，D01—D08，状态为 Proposed。
- 核查对象：[核心 Mock](../原型Mock/index.html)、[租户专题](../原型Mock/tenant.html)、[加工与恢复](../原型Mock/p3-extended.html)，及其 JavaScript 状态、场景和资料配置。
- 执行核心9场景的37个预定义步骤，以及租户专题11步；核对返回状态顺序。另做两项授权边界探查。
- 本轮未进行浏览器渲染、布局或完整点击验收；执行的是页面所用的场景函数和模拟状态模型。未调用后端、真实模型、Entra或P2。本报告不评价P2内部实现。

Mock不调用真实模型或真实存储，本身不构成不符合。评审原型应准确表达目标行为、状态和边界；真实效果由后续集成验收证明。本次指出的是原型内部矛盾、缺失场景及尚不能代表完整设计的部分。

## 2 已符合的主要方向

| 要求 | 当前表现 | 判断 |
|---|---|---|
| D01：两个对外功能、Operate内部自动运行 | 保存和召回为主；加工、对账按钮说明为模拟推进 | 方向符合 |
| D02：保存与长期就绪分开 | S01/S03区分saved、加工失败、ready；失败保留原内容 | 样例符合 |
| D02/D03：更正、删除影响旧结果 | S02阻断旧版本结果；S05删除后阻断新召回、旧结果及迟到加工 | 样例符合 |
| D03：四种召回结果及完整组预算 | S04区分完整、空、降级、不可用；S08跳过过长冲突组继续尝试后组 | 样例语义符合；预算仍是字符模拟 |
| D06：未知动作查询原结果 | S06沿用原动作核对，显示Unknown到已确认 | 样例符合 |
| FR15：映射、同租户共享、撤权、停用 | 租户专题演示未绑定拒绝、只读共享不能删除、旧结果复核、停用阻断后台 | 部分覆盖V1.3 |
| 证据边界 | 页面标明模拟、无后端请求，主ADR保留Proposed | 方向符合；版本和覆盖元数据仍需修正 |

## 3 必须修正的偏差

优先级含义：“评审前修正”指会直接造成解释矛盾；“补齐后才能称完整覆盖”指可以先评审已有部分，但不能据此宣布全量通过。

| 编号 | 发现及证据 | 对应要求 | 建议处理 |
|---|---|---|---|
| M01 版本不一致 | 首页提示V1.3；`content.js`的当前产品依据仍为V1.2；`app.js`导出记录也标V1.2 | 单一需求基线、D08 | **评审前修正**页面依据、导出元数据和历史资料标识，不能只修改页眉 |
| M02 ADR对应不直接 | 页面仍以REVIEW-001—008组织摘要，场景按钮显示ADR 001等；其编号不等于主ADR的D01—D08 | 设计到场景可追溯 | **评审前修正**为主ADR决策映射或明确对应表。已有“历史摘要”提示，故不判为偷偷替换正式ADR，但现场仍易混淆 |
| M03 两套模拟授权规则不统一 | 核心`ReviewModel.replay`只查版本/删除，不查当前主体；租户模型的replay会查主体和许可。切换核心模型可信凭证后，原结果正文仍能返回 | FR15、8.2、D03/D07 | **评审前修正**共用模拟可信上下文与授权规则。此为模型层探查，不是线上漏洞结论，也不是现有浏览器引导已提供的越权操作 |
| M04 后台按钮身份语义不明确 | 自由试用的写、读、更正、删除使用所选请求范围；“推进后台加工”只传memory_id，不校验所选范围，也没有显式保存原任务主体供复核 | FR15后台归属及当前许可检查、D07 | **评审前修正**让推进按钮明确代表执行原任务，并显示、复核原主体；不应把演示员当前身份当原业务授权，也不能无范围推进 |
| M05 V1.3关键场景缺失 | 租户11步末尾是重新启用后拒绝过期凭证，没有恢复旧配置；没有在途读取撤权暂停点、主体停用、配置更新失败不部分开通等演示 | FR15、9.3、12.8、D07 | 补齐后才能称完整覆盖；尤其增加旧快照恢复不能复活权限、在途最终交付复核 |
| M06 需求覆盖表过期 | `content.js`仍称FR06未模拟、FR04未覆盖归档、FR15仅固定凭证；实际上补充页已有压缩/归档预设，租户专题已有映射和共享 | 评审材料一致性、D08 | **评审前修正**覆盖表，加入S10/S11和租户专题，同时区分预设展示、状态模拟和真实验证 |

M04不是要求演示控制按钮使用最终用户权限。正确模型应是：演示员推进模拟时间，任务按它保存的原主体、原范围和当前许可执行。目前这条联系在核心模型中没有表达完整。

## 4 尚不完整的流程与公共能力展示

| 范围 | 当前限制 | 原型需要补到什么程度 |
|---|---|---|
| Remember | 长文解析、提取与压缩主要是S10预设输出；类型主要由输入选择，未完整展示候选审核、质量拒绝及恢复中断点 | 让评审人看到输入、候选、来源、拒绝原因、正式提交和就绪条件；不要求原型接真实模型 |
| Recall | 词匹配和预算数字规则代替检索/冲突算法；字符预算不能代表正式token预算；没有暂停后撤权再交付的交互 | 保留模拟标识，说明预算口径；增加候选形成后撤权/删除及最终交付分支。正式tokenizer配置已存在，旧“待确定”文案需同步 |
| Operate | 仅有“两次交付温→热”样例和容量暂缓；没有完整降层、明确执行失败、观察证据丢失等状态 | 增加相邻降层、拒绝/失败、证据不足保持未知；显示触发依据、原动作和下一次读取状态 |
| Trace与健康检测 | 核心仅顺序事件列表，未形成一个trace_id串联请求、任务、事件及动作的完整查询；S11为固定trace_id预设展示；无完整依赖健康及恢复闭环 | 增加受控诊断视图：按trace_id显示关联节点、结果、失败原因；依赖失效→任务受影响→恢复判定→继续/失败分别表达，不新增产品管理平台 |
| 连续性 | 核心场景切换重置；租户页与核心页使用不同数据模型 | 若要宣称“完整业务连续走查”，需共用一份模拟业务状态，串起保存、共享、更正、撤权、后台和恢复；当前只能说独立场景集合 |

这里不要求建设性能指标面板。按当前工作重心，优先补业务行为、状态、追踪和恢复解释；生产性能与长稳仍由PRD验收阶段处理。

## 5 PRD 12.8六组覆盖

| 验收组 | 当前原型覆盖 | 仍缺少的内容 |
|---|---|---|
| 合法接入与未绑定 | 已有允许/拒绝样例 | 开通配置的完整变更及失败表达 |
| 跨租户与编号伪造 | 请求范围伪造、私有记忆读取边界 | 任务查询、结果查询、不同写操作完整矩阵 |
| 同租户共享与操作权限 | 只读共享及拒绝删除 | 授权有效期、版本变化与来源/派生范围的展示 |
| 撤权与旧结果 | 租户页已有旧结果复核 | 核心规则一致性、在途交付竞态 |
| 停用与后台恢复 | 排队后停用阻断、重新启用后拒绝过期凭证 | 旧配置/数据快照恢复；已发生外部动作继续受控核对 |
| 外部撤权与真实底层 | 无真实验证 | 原型可补传播时间线和超窗异常目标行为；真实Entra/P2证据只能联调取得 |

## 6 本次证据与结论

| 证据编号 | 内容 | 结果 |
|---|---|---|
| E01 | 最新PRD正文与主ADR、页面资料和导出配置对照 | 发现M01、M02、M05、M06及覆盖缺口 |
| E02 | 核心9场景、37步骤的预定义函数执行 | 预期状态顺序通过；只说明这些样例可按预设推进 |
| E03 | 租户11步的预定义函数执行 | 预期状态顺序通过；不等于12.8全部覆盖 |
| E04 | 更换核心模拟可信主体后重新获取原Context | 仍返回正文，复现M03 |
| E05 | 自由加工按钮调用路径与模型处理探查 | 未绑定所选请求范围或可复核的原任务主体，确认M04的建模缺口 |

原始执行记录和核查脚本保存在项目外助手工作区，不作为用户交付目录内容。本轮没有修改Mock或业务代码，未运行生产安全、真实故障或性能验收。

推荐顺序：先修正M01—M04和M06，再补M05及完整连续场景，最后逐项复核覆盖表。修正前可用于已覆盖部分的讨论，但应明确说明缺口；不能宣称“Mock已经完整符合最新PRD与ADR”。
