# Working 向量召回工程验收记录

日期：2026-09-30。需求依据：用户明确要求 Working 进入向量库并通过向量召回，且选择“先保存、异步向量化”。需求基线为 PRD V1.4。

## 结论

本次代码、契约与文档变更已落地；在可用的本地环境中，最终 Python 回归 **1379 项通过**，源码 Ruff、Mypy 及 126 个 Schema 一致性检查通过。真实 BGE 编码、持久化本地向量、Working 语义召回与重启恢复已验证。独立代码审查发现的 4 项问题均已修复并复验。

本结论属于本地工程核验。真实 P2/Milvus、Docker 容器联调、生产性能与长稳、Word 实际分页仍未完成验证。不能以本报告表示整个 P3 或十月版本已完成产品验收。

## 实际行为

1. Working 保存可靠内容并登记独立的 `remember.project` 任务，返回 saved；不等待编码，也不等待长期事实提取达到阈值。
2. 后台复用分块、编码、写入及发布清单核验。只有当前有效正文对应的全部预期块就绪，才发布 ready。长文保留先完成工作摘要、再索引实际交付正文的规则。
3. Working、长期和混合来源均经过 Query 编码与向量候选检索。`working_only` 只控制来源；Working 必须限定会话或任务。候选核验之后读取精确正文，交付和旧 Context 再取时重新核验。
4. 保存、按 ID 读取正文、向量就绪与语义召回分别表达。未就绪、依赖错误与正常空结果明确区分；有可信部分结果时保留覆盖限制。向量或模型故障不再自动使用词法结果报告成功。
5. 补索引复用当前版本和未完成任务，不重新抽取。更正、摘要变更、归档、删除、到期及撤权阻断旧资格；迟到写入不复活旧版本。历史无来源标签向量按长期解释，历史 Working 需要显式补索引。

## 首轮失败与未覆盖范围

首轮回归为 1358 项通过、3 项失败。两项旧用例仍假定 Working 不需要会话范围或向量故障可词法降级，已按新需求修订并进入最终回归。Docker 用例因本机 `dockerDesktopLinuxEngine` 管道不存在而失败，说明 Docker 引擎未运行；最终回归明确排除该单个用例，没有修改测试使其假报成功。

真实 Milvus 适配的来源过滤和历史兼容已有本地适配测试；本次没有连接真实 Milvus，也没有修改 P2 引擎内部实现。P2 团队需按更新的 V2.1 接口要求联合验证来源过滤、租户/任务隔离、准确正文和断点恢复。

PRD 的 XML、结构、原文保留、修订颜色及嵌入图片均已检查。当前环境没有可用的 LibreOffice 渲染器或 Word COM，未完成逐页渲染，不能声称分页排版已通过目视验收。流程图文件已进行结构及图像检查。

本次没有运行生产规模吞吐/延迟、P99、召回质量标注集、72 小时长稳或批量历史数据迁移，也没有以测试结果关闭其他会后问题。
