## 接口范围

元数据接口包括 `transaction()`、`get/put_if_revision`、`read/write/rows/rows_after`、`revision/page`、任务/事件/意图选择、`check/abort`、raw 原子记录操作，以及提交前护栏。不能只实现简单 CRUD 就认为满足调用方要求。后续跨服务协议需表达原子操作与条件，或设计受控的事务会话；Python 回调、连接对象和上下文管理器不能直接序列化传递。

对象接口包括同步/异步不可变写、完整读、删除、range 读及关闭。原始 Temporal 输入、P4 定义/状态所使用的持久输入都必须从同一个受控对象接口恢复。切换 Ceph 环境或资源时，保留的 input/body binding 应阻止静默重新绑定。历史对象迁移须另有明确清单。

缓存执行接口包括 `ensure/repair/purge/inspect/copies/repair_record/cleanup_complete/read_cached/probe` 和异步 `resources/observe/submit/query/verify_read`。只实现 ExecutorPort 中少数动作方法不够覆盖维护与恢复调用。当前只支持 Redis 热副本，`supported_moves` 为空；不支持动作返回稳定失败回执，P3 控制器也会避免预约新动作。

## 原子性、幂等性和恢复

1. 请求继续携带原 operation/job/workflow/run ID、Scope、MemoryRef、hash、字节长度、版本、auth_epoch、fence。客户端的 Scope 参数本身不能授予访问权限。
2. PG 事务内不执行 Redis、Milvus、Ceph 网络访问。先保存意图，退出事务后执行外部作用，再读回和复核发布条件。
3. 连接超时不自动表示“没有发生”。写响应丢失时查询原对象、原动作或原投影；无法确认则保持待确认状态，不能换新 ID 掩盖重复作用。
4. `saved` 仅表示持久保存确认；`ready` 还要求对应版本的投影完成。向量故障不能悄悄改为词法检索结果。
5. 删除/撤销后的旧缓存和向量不得重新发布。逻辑不可见、缓存清理、向量删除和 Ceph 物理清理是不同检查点。
6. Redis 是可丢弃副本。任务回执、唯一原文和恢复输入不能只存于 Redis。

## 错误和结果

| 情况 | 调用方结果 |
|---|---|
| 同一不可变对象写入不同内容 | IDEMPOTENCY_CONFLICT |
| 响应 hash/长度/range 不符合契约 | CONTRACT_VIOLATION |
| 外部作用可能发生但无法确认 | COMMIT_UNCONFIRMED 或原任务的待确认结果 |
| 存储连接不可用 | DEPENDENCY_UNAVAILABLE |
| 资源/环境/版本绑定不兼容 | VERSION_CONFLICT 或初始化明确拒绝，需迁移 |
| 不支持的层级迁移 | failed 回执，reason=unsupported_tier_transition；新调度记录 defer |
| 正常缓存不存在或过期 | 明确的 miss；不与损坏或连接故障合并 |

驱动错误在实现边界脱敏，不能把 DSN、token、密钥或任意驱动异常原文返回给用户。回执必须描述可验证的实际结果。

未写全路径的上述 Azure 用例均在 `tests/runtime/flows/`。这些测试尚未全部参数化为任意远程 provider 的认证测试包。P2 远程 adapter、可序列化请求/响应 schema、双方确认的 RPC 仍需后续完成，不能只更换 endpoint 宣称接管成功。本阶段复用现有 Azure 资源和数据库，不导入旧数据或旧任务。后续 P2 接管时，应对本阶段新产生的数据和进行中任务另行确认接管方案。

## 恢复期间确认原输入（2026-10-03 增量）

P3 新增 `PUT /p3/client-runs/{run_id}/recoveries/{transfer_id}/inputs/{operation_id}`，请求体为空，查询参数为 `expected_owner_id`、`expected_revision`、`expected_record_hash`（完整原运行 SHA-256）。必须仍持有该 transfer 的恢复占用，并具备当前 RECOVER 权限。

成功响应复用 `ClientInputReceipt`：`run_id`、`operation_id`、`request_hash`、`binding_digest`、`size_bytes`、`state: ready`。P3 只确认已经存在且 hash/长度一致的原对象，不向对象端补写、替换或移动字节，不释放恢复占用，不推进运行 head/journal。原 writer 保留；pending→ready 使用元数据修订号 CAS。

原 pending 字节缺失返回 `COMMIT_UNCONFIRMED`；已确认字节丢失或损坏返回 `CONTRACT_VIOLATION`；身份/占用变化拒绝；对象或元数据依赖失败返回 `DEPENDENCY_UNAVAILABLE`。响应丢失后，P4 读取同一恢复路径的 GET 核对原输入状态，不能据此重发业务请求。原确认已成功但 GET 尚未取得可靠结果时仍保持待核对。P2 只需兑现既有不可变对象读取和事务/CAS 接口，无新增业务判断责任。
