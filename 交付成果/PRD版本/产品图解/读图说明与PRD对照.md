# AetherBrain P3 产品图解

依据：`AetherBrain_P3_PRD_框架修订版_V1.2.docx`，2026年9月18日，产品评审稿。

两张图表达该版本的产品设计，不代表当前代码已经实现或指标已经验收。按“架构图 → 流程图”的顺序阅读。

## 产品究竟做什么

P3 是供应用、Agent、RAG 和 Workflow 接入的记忆服务。应用把对话、任务状态、事件或文档交给它；以后需要相关历史时，P3 在授权范围内提供当前有效、具有来源、符合长度预算的记忆材料。上层应用负责使用这些材料生成最终回答、执行工具和继续任务。

## 架构图怎么读

1. 最上方是使用者与上层应用。终端用户通过应用间接使用 P3；应用决定什么时候写入、什么时候召回。
2. P3 边界内有两个对外功能：Remember 负责存储和维护，Recall 负责查询并交付上下文。更正、删除和状态查询是配套操作。
3. 中下方是内部记忆组织与语义加工。当前状态可以直接更新；长期内容执行适用加工，合格后进入长期检索。
4. 右侧 Operate 是 MVP 已包含的内部自动调度。它同时利用存储和召回历史、当前状态及资源约束，完成决策、执行和结果反馈。应用无需调用第三个调度入口。
5. 最下方是底层存储与执行服务，承担实际保存、读取、检索和调整。它返回“已接收”不等于目标已完成，P3 要核对实际结果。

记忆的两个维度必须分开理解：

| 维度 | 分类 | 回答的问题 |
| --- | --- | --- |
| 业务记忆类型 | Working 当前任务、Episodic 事件、Semantic 稳定事实 | 记住的是什么？ |
| 访问层级 | 热、温、冷 | 内容以怎样的资源成本和读取准备程度被访问？ |

它们不一一对应。访问频繁不会自动把事件变成稳定事实，降层也不表示删除。普通升降层沿相邻层级执行。

## 流程图怎么读

- **A 写入与长期化**：校验并可靠保存；适用的当前状态可以使用，后台长期加工独立推进。加工失败保留已保存原文、来源和失败阶段。
- **B 按需召回**：应用发起统一 Recall；P3 确定来源，核验并读取正文，排序去重和保留冲突，按预算组装，交付前再次核验。A 到 B 的青色虚线表示可用内容供给，不表示 P3 自动触发 Recall。
- **C 后台调度**：两条业务流程持续提供历史与状态；算法决策后检查执行条件，实际执行并核对，结果进入下一轮判断。灰色虚线表示各流程全程的轨迹汇集，连线落点不限定采集阶段。
- **D 持续维护**：更正、到期、归档、删除改变后续使用资格，并约束召回、派生产物、历史结果再次获取和后台任务。

召回返回的四种结果：

| 结果 | 含义 |
| --- | --- |
| 完整可用 | 必需来源完成，没有来源、正文或语义缺失，且有可信材料可以交付。 |
| 正常为空 | 必需来源完成，没有缺失，确实没有合格内容。 |
| 降级可用 | 存在来源或内容缺失，但仍有可信材料可以交付。 |
| 不可用 | 安全阻断、没有可信输出、所有合格内容组均超预算，或无法完成组装等。 |

正常预算选择导致部分条目未入选，并不自动构成降级。首组装不下时继续尝试后组；所有组都装不下不能报告“正常为空”。

## 用 PRD 的项目助手示例串起来

1. 应用提交“预算上限20万元”和项目目标。P3 保存内容与来源，更新当前任务记忆。
2. 下一轮对话可以召回有效的当前预算，无需等待长期加工。
3. 会议长文在后台整理，通过适用质量和就绪检查后，可在新会话被检索。
4. 应用请求项目风险相关材料，P3 结合当前约束和相关历史，按预算交付带来源的上下文；应用再生成风险总结。
5. 用户把预算更正为15万元。后续默认召回使用新预算，旧预算不能继续冒充当前事实；未裁决的有效分歧则保留冲突说明。
6. 用户删除某段会议记录。P3 先阻断后续交付，再清理相关内容；旧任务晚完成也不能重新启用它。

以上业务持续产生历史与状态，内部调度据此调整热、温、冷访问准备；它没有固定串行位置，也不等待模型提供“已采用这条记忆”的回执。

## 图中内容与 PRD 的对应依据

| 图中模块或关系 | PRD 位置 | 表达的事实 |
| --- | --- | --- |
| 上层应用与 P3 的边界 | §1.3、§3.1、§4.3、§5.3 | 上层决定召回时机和如何回答；P3提供可信记忆材料。 |
| 两个对外功能 | §4.1、§5.1–5.2、§8.1、§8.5 | Remember 与统一 Recall；查询、更正、删除属于配套接口。 |
| 多租户与访问权限 | §3.3、§7.16 FR15、§11 | 可信身份、租户、资源范围及操作授权贯穿前后台。 |
| 当前记忆直接使用 | §5.2、§6.3、§7.3 FR02 | 当前记忆不等待长期加工完成。 |
| 按内容执行加工 | §6.3、§7.4–7.8 FR03–FR07 | 整理、提纯、压缩、事实形成与语义准备按适用规则执行，并非所有内容必经全部步骤。 |
| 三类业务记忆 | §5.5、§7.5 FR04 | Working、Episodic、Semantic 表示不同业务意义。 |
| 来源选择 | §6.4、§7.9 FR08、§8.5 | 指定则按范围执行；未指定则自动选择；不得静默缩减失败来源并报完整。 |
| 核验、排序与冲突 | §7.9–7.10 FR08–FR09 | 命中不等于可交付；有效分歧成组表达，替代版本退出默认使用。 |
| 预算组装与四类结果 | §6.4、§6.8、§7.11 FR10 | 完整组装、尝试后组、交付前复核，准确表达完整／空／降级／不可用。 |
| 原请求与历史结果查询 | §7.12 FR11、§8.3、§8.6 | 查询原处理不制造新效果；历史结果再次获取仍核验当前资格。 |
| 双侧轨迹与调度闭环 | §5.2、§6.2、§6.5、§7.13–7.15 FR12–FR14 | 两侧轨迹与当前状态驱动基础算法，自动执行并核对结果，更新下一轮依据。 |
| 热温冷及相邻升降层 | §5.5、§7.14 FR13 | 访问层级不同于记忆类型，普通升降层沿相邻层级执行。 |
| 调度安全与结果不明 | §6.5、§6.8、§7.14–7.15、§9.5 | 条件不足暂缓，结果不明核对原操作，确认前保留原有有效读取能力。 |
| 更正、到期、归档、删除 | §6.6、§7.5–7.6、§7.18 FR17 | 更新使用资格；删除先阻断后清理；晚到产物不重新启用失效内容。 |
| 运行保障 | §7.19 FR18、§9、§10.4–10.7 | 状态真实、异常可查、已确认内容可恢复，资源紧张时保护在线业务。 |
| P1 预测增强 | §4.2、§7.17 FR16、§13 | 后续增加访问预测和提前预热，沿用执行反馈流程，并可回退基础算法。 |

## 范围与抽象说明

- 图中是产品职责和业务关系，不指定数据库、消息队列、模型品牌、协议字段或部署拓扑；这些不由该 PRD 的核心流程唯一确定。
- 本期不包含独立 Web 管理端、RBAC 角色分配、独立身份系统或运维审计平台。已有身份、监控设施可按部署环境选择对接。
- 压缩质量、稳定事实形成标准、租户内共享细则、轨迹口径和算法评价条件仍按 §14.2 在对应交付前确定，图中不虚构具体阈值或裁决算法。
- 图中未铺开性能指标、排期和全部故障分支。产品目标与验收以 PRD §2.3、§10、§12、§13 为准，不作为已经达到的效果。
