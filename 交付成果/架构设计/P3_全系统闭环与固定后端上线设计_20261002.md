# P3 全系统闭环与 P2 分阶段接入设计

日期：2026-10-02；实施基线：a106f8383c4b7dc03a8e505f8cff9e1280dfe678。

## 目标与职责

完成 P3 每个业务模块、流程、配置与异常恢复，最终交付可上线版本。用户明确：数据库相关能力由 P2 实现，P3 使用其接口；PG、Redis、Milvus、Ceph 是 P2 的既定后端，P3 不重新选型、不修改 P2 引擎或共享 proto，也不自行改造共享数据库。P3 负责业务语义、可信作用域、版本/来源/权限复核、编排、客户端适配和消费验收。Temporal 继续负责持久编排。

## 用户确认的分阶段路线

1. **现有 P2 开发联调。** 使用未经修改的现有 P2 Object/Vector/Segment gRPC 服务，实际运行写入、回读、范围读取、向量搜索、删除与重启验证；完成 P3 独立可实现的业务及 Temporal 恢复。现有 P2 的本地引擎实现只作为开发联调基线，不能称为目标后端或生产验收。缺少 P2 事务/任务日志/缓存接口时，P3 参考实现仅在显式 development/test 配置使用，保留缺口清单，不冒充已经全部经 P2。
2. **正式 P2 与真实数据库联调。** 正式 P2 提供所需接口及后端实现后，P3 通过 P2 访问真实 PostgreSQL、Redis、Milvus、Ceph。已有数据库可用于隔离的依赖诊断；直接 SDK 的单项成功仅记依赖证据，不作为 P3→P2 全链路证据。保持同一业务规则及验收场景。
3. **迁移与上线验收。** 在 P2 负责人明确实际契约后切换 adapter/endpoint/namespace/TLS/auth，显式迁移原数据、任务、事件和 provider binding；完成 AKS 镜像、生产 Temporal、身份、故障、灾备和长期验收后交付。staging/production 不可选择当前参考后端，不允许自动回落本地实现。

## 稳定消费边界

| P3 消费能力 | 当前 P2 支持情况 | 正式联调要求 |
|---|---|---|
| Object Put/Get/Head/Range/Delete | 现有 gRPC，当前服务为本地对象及 SQLite 元信息 | 通过正式 P2 真实读写 Ceph；不可变/范围/hash/授权/重启证据 |
| Vector Insert/Search/Delete | 现有 gRPC，当前服务为 FlatIndex＋WAL | 模型空间/版本/租户/来源过滤、精确 projection/原操作查询、Milvus真实证据 |
| Segment 查询与迁移回调 | 现有 gRPC 子集 | 路由 epoch、fence、迁移作用和失败回查 |
| 原子业务元数据/权限/任务/Outbox/Inbox | 当前 proto 未提供 | P2 提供原子 CAS 事务、分页、原操作查询、提交与撤权竞态语义 |
| 缓存放置/TTL/配额/repair/purge | 当前 proto 未提供完整业务能力 | P2 提供放置、资源查询、原动作回查与缓存读取证据；P3只发决策 |

## 迁移约束

保持 operation/workflow/input/version/scope/source/auth_epoch/fence，未知作用回查原操作；saved 与 ready 分开。盘点、冻结写入或建立明确切换水位、备份、按稳定逻辑 ID 导入、逐条内容/hash/版本/删除校验、重建可派生投影、绑定升级、恢复原任务、业务复验、最后切流。不得使用跨 PostgreSQL/Ceph/Milvus/Temporal 的虚构全局事务；补偿和失败恢复必须可追溯。回滚避免双边接受新写入，禁止清库或删 fence 掩盖问题。

## 验收与文件约定

分别记录代码/单元/现有真实 P2/目标真实后端/Azure/长期/生产验收。未提供正式 P2、未执行 Ceph 真实操作或尚缺故障、迁移、身份等证据时保持未完成。正式成果放交付成果，源代码及必要运行资源留 AgentJYS-main，处理过程统一项目外。原工作区用户改动原样保留，当前隔离工作树实施，串行推进。

## 当前 P2 消费的已验证约束

- 搜索未命中不能推断投影不存在。P3 保留 unknown；当前 P2 的 DeleteVectors 成功回执确认持久查询墓碑，按原目标记录确认。该墓碑可阻止迟到插入重新被检索，仍不代表物理擦除。
- 当前 P2 使用 cosine；P3 对经过单位长度检查的 inner_product 模型空间使用数学等价的评分，不修改模型空间标识，不自动归一化异常输入。非单位向量及不支持的度量拒绝执行。
- 缓存清理按 Memory ID、作用域和版本确认。另一条仍有效记忆可拥有相同正文哈希，不能因此将本次目标的清理判为失败，也不能删除另一条有效记忆。
- P2 向量请求使用不晚于调用者的截止时间，并限制远端等待；过期请求不得开始写入。写入等待超时不证明无副作用，原持久意图保留，恢复只检查原投影，不重复插入。查询返回后复核目标读取授权，搜索回执超过条数上限或出现重复 ID 时拒绝接受。
- Operate 已生成但未提交的动作若因更正或删除而失效，按原 action_id 持久化取消结果并完成原工作流。已提交或结果未知的动作继续查询原 action_id；只有取得确定结果后才能收尾，取消后的既有副本仍由清理流程处理。
- 缓存完整性检查和读取必须保留原始正文的字节含义，包含 CRLF 换行；非法 UTF-8 和哈希不一致均不可作为有效正文。
- 正式 P2 缺少事务与缓存适配时，production_p2 入口拒绝启动。现有开发模式的 P3 元数据/缓存仍含 SQLite 参考组件；最终替换目标继续有效。
