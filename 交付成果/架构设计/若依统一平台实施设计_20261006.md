## 需求与接口边界

1. 普通用户无需输入租户；统一身份由后端映射。管理角色与普通用户角色分离，租户管理员不得获得跨租户或全局维护权限。
2. 若依为最终目录权威；已有 Python 目录保留稳定业务 ID 作为受控映射，不再独立创建权限事实。令牌校验覆盖用户和租户启停用、角色变化、过期、撤销；失败关闭。
3. Java 管理后端查询 Python 的 /platform-ops/v1/* 受控接口，用户身份由服务端验证，不能信任浏览器自填租户。管理 API 验证身份与权限，P3 再执行对象级授权。禁止可变任意 URL 代理或直接改 P3 表。
4. 页面：运行总览、请求诊断、任务与积压、记忆状态、故障与告警、租户用户角色、日志审计、配置发布、备份恢复、容量用量、资源台账、运营支持。复用原生 system/infra 能力；领域页面提供真实数据、采集时间、错误及未知状态。
5. 命令受理与执行完成分开；原 operation/job 不因超时重新提交。不支持的控制动作应明确拒绝；配置有版本校验；备份必须真实执行并有隔离恢复证据，不以现有拒绝执行的路由冒充能力。
6. 指标历史、告警规则与状态持久化；支持认领、维护静默、恢复。通知投递状态可见。日志默认不含令牌、密码或业务正文。
7. 数据迁移不复用同名即同人的假设。保留原用户/租户/主体映射；密码格式不兼容时使用受控重置，不记录明文密码到 Git。
