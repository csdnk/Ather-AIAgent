# P3 流程图与 PRD V1.3 一致性检查

日期：2026-09-21。本次核对当前[完整流程图](P3全景流程_Excalidraw/P3_整体架构与完整流程.excalidraw)与[PRD 租户补全版 V1.3](../PRD版本/AetherBrain_P3_PRD_租户补全版_V1.3.docx)的正文、表格条款。图源SHA-256：`fb1e66847adbce9ccd518d45fd98e76245643d9d977d8bb6f09714cae35ba020`。

本次只审查产品行为一致性，未修改图、PRD或业务代码；不将对象契约检查通过视为产品行为验收。

## 结论

两个对外入口、三流程职责、保存与Ready分离、可信授权、删除先阻断、历史结果重验、实际读取计热及内部自动调度，与PRD的主架构一致。

发现**两处按图中文字实现会收紧PRD降级行为的差异**，均在Recall；另有一处压缩产物适用范围收窄，三组需要补明的流程要求，以及一处配置版本表述歧义。应先校正这些节点，再以流程图指导服务接线。

## F01 必需来源故障被直接等同于整次失败

性质：行为差异，优先修正。

**图中证据：**A.1b底部写“必需来源故障失败，可选来源须明确允许降级”；A.1d底部写“必需来源故障 → Failed”。节点ID为`rc26-body-status`、`rc26-context-source-policy`。

**PRD依据：**

- 第6.8节“长期来源暂不可用”：请求需查询历史但长期超时，仍保留已核验、可独立使用的内容；“有可信部分则降级；没有可用内容则不可用”。
- FR08 / 第7.9节验收：“合并来源时长期故障可保留可信当前内容并说明降级”。
- FR10 / 第7.11节：“存在来源、正文或语义缺失，但仍有可信材料可交付”属于降级可用。
- 第12.4节“部分来源失败”：仍有独立可信材料时“按规则交付并说明降级”。

**具体差异：**请求Working与长期，长期检索超时，Working中还有完整可信材料。若把“已选来源”都解释为“必需来源”，现图直接失败；PRD要求支持降级结果。来源必须被查询，不等于来源失败后必须拒绝全部独立结果。

**建议替换：**“所选来源故障 → 记录缺失；仍有独立完整可信材料且满足交付条件 → 降级；无可信材料或无法安全交付 → 不可用。”

如确需提供业务上的强制全部来源成功模式，应另行明确其触发条件与产品约定，不能用未定义的“必需来源”覆盖PRD已有的合并来源降级场景。全局授权无法确认等安全问题仍应阻断。

## F02 任意必需关系组不完整就判整次不可用

性质：行为差异，优先修正。

**图中证据：**A.1d底部写“全组超预算、必需关系不完整或重组超限 → 不可用”；关系组不完整分支进入无可交付组处理区域。相关节点：`rc26-context-source-policy`、`rc26-group-complete-text`、`rc26-no-pack-text`。

**PRD依据：**FR09 / 第7.10节：“必要正文或冲突信息缺失时，不能把残缺内容装成确定结论。P3可以使用其他完整可信内容，但需要如实反映缺失。”FR10继续规定，有缺失但仍有可信材料时属于降级可用。

**具体差异：**候选组A的冲突另一方读不到，候选组B独立完整。A不能拆开交付，但不应仅因A失败便丢弃B。

**建议改动：**“本组不完整 → 整组排除并记录缺失 → 继续其他候选组”；完成选组后统一判断：有独立完整可信组则降级，无可安全交付组才不可用。

“必需”应约束同一冲突组成员共同交付。若其他组依赖缺失材料、无法确认组间独立性或存在全局安全阻断，仍不能交付；本建议不允许删掉冲突另一方后把剩余一方当成完整组。

## F03 合格压缩表示没有进入长期读取或Context的明确路径

性质：范围收窄，需要明确兼容策略；不将“读完整正文”本身判为错误。

**图中证据：**B.4写“供B.5复用”“派生物不直接送Recall或向量库”；A.1b按MemoryRecord读取完整权威正文，未画经授权核验的合格压缩表示选择路径。

**PRD依据：**FR06 / 第7.7节：用户能够知道读的是原文还是处理后内容；“合格压缩内容”可供“适用长期读取或上下文使用”，并保留原文、来源、版本及质量关联。FR09也明确当前、历史事件和压缩内容可能提供相同信息，需要按关系去重。

**判断：**“加工产物不能自动成为新记忆”和“不能拿命中块冒充全文”均正确；但若把现图解读为压缩产物只能作为提取中间材料、永不允许用于相应读取，就收窄了FR06。图中也没有明确说明B.5形成的正式Memory正文与合格压缩表示之间如何满足该条款。

**建议：**保留完整权威正文作为默认路径，另定义受控的完整表示选择：原文表示或合格压缩表示，都绑定同一记忆及来源版本、质量结论、表示类型和完整性。表示选择完成后，仍以完整条目/完整冲突组装包；不在超预算时静默替换为摘要。若本轮先仅接原文路径，应登记压缩读取尚未实现，不能标记FR06全量完成。

## G01 自动来源选择未展开

性质：遗漏，不能据此认定设计禁止自动选择。

PRD FR08、第8.5和第12.4节明确：调用方可指定当前、长期或两者；不指定时P3自动选择。A.1目前只画“确定来源：仅Working / 含长期”，未区分显式指定与未指定，也未完整展示三种显式选择。

建议在来源节点补“已指定？是：严格按指定来源；否：按查询、任务与记忆状态自动选择并记录”。自动选择只能在检索前决定，不能在来源失败后改写选择结果掩盖故障。

## G02 基础调度的周期触发与相邻层约束未写明

性质：遗漏，主要对应C.1/C.2。

PRD FR13 / 第7.14节规定内容/访问状态变化及周期评估可触发判断，并要求普通升降层沿相邻层级执行。现图明确了事件聚合和目标层比较，但未明示周期评估输入或相邻层检查。

建议补入周期重评入口；无新访问时也能根据时间、当前状态与策略判断低频内容。动作规划处明确普通迁移按Cold↔Warm↔Hot逐级执行，最终目标与本次动作目标分开。现有PlacementDecision已有相邻层校验，可以据此同步图文。

## G03 迁移期间保留旧读取路径与旧副本清理尚不明确

性质：遗漏，主要对应C.3。

PRD FR14 / 第7.15节明确：目标确认前保留已有有效读取能力；目标生效和旧副本清理待办分别展示。现图有实际层、可读性、地址条件更新和独立删除清理，但没有完整写出普通迁移的“保留旧可读副本 → 确认新地址 → 单独清理旧副本”。

建议把本次新增MigrationPlan、ReferenceHandoffReceipt和ProtectionReference的交接条件同步回图。该项已有对象骨架支撑，不能因此认为图中步骤或服务实现已补齐。

## A01 “配置版本随任务固定”须区分生成策略与当前执行约束

性质：表述歧义，非已确认的权限冲突。

B.8写“配置版本随任务固定”，而PRD FR18要求恢复继续遵守“最新权限、内容版本、删除及当前有效配置”。图的P3.2及B.8其他节点已要求权限重验，所以不能笼统断言当前设计使用旧授权。

建议明确：为复现结果而固定输入和生成策略版本；执行前重新检查当前租户启用、授权、资源限制、部署禁用及策略是否仍被允许。已撤销的旧配置不能因任务快照继续生效。若生成策略已被禁止，任务应迁移、重建或明确结束。
