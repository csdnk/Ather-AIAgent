## 现在每一步怎么写

每一步固定包含：**当前在哪个方法 → 收到什么 → 这段怎样处理 → 实际源码 → 得到什么 → 接下来调用或返回哪里 → 失败时谁负责**。

例如 Remember 不再要求先通读 extraction.py，而是这样阅读：

```text
ainvoke 先读 messages / existing
  ↓ 暂停调用方，展开 _prepare_messages 的实际源码
返回 prepared_messages
  ↓ 展开 _prepare_existing 的实际源码
返回 prepared_existing
  ↓ 回到 ainvoke，创建 extractor 并调用模型
模型返回 response
  ↓ 继续阅读 ainvoke 汇总结果的源码
  ↓ 展开 _filter_response 的实际源码
返回候选 → P3 决定是否正式提交
```

代码块是核对过来源的**真实摘录**。长方法按执行阶段拆开，短方法直接全文摘录；方法内部的中文说明随源码保留。初始化只执行一次、单次请求会反复执行、可选旁支不一定执行，这三种位置在流程中分别标明。

## 三种连接要分清

| 连接 | 本材料怎样表示 | 实际含义 |
|---|---|---|
| 上游真实调用 | 进入某方法，展开其调用，再返回 | 可以在对应源码中找到实际调用语句 |
| 对框架机制的借鉴 | “P3 责任”“P3 边界” | 我们需要自己的领域逻辑，不能复制接口名就当已实现 |
| 不同框架的能力连接 | 通过适配器接入 | LlamaIndex 不会因为安装了 FastEmbed 就自动调用它；CrossEncoder/tiktoken 也不自动拼成 ContextPack |

例如第二章展示 FastEmbed 的实际向量生成链，第三章展示 LlamaIndex 的可替换 Embedding 接口；两者之间必须适配。第五章的 c.Do.Reconcile 是领域实现边界，源码中没有现成的 P3 调度策略、Unknown 状态机或动作数据库。

## 阅读范围与源码来源

本次展开所选主路径的核心方法及帮助函数；外部模型 SDK、数据库客户端、C++/Rust 计算内核、标准数组/序列化库在各章末尾列出接口边界，不把整套依赖递归复制进来。StoreManager、IndexNode、并行编码等旁支也标明进入条件；没有展开的上游功能不属于本轮主线。

长期检索保持稠密向量路线。上游完整方法中偶尔出现未采用的选项，仅用于保留该方法的真实行为，不增加项目选型或开发任务。可监测与可恢复的 P3 实现边界在第五章说明；本文没有添加指标平台工作。

这些摘录是阅读材料，不是重新拼装的可运行库。省略了导入及大段英文说明；分段方法可能从循环内部开始、在调用点结束，因此不能复制各代码块直接作为完整应用运行。英文提示词等执行字符串保持原样，没有伪造上游业务实现。

来源版本沿用已核对的 [来源与注释校验](../第三方源码中文注释/来源与注释校验.json)，许可证随[原结构源码对照版](../第三方源码中文注释/README.md)保留。原结构版用于查证；本目录作为**流程学习入口**。
