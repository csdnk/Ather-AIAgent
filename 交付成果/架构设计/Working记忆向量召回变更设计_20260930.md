# Working 记忆向量召回变更设计

实施与本地验证结果见[工程验收记录](../测试与验收/Working向量召回工程验收_20260930.md)，部署及历史数据处理见[运行说明](../部署运行/Working向量召回与历史补索引_20260930.md)。

日期：2026-09-30。依据：用户要求 Working 记忆写入向量库并通过向量召回，且已确认采用先可靠保存、异步向量化。此文定义目标设计，实施与验证状态见后续验收报告。

## 业务决定

Working、Episodic、Semantic 都具备向量检索表示。Working 仍表示当前任务/会话的工作记忆，进入向量库不改变它的范围、有效期或业务类型，也不意味着自动转为长期事实。

保存成功只表示正文与元数据可靠保存。Working 的后台任务负责分块、编码、写入、逐块核验和当前版本索引发布；发布成功后才可通过语义查询召回。长文先完成既有正文整理/工作摘要，再对实际可交付正文建立索引。失败或尚未完成时明确显示未就绪；按 ID 查看获准的已保存正文与语义召回分开。

## 保存与更新

1. 身份、来源、版本、幂等检查通过后保存权威内容，登记向量任务，返回已保存和后台任务信息。
2. 使用与查询兼容的模型空间编码。对象正文不因进入向量库而被向量替代；向量只用于候选匹配。
3. 索引绑定记忆版本、正文哈希、模型空间、完整分块清单和来源类型。全部分块核验通过且记忆仍有效后，发布 Ready。
4. 更正、摘要更新、归档、到期、删除、撤权立即影响资格。旧向量即使仍存在也不得作为当前记忆交付；迟到任务不得复活失效版本。
5. Working 的投影任务独立于提取长期事实的任务，不等待长期化的批量阈值。保留现有抽取和摘要功能。

## 召回

请求选定 Working/长期/两者后，先编码 Query，再在获准范围及来源类型下查询向量，按记忆聚合候选，经 Remember 核验当前版本和已发布索引，读取准确正文，处理关系与预算，交付前再次核验。

`working_only` 表示只搜索 Working 来源，不再表示绕过向量库。单来源按向量候选名次排序；多来源按现有记忆级融合规则组织。任务/会话隔离继续有效，不能因为共用向量集合扩大范围。

没有匹配项、索引尚未就绪和向量依赖故障必须区分。未就绪/故障不得静默使用词法路径冒充向量召回成功，也不得自动扩大到未选择的来源。存在可核验部分结果时附覆盖限制；没有可核验结果时返回明确未就绪或依赖错误。

## 实现边界

- 复用现有 RF 持久任务、Remember 投影及 Generation Recall，避免第二套 Working 向量引擎。
- 同模型空间共用向量基础设施，以来源标签过滤；Remember 对标签与权威记忆类型再次核对。历史没有标签的向量按原长期向量解释，新增 Working 标签明确保存。
- 基础内容读取与后台加工资格不强制 Ready，防止待投影任务被自身就绪条件阻塞。Ready 由向量候选、发布清单和最终上下文核验共同保证。
- 历史 Working 必须显式补索引；补索引复用当前版本和任务幂等，不重复抽取、不改变原文及授权。未补齐期间如实报告覆盖情况。
- P2 的物理实现不在本次直接修改范围；来源过滤、就绪与恢复要求同步到对接契约，真实 P2/Milvus 单独验证。

## 交付与验收

修订 Word PRD（V1.4，变化标红）、总体与独立 Remember/Recall 流程图、ADR、当前入口、逻辑契约/Schema、业务实现与必要用例；旧 PRD 作为历史基线保留。过程脚本与渲染记录放项目外工作区。

必须验证：保存不等待编码；未就绪不假报正常空；纯 Working 确实调用编码和向量查询；语义命中不依赖词面相同；Working/长期来源与租户/任务隔离；更正、删除及处理中撤权；摘要更新和失败；重启恢复与历史补索引；向量依赖故障明确反馈；整条正文、预算及最终资格核验保持有效。

自动化测试替身只能证明控制规则；本地真实编码与向量后端证明对应本地链路；真实 Milvus/P2 需要独立环境记录。不得以修改 PRD 或通过单元测试表示产品验收完成。
