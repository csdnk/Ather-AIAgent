# EP-P3-06 隔离、追踪与恢复

状态：评审稿。需求：FR11 FR12 FR15 FR18。结果责任角色：RF/A/B/C。Gate：G1/G2 设计与原型评审；G3 核心可运行；G4 集成/质量；G5 用户与发布验收。

## Story

接入方和运维角色需要拒绝越权，并通过同一 Trace 解释失败和恢复。

租户补充：公司应用以获准身份接入，只能处理绑定业务租户及资源范围内的记忆；同租户 Agent 的共享需明确授权，停用或撤权影响新请求、后台执行和旧结果获取。依据 [PRD-ADD-07](../PRD版本/PRD补充_租户与身份接入.md)，实现采用方案见主 ADR D07。

打开 [S09 原型](../原型Mock/index.html#scenario=S09)。调用方可查看输入、逐步执行与输出/失败原因。所有数据是 Mock；当前实现边界见下文。
场景成功与异常均按步骤展示，切换或重置清空模拟状态。

S09 保留基础隔离演示，新增[租户专题 Mock](../原型Mock/tenant.html)模拟身份映射、未绑定身份、只读共享、撤权与租户停用。真实 Entra 接入及外部撤权传播没有因此完成。补充展示范围见 [Mock 设计说明](../原型Mock/原型Mock设计与演示说明.md)。

## Flow

可信身份→资源授权→请求/任务/事件Trace→失败定位→重启核对。失败、超时或版本变化必须按 [总体流程](../架构设计/总体架构与流程.md) 处理，不能将受理当完成。

模块协作：Identity + SQLite UoW + task/event/log。[主 ADR](../ADR版本/ADR-P2P3-001_总体架构决策.md)：D02 D07。权威数据和跨模块边界见总体架构。
