# P3 Temporal 全面接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 用户已选择串行连续实施；任务 1—13 已实现并提交，任务 14 的本地源码接入、审查整改与安全合入已完成；步骤 4 的 Docker 验收仍有外部阻断，保留未完成。

**Goal:** 将统一 P3 的所有持久任务、事件投递和可恢复业务步骤迁移至 Temporal，并通过本地真实进程中断验证后交付。

**Architecture:** 单个 P3 实例承载 API、事务意图转交器和 Temporal Worker，独立 Temporal Server 持久保存执行历史。P3 继续负责业务事务、权限、版本、幂等和完成凭据；Temporal 是唯一在线业务调度方。当前本地存储接口保留，Azure 部署和跨 Pod 共享存储不在本轮执行范围。

**Tech Stack:** Python 3.13、FastAPI、Pydantic、Temporal Python SDK、SQLite 业务事务、pytest/pytest-asyncio、Ruff/Mypy、现有 React/Vitest Web。

**Spec:** [已确认的 P3 Temporal 全面接入迁移设计](../架构设计/P3_Temporal全面接入迁移设计_20260930.md)。必须与本计划一起阅读。

状态：已按用户批准的设计实施。任务 1—13 的检查已完成；任务 14 的最终结果以 [工程验收报告](../测试与验收/P3_Temporal接入工程验收_20260930.md) 为准。Docker/生产基础设施限制单独记录，不能据此视为生产接入完成。

## Global Constraints

- 全面使用 Temporal；覆盖整个 P3，而非仅 Recall；先完成本地接入和验证，再部署 Azure AKS。
- 数据库维护、数据库恢复、SQLite/Ceph 存储改造以及 P2 故障修复不属于本次任务。
- 一个 P3 应用实例内承载 API 和 Temporal Worker，使用一份持久化业务目录，连接独立 Temporal Server。
- 生产运行路径中，所有已受理的持久任务均有 Temporal 执行归属；RF 不再作为另一套在线任务调度器。
- 禁止在持有 SQLite 事务时调用 Temporal RPC；unknown 不得仅凭超时改成 no_effect 或 failed。
- 业务数据及 Temporal 历史部署后留在 Azure；本轮不接入任何云端 Temporal 服务。
- 当前 Remember 策略、Working/长期双来源、租户授权、删除撤销、token 预算和版本守卫保持有效。
- 当前任务执行预算 3 次、核对预算 6 次；每 scope 待处理上限 100、每 tenant 上限 300；默认 scope 执行并发 1、tenant/class 并发 1。读取部署已有配置，不重置旧任务预算。
- 业务源码/必要运行资源在 `AgentJYS-main`；用户成果在 `交付成果`；临时环境、下载、原始日志和故障注入数据在 `E:/projects/codex/.agent-work/aether/workspace-support/temporal-migration-20260930/`。
- 保留当前未提交改动。使用当前工作区的业务文件快照作为隔离实现基线，不能仅从远程默认分支开始而丢失 Working/RF 变更。

## Review Focus

1. 任务已完成且 Temporal 历史已清理，调用者再次提交同一业务 ID：仍复用/拒绝原请求，不产生新效果（任务 2、3）。
2. 执行过程中撤销权限，HTTP 等待随后断开：Workflow 不因断线丢失，但后续执行和结果读取不得绕过撤权（任务 4、7、11）。
3. 上传进程在文件写完、输入记录提交前中断，或重传同 ID 不同内容：不能误受理残缺字节或覆盖已绑定内容（任务 5）。
4. 外部效果已发生但本地记录或 Activity ACK 未确认，旧 Activity 又迟到：只核对原操作，不重复写入；旧代次不能提交（任务 4、8）。
5. 周期批次中只有前半段对象已提交就崩溃：重跑不重复处理前半段，也不能跳过后半段；续接不丢控制消息（任务 10）。

```python
# models.py：Pydantic DTO；通过 SDK 的 Pydantic data converter 传输。
WorkflowInput(job_id: str, kind: str, deployment_id: str,
              input_hash: str, plan_version: str, entry: Literal['execute', 'reconcile'])
WorkflowBinding(namespace: str, workflow_id: str, first_run_id: str,
                current_run_id: str, input_hash: str, plan_version: str)
StartIntent(intent_id: str, job: WorkflowInput, task_queue: str)
ControlIntent(control_id: str, job_id: str, action: Literal['cancel', 'reconcile'],
              expected_revision: int)
StepRequest(job: WorkflowInput, stage: str, ordinal: int,
            mode: Literal['execute', 'reconcile'])
ExecutionRef(namespace: str, workflow_id: str, run_id: str,
             activity_id: str, delivery_attempt: int, epoch: int)
StepResult(outcome: Literal['done', 'retry', 'query', 'obsolete', 'failed', 'attention'],
           next_stage: str | None, result_ref: RecordRef | None,
           effect_status: EffectStatus, original_operation_id: str | None,
           reason_code: str)
ExecutionStatus(state: Literal['running', 'completed', 'failed', 'cancelled',
                              'terminated', 'timed_out', 'not_found'],
                run_id: str | None)
```

`job_id` 对后台任务等于原 `task_id`；前台持久命令生成有任务记录的稳定 job ID，并独立保存 caller operation ID、Recall ID 等业务关联。输入引用、权限主体、业务截止时间、执行/查询预算存入 P3，不由 Workflow 客户端任意覆盖。`RecordRef/EffectStatus/TaskSpec/TrustedContext` 复用现有契约。`StepResult` 校验 unknown 只能导向 query/attention；done 必须具有持久结果或合法下一阶段。

任务按编号串行完成；先前任务只需自己的局部测试通过，统一生产入口在任务 11 装配、任务 12 切换后才称为迁移完成。
