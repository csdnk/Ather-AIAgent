# 记忆与召回管理

## 需求与范围

用户要求独立的记忆管理、召回管理页面，具备基本增删改查以及租户和权限控制。现有记忆正文读取复用，新增管理端正式写入通路。用户已确认召回按“可保存的查询方案增删改查、执行并查看命中的记忆正文、保留真实执行记录供追溯”实现。

记忆管理：按企业和用户选择，按类别、状态查询；显示正文、索引状态；新增、修改正文、删除，兼顾归档与恢复。修改、归档、恢复及删除均校验正文版本与对象修订号。删除明确告知后果并需要确认，通过 P3 提交逻辑删除并跟踪清理，不能直接改数据库绕过 P3。

召回管理：方案名称、查询内容、所属用户、范围及结果预算；方案新增、查看、修改、删除；执行实际 Recall，查看命中的正文及来源、执行状态与时间。删除方案不删除历史执行证据。

权限：平台管理员可选择企业，租户管理员只允许本企业；普通 Agent 用户不能访问管理接口。正文读取、记忆写入、修改、删除、召回方案管理、召回执行分别校验权限。Python 管理层与 P3 同时校验租户、目标对象和实时身份；审计记录操作者，不冒充目标用户。仅授权角色可得到对应菜单与按钮。

## 实施与验收

1. P3：增加明确的管理操作授权与目标范围绑定，复用 Remember、Recall 和 Temporal 业务执行及幂等回执；保留真实操作者，撤权后禁止继续执行。
2. Python 管理服务：持久化召回方案与操作记录；严格参数模型、用户范围解析、幂等及版本冲突；代理 P3 管理操作与结果查询。
3. 若依页面：独立两页面，企业/用户筛选、正文表单、确认删除、召回结果、原操作查询；配置菜单与权限。
4. 验证：跨租户访问、角色/细粒度权限、版本冲突、重复与未知提交、CRUD 与真实召回；前端编译和页面操作。
5. 发布：对若依相关前端、管理服务及 P3 按不可变镜像发布，保留原镜像。新增数据表回滚时保留；不修改独立旧版系统。
