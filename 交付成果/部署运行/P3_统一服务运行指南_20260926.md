# P3 统一服务运行指南

日期：2026-09-26。需求依据为 PRD V1.3 及「P3 整体架构与完整流程」图。

统一入口把 Remember、Generation Recall、内部 Operate 接到同一 RF 持久事务、任务队列和事件通道。服务启动即运行后台处理；调用方不需要手动调用 `drain()`，也不需要另起独立 Operate 演示程序。对外业务仍是存储记忆与召回记忆。

## 1. 安装与启动

Python 3.13；以下命令在 `AgentJYS-main` 执行。虚拟环境及部署数据使用项目外目录。已有开发环境可以直接使用，不必重复创建。

```powershell
python -m venv E:/projects/codex/.agent-work/aether/workspace-support/p3-service-venv
E:/projects/codex/.agent-work/aether/workspace-support/p3-service-venv/Scripts/Activate.ps1
python -m pip install -e '.[embedding-onnx,resource-documents]'
python scripts/generate_proto.py
python -m aether_agent_memory init --directory E:/projects/codex/.agent-work/aether/workspace-support/p3-deployment --embedding-profile native
python -m aether_agent_memory check-config --config E:/projects/codex/.agent-work/aether/workspace-support/p3-deployment/service.yaml
python -m aether_agent_memory serve --config E:/projects/codex/.agent-work/aether/workspace-support/p3-deployment/service.yaml
```

安装后也可用 `aether-p3` 代替 `python -m aether_agent_memory`。默认监听 `127.0.0.1:8080`，接口定义在 `/docs`。

`init` 创建服务配置、身份配置、凭据文件；native 模式另建 `embedding.json`，模型缓存指向部署目录。已有配置或凭据时拒绝覆盖。凭据值不打印到终端。native 模式需要 BGE 模型；可以在 `embedding.json` 指定已有 `model_path`，避免重新下载。

无模型的本地联通验证可将初始化参数改为 `--embedding-profile lexical`。词法模式使用词项相似度，不能用于语义质量验收。未配置 `language_model` 时，保存原文片段作为事件记忆，压缩只使用保守的重复段落处理，不宣称已经形成真实模型推理能力。

## 2. 真实模型与 P2 配置

[`configs/p3.production.example.yaml`](../../AgentJYS-main/configs/p3.production.example.yaml) 提供完整配置样例。复制到部署目录后填写真实模型名称、端点和 P2 地址。可在初始化时用 `--model 模型名称 --model-endpoint http://模型服务/v1` 接入兼容 JSON Chat Completions 的模型。

| 配置 | 作用 |
|---|---|
| `language_model` | 抽取、比较、更正/冲突建议、压缩和工作摘要 |
| `verifier_model` | 可选独立审核模型；省略时用同一模型进行独立审核调用 |
| `embedding_profile: native` | 本地 BGE 中文 512 维编码；Query/Passage 共享完整空间绑定 |
| `embedding_config` | 原生模型目录、缓存、线程、精度配置 |
| `recall_config` | Recall 预算、CrossEncoder、Milvus 等已有参数 |
| `p2_endpoint` | P2 gRPC 地址；正文、文档与范围读取使用该 Provider |
| `redis_url_env` | 可选 Redis URL 的环境变量名；正文缓存后备路径 |
| `maintenance_principals` | 允许后台按其当前有效权限执行已注册维护规则的身份 |

模型密钥通过 `language_model.api_key_env` 指定的环境变量传入，默认 `AETHER_LLM_API_KEY`。模型响应必须符合结构化 Schema，随后仍经过原文证据、版本、授权和提交复核。模型失败不会自动改成规则模型成功。模型健康检查验证 `/models` 中存在配置模型，推理质量需业务评测。

`profile: production` 要求 native 编码、模型配置和真实 P2 地址同时存在；这是配置约束，不是生产验收标签。默认未配置 P2 时使用独立 SQLite 对象存储。默认向量存储为 SQLite；Milvus 使用已有 `recall_config` 接入，候选达到检索上限时明确返回 partial。native 的单位化余弦空间可使用 Milvus 内积索引。

不要直接把已有词法数据库切换到 native，也不要替换绑定后的正文 Provider 路径。模型空间和存储绑定会拒绝这种隐式迁移；迁移需要单独建立新索引并验证。

## 3. 业务接口与自动闭环

所有受保护接口使用 `Authorization: Bearer <credential文件内容>`。每次业务操作可提交唯一的 `X-Operation-ID`；重试同一操作复用原编号，不要用新编号掩盖未知结果。

```json
POST /p3/remember
{
  "source": {
    "kind": "conversation",
    "external_id": "meeting-001",
    "external_version": "1",
    "occurred_at": "2026-09-26T00:00:00.000Z"
  },
  "selection": {"session_id": "session-001"},
  "content": {"kind": "text", "text": "用户喝咖啡不加糖。"}
}
```

```json
POST /p3/recall
{
  "query": "用户喝咖啡有什么偏好？",
  "selection": {"session_id": "session-001"},
  "sources": "both",
  "token_budget": 1000
}
```

保存先产生可用 Working 记忆；后台按条数、token 或时间触发长期化，默认是 32 条、8000 token 或 600 秒。需要主动结束批次时可调用 `POST /p3/remember/consolidate`，请求体为对应 `selection`。不要把保存响应当作长期索引已经发布。

后续路径：抽取与证据核验 → 记忆提交 → 多块索引发布 → 召回候选资格检查 → 精确版本正文读取 → 排序/去重/冲突表达 → token 预算组包 → 最终复核。存储事件及成功读取事件驱动 Operate；真实文件冷热迁移经读回验证后确认，后续正文读取使用已准备文件。

| 接口 | 用途 |
|---|---|
| `PUT /p3/documents/{id}?version=1` | 上传 TXT/PDF/DOCX 原件，返回可直接用于 Remember 的 `content`；同版本不可改写 |
| `GET /p3/memories` | 授权范围内的分页元数据目录 |
| `GET /p3/remember/{id}/processing` | 后台处理状态与任务 |
| `POST /p3/remember/{id}/correct` | 有版本条件的更正 |
| `POST /p3/remember/{id}/lifecycle` | 归档与激活 |
| `POST /p3/remember/{id}/delete` | 先阻断使用，再异步清理 |
| `POST /p3/sources/{id}/revoke` | 撤销来源，传播使用阻断 |
| `/p3/remember/{id}/retention` | 配置及查询保留策略 |
| `/p3/remember/reflection`、`/p3/remember/distill` | 条件化反思与显式提炼 |
| `GET /p3/recalls/{id}`、`.../result` | 进度及再次取结果；旧结果重新做版本/权限复核 |

完整字段以当前 `/docs` 和仓库契约为准。

## 4. 持续运行与恢复

HTTP 和 Remember、Operate、maintenance、io、model 使用独立异步执行循环；事件投递、到期检查、身份重载和维护采样持续运行。耗时模型调用受并发、响应大小和超时约束。原生推理使用已有线程后端。

RF 持久化任务状态、租约、输入、原动作编号和恢复证据。正常关闭先等待任务，超时则取消本次执行，重启后按租约及领域恢复规则处理。Unknown 只能查询原动作或转人工处置。容量不足在提交副作用前明确延后；冷态稳定且读回核验通过后回收可选缓存和热度统计，保留来源/权限水位，后续读取可重新唤醒。

服务采用单进程宿主：使用 `workers=1`，不要在同一部署目录启动第二个宿主。生产多实例、高吞吐和跨主机一致性需要另行部署设计及压测。

| 观察入口 | 含义 |
|---|---|
| `/p3/live` | 进程可响应，不代表依赖可用 |
| `/p3/ready` | 数据库、日志、正文 Provider、模型空间、向量、tokenizer、执行器及 worker 等必需依赖可用 |
| `/p3/health` | 有时效的能力与依赖证据；需要 DIAGNOSE 权限 |
| `/p3/runtime` | worker、队列、过期租约及 Unknown 动作 |
| `/p3/tasks/{id}`、`.../progress` | 任务状态与恢复证据 |
| `/p3/operate/memories/{id}` | 授权的热度、输入水位和动作诊断 |
| `/p3/incidents`、`/p3/logs/{trace_id}` | 维护事件和受控过程日志 |

历史业务/动作证据仍需部署方规划归档、磁盘容量与备份周期。日志已有保留上限；不能把这一点等同于所有业务历史无限增长均已解决。现有备份接口主要覆盖 RF 数据库；完整灾备还必须覆盖正文 Provider、配置、向量索引及外部模型绑定，不能仅备份 `p3.db`。

## 5. 租户与授权变更

`identities.yaml` 包含显式业务租户、凭据 SHA256、principal 与共享资源授权。每次修改增加顶层 `revision`；身份/权限/凭据变更增加 `auth_epoch`。服务周期重载；非法新配置保留最后有效权限并标记 degraded，不会悄悄放开访问。建议完整写入新文件后原子替换，避免读到半份配置。

同租户共享使用 `grants` 指定 `grantee_id`、`grantee_tenant_id`、`resource`、`permissions`、授权 `revision`；跨租户共享会被拒绝。资源授权覆盖发现、读正文和结果再次获取。业务租户停用立即阻断；重新启用必须增加相关身份的 `auth_epoch`，旧在途上下文不能复活。Recall 的 `selection` 用于缩小范围，不是修改请求身份。

## 6. 容器运行

统一服务专用部署文件为 [`compose.p3.yaml`](../../AgentJYS-main/compose.p3.yaml)；原 `compose.yaml` 保留 B1/B2/B3 兼容演示，不是此统一宿主。

```powershell
$env:AETHER_DEPLOYMENT_DIR='E:/projects/codex/.agent-work/aether/workspace-support/p3-container-deployment'
docker compose -f compose.p3.yaml run --rm --no-deps p3 python -m aether_agent_memory init --directory /deployment --embedding-profile native --host 0.0.0.0
# 在宿主机编辑部署目录内的模型/P2/身份配置。
docker compose -f compose.p3.yaml --profile p2 up -d --build
docker compose -f compose.p3.yaml logs -f p3
```

容器配置路径以容器内 `/deployment` 为准；不要复制 Windows 模型绝对路径到容器内使用。内置 P2 地址为 `engine:50052`。`restart: unless-stopped` 提供进程退出后的重启；容器 healthcheck 检查存活，业务就绪另查授权 `/p3/ready`。本次仅验证 Compose 配置解析，Docker 引擎不可用时不能声称镜像构建或容器联调通过。

## 7. 验证与当前边界

对已启动服务运行真实 TCP 冒烟，会写入一条带唯一标识的测试记忆：

```powershell
python scripts/p3/smoke_service.py --url http://127.0.0.1:8080 --credential-file E:/projects/codex/.agent-work/aether/workspace-support/p3-deployment/credential
```

当前已经有统一 HTTP、真实 RF/SQLite 与文件缓存的持续闭环测试，并额外验证真实 BGE。JSON 模型、P2 Range 和 Milvus 适配的协议测试不代表外部服务质量验收。真实 LLM 抽取/冲突判断、真实 P2/Milvus 集群、压缩质量与 5 倍目标、24/72 小时长稳、业务性能以及 PRD P1 的预测预热需各自证据，不能用短时回归代替。
