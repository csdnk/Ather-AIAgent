## 2. 磁盘和网络

“磁盘”页：

- OS 磁盘类型选 Premium SSD / 高级 SSD，本地冗余 `Premium_LRS`。
- OS 磁盘大小选 **128 GiB**；暂不加数据盘。

“网络”页：

| 字段 | 填写值 |
|---|---|
| 虚拟网络 | 选择现有 `vnet`，地址空间 `10.64.0.0/16` |
| 子网 | 选择现有 `development`，地址段 `10.64.1.0/24` |
| 公共 IP | 新建 `aether-p3-service-01-ip`，Standard、静态分配 |
| NIC 网络安全组 | 新建专用于此 VM 的 NSG，建议名称 `aether-p3-service-01-nsg`；基本模式自动创建时可保留自动名称 |
| 公共入站端口 | 仅勾选 HTTP 80、HTTPS 443 |
| 负载均衡 | 不配置额外负载均衡器 |

必须使用上述现有 VNet/子网，它已与 AKS 网络建立对等连接，后续要从 VM 访问现有 Milvus 私网入口和 Azure 私有依赖。不要让门户默认创建另一个 VNet。

## 4. 配置 SSH 和域名

进入虚拟机“网络设置 / Networking”，打开它关联的 NSG，新建入站规则：

| 字段 | 填写值 |
|---|---|
| 源 | IP Addresses / IP 地址 |
| 源 IP/CIDR | `207.174.28.211/32`，本任务已使用的管理代理出口；后续 SSH 使用同一路径 |
| 源端口范围 | `*` |
| 目标 | Any |
| 服务 / 目标端口 | Custom，TCP `22` |
| 操作 | Allow |
| 优先级 | `100`；若已被占用，选未使用且低于拒绝规则的值 |
| 名称 | `SSH-From-Administrator` |

检查没有另外一条允许 `Any/Internet → 22` 的规则。80/443 可以公开，8080、7233、5432、6380、19530 不需要新增公网规则。若管理出口改变，修改上述单一来源即可。

点击 VM 概览中的公共 IP 资源，进入“配置”，将 DNS 名称标签设为：

```text
aether-p3-service-01-c50c3827
```

区域域名预期为：

```text
aether-p3-service-01-c50c3827.southeastasia.cloudapp.azure.com
```

以门户最终生成的 FQDN 为准。如果提示标签已被使用，请记录实际可用标签；后续服务配置和 HTTPS 证书会使用真实分配的域名。

## 5. 允许现有 PostgreSQL 安装 Temporal 所需扩展

在门户搜索“Azure Database for PostgreSQL 灵活服务器”，打开现有 **`postgresp3`**：

1. 打开“设置 → 服务器参数 / Server parameters”。
2. 搜索 `azure.extensions`。
3. 在现有允许列表中添加或勾选 **`BTREE_GIN`**；保留原有其他值。
4. 点击“保存”，保存后确认列表包含 `BTREE_GIN`。

这一步只允许扩展安装。之后由助手在现有 `agent` 数据库完成安装，并从上次版本继续官方 schema 升级；不重新初始化、不新建数据库、不重置数据。该参数当前检查没有待重启标记，不需主动重启数据库。
