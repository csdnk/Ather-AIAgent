## Redis：新建 Redis 数据源

在 DataGrip 选择 **＋ → 数据源 → Redis**，下载提示的 Redis 驱动，使用 standalone 连接类型：

| 字段 | 内容 |
| --- | --- |
| 名称 | `Azure-P3-Redis` |
| 主机 | `redisp3.redis.cache.windows.net` |
| 端口 | `46380` |
| 数据库 | `0` |
| 认证 | 用户与密码；现有 Azure 配置使用 access key 密码认证 |
| 用户 | 留空；如果驱动要求 ACL 用户，则填写 `default` |
| 密码 | 下方命令复制的 Redis 密码 |

```powershell
& 'E:/projects/codex/aether/交付成果/部署运行/Azure数据库连接/连接Azure数据库.ps1' -Action CopyPassword -Target Redis
```

将剪贴板密码粘贴到 Password。不要把密码放到 URL。

**高级 → VM options** 填：

```text
-Djdk.net.hosts.file=E:/projects/codex/aether/交付成果/部署运行/Azure数据库连接/azure-pg.hosts
```

该驱动专用 hosts 文件已同时包含 Redis 域名，Windows 全局 hosts 没有修改。

在 **SSH/SSL** 页启用 **Use SSL**，CA 文件选择：

```text
E:/projects/codex/aether/交付成果/部署运行/Azure数据库连接/azure-root-ca.pem
```

保留证书及主机名校验，点击测试连接。Redis 的真实服务端口是 6380，本机入口是 46380。此处不需要另外设置 SSH 隧道。当前未发现 key，因此成功连接后显示空是正常的。

已经使用真实 RESP 协议验证 Redis 的 TLS、认证、PING、DBSIZE；DataGrip Redis 图形界面的最后一次测试连接需要在用户窗口内完成。

参考：[DataGrip Redis](https://www.jetbrains.com/help/datagrip/redis.html)。

## 管理连接

```powershell
# 查看端口和后台进程
& 'E:/projects/codex/aether/交付成果/部署运行/Azure数据库连接/连接Azure数据库.ps1' -Action Status
# 实际只读验证全部三个后端
& 'E:/projects/codex/aether/交付成果/部署运行/Azure数据库连接/连接Azure数据库.ps1' -Action Verify -Target All
# 停止本机转发与自动重连
& 'E:/projects/codex/aether/交付成果/部署运行/Azure数据库连接/连接Azure数据库.ps1' -Action Stop
```

本次没有设置开机自动启动。持续连接过程中，网络故障或 Azure 登录过期仍会造成中断；账号过期后完成 Azure 登录，再连接。旧事务和 SQL 不会自动重发。P3 和本地 Temporal 仍保持停止。

本机直连 AKS 曾连续出现 TLS 握手超时；经现有 `127.0.0.1:3067` 代理查询同一 AKS 成功。脚本优先沿用已有 `HTTPS_PROXY`，否则在该代理监听时仅为 kubectl 子进程设置代理，不修改 Windows 全局代理。保持现有代理可用；若关闭代理且直连网络仍不可用，通道会持续重试，数据库客户端需要等待网络恢复。

已在 Windows PowerShell 5.1 实测：三个端口就绪时主动终止本任务转发子进程，原后台进程约 9.7 秒建立新转发，随后 PostgreSQL、Redis、Milvus 真实查询全部成功。这是一次恢复测量；此前直连网络故障时曾在 55 秒测试窗口内未恢复，不能保证每次均在相同时间恢复。
