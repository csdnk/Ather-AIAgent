## 运行结构

P3 的业务逻辑调用内部存储接口。当前实现使用 PostgreSQL 保存权威记录、任务和回执，Ceph 保存原始正文及恢复输入，Milvus 保存可重建的向量投影，Redis 保存有 TTL 和配额的热副本。Temporal 管理工作流执行。后续由 P2 适配相同契约，业务层不直接依赖 P2 的内部表结构。

这四种后端必须完整配置。`storage_mode: azure` 不会回退 SQLite、本地正文或本地向量。数据目录仍可保存模型缓存和临时文件，但不能作为跨实例恢复的唯一存储。

## 环境切换

源码 `configs/` 下的 `p3.development.example.yaml`、`p3.test.example.yaml`、`p3.staging.example.yaml`、`p3.production.example.yaml` 使用同一套 Azure 配置结构。`p3.azure.example.yaml` 提供测试环境示例。选择配置文件即可选择环境；启动命令中的 `--require-profile` 防止拿错配置。

环境必须隔离 PG 应用 schema/角色、Redis namespace、Milvus collection、Ceph 对象前缀，以及 Temporal namespace/deployment。选用已有且已授权的数据库和 bucket，不因切换 `profile` 创建数据库资源。Redis、Ceph、Milvus 的环境身份与已保存的元数据绑定；新业务一旦写入，不能随意改变绑定或重定向进行中的任务。

示例中的 Ceph、LLM、Temporal 地址及身份文件需要替换为实际部署值。示例文件没有声称对应资源已经创建，也不包含访问密钥。

## 必备资源和凭据

| 项目 | 配置与要求 |
|---|---|
| PostgreSQL | `AETHER_POSTGRES_DSN`：显式 host、dbname、user、password、`sslmode=verify-full`、`sslrootcert`；使用专用应用数据库和角色。配置的 schema 需提前由管理员授权创建，运行时不回退 public。已核实服务器为 postgresp3.postgres.database.azure.com |
| Redis | redisp3.redis.cache.windows.net:6380；`AETHER_REDIS_PASSWORD`；可信 CA 文件。域名和证书校验均启用 |
| Milvus | 集群内 milvus.internal:19530；独立 database、逻辑 collection、CA 和 TLS server name；`AETHER_MILVUS_TOKEN`。实际 collection 名由环境、database 和逻辑名派生 |
| Ceph | 有效 HTTPS RGW 地址、专用 bucket、`AETHER_CEPH_ACCESS_KEY`、`AETHER_CEPH_SECRET_KEY`。如采用私有 CA，再配置 `ca_file`；不关闭证书验证 |
| Temporal | 已持久化的服务、授权 namespace、固定 deployment ID/队列前缀；按目标环境配置 TLS。生产不能用 `server start-dev` 充当验收 |
| 身份 | `identities.yaml`：租户、主体、权限及 JWT/Keycloak 设置；可参考已有 identities.jwt / identities.keycloak-organizations 示例。维护主体必须实际配置并授予需要的权限 |
| 模型 | 经过验收的 LLM 地址、模型名、`AETHER_LLM_API_KEY`；BGE 模型及 `embedding.azure.example.json`；Recall 策略 `recall.azure.json` |

Secret 通过 Kubernetes Secret、受控环境文件或组织已有密钥管理方案注入。只在 YAML 中保存变量名。部署时核对已有 PG 数据库、Milvus database、Ceph bucket 及应用范围的权限；必要的应用表、集合和命名空间在这些现有资源中初始化。缺少权限或可用 bucket 时明确报告缺口，不自动新建数据库资源或修改网络权限。

当前 PG、Redis 是私网资源。AKS 内可以使用现有网络；开发机需要经过批准的私网通道。临时测试 relay 仅为本轮验证，具有到期时间，不能写入长期运行配置。

## Ceph 公网路线

允许先使用 Ceph 的公网 HTTPS 入口。公网接入仍需要专用 S3 账号和 bucket 授权。已知节点1 `20.191.146.177:8080` 只有 TCP 可达证据，尚未证明 HTTPS、签名读写或 bucket 权限。

资源所有者需要提供或配置：稳定的 RGW HTTPS 域名/证书、专用 bucket、具有所需 Get/Put/Delete/Range 操作权限的 S3 凭据，以及允许 P3 出站地址访问的网络规则。不要向聊天中粘贴密钥。凭据可以写入指定 Secret，再将条目名称提供给部署方。

当前 Azure 身份执行 VM Run Command 已被拒绝，尚无法代为在现有 Ceph VM 上创建账号或配置入口。此限制不会通过匿名写入、替换数据库或关闭 TLS 绕过。

## 安装和启动

从上述业务源码目录执行，配置放在受控的部署目录。安装步骤不自动创建数据库或 bucket：

```powershell
python -m pip install ".[embedding-onnx,resource-documents,recall-rerank,remember-ceph]"
python -m aether_agent_memory check-config --config E:/deployment/p3-test/service.yaml
python -m aether_agent_memory serve --config E:/deployment/p3-test/service.yaml --require-profile test
```

`check-config` 验证配置与身份文件结构，不等于凭据或网络可用。实际 Service 初始化会检查完整存储凭据与 CA，装配 PG、Redis、Ceph 和 Milvus。完整健康和写入验证仍需服务启动后执行。

`embedding.azure.example.json` 中 `/models` 是容器目录示例。Windows 开发时改为受控的本机模型路径。模型、tokenizer 与推理版本需要在最终镜像中固定并验证，不能依靠运行时临时下载来完成发布验收。

`Dockerfile.p3` 已加入 Ceph 所需的 boto3 安装组。构建命令：

```powershell
docker build -f Dockerfile.p3 -t aether-p3:azure-candidate .
```

这条命令只生成镜像，不会发布或替换 Azure 服务。最终部署还需固定提交、镜像摘要、配置版本和 Secret 引用，补齐 probe、资源限制、身份入口与回滚方案。

## 当前能力和验收边界

Redis 实现提供热副本、容量/TTL、检查、修复、删除和 PG 回执。它不声明温层或冷层迁移能力。控制器应记录不支持该迁移，不应将位置标签改变当作真实搬迁成功。
