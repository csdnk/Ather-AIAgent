# P3 公网 HTTPS 接入方案与执行计划

日期：2026-10-01。用户要求为现有 Azure 服务配置公网访问，并已选择先使用 Azure 提供的域名。

执行结果：已完成。[公网使用说明](P3_公网访问说明_20261001.md)、[真实接入验证](../测试与验收/P3_公网HTTPS接入验证_20261001.md)。以下保留选定方案与操作边界。

## 目标与当前依据

浏览器通过固定 HTTPS 网址访问现有 P3 监测网页，无需 Azure CLI、kubectl 或本机端口转发。当前集群为 `aetherstore-p3/aks`，命名空间为 `aether-p3-demo`。P3、Web、Temporal 和 Temporal UI 的 Deployment 均为 1/1 Ready；四项 Service 均为 ClusterIP，集群没有现成 IngressClass。

本机已验证 `/p3/runtime`：无令牌 401、错误令牌 401、正确部署令牌 200。保留现有 Bearer 认证和单实例数据绑定。此次为当前测试环境增加访问入口，不变更 P4 统一身份职责，也不代替完整生产验收。

## 选定方案

独立 Caddy 代理 → 现有 `web:80` → 现有 `p3:8080`。Caddy 自动申请并续期公共可信 HTTPS 证书，HTTP 自动跳转 HTTPS。客户端 Authorization 请求头通过现有 Web 传递给 P3；代理不注入、保存或公开 P3 令牌。前端只在内存中使用手动输入的令牌。

固定域名拟为 `aether-p3-demo-c50c3827.southeastasia.cloudapp.azure.com`，实际名称以 Azure 创建结果为准。2026-10-01 DNS 可用性检查返回 true。公网 IP 名 `aether-p3-public-ip`，位于现有节点资源组 `aetherstore-p3-nodes`，使用 Standard、Static、IPv4。独立 Service 仅发布 TCP 80 和 443；不发布 P3 原端口、Temporal、Temporal UI 或数据库。

代理资源名为 `public-web`、ConfigMap 为 `public-web-caddy`、证书数据 PVC 为 `public-web-caddy-data`。代理单副本，Recreate，证书存储使用 managed-csi 1Gi PVC。保留当前两块业务数据 PVC。代理不依赖 P3 就绪探针作为自身 liveness，避免业务依赖故障触发反复重启。配置限制请求体为 70MiB、上游等待 65 秒，匹配现有 Web；提供基础浏览器安全响应头。明确 HTTP 路由顺序，独立健康路径 200、其他 HTTP 308；禁用自动重定向但保留证书自动化，仅启用 HTTP/1.1、HTTP/2。公网维护路径及子路径返回 404。

镜像使用官方 `caddy:2.11.4-alpine` 的 Linux amd64 Digest，导入现有 ACR 并在 Deployment 固定 Digest。预先验证镜像元数据、Caddy 配置和 Kubernetes 服务端 dry-run。TLS 私钥及 ACME 账户保存在代理 PVC，不写入项目资料、源码或聊天。

Linux 启动验证发现官方二进制文件能力与 drop ALL 冲突后，非 root init 将同一二进制复制到 emptyDir 去除文件能力；应用容器只读挂载并运行副本。没有增加容器能力或权限提升，也不挂载 Kubernetes service account token。该处理已用真实 Linux Job 及实际代理启动验证。

## 顺序执行

1. 保存独立配置、验证程序和执行记录到项目外 `E:/projects/codex/.agent-work/aether/workspace-support/aks-public-20261001/`；正式使用说明保存在本目录。
2. 先运行公网行为探测，记录当前域名尚未提供服务。准备并验证 Caddy 配置、资源名冲突、官方镜像 Digest 和服务端 dry-run；只提交本次独立资源，不更改其他团队服务。
3. 将代理镜像导入 ACR，创建静态公网 IP 和 Azure DNS 标签，核对 IP/FQDN。若任一步失败，停在实际失败点检查原因，不跳过错误继续发布。
4. 发布独立代理 ConfigMap/PVC/Deployment/Service，等待 Pod Ready、负载均衡 IP 和证书签发。出现签发失败时保留原服务，检查 DNS、80/443、ACME 和代理日志。
5. 验证域名解析、公共证书信任与主机名、HTTP→HTTPS、网页及静态资源、无令牌/错误令牌 401、正确令牌的运行状态与任务读取。确认 P3/Web/Temporal 原 Pod、PVC 和 ClusterIP 保持现有状态。
6. 执行独立配置审查，修复阻塞问题，更新访问入口与已验证结论，打开正式 HTTPS 网页并将本机令牌复制到剪贴板供用户粘贴。

## 验收与回退

成功条件为公共可信 HTTPS 首页 200、HTTP 跳转 HTTPS、认证拒绝与允许符合预期、服务状态查询成功、原服务保持 Ready。证书签发与公网连通必须以真实请求验证；仅 Kubernetes apply 成功不算通过。原始日志保存在项目外，正式结论列出证据编号与限制。

如需关闭公网，先删除本次 `service/public-web` 以撤销入口，再删除独立代理 Deployment 和 ConfigMap。确认没有负载均衡引用后，单独删除 `aether-p3-public-ip`。证书 PVC 默认保留供恢复；不删除命名空间、p3-data 或 temporal-data。公网 IP 和证书数据磁盘会产生 Azure 费用，复用现有集群与负载均衡。
