# P3 监测与中文对话演示：完整启动命令

本说明对应当前 Windows 电脑和已安装的 Python 3.13 / Node.js 22 环境。业务代码在 `E:\projects\codex\aether\AgentJYS-main`，部署数据与依赖在项目外。重新打开电脑后可按顺序启动；不要依赖助手终端一直运行。

演示为真实本地 P3 服务、SQLite 持久化、lexical 检索和原文加工基线，没有配置聊天大模型。中文脚本验证记忆读写、跨会话召回、明确纠错及后台事件处理；不是模拟模型聊天回复。

## 0. 当前已有服务时

本次交付时 API `18080`、Web `15173` 已启动，可以直接做第 3、4 步。不要在同一部署目录再启动一个 P3 宿主。检查方式：

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:18080/p3/live" -TimeoutSec 5
```

返回 `liveness: alive` 表示后端仍在；访问 [Web](http://127.0.0.1:15173/) 检查前端。若连接被拒绝，则启动对应服务。`live` 只表示进程存活，测试脚本还会检查带鉴权的就绪状态。

## 1. 终端一：启动 P3 后端

新开 PowerShell，复制整个代码块。此终端保持打开；出现 Uvicorn 监听 `127.0.0.1:18080` 后进行下一步。

```powershell
Set-Location "E:\projects\codex\aether\AgentJYS-main"
$env:PYTHONPATH = "E:\projects\codex\aether\AgentJYS-main\src"
$P3Python = "E:\projects\codex\.agent-work\aether\workspace-support\ci-repair-20260923\venv\Scripts\python.exe"
$P3Deploy = "E:\projects\codex\.agent-work\aether\workspace-support\monitor-web-20260928\deployment"

# 已有部署只启动，不重复初始化。缺少整个部署时才创建。
if (-not (Test-Path (Join-Path $P3Deploy "service.yaml"))) {
    & $P3Python -m aether_agent_memory init --directory $P3Deploy --embedding-profile lexical --host 127.0.0.1 --port 18080
    if ($LASTEXITCODE -ne 0) { throw "P3 初始化失败，请查看上方错误。" }
}
& $P3Python -m aether_agent_memory check-config --config (Join-Path $P3Deploy "service.yaml")
if ($LASTEXITCODE -ne 0) { throw "P3 配置检查失败。" }
& $P3Python -m aether_agent_memory serve --config (Join-Path $P3Deploy "service.yaml")
```

接口文档：[http://127.0.0.1:18080/docs](http://127.0.0.1:18080/docs)。已有数据库继续使用，重启不会清空记忆和持久任务。若部署目录只剩部分文件，初始化会拒绝覆盖；先核对文件，不要删掉旧数据来强行初始化。

## 2. 终端二：启动监测 Web

另开 PowerShell，复制整个代码块。此终端也保持打开。当前依赖已经安装，`web/node_modules` 指向项目外依赖目录，无需再运行 `npm ci`。

```powershell
Set-Location "E:\projects\codex\aether\AgentJYS-main\web"
$env:Path = "E:\nodejs;" + $env:Path
$env:VITE_AETHER_PROXY_TARGET = "http://127.0.0.1:18080"
$env:AETHER_WEB_CACHE_DIR = "E:\projects\codex\.agent-work\aether\workspace-support\monitor-web-20260928\vite-cache"
& "E:\nodejs\npm.cmd" run dev -- --port 15173 --strictPort
```

打开 [http://127.0.0.1:15173/](http://127.0.0.1:15173/)。`--strictPort` 防止端口被占用时悄悜改用另一个地址；若报端口占用，先查看已经打开的页面及已有启动终端。

## 3. 终端三：复制凭据并连接页面

另开 PowerShell，运行：

```powershell
Get-Content -Raw "E:\projects\codex\.agent-work\aether\workspace-support\monitor-web-20260928\deployment\credential" | Set-Clipboard
Start-Process "http://127.0.0.1:15173/"
```

在页面点击“配置连接”，将剪贴板内容粘贴到“Bearer 凭据”，点击“连接并读取监测”。不要添加 `Bearer ` 前缀。凭据只存在页面内存，刷新后需重新输入。始终读取本部署文件；重新初始化产生的凭据不一定与之前相同。

## 4. 终端三：运行中文多轮对话测试

整行复制执行，当前终端在哪个目录都可以：

```powershell
& "E:\projects\codex\.agent-work\aether\workspace-support\ci-repair-20260923\venv\Scripts\python.exe" "E:\projects\codex\aether\AgentJYS-main\scripts\p3\dialogue_demo.py" --url "http://127.0.0.1:18080" --credential-file "E:\projects\codex\.agent-work\aether\workspace-support\monitor-web-20260928\deployment\credential"
```

用例顺序：记录“无糖咖啡”和“上海出差” → 本会话追问 → 长期化 → 新会话回忆 → 更正为“无糖红茶” → 旧结果失效检查 → 新版本召回 → 检查后台任务和三流程 Trace。

逐轮输出“用户”“P3 实际召回”“PASS”，最终 `"passed": true`、12 项检查通过、进程退出码 0 表示通过。默认检查间隔 2 秒，可在命令末尾加 `--step-delay 5` 放慢展示。每次创建独立 `dialogue_...` 业务范围，保留测试数据供查看。

可用 `$LASTEXITCODE` 查看刚执行脚本的退出码。失败时根据具体断言检查任务/Trace；不要仅凭出现过 PASS 就判断整轮通过。

## 5. 查看对应记录

- 页面刷新频率选择“每 5 秒”。
- 输出 `tasks` 中的 `task_id` → “后台任务”查询 → 查看状态、进度及关联 Trace。
- 输出 `traces` 中的 `dialogue_steps` 对应中文步骤；旁边 `trace_id` → “链路追踪”查询 → 瀑布图与节点记录。
- 短任务可以在两次采样之间完成，总览待处理数为 0 不表示没运行。以持久任务和 Trace 记录为准。
- 纠错后旧结果返回 HTTP 410 是预期行为。Trace 只覆盖保留期内记录。

如果还要单独演示连续读取触发 hot 放置，将命令中的 `dialogue_demo.py` 换成 `monitor_demo.py`。两者是不同用例，不要把热度压力读取解释成自然对话。

## 6. 停止与下次启动

在自己启动的 Web 终端按 `Ctrl+C` 停止 Web，再在 P3 终端按 `Ctrl+C` 停止后端。测试命令结束不会关闭服务。下次重复第 1～4 步即可，不清理部署目录、不重复初始化。当前由助手启动的实例仍在运行时，直接使用第 3～4 步。

换机器首次安装：参考 [业务 README](../../AgentJYS-main/README.md#快速启动) 创建外部 Python 环境并安装包，再按 [Web README](../../AgentJYS-main/web/README.md#本地启动) 安装 Node 依赖；替换本说明中的本机环境路径。源代码提交不会包含本机虚拟环境、凭据、数据库或依赖缓存。
