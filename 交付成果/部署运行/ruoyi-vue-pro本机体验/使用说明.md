## 已部署范围

采用官方默认启用的 `system` 和 `infra` 模块，包括用户、角色、菜单、部门、岗位、租户、租户套餐、字典及基础设施管理。MySQL 和 Redis 都是独立容器，数据保存在独立 Docker 数据卷。

官方完整后端源码和 Vue 3 + Element Plus 管理前端源码均已下载。商城、支付、审批、AI、ERP 等扩展模块的源码也在后端仓库内，但本次没有开启这些扩展服务。官方初始化菜单可能显示扩展模块入口；菜单可见不代表对应模块已经启动，也不代表需要购买授权解锁。用户小程序属于另一套前端，本次未部署。

本次没有将 ruoyi 接入 Aether 的 Keycloak、Agent、P3、Temporal 或云端数据库，也没有替换现有 Aether 后台。

## 启动、停止、状态与验证

先启动 Docker Desktop，然后在本目录打开 PowerShell：

```powershell
.\管理部署.ps1 -Action Start
.\管理部署.ps1 -Action Status
.\管理部署.ps1 -Action Verify
.\管理部署.ps1 -Action Stop
```

`Stop` 只停止本体验环境的容器，保留数据。`Start` 可以再次启动。容器设置了 `unless-stopped`；Docker 未启动、电脑关机或睡眠时不提供服务。数据库端口未映射到宿主机，网页端口仅绑定 `127.0.0.1:18888`。

`Verify` 检查页面及默认租户接口，不能替代用户、角色、跨租户和业务全流程验收。服务刚启动时需要等待 Java 完成初始化后再执行。

### 上游构建缺文件的本地修补

下载的前端提交中，OA 考勤页面引用了缺失的 `src/views/oa/utils/constants.ts`，导致完整前端构建失败。本次新增该文件，数值取自下载后端的 `OaAttendanceTypeEnum` 和 `OaAttendanceStatusEnum`：上班/下班为 1/2，正常/迟到/早退为 1/2/3。未改写现有页面或开启 OA 服务。补丁保留在前端源码中，Git 可见为新增文件；后端源码保持原样。

源码没有合并进入 Aether 业务代码。构建在项目外工作区和 Docker 构建卷执行，`node_modules`、Maven 缓存和原始日志未混入交付目录。私有运行配置位于项目外工作区，由管理脚本引用；它是本机部署的必要运行资源，清理工作区时必须保留。

## 重新构建

后端使用 Java 17、Maven 3.9。先复制源码到独立构建目录，推荐使用 Docker 原生数据卷，避免 Windows 挂载目录的扫描开销。在源码根目录执行：

```text
mvn -B -ntp -Dmaven.test.skip=true package
```

将 `yudao-server/target/yudao-server.jar` 作为新的后端制品。本次部署构建跳过了上游自动化测试，不能将构建成功写成上游测试全部通过。

前端使用 Node 22.23.0、pnpm 10.34.6。在独立构建目录复制 `build-config/.env.eval` 为 `.env.eval`，执行：

```text
pnpm install --frozen-lockfile
node --max_old_space_size=6144 ./node_modules/vite/bin/vite.js build --mode eval
```

构建目录为 `dist/`。替换正在使用的制品前先停止本体验环境，保留上一版制品，再启动验证。
