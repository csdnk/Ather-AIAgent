# P3 运维后台业务监测改造设计

日期：2026-10-06。状态：已按用户授权实施并发布；验证范围和未完成边界见 [使用说明与验收结果](../部署运行/P3业务与Temporal运维后台_20261006/使用说明与验收结果.md)。

## 1. 目标与验收对象

面向不会写代码的值班运维人员。进入后台后应能判断 P3 是否能够接收业务、哪些业务正在失败、影响哪些企业和用户、用户记忆的实际内容、问题处于哪一步、可以采取什么操作，以及操作是否产生预期结果。

用户已要求补齐其他 P3 业务监测、合并重复页面、移除不合理入口，并将 Temporal 的监测和操作纳入若依。本设计将这些要求作为同一轮改造范围。若依承担管理界面和权限入口，Python P3 继续执行记忆业务，Temporal 继续执行工作流调度。

## 2. 改造前审查结论

改造前的后台不足以让非开发运维人员充分理解 P3 运行状况。以下保留当时的问题与证据，实施结果以验收报告为准。

| 问题 | 已核对事实 | 影响 |
|---|---|---|
| 记忆页面没有正文 | operations/service.py 的 memories 分支直接复用 requests，读取 chat_turns.memory_evidence | 保存回执被当成记忆目录，无法检查记忆内容 |
| 审计与命令页面重复 | audit、commands 都调用 store.commands | 两个入口无法形成不同的工作目的 |
| 查询局限于本页 | ResourcePanel 搜索框明确为“搜索本页” | 可能误以为没有某用户或某时间范围的数据 |
| 告警覆盖有限 | collector 主要采集近期请求失败、最久等待和配置的 HTTP 探测 | 服务连通不代表召回、写入、长期整理等业务正常 |
| P3 业务证据未充分接入 | P3 有任务进度、追踪、日志、召回结果、记忆读取与存储维护查询 | 运维不得不离开后台或接触代码 |
| 容量命名超出数据范围 | usage 主要是近 24 小时请求和部分模型计量 | 无法据此判断完整物理存储容量 |
| 管理权限与内容读取不同 | P3 管理身份位于独立运维作用域；任务维护授权明确不涵盖记忆正文 | 不能靠修改前端 tenant 参数接入用户内容 |
| Temporal 控制已有约束 | ControlRequest 只接受 cancel、reconcile，要求原任务版本及理由 | 不能将“核对状态”包装成任意重跑，不能承诺已有暂停或重置能力 |

本轮审查基于 codex/ruoyi-platform-20261006，提交 cdc4b9c16ebed395d23298705cc33c27ea35c880。此处是实现能力审查，不是对当前云端所有 P3 业务健康状态的结论。

## 3. 导航结构与旧页面去留

一级入口保留七个；每个入口按具体工作组织标签页，避免为一个数据表新增一个菜单。

| 新入口 | 内容 | 旧入口处理 |
|---|---|---|
| 值班总览 | 当前服务能力、受影响业务、待处理事项、最新变化、采样时间 | 运行总览升级 |
| 用户与业务 | 用户检索；用户详情中的会话、记忆、召回、异常；全局业务记录 | 请求诊断、记忆状态合入；保留旧地址跳转 |
| 任务与调度 | 业务任务、Temporal 工作流、执行器与队列、周期维护 | 任务与积压升级；不另建重复的 Temporal 任务列表 |
| 故障处理 | 告警、关联故障、工单、处置记录、告警规则 | 故障与告警、运营支持、告警规则合并 |
| 用量与资源 | 请求及模型用量、配额、服务清单、已接入的存储容量 | 容量与用量、配额管理、资源台账合并 |
| 配置与恢复 | 实际配置版本、发布信息、平台/P3 分项备份及恢复验证 | 配置与发布、备份与恢复合并；标明各自覆盖范围 |
| 操作历史 | 内容访问、配置修改、任务操作、执行进度与最终结果 | 运维审计、命令记录合并 |

若依原有用户、租户、角色管理继续放在系统管理；用户业务详情可链接账号管理，避免复制一套身份管理功能。

删除对象是重复菜单和失去用途的页面实现，不是业务数据、操作历史、授权记录或底层服务。旧地址设为兼容跳转；菜单迁移保留权限映射及回退记录。没有实时数据源的资源登记不得标注为实时监控。

## 4. 各类 P3 业务必须看到什么

| 业务 | 值班需要回答的问题 | 详情与关联 |
|---|---|---|
| 记忆写入 | 收到了多少写入，成功多少，哪些仍在处理或失败？ | 用户、来源内容、接收时间、提取/提交/投影阶段、产出记忆、失败原因、任务 |
| 记忆召回 | 本次回答找到了什么，没找到是没有记忆还是检索异常？ | 召回范围、近期/长期覆盖、返回内容、关联记忆、上下文用量、降级原因、会话 |
| 长期记忆整理 | 有没有执行整理、提炼和反思，产生了什么？ | 输入记忆、阶段、输出记忆、来源关系、定期执行状态；未启用与失败分开 |
| 记忆生命周期 | 哪些仍有效，哪些已替代、过期或归档？ | 版本、有效性、来源、到期时间、策略与已有处理记录 |
| 存储维护 | 存储策略是否执行，迁移/清理等实际动作有无失败？ | 存储位置、热度、策略决策、动作结果、关联任务；仅展示真实存在的动作 |
| 业务执行 | 哪些任务排队、重试、等待恢复或已完成？ | 所属业务、用户、进度、等待时间、尝试次数、业务效果和 Temporal 执行状态 |
| 周期维护 | 最近一次何时运行，下一次是否有可靠依据，是否连续失败？ | 周期工作流、检查记录、当前绑定、失败原因；无调度依据时不编造下次时间 |
| 依赖服务 | 哪项能力不可用，影响哪些业务？ | 数据库、原文存储、向量检索、模型、执行器、调度服务；注明检查时间与过期时间 |

“未发生业务”“尚未采集”“采集失败”“未启用”“采样已过期”分别显示。统计必须标明时间范围、覆盖范围和分母；不把分页样本当全量，不把空列表当零失败，不把 workflow 完成当记忆已生效。

## 5. 用户记忆与会话详情

操作路径：按企业和姓名搜索 → 选择用户 → 查看会话/记忆 → 打开具体记录 → 查看来源和处理过程。

记忆列表：正文摘要、类型（工作记忆/情景记忆/语义记忆及解释）、状态、来源、创建时间、是否可检索。详情：真实全文、版本、来源内容及位置、投影状态、处理任务、存储维护记录、相关召回记录。正文与元数据分别读取，分页与长度受控，读取失败不能伪装成无内容。

会话详情：用户提问、实际回复、请求时间线、保存产物、召回内容。明确区分“检索返回”“已组装为上下文”“确有证据发送给模型”，不推断模型一定采用了某条记忆。

历史关联不完整时显示“该历史记录未保存关联信息”，不拼接虚构关系。历史召回结果若受生命周期权限影响不能再读取，展示原因，不绕过 P3 重新校验恢复已删除内容。

搜索按企业、用户、时间、业务类别、状态在服务端执行，并支持分页；浏览器的本页文本过滤只能作为辅助。

## 6. Temporal 纳入若依

将 Temporal 融入“任务与调度”。中文界面保留业务任务与工作流的对应关系；技术详情才展示 namespace、workflow ID、run ID、task queue 和 Activity 名称。

### 6.1 监测

- 工作流：运行中、等待、完成、失败、已取消、已终止、超时，以及开始时间、持续时间和关联业务。
- 执行步骤：当前步骤、已完成步骤、重试次数、下一次重试时间（有依据时）、可读错误说明。
- 执行器和队列：实际轮询者/执行器观测、积压、等待时间。需要 Temporal 服务指标或查询 API 支撑，绑定存在不能代表执行器在线。
- 周期任务：P3 已绑定的周期工作流和执行记录；不假定当前系统使用 Temporal Schedule API。
- 业务结果：同时显示 P3 的效果确认状态。工作流结束但效果未知时，进入待核对事项。
- 默认限定本次若依部署对应的 namespace、任务队列及工作流绑定，不能把共享集群其他应用和独立旧版系统混入。

### 6.2 操作范围

| 中文操作 | 接入方式与前置条件 |
|---|---|
| 刷新执行进度 | 查询现有任务进度、工作流状态和业务回执 |
| 申请取消任务 | 复用 P3 cancel；校验当前版本、原工作流绑定、权限及操作理由 |
| 核对执行结果 | 复用 P3 reconcile；追踪原任务，不创建新的业务请求 |
| 查看操作处理结果 | 持续查询同一个 operation_id，分别显示已受理、处理中、完成、失败和结果未知 |

任意工作流重跑、Reset、强制终止、随意发 Signal、暂停/恢复均不直接列为现成按钮。当前控制合同没有这些完整语义。需要时另行扩展具有业务效果核验的控制合同；本次先交付现有受控操作和充分监测。周期控制同样按实际合同展示，不把 cancel 叫成“暂停”。

后端通过 P3 和 Temporal SDK/服务指标接入，不在浏览器中持有 Temporal 凭据或直接访问管理端口。Temporal Web 保留为技术排障入口，不作为普通值班验收必经步骤。

## 7. 数据、权限及实现边界

若依前端 → Python 管理聚合接口 → P3 受控管理读取/现有业务服务与 Temporal 查询适配器。

新增专用只读内容权限与服务端目标范围校验。平台管理员可查询授权部署内企业的用户内容；企业管理员仅查询所属企业；业务用户无运维入口。每次内容读取校验当前身份与对象归属，记录操作者、目标、时间、用途和结果，不把正文或凭据写进操作日志。不能伪造业务用户登录、修改 X-P3-Tenant 绕过身份校验，也不能给通用 READ 权限增加任意跨租户能力。

P3 的内容、来源和召回最终读取仍走其业务服务，保留生命周期与权限复核。管理列表需要针对授权目标的显式诊断查询；任务维护特例不扩展成任意内容读取。

新增读取审计采用独立的访问事件，操作历史聚合访问事件与既有命令回执；展示时间顺序与关联关系，避免复制或改写原记录。

指标采用持续、限频采集并保留采样时间，避免浏览器开启与否影响监测；长历史、正文和步骤详情按需加载。超时、权限不足、数据过期和无记录分别返回可识别状态。新增聚合查询不能遍历所有正文或在页面打开时重复发起 LLM 调用。

部署可能需要同时更新若依前端、Python 平台和 P3 服务。数据库变更使用可兼容的增量迁移；上线前核对对应运行版本。独立旧版 Agent、共享网关、历史内容与原账号密码保持原状。

## 8. 数据来源及开发前核对表

| 数据 | 已存在的代码接口 | 实施要求 |
|---|---|---|
| 记忆目录 | GET /p3/memories | 当前为身份范围内元数据；新增管理查询边界及服务端过滤 |
| 正文/来源 | GET /p3/remember/{id}；POST /p3/remember/body；来源读取接口 | 按内容权限受控调用，不绕过生命周期 |
| 处理状态 | GET /p3/remember/{id}/processing | 中文阶段与真实产物关联 |
| 召回 | GET /p3/recalls/{id} 及 /result | 最终权限复核；完善历史记录关联 |
| 存储维护 | GET /p3/operate/memories/{id} | 关联实际决策和动作，缺数据明确说明 |
| 追踪与日志 | GET /p3/traces；GET /p3/logs/{trace_id} | 当前访问受作用域约束，需要管理读取边界 |
| 任务 | GET /p3/tasks、/{id}、/{id}/progress | 服务端筛选、绑定关系、进度与结果 |
| 运行状态 | /p3/health、/runtime、/ready、/periodic/control | 健康采样与业务统计分开；周期读权限按实际合同落实 |
| 任务控制 | POST /p3/tasks/{id}/control；GET /p3/controls/{operation_id} | 保留版本、幂等、原绑定、理由、结果核验 |
| Temporal 服务数据 | runtime/temporal/gateway.py 已有 describe 与原绑定核对 | 工作流可视查询、队列及执行器指标仍需实现并在云端验证 |

以上接口存在仅证明可复用的实现，不代表全部已接入若依或在当前云端验证。

## 9. 验收场景

由普通运维视角执行，主要步骤不允许依赖 SQL、命令行、JSON 或手工复制内部编号。

1. 进入首页，在一分钟内指出系统是否能接收业务、最紧急的事项、受影响企业，以及数据最后更新时间。
2. 按姓名找到一个真实演示用户，查看记忆全文，追溯来源，区分保存成功与可检索。
3. 从一次会话进入召回详情，说明返回了哪些记忆、覆盖是否完整；空结果与检索故障表现不同。
4. 查看一次写入从提交、处理到产物的全过程，分别呈现未完成、失败和成功的证据。
5. 查看长期整理和存储维护实际记录；无记录/未启用不显示为成功运行。
6. 从失败任务进入 Temporal 对应执行，看到当前步骤、重试和中文原因，再返回关联用户。
7. 对专用可控测试任务申请取消、核对结果；重复点击或响应超时不会创建重复业务任务，不操作用户的真实进行中任务。
8. 模拟执行器缺失或监测超时，通过隔离测试验证“未知/不可用”的显示，不为了演示破坏线上服务。
9. 平台管理员可按授权查询用户内容，企业管理员跨企业查询被拒绝；替换 ID、分页游标和来源引用不能越权。
10. 查看内容后产生访问记录；操作历史能区分谁查看了内容、谁修改了系统和最终执行效果。
11. 已替代、过期或删除内容按 P3 合同处理，不能从旧缓存或历史召回接口意外恢复。
12. 旧菜单地址跳转正确、原权限不丢失；正常屏幕可读，空态与错误提示明确。
13. 发布后核对 ACR 镜像、Pod 实际版本、公开页面与上述业务场景。单独报告页面、真实业务、部署和高可用验收结果。

完整验收需要真实业务样例及其证据；自动测试通过、Pod Ready 或 HTTP 200 不能替代上述场景。

## 10. 发布与回退要求

按内容授权与读取、业务详情与监测、Temporal 聚合、导航迁移的依赖顺序实施并回归。发布前保存菜单、配置与镜像清单；菜单迁移可回退，新审计表保留数据，不以数据库整体恢复覆盖新增业务。上线失败时回退匹配的服务镜像与菜单，避免新页面调用旧接口。

## 11. 评审结论与待实施项

推荐按本文进行结构调整，优先完成真实用户内容与业务链路，然后接入 Temporal 和持续监测，最后统一菜单。仅改菜单标题或将 Temporal Web 嵌入页面，不能通过验收。

当前完成的是源代码审查和改造设计。新增数据接口、授权、页面、监测、测试及云端发布均待实施；本文不宣称这些工作已完成。
