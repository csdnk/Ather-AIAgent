# P3 全量对象与接口索引

> 2026-09-22职责更新：五个投影对象已迁至 remember，写入与搜索接口拆分；118 个对象、68 个方法不变，正式接口组为 24。旧导入仅兼容。详见[本轮实现说明](12_投影与搜索职责调整_20260922.md)。

日期：2026-09-22。主入口：[完整框架流程讲解](09_P3完整框架对象与接口流程讲解_20260922.md)。

范围：四模块 `contracts/models.py` 与 `contracts/foundation.py` 中的 **118个Pydantic对象**，以及对应 `contracts/ports.py` 的 **68个接口方法**（24组Protocol）。其中已有72个对象/55个方法，新增46个对象/13个方法。枚举、类型别名、Host、配置类、适配器和内部辅助方法不计入这些数量，另见主文运行支撑表。

“已有”表示这轮增量之前已定义，不自动表示全部功能完成。“本地实现”依据服务源码与Host装配判断；2026-09-22 RF运行验证见11实现说明。接口catalog中的统一`implemented: false`是其历史契约标记，不用于判定本地实现是否存在。

字段表直接从当前模型提取，含继承字段、类型、必填/默认值及可表达的字段约束。默认值不代表持久化值；`必填`但类型含`None`表示必须传字段、值可以为空。跨字段规则由模型validator负责，不能仅看字段表判断业务成功。一个对象也不等于一张数据库表。

## 容易混淆的名称

| 名称 | 应如何理解 |
|---|---|
| SourceRef / SourceRecord | 前者是来源引用；后者是新增原件地址、操作与任务的权威登记。当前source()返回前者。 |
| MemorySnapshot / MemoryRecord | 前者在当前基础实现中内联正文；后者是新增的正文地址与发布索引权威对象，尚未替换前者。 |
| ArtifactRecord / DerivedArtifact | 前者是记忆级表示；后者是来源级加工产物。不能仅因都有artifact_id而混用。 |
| ProjectionTarget / ProjectionManifest | 前者定位旧接口的一个投影；后者规定精确版本下一个完整索引批次与全部预期块。 |
| VectorCandidate / MemoryCandidate | 前者是向量命中；后者是验证版本/批次后按记忆聚合的候选。 |
| MemoryReadBatch / FullBodyReadResult | 前者是当前快照读取批次；后者逐项描述新权威正文读取、路径和资格凭据。 |
| EligibilityBatch / GuardStamp | 前者给准入结论；后者还绑定对象、关系、授权修订及正文指纹，不能只重命名替换。 |
| ContextGroup / ContextPackUnit | 前者是最终输出分组；后者是新增计划阶段整体预算单元，还记录正文读取证据及长期主候选。 |
| ContextPack / ContextAssemblyPlan | 前者是已提交输出；后者是待核验计划，不能提前作为提交结果返回。 |
| HealthReport / RuntimeHealthSnapshot | 旧接口兼容前者，新统一接口返回后者；Health.report已将真实探针映射并保存新快照。 |
| UnitOfWork.transaction / ContextAssemblyPort.commit | 前者管理通用提交/回滚；后者是新增Recall业务提交方法。没有通用Transaction.commit契约。 |
| 13个方法 / 6组接口 | 新增13个方法归属6组Protocol。全量68个方法归属24组Protocol；均不自动等于HTTP路由。 |

RF本地服务现状与接入边界见[11实现说明](11_RF公共底座实现与接入_20260922.md)。

校核口径：全量对象来自运行时模型发现，接口来自接口目录并与四模块Protocol定义核对。本索引不修改任何契约、表结构或服务逻辑。
