日期：2026-09-23。按目前确定的安排，共 **7 人：总体架构负责人 1 人、流程开发负责人 3 人、测试与 P2 对接负责人 3 人**。后三人同时负责对应流程的测试用例、环境搭建和 P2 对接，不另设三套人员。已按当前填写的姓名同步全文；A 流程开发负责人尚未填写，保留为待确定。

## 2. 三个流程的具体工作与测试重点

| 流程 | 开发任务 | 对应测试与验收重点 | 开发 / 测试与 P2 对接 |
|---|---|---|---|
| A：编码与检索 | 统一模型空间；提供 B 所需 Passage 编码及自身 Query 编码；查询兼容空间中的向量 | Query/Passage 配置一致；维度/空间不匹配拒绝；依赖超时与降级可解释 | A 开发负责人（待确定） / 肖宇 |
| A：候选与组包 | 调 B 审查；按记忆占 Top K；有界补取；读取完整正文；排序、关系组与 token 预算；最终条件提交 | 多块不重复占 K；无效块不计分；不混版本/批次；正文不可读、关系变化、预算不足及撤权时正确处理 | A 开发负责人（待确定） / 肖宇 |
| B：保存与加工 | 来源保存、任务登记、内容加工、记忆版本与生命周期 | 重复提交、处理中退出、来源失效、纠错、删除及到期；业务记录与任务/事件提交一致 | 杨鹏通 / 赵旭东 |
| B：资格、正文与索引 | 实现候选资格接口、完整正文读取、批次写入核验与发布、最终资格复核 | 租户与资源授权；allowed/excluded/unverifiable；旧批次/指纹不符；写后丢回执；读取与提交间状态变化 | 杨鹏通 / 赵旭东 |
| C：消费与决策 | 消费存储/访问事件；去重更新视图；按规则决定存储位置 | 重放不重复累计；资格通过不误计为正文读取；视图落后、决策水位、配额及权限限制 | 沈佳隆 / 谭旭梁 |
| C：执行与恢复 | 迁移/清理、查询原动作、验证目标可读、向 B 交接地址及恢复对账 | 执行后丢响应、效果未知、迟到返回；交接前不误删旧副本；撤权、重启及失败恢复 | 沈佳隆 / 谭旭梁 |
| 三流程共同要求 | 使用统一身份、任务、事件、日志和监测机制；按节点提供业务信号 | 业务结果、日志、指标、事件及健康状态一致；追踪完整；重试和事件重放不重复计数 | 三位流程开发负责人分别实现，肖宇、赵旭东、谭旭梁分别验证，陈凯统一口径 |

以上是工作范围，不表示这些功能已经全部实现。已有基础代码继续复用；新增多块、候选资格、组包和地址交接等能力，按当前实现说明逐项接入。

## 3. 环境搭建与 P2 对接：由同三位测试人员承担

肖宇、赵旭东、谭旭梁分别负责 A、B、C 的测试、环境搭建及与 P2 对接。下表的公共环境牵头分配为建议安排；具体机器、P2 联系人、接口版本和联调时间由团队补齐。

| 工作项 | 牵头人 | 配合人 | 完成标准 |
|---|---|---|---|
| 公共开发环境基线 | 肖宇 | 赵旭东、谭旭梁；陈凯确认标准 | 统一代码基线、Python/依赖版本、启动方式和环境变量说明；三方可复现，公共环境不重复搭建 |
| A 专用环境 | 肖宇 | A 开发负责人（待确定） | 编码、tokenizer、重排和 P2 检索客户端可运行；模型空间明确；替身与真实 P2 分开配置 |
| B 专用环境及共享存储依赖 | 赵旭东 | 杨鹏通、P2 对应负责人 | 正文/元数据存取和索引写入依赖可用；测试数据、隔离、重置及版本约定一致 |
| C 专用环境 | 谭旭梁 | 沈佳隆、P2 对应负责人 | Worker、执行适配器、授权测试目标及故障模拟可运行；真实 P2 执行能力按已确认契约配置 |
| A↔P2：向量检索 | 肖宇 | A 开发负责人（待确定）、P2 检索负责人 | 对齐模型空间、租户过滤、候选引用/版本/批次、分数含义、分页及超时错误；提供真实联调记录 |
| B↔P2：正文存取与索引写入 | 赵旭东 | 杨鹏通、P2 存储/索引负责人 | 对齐对象保存与精确读取、索引写入/核验/清理、幂等和原操作查询；验证权限隔离及异常行为 |
| C↔P2：执行与状态查询 | 谭旭梁 | 沈佳隆、P2 执行负责人 | 对齐已约定的迁移/清理动作、操作编号、状态查询、执行证据及失败语义；P2 未提供的能力明确登记缺口 |

三人对 P2 使用同一份接口版本、连接配置和租户身份约定，分别维护各流程的接口样例、联调结果及问题清单；A 检索与 B 写入使用同一套向量空间和索引约定。发生跨流程冲突时由陈凯协调确认，不由各人独立修改公共约定。

P2 负责人由 P2 团队提供，不计入本项目上述 7 人。三位对接负责人跟踪问题到关闭，提供复现材料；具体代码问题交给对应 P3 开发或 P2 提供方修复。P2 尚未提供的接口、权限或环境应明确标为阻塞，不能用替身测试代替真实联调完成。

## 4. 公共底座与总体架构的责任边界

陈凯负责 RF 的架构所有权和统一规则，包括租户鉴权、事务、持久任务、可靠事件、日志、监测、健康、配置和恢复。**总体架构负责人不因此自动承担全部公共底座编码工作。**

公共底座若需要改代码，由陈凯将具体任务指派给 A 开发负责人（待确定）、杨鹏通、沈佳隆中的一位，登记唯一实现负责人；该开发负责人组织与 A/B/C 消费方的内部接入，肖宇、赵旭东、谭旭梁验证各自流程的公共能力。未分派实现人的 RF 任务应明确标为“待分派”，不能默认落给测试人员或无人负责。

| 决策或交付 | 最终责任 | 参与方式 |
|---|---|---|
| 总体方案、接口归属、公共日志与监测口径 | 陈凯 | 三位流程开发负责人提供实现意见，肖宇、赵旭东、谭旭梁核对可测试性与接入条件 |
| 某流程的业务实现与修复 | 对应流程开发负责人 | 对应测试与 P2 对接负责人提供复现和验证；跨模块影响由相关流程开发负责人共同评审 |
| 测试用例、样例数据与测试结论 | 对应测试与 P2 对接负责人 | 对应流程开发负责人审查可执行性；预期不明确时由陈凯协调确认，不能直接以当前代码行为代替规则 |
| 环境搭建与 P2 对接 | 对应测试与 P2 对接负责人 | 流程开发负责人负责 P3 代码/适配问题，P2 负责人负责其服务问题 |
| P3 内部接口协作 | 接口提供方开发负责人牵头，消费方开发负责人共同完成 | 陈凯确认公共边界；对应测试人员准备和执行验证用例 |
| RF 具体代码任务 | 陈凯指定的一位流程开发负责人 | 必须在任务单明确；不能以“大家负责”替代负责人 |
| 整体阶段验收与发布范围 | 陈凯组织并确认 | 肖宇、赵旭东、谭旭梁提供测试证据，三位流程开发负责人提供实现与限制说明；真实环境缺口明确登记 |

## 5. 每项任务怎么交接和判定完成

每个任务至少登记以下内容；实际执行时从对应人员中指定唯一负责人。A 流程开发负责人确定后需同步补齐：

| 任务编号 | 流程/公共模块 | 工作内容与范围 | 实现负责人 | 测试与 P2 对接负责人 | 依赖及 P2 联系人（如涉及） | 验收条件 | 计划完成时间 | 状态/阻塞 |
|---|---|---|---|---|---|---|---|---|
| 待填 | A / B / C / RF | 待填 | A 开发负责人（待确定） / 杨鹏通 / 沈佳隆中一人 | 肖宇 / 赵旭东 / 谭旭梁中一人 | 待填 | 正常、异常及记录要求 | 待填 | 待开始 |

工作顺序：陈凯确认规则和边界 → 对应开发与测试人员一起核对接口样例及验收条件 → 开发人员实现、测试与 P2 对接人员同步准备环境和用例 → 开发负责人完成 P3 内部接入、对应对接负责人组织 P2 联调 → 测试人员执行与回归 → 相关开发人员评审 → 陈凯组织阶段验收。

完成需同时具备：代码与契约一致、环境可复现、关键正常/失败路径通过、日志监测符合统一口径、相关提供方和消费方联调通过、文档更新、遗留项明确。替身测试通过和真实模块联调通过分别记录。现阶段不编造性能门槛、人员姓名或交付日期。

现有协同规则见 [协同开发规范](02_协同开发规范.md)；当前状态见 [新对话交接](../项目总览/P3_新对话交接_2026-09-23.md)；测试人员使用 [独立测试交接包](../测试与验收/测试人员交接包_20260922/00_先读我_测试交接说明.md)。本表明确人员分工，不改变现有 A/B/C 业务所有权，也不表示已开始管理台建设。
