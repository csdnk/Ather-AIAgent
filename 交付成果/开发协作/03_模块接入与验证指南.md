# 模块接入与验证指南

日期：2026-09-20。示例全部指向当前真实代码，避免复制一份会漂移的伪实现。

## 新成员第一天

1. 阅读[当前状态](01_当前实现与待办.md)与[协同规范](02_协同开发规范.md)，确认自己的 Owner 和消费方。
2. 独立检出仓库，准备 Python 3.13。安装 `scripts/p3/requirements-collaboration.txt`；只做离线机制验证时不需下载 BGE 权重，不需启动 Milvus。
3. 执行 `python scripts/p3/validate_collaboration.py`。首次 tiktoken 可能下载小型词表；受限网络需预置 TIKTOKEN_CACHE_DIR，此门禁不是完全无网络安装。
4. 运行下面的工程示例，读一次 Task、Outbox、Trace 的关联，再开始修改业务。

## 样例一：持久任务与原子事件

运行 `python scripts/p3/demo_foundation.py --directory <项目外新的运行目录>`。不要复用已有业务库。

跟读 [sample.py](../../AgentJYS-main/src/aether_agent_memory/runtime/foundation/sample.py)：

| 入口 | 看什么 | 新模块怎么用 |
|---|---|---|
| `__init__` | 任务类型、事件类型和消费者注册 | 在 Host 装配时注册，不能根据请求临时注册任意 Handler |
| `submit` | 授权、保存输入、enqueue、append 共用事务 | 领域 Repository 传递同一 Transaction |
| `run` | guard、输入 hash 核验、结果与 complete 同事务 | 网络计算放事务外，回来重新检查资格 |
| `recover` | 根据持久结果决定恢复，不扫描日志猜测 | 本样例只有本地事务副作用，不能照搬到外部动作 |
| `consume` | 在传入事务保存效果，由公共 Inbox 去重 | 需要外部调用时保存后续任务，事务内不发请求 |

输出的 trace_id 和授权追踪摘要可证明示例已接入节点观测。它只演示公共机制，不是 Remember 业务提取。新业务的节点参考 `@observed` 接入方式。

## 样例二：Recall 与依赖接入

阅读 [Recall service](../../AgentJYS-main/src/aether_agent_memory/recall/basic/service.py)、[检索来源](../../AgentJYS-main/src/aether_agent_memory/recall/basic/retrievers.py) 和 [Host](../../AgentJYS-main/src/aether_agent_memory/runtime/flows/host.py)。按“授权 → 来源发现 → 精确版本读取 → 排序 → 预算 → 最终核验 → Pack/事件提交”跟踪。

新增适配器通过 Port 注入，Host 接 `attach_provider` 和健康探针。阅读 [故障测试](../../AgentJYS-main/tests/runtime/flows/test_recall_pipeline.py)：用可控超时、删除/撤权钩子验证，不依赖真实服务恰好失败。

验证真实模型时另外安装 `scripts/p3/requirements-recall.txt`，运行 `python scripts/p3/validate_recall.py --recall-config configs/recall.rerank.local.json`。有 Milvus 环境后改用对应配置；真实验证不在每次普通 PR 强制下载模型。

## 样例三：外部副作用与恢复

阅读 [Operate service](../../AgentJYS-main/src/aether_agent_memory/operate/basic/service.py)、[本地执行端](../../AgentJYS-main/src/aether_agent_memory/operate/basic/executor.py) 和 [三流程故障测试](../../AgentJYS-main/tests/runtime/flows/test_flows.py)。重点跟踪：保存 action_id → 执行 → 故意丢响应 → Unknown → 查询原动作 → 依据观察确认。

新 Provider 必须回答：能否查原动作、实例重启后证据是否保留、部分效果怎么报告、删除屏障如何生效。回答不清楚时不能把它接成“失败自动重试”。

## 日志与健康接入

每个模块列出节点名、输入输出摘要、成功/降级/失败/未知的业务意义及关联 ID。`@observed` 自动记录方法开始/结束，但业务阶段仍由模块负责人明确定义。用 [观测测试](../../AgentJYS-main/tests/runtime/flows/test_observability.py)检查跨任务 Trace、回滚证据、取消、强退、越权查询及日志丢失。

探针必须说明是配置检查、存活检查还是实际推理/读写。轻量存活探针不做模型推理；深度探测失败影响对应能力，不能无差别重启整个系统。

## 提交前执行

```text
python scripts/p3/generate_schemas.py
python scripts/p3/validate_collaboration.py --report <项目外报告路径>
```

只有改动契约模型时才需要第一条生成命令；校验入口只检查漂移，不改文件。门禁组合已有三流程/底座/契约回归、原 Recall 回归、原生适配器测试、贡献文档及本批脚本检查。实际模型、Milvus、Azure、AKS、备份与产品验收另列，不因门禁通过自动变为完成。

最后按 PR 模板填写：需求/问题 → 行为变化 → 提供方/消费方 → 故障与恢复 → 验证证据 → 尚未覆盖。RF 负责集成，领域负责人对业务正确性负责。
