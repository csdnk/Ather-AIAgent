# P3/P4 运行作用域与文档命名空间隔离

继续 T06/T07，在已有隔离工作树串行实施。上一轮已完成原操作索引与执行者准入，本轮补齐换用未登记 operation ID 的业务写入隔离。正式数据库能力由 P2 提供，当前元数据/缓存仍使用明确的开发测试参考组件；不修改 P2 引擎或共享协议，不提交或部署，不提前创建导学会话。

## 代码核对与设计

- 当前 Remember consolidate 和 reflection 都按完整 scope 精确匹配，省略 task/session 不表示跨 scope 写入。distill 接收显式记忆引用，其他变更从当前记忆或来源取得真实作用域。保持这些既有业务语义。
- 登记增加不可变的可选 `scope_policy=p4_task_v1`。新版 P4 必须请求并核对该策略；P4 保留旧记录的读取，不自动推定其已隔离。
- P3 分配 `p4r_<摘要>` 任务命名空间及其 `_session`，随首次登记在同一事务内保存命名空间到原 run 引用的关联。策略要求调用方 home scope 未绑定 task/session；原有固定范围身份仍可使用普通 API。
- 命名空间覆盖该 task 下的合法运行作用域（session 为空或该运行的 session），以及同根身份范围下以该命名空间开头的文档 ID。语法保留但未登记的命名空间不能被普通写入抢占。保留标识由 P3 权威登记确认，不把 operation ID 前缀当作执行权限。
- 所有十四类业务入口继续检查原操作与执行者。在业务事务内同时校验实际目标；保护范围内即使换一个未登记 operation ID 或省略运行请求头，也必须拒绝。带托管运行声明的操作不能写入运行之外。
- Remember/correct/document 在不可变命令输入暂存之前先校验真实目标，最终准入事务再校验一次。更正通过 P3 元数据引用解析当前记忆范围，不为判断作用域读取远端正文。Recall 根据本次明确选择的 scope 校验，普通跨范围读取继续受现有权限控制。
- 已接纳 Temporal 任务继续执行原任务，不在 Activity 中重新套用调用方最新 owner；运行结束不会自动解除持久命名空间保护。正式清退和旧记录迁移继续单独实现。
- 当前事务证据属于 development/test 参考组件；对象调用为真实当前 P2。正式 P2 的隔离能力、真实数据库链路、完整接管恢复及生产验收仍未完成。

## 实施与验证结果

首次红测试 8 项失败，随后这 8 项均通过。P4 的三项新增红测试分别复现未请求策略、接受新登记降级和接受重复登记降级，已按登记回执校验策略和命名空间，并通过后续回归。

真实业务目标由 P3 解析：Remember 使用经过身份约束的 selection，更正从当前元数据引用取得 scope，文档使用真实 document ID 与 home scope，Recall 使用本次明确选择的 scope；十类同步变更使用既有业务目标引用。命名空间同时检查 task 和 session，文档接受准确命名空间或其下划线后缀。普通授权读取保持原有规则，未限定范围的合并与反思仍按完整 scope 精确匹配。

P3 登记策略默认缺失以保留历史读取与普通调用方兼容性；新版 P4 必须使用新策略。旧 P4 记录可以 GET 核对，P4 不把旧策略登记用于新执行或 checkpoint。旧数据与旧 checkpoint 不自动回填保护，容量清退、所有权转移和自动续跑仍待后续实现。

扩展批次 72 项中 70 通过、2 失败；失败为新增用例未按既有契约提供 Correction 的 content/source 和 Recall 的 selection。修正测试输入后，包含后续四项兼容边界的专项 33 项全部通过，36.31 秒。全目录 Ruff 通过，Mypy 修正现有元数据事务类型与字典值收窄后，434 源文件通过。最终合并回归另行记录，不将不同批次相加。
