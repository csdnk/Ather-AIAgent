# B1/B2 融合后 B2 有效性验证步骤

## 1. 验证目标

本验证不是只证明 B2 能把文本写入数据库，而是证明融合后的完整链路真实成立：

```text
长文本提交到 B2
→ Redis 创建异步任务
→ Celery Worker 调用 B1 Sidecar
→ B1 Sidecar 切分文本并生成 512 维向量
→ B2 保存记忆关联字段、分类结果和 B1 返回的文本块
→ Milvus 入库
→ B2 按 tenant / user / agent 隔离检索
```

通过本文件全部必测项，即可说明 B2 在 B1/B2 融合后可用。

## 2. 验收标准

| 编号 | 验收点 | 通过标准 |
| --- | --- | --- |
| V1 | 服务启动 | Redis、Milvus、B1 Sidecar、P3、Celery Worker 均运行；B1 为 ready。 |
| V2 | B1 真实参与 | B1 指标中的请求数、文本块数、向量数在 B2 任务后增加；B1 返回多文本块和 512 维向量。 |
| V3 | B2 异步性 | 长文本接口立即返回 `task_id`，任务状态随后经历 `PENDING`/`PROCESSING`/`SUCCEEDED`。 |
| V4 | B2 入库 | Redis 保存任务追踪字段；Milvus 保存 B1 返回的文本块、向量和 B2 记忆关联字段。 |
| V5 | 隔离检索 | 相同 tenant/user/agent 能召回；错误 agent 不能召回。 |
| V6 | 分类 | 任务文本保存 `category=task`，并带有关键词。 |
| V7 | 异常处理 | B1 不可用时，B2 任务最终 `FAILED`，并保留错误原因；B1 恢复后可继续处理。 |

## 3. 前置条件

- Docker Desktop 已启动。
- 当前目录为本项目根目录：`C:\Users\Administrator\Desktop\1`。
- 首次启动 B1 Sidecar 可能下载模型，耗时比其他容器更长。
- PowerShell 中文输入建议先设置 UTF-8：

```powershell
chcp 65001
[Console]::InputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
```

## 4. 启动融合环境（V1）

```powershell
cd C:\Users\Administrator\Desktop\1
docker compose up -d --build
docker compose ps
```

必须看到以下服务处于 `Up`，其中 `b1-sidecar` 最好为 `healthy`：

```text
redis
milvus
b1-sidecar
engine
p3
celery-worker
```

如果 B1 还没有 ready，查看模型加载日志：

```powershell
docker compose logs -f b1-sidecar
```

检查 B1 健康状态和当前模型维度：

```powershell
Invoke-RestMethod http://localhost:18081/health/ready
Invoke-RestMethod http://localhost:18081/v1/capabilities
```

预期：`/health/ready` 返回 `status=ready`，并显示向量维度为 `512`。B2 的 Compose 配置也应为：

```text
AETHER_B2_VECTOR_DIMENSION=512
```

检查 P3 基础服务：

```powershell
Invoke-RestMethod http://localhost:8080/health
```

预期：`p2_online : True`。

## 5. 记录 B1 基线指标（用于证明 B1 真实参与）

在提交 B2 任务前先记录一次 B1 指标：

```powershell
$b1Before = Invoke-RestMethod http://localhost:18081/metrics
$b1Before | ConvertTo-Json -Depth 5
```

重点记下：

```text
requests
success
total_chunks
total_vectors
embedding_dim（如接口返回）
```

## 6. 提交 B2 长文本任务（V3）

以下文本长度超过 B1 的单块限制，预期会被 B1 切为多个 chunk。

```powershell
$body = @{
  tenant_id  = "verify-tenant"
  user_id    = "verify-user"
  agent_id   = "verify-agent-a"
  session_id = "verify-session-001"
  source_id  = "verify-nanjing-trip-001"
  request_id = "verify-request-001"
  trace_id   = "verify-trace-001"
  text       = ("小王下周前往南京出差，需要携带已经签好的合同、身份证和电脑电源。请在出发前一天提醒他检查材料是否齐全。 " * 80)
} | ConvertTo-Json

$result = Invoke-RestMethod `
  -Method Post `
  -Uri http://localhost:8080/api/v1/b2/long-text `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))

$result
$taskId = $result.task_id
```

立即返回以下内容即通过“非阻塞提交”检查：

```text
task_id
memory_id
state = PENDING
```

## 7. 轮询 B2 任务状态（V3）

```powershell
do {
  Start-Sleep -Seconds 1
  $status = Invoke-RestMethod "http://localhost:8080/api/v1/b2/tasks/$taskId"
  $status
} while ($status.state -in @("PENDING", "PROCESSING"))
```

通过条件：

```text
state = SUCCEEDED
chunk_count > 1
memory_id = <非空>
request_id = verify-request-001
trace_id = verify-trace-001
source_id = verify-nanjing-trip-001
category = task
keywords = <非空>
```

如果状态为 `FAILED`，不要继续后续检查，先执行：

```powershell
docker compose logs --tail=200 celery-worker b1-sidecar p3
```

## 8. 证明 B1 真正处理了本次 B2 任务（V2）

再次读取 B1 指标：

```powershell
$b1After = Invoke-RestMethod http://localhost:18081/metrics
$b1After | ConvertTo-Json -Depth 5
```

比较前后数值：

```powershell
[PSCustomObject]@{
  RequestsBefore = $b1Before.requests
  RequestsAfter  = $b1After.requests
  ChunksBefore   = $b1Before.total_chunks
  ChunksAfter    = $b1After.total_chunks
  VectorsBefore  = $b1Before.total_vectors
  VectorsAfter   = $b1After.total_vectors
}
```

通过条件：

```text
RequestsAfter > RequestsBefore
ChunksAfter > ChunksBefore
VectorsAfter > VectorsBefore
```

也可查看 B1 最近事件，确认其中存在同一个 `request_id` 或 `trace_id`：

```powershell
Invoke-RestMethod http://localhost:18081/v1/events | ConvertTo-Json -Depth 8
```

这一步是融合验收的核心证据：它说明不是 B2 伪造向量，而是 B1 Sidecar 实际完成了切分和向量生成。

## 10. 检查 Milvus 记忆库（V4、V6）

以下命令从 `p3` 容器连接 Milvus，查询当前测试租户的数据：

```powershell
@'
from pymilvus import connections, Collection

connections.connect(alias="inspect", uri="http://milvus:19530")
collection = Collection("b2_memory_chunks_v3", using="inspect")
collection.load()

rows = collection.query(
    expr='tenant_id == "verify-tenant" && user_id == "verify-user" && agent_id == "verify-agent-a"',
    output_fields=[
        "memory_id", "chunk_id", "task_id", "tenant_id", "user_id", "agent_id",
        "session_id", "source_id", "content_ref", "category", "keywords", "text"
    ],
    limit=100,
)

print("命中行数:", len(rows))
for row in rows:
    print(row)
'@ | docker compose exec -T p3 python -c "import sys; exec(sys.stdin.read().lstrip(chr(0xfeff)))"
```

通过条件：

1. `命中行数` 等于 Redis 中的 `chunk_count`。
2. 每行的 `task_id` 等于 `$taskId`。
3. 每行的 `memory_id` 等于 B2 返回的 `memory_id`。
4. 每行的 `tenant_id`、`user_id`、`agent_id`、`session_id`、`source_id` 与提交值一致。
5. `category` 为 `task`，`keywords` 非空。
6. `text` 是原长文本的一部分，不是空值。

## 11. 通过 B2 检索接口验证读链路（V5）

```powershell
$searchBody = @{
  tenant_id = "verify-tenant"
  user_id   = "verify-user"
  agent_id  = "verify-agent-a"
  query     = "南京出差前要带什么材料？"
  limit     = 3
} | ConvertTo-Json

$searchResult = Invoke-RestMethod `
  -Method Post `
  -Uri http://localhost:8080/api/v1/b2/search `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($searchBody))

$searchResult.items | ConvertTo-Json -Depth 6
```

通过条件：返回的 `text` 包含“合同”“身份证”或“电脑电源”，并且返回项的 `category` 为 `task`。

注意：本融合版本使用真实 B1 向量，排序应具有语义意义；但模型首次加载、CPU 性能和测试文本重复度仍会影响具体 score 数值。验收重点是相关文本被召回，而不是固定分数阈值。

## 12. Agent 隔离验证（V5）

相同 tenant 和 user，但换成另一个 Agent 检索：

```powershell
$wrongAgentBody = @{
  tenant_id = "verify-tenant"
  user_id   = "verify-user"
  agent_id  = "verify-agent-b"
  query     = "南京出差前要带什么材料？"
  limit     = 3
} | ConvertTo-Json

$wrongResult = Invoke-RestMethod `
  -Method Post `
  -Uri http://localhost:8080/api/v1/b2/search `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($wrongAgentBody))

$wrongResult.items | ConvertTo-Json -Depth 6
```

通过条件：`items` 为空数组。这样说明 B2 没有把 Agent A 的记忆泄露给 Agent B。

## 13. B1 不可用时的异常验证（可选，V7）

> 此步骤会暂时停止 B1 Sidecar，仅在正常链路全部通过后执行。

```powershell
docker compose stop b1-sidecar
```

重新使用第 6 节命令提交任务，但将 `request_id`、`trace_id`、`source_id` 改成新的值。等待超过 Celery 重试时间后查询任务状态。

```
Start-Sleep -Seconds 15

$status = Invoke-RestMethod "http://localhost:8080/api/v1/b2/tasks/$taskId"
$status | ConvertTo-Json -Depth 5
```

通过条件：

```text
state = FAILED
error 中包含 B1 不可用或连接失败信息
```

恢复 B1：

```powershell
docker compose start b1-sidecar
```

等待以下命令返回 `ready` 后，再重新提交一条任务：

```powershell
Invoke-RestMethod http://localhost:18081/health/ready
```

## 15. 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `b1-sidecar` 长时间未 healthy | `docker compose logs -f b1-sidecar`；首次通常是模型下载或加载。 |
| B2 任务一直 `PENDING` | `docker compose ps` 确认 `celery-worker` 为 Up；查看 `docker compose logs celery-worker`。 |
| B2 任务 `FAILED` 且提示维度错误 | 对齐 `AETHER_B2_VECTOR_DIMENSION` 与 B1 `/health/ready` 返回维度；当前应均为 512。 |
| Milvus 查不到数据 | 确认使用 collection `b2_memory_chunks_v3`，并确认 tenant/user/agent 三个过滤字段与提交值一致。 |
| PowerShell 显示中文为问号 | 在提交前执行第 3 节的 UTF-8 设置，并重新创建请求体。 |
| B1 指标不增加 | 说明 B2 未调用 B1 或任务未真正执行；检查 `AETHER_B1_EMBEDDING_URL=http://b1-sidecar:18081/v1/intercept` 和 Celery 日志。 |
