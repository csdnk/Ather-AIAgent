# B2 与 B1 对接清单

本文件说明合并后的 B2 异步记忆链路与 B1 Embedding Sidecar 的边界。B2 不实现正式
切分算法，也不生成向量；这些工作全部由 B1 Sidecar 完成。

## 服务地址

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `AETHER_B1_SIDECAR_URL` | `http://b1-sidecar:18081` | P3 同步嵌入客户端的 Sidecar 基地址。 |
| `AETHER_B1_EMBEDDING_URL` | `http://b1-sidecar:18081/v1/intercept` | B2 Celery worker 和检索接口调用的 B1 端点。 |
| `AETHER_P2_GRPC` | `engine:50052` | B2 原文、向量写入和检索的 P2 gRPC 端点。 |
| `AETHER_P2_BUCKET` | `p3-memory` | P2 E2 原文对象桶。 |
| `AETHER_P2_COLLECTION` | `p3` | P2 E1 分区集合名称前缀。 |
| `AETHER_B2_MILVUS_PROJECTION` | `false` | 是否启用可选 Milvus 投影。 |
| `AETHER_B2_VECTOR_DIMENSION` | `512` | 可选 Milvus collection 的向量维度。 |

Docker Compose 为 P3 和 `celery-worker` 设置上述服务内地址；宿主机直接访问 Sidecar 时使用
`http://localhost:18081/v1/intercept`。

## B2 到 B1 的请求映射

B2 的长文本任务保留业务字段 `memory_id`、`session_id`、`agent_id`。Sidecar 顶层使用
严格字段白名单，因此适配器 `b2/b1_client.py` 将 `memory_id` 放入 `metadata`，并发送：

```json
{
  "text": "长文本原文",
  "source_type": "document",
  "request_id": "request-001",
  "trace_id": "trace-001",
  "tenant_id": "tenant-001",
  "source_id": "document-001",
  "object_id": "object-001",
  "metadata": {
    "memory_id": "memory-001",
    "session_id": "session-001",
    "agent_id": "agent-001"
  },
  "input_type": "passage"
}
```

检索请求将 `input_type` 设为 `query`，以使用 B1 的 query embedding 路径。`tenant_id`、
`user_id` 与 `agent_id` 由 B2 用于 P2 E1 collection 隔离，并写入向量元数据做二次校验。

## B1 响应与 B2 记录

B1 返回一个 `results` 数组，其中每个成功项含 `embedding_model` 与 `chunks`。每个 chunk
含 `chunk_id`、`chunk_index`、`start_char`、`end_char`、`chunk_text` 和 `vector`。B2 适配器
将单项结果标准化为以下内部记录：

```json
{
  "status": "success",
  "request_id": "request-001",
  "trace_id": "trace-001",
  "source_id": "document-001",
  "records": [
    {
      "chunk_id": "document-001:0000",
      "chunk_text": "B1 切分后的文本块",
      "vector": [0.1, 0.2],
      "object_id": "object-001",
      "embedding_model": "BAAI/bge-small-zh-v1.5",
      "metadata": {
        "chunk_index": 0,
        "start_char": 0,
        "end_char": 800
      }
    }
  ]
}
```

## 失败与维度处理

`B1_MODEL_NOT_READY`、`B1_BUSY`、`B1_EMBEDDING_TIMEOUT` 和 P2 gRPC 暂时不可用被 B2
视为可重试错误，Celery 最多重试三次。其他 B1 协议错误、无效向量和存储错误会将任务
标记为 `FAILED`。

B1 默认模型产生 512 维归一化 FP32 向量。P2 E1 collection 名称包含实际向量维度；启用
Milvus 投影时仍必须同步调整 `AETHER_B2_VECTOR_DIMENSION`，已有 Milvus collection 的
schema 不能改变维度。
