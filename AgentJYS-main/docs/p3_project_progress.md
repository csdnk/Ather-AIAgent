# P3 项目进展跟踪

## 2026-07-19 融合状态同步

P3 已与同仓库中的 P2 Rust 存储基座完成最小 gRPC 联调闭环：P3-B1 可将测试向量写入 P2-E1，P3 可将对象写入 P2-E2，随后完成 B2 Context Pack 和 B3 调度决策。Docker Compose 提供命令行 `demo` 与浏览器 `dashboard` 两种验证入口，浏览器页面可显示五段内部处理数据、评分和执行反馈。

当前常驻闭环的 B3 执行器为 `P2MigrationExecutor`：`promote`/`prefetch` 会调用 P2 SegmentControlService，完成冻结、逻辑路由提交、route epoch 更新和幂等反馈。该闭环不包含对象字节搬运，因此仍不代表真实物理迁移已经完成。使用方式见 [Web 联调仪表盘使用说明](WEB_DASHBOARD.md)，接口边界见 [P2/P3 融合架构与验证](INTEGRATION.md)。

## 2. 项目概览

当前整体状态：**黄色——本地 MVP 闭环已完成，准真实联调和生产验收尚未开始。**

已经形成可运行的 B1 → B2 → B3 链路：B1 支持 Mock 和 CPU 真实 Embedding；B2 支持三层记忆、身份隔离、Context Pack、会话归档和 SQLite 持久化；B3 支持 Heuristic 评分、动作生成、P2 控制面执行反馈、跨重启幂等和 Keep 回退，Mock Executor 仅保留给隔离测试。

当前结果可以证明接口与策略闭环可运行，但不能证明 4K QPS、Redis/Milvus/Celery 分布式能力、P1/P2 真实物理迁移收益以及最终召回/压缩指标。

## 11. 更新规则

1. 任务状态变化时同步更新任务表，不只在聊天或会议中口头确认。
2. “已完成”必须附 commit、测试结果、接口回执或评审结论，只有代码不算完成。
3. 出现外部阻塞时填写依赖方、影响、跟进人和期望解决时间。
4. 修改 Signal、Action、Feedback 或 Context Pack 字段时，同步更新 Schema、测试和本文档。
5. 修改 Heuristic 权重或阈值时提升 `policy_version`，保留旧策略回放结果。
6. 每次合并前运行 pytest、ruff、mypy 和相关闭环冒烟。
7. 每周至少更新一次“项目概览、当前任务、依赖阻塞、验证记录”。
