# 02 三流程接入与责任表

2026-09-20基线更新：当前按PRD V1.3开发，见[基线与租户增量](../../../contracts/p3/prd-baseline.yaml)。下文V1.2条款及批次说明保留原出处，不代表当前仍采用旧版本，也不证明V1.3增量已经实现。

## 职责与代码归属

| Owner | 修改区域与交付 | 首先消费的公共能力 |
|---|---|---|
| B | remember/，领域Repository、LangMem、文档获取/解析、生命周期、压缩、投影资格 | TrustedContext、UoW、TaskHandler、EventPort、DiagnosticsPort |
| A | recall/，ContextPack、Embedding/向量适配、来源与预算规则 | TrustedContext、UoW、MemoryReadPort、EventPort、DiagnosticsPort |
| C | operate/，输入视图、策略、动作Journal适配、Provider与对账 | UoW、TaskHandler、EventPort、MemoryReadPort、DiagnosticsPort |
| RF | runtime公共机制、Host装配、部署和交付校验 | 各流程注册的Handler及端口实现 |

模型与端口只在Owner目录定义，公共封套由RF维护。依赖锁、Host、公共契约和CI由RF整合；各组提交小变更与消费者样例，不直接抢改同一工作目录。其余两人不在本轮关键路径分配，但可在后续承担独立交叉验收。

## B：Remember接入次序

1. Source/MemoryVersion/指针及来源依赖Repository使用RF UoW；先完成保存、显式更正、归档和删除资格。
2. 实现MemoryReadPort：精确版本与来源、Working、历史、final_guard。A/C只能通过这些读取业务事实。
3. 实现DocumentReader.acquire/parse与LangMem ExtractionPort，保存不可变输入和形成批次；空候选合法，伪造证据拒绝。
4. 接入A的EmbeddingPort/VectorPort；B保存分块清单、核验全部块和正文后判断ready。
5. 实现压缩Artifact与质量门禁，保留原始证据和实际字节统计；失败不能被排除出评估。
6. 为提取、解析、压缩、投影、清理注册run/recover；每次远端调用前和本地提交前复核授权、版本、来源和lease。

验收：FR01～FR07、FR17及相关恢复；不能以“公共层会重试”替代删除屏障或正式提交幂等。

## A：Recall与共享能力接入次序

1. 实现统一Recall入口、来源选择、截止、幂等与状态查询；Agent工具复用同入口。
2. 验证真实Embedding与Milvus，固定模型/预处理/tokenizer和Query/Passage配额；Provider不回零向量伪成功。
3. 接B的Working/长期正文/资格接口，按memory版本去重，保留同文独立来源和完整冲突。
4. 按完整组、固定tokenizer计入所有渲染文本；结果只在最终同事务Guard+Pack+事件提交后发送。
5. 实现历史Pack重新获取资格检查；原结果失效返回410，不在GET中重新检索。
6. 接入查询、候选、读取、packed、delivered记录；重启有提交保留、无提交结束，不能无条件续跑短请求。

验收：FR08～FR12及共享机制、质量/性能边界；Recall负责人承担端到端交付正确性。

## C：Operate接入次序

1. EventPort.consume将Inbox与输入视图、水位、评估任务一起保存；覆盖存储和读取两侧。
2. 基础策略输出promote/demote/keep/defer；相邻层级、容量、主流程保护和确定规则可解释。基础算法的正式规则集与负载是MVP前门禁，不能拿工程阈值冒充产品最优策略。
3. 持久Action意图和跨版本目标fence；执行前读取当前B资格与Provider资源。
4. 接真实ExecutorPort；成功需要原动作反馈、正确目标及verify_read，模拟Adapter仅用于故障测试。
5. Unknown查原ID，boot/实例变化时不猜结果；目标生效和旧副本清理分别记录。
6. P1预测复用同一约束和执行链，度量先预测、先准备、后访问，失效回退基础策略。

验收：FR12～FR14、FR16后续阶段；不得通过单条人工调度或模拟效果替代自动实际执行。

## 每次交接的完成条件

提供方提交代码、正反样例、错误和恢复行为、真实依赖状态；消费方用相同样例验证。每日集成结果比各组各自“完成”更重要。接口破坏性变更同步模型、Schema、目录、消费者测试与需求追踪，不由公共层默默兜底。
