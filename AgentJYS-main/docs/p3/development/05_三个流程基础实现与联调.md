## 实际能做什么

| 流程 | 本批代码 | 可运行能力 |
|---|---|---|
| Remember / B | `remember/basic/service.py` | 保存文本与来源、Working记录、持久提取任务、派生Episodic记忆、投影任务、显式纠错、归档/恢复、逻辑删除、来源删除、精确读取与最终资格核验 |
| 提取适配 / B | `remember/basic/extraction.py` | 默认逐字保存为事件记忆；另提供LangMem Core候选适配器，可注入真实manager/model，不自动更新或删除正式记忆 |
| Recall / A | `recall/basic/service.py` | 统一入口、来源选择、截止、状态、Working与长期候选、RRF、按记忆版本去重、完整条目预算、ContextPack、历史结果重新核验 |
| 检索适配 / A | `recall/basic/adapters.py` | SQLite持久投影与精确绑定校验；默认使用原生BGE，词法适配用于显式测试；另有milvus.py适配器 |
| Operate / C | `operate/basic/service.py` | 消费存储及实际读取事件、持久评估任务、相邻层级规则、动作日志、未知结果原ID对账、周期重查、缓存清理 |
| 执行适配 / C | `operate/basic/executor.py` | 真实本地文件复制、目标读取校验、独立动作数据库、动作收据、容量/epoch检查、删除版本屏障；不改权威正文 |
| 装配 / RF | `runtime/flows/host.py`、`__main__.py` | 注册全部Handler和事件消费者、统一Worker、命令行业务入口及状态查询 |

任务、Outbox、Inbox、Delivery、身份、事务、追溯与恢复均使用已有`runtime/foundation/`。没有为三流程各建私有队列，也没有改动旧v1服务路由。

## 真实与基础适配的边界

- 默认提取器`LiteralExtraction`将用户原文保留为Episodic事件，不声称理解了偏好，也不自动生成Semantic事实。Working原文与长期事件使用不同memory_id，来源可追踪。
- 默认原生BGE中文模型生成512维语义向量，SQLite保存投影并检索。`--embedding-profile lexical`显式启用词法测试替身。Milvus由Recall配置启用，不能在依赖失败时静默切回本地。
- 当前使用真实tokenizer计算整个rendered_context，默认 `o200k_base`，包括编号和换行；旧字节预算不再用于当前Recall。接收模型变化后须校准tokenizer；下游模板和回答预算另留。
- LocalCacheExecutor的`provider_mode=real`表示确实复制并读取验证文件。cold/warm/hot是同一本地根目录下的文件夹，不代表三种真实物理介质，也不是PRD生产调度验收。Remember的SQLite正文始终保留。
- LangMem适配代码已交付，但本轮未安装/调用真实LangMem模型。测试使用manager替身校验输入输出和来源边界，不能当成真实模型实验。LlamaIndex检索分层、Controller当前状态对账模式作为实现参考，没有引入完整Query Engine或Kubernetes CRD。

## 一键演示

从仓库根目录，使用Python 3.13隔离环境：

```text
python -m pip install -r scripts/p3/requirements-native.txt
python scripts/p3/demo_flows.py --directory <新的运行目录>
```

演示自动执行：写入“无糖咖啡” → Worker形成长期事件和投影 → 自动进入warm缓存 → 跨会话范围召回 → 实际读取事件驱动hot缓存 → 纠错为“红茶” → 旧ContextPack失效 → 删除 → 新召回为空。

指定目录中保存`p3.db`、`cache/`、`demo-credentials.json`和`evidence.json`。生成两租户各两用户的随机工程凭证，程序不打印凭证；目录须在仓库外并限制访问。已有目录不会被覆盖。演示结束后的目标记忆已删除，这是演示步骤，不是系统丢失数据。

## 手动运行

先运行演示初始化工程身份，或沿用公共底座的`configure --identities`命令配置身份。PowerShell环境示例：

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$runDir = 'E:/p3-three-flow-demo'
$demoKeys = Get-Content (Join-Path $runDir 'demo-credentials.json') -Raw | ConvertFrom-Json
$env:P3_API_KEY = $demoKeys.alice
```

下列命令中的全局参数均为同一个数据库及缓存目录：

```text
python -m aether_agent_memory.runtime.flows --db <p3.db> --cache-root <cache目录> --operation-id save_001 remember --text-file <UTF-8文件> --session-id session_a
python -m aether_agent_memory.runtime.flows --db <p3.db> --cache-root <cache目录> worker
python -m aether_agent_memory.runtime.flows --db <p3.db> --cache-root <cache目录> task --task-id <Remember回执中的提取任务ID>
python -m aether_agent_memory.runtime.flows --db <p3.db> --cache-root <cache目录> --operation-id recall_001 recall --query 咖啡 --sources long_term
python -m aether_agent_memory.runtime.flows --db <p3.db> --cache-root <cache目录> actions
```

`worker`持续处理任务、投递事件并周期重查；测试时可用`worker --drain`等待当前待办收敛，不启动周期新任务。Operate没有独立用户调度入口。`actions`只读取经过授权的动作记录，不执行对账或新动作。

Remember回执先返回Working记忆；通过`task`结果中的`memories`找到生成的长期记忆ID。新输入使用新operation_id；重试同一请求保持operation_id和内容不变。调用Python服务时，SourceInput也是请求内容，重试应原样复用。CLI会复用原操作生成的来源时间，避免重试自动生成新时间导致指纹冲突。

继续使用`memory`获取当前version/object_revision，再通过`correct --version`、`delete --revision`或`lifecycle --version --target archived|active`执行受控修改。完整参数使用对应命令`--help`。`result --recall-id`重新核验原Pack，失效返回RESULT_INVALIDATED，不静默生成新结果。

## 数据与异常行为

### Remember

输入、来源、Working记忆、提取Task和memory.changed在同一SQLite事务提交。提取在事务外执行，回到事务后再次核验任务租约、版本、删除与来源，然后原子提交整批候选、投影待办和结果。

提取候选不能指定正式ID、版本或租户。基本LangMem适配只接受原文中的精确引文，且候选文本必须是引文子串；不支持在此阶段将未经核验的概括直接作为正式事实。候选为空合法，最多32条，批次提交不能重复形成第二组记忆。

纠错递增正式版本，旧向量可能暂时存在，但返回前必须通过B的当前版本核验。纠错或删除某条长期记忆会阻断包含旧文字的Working原文；其他独立派生事实不自动改写。删除整个Working记录则阻断其相关派生事实。删除来源则阻断所有依赖该来源的当前记忆。

删除回执准确区分“业务已阻断”和“清理完成”。向量及缓存通过任务清理；源正文和历史证据的保留政策尚未实现最终物理擦除，因此回执保留pending/remaining_targets，不能宣称已完成全介质删除。投影恢复先查询原绑定，已确认的外部写入不能记为“没有效果”。

### Recall

`auto`在有session/task限制时选择Working＋长期，否则选择长期；显式selection始终是范围限制。需要跨会话检索时不指定session限制，由服务端身份限定租户、用户、Agent。当前自动发现不扩展到其他用户共享数据；授权对象的精确读取与广域共享检索是不同能力。

默认每路取20个排名候选；长期检索遇旧向量挤占时有界扩大到最多100个发现候选。按范围内memory_id＋version合并并使用从1开始的RRF名次；可配置CrossEncoder重排序。默认最终最多5个完整条目。过长条目跳过后继续尝试后续条目；所有候选都放不下返回BUDGET_TOO_SMALL。Working扫描超过本批上限时标partial，不假称完整。

Recall记录实际阶段；已读取正文的记忆发布read事件，即使最后没有进入Pack。read使用稳定access_key去重，packed不重复计热。耗时是对应批量正文读取的实际耗时，用于追溯，不在本批作为指标门禁。Pack与packed事件在最终授权/有效性Guard后原子提交；传输交付尚无HTTP确认，所以不伪造delivered事件。

长期检索依赖失败时，有合法Working结果则明确degraded；没有有效来源时返回失败，不能伪装empty。已提交Pack可在重启后重新核验取回；未完成短请求到期后标failed，不跨重启续算旧请求。

### Operate

事件只触发重新检查。C可靠保存输入水位和评估任务后由Inbox确认，消费重复事件不重复计热。首次有效记忆从cold到warm；观察到成功读取后从warm到hot；当前版本没有读取而处于hot时允许退到warm。规则是基础可解释策略，不声称业务最优或RL收益。

意图先入P3动作日志，再调用执行端。执行端先保存action_id与完整意图，再复制文件、校验目标、保存独立收据，最后清理原缓存文件。响应丢失时保持Unknown，恢复只查询原action_id。执行端实例或历史丢失时不假设成功；有限查询后需要处理。

删除缓存时先持久化版本屏障，阻止旧任务重新写回同一已删除版本。旧归档事件不能清理当前已经重新激活的版本。Task的succeeded只表示Handler已处理并保存结果，业务Action仍可能是failed/cancelled/unknown，使用方必须读取业务状态。

## 四位负责人接下来从哪里修改

| Owner | 保留的边界 | 下一批主要工作 |
|---|---|---|
| B | 来源/版本/生命周期/最终Guard，ExtractionPort | 真实LangMem模型验证、文档获取解析、Semantic分类、冲突及压缩质量规则 |
| A | Recall编排、EmbeddingPort/VectorPort、ContextPack | Milvus真实联调、下游模型tokenizer校准、冲突组组织与检索质量；Embedding/重排序/预算代码已接通 |
| C | 事件消费、决策、Action与对账 | 将本地缓存prepare/purge扩展拆为明确Provider能力，接真实P2存储与生产资源观察，不把目录复制当生产分层 |
| RF | 共享事务、任务、事件和身份 | 正式HTTP Host、跨网络追踪及OTel导出、外部持续检测、容器/Azure部署和备份恢复 |

ThreeFlows支持注入ExtractionPort、EmbeddingPort、VectorPort、reranker、tokenizer及服务端配置。默认使用原生Embedding和SQLite；不在真实适配失败时静默回退。LocalCacheExecutor的ensure/purge是本地profile扩展，不是偷偷扩展既有ExecutorPort契约。

接入只读Recall时，公共层按Host注册的Handler/事件权限策略校验，不要求调用者拥有memory:write。这些策略只能由可信装配代码注册；对外save/correct/delete仍分别校验WRITE/CORRECT/DELETE，调用者不能自行指定后台任务权限。
