# CI 检查与复验

更新：2026-10-04。当前唯一依赖定义为 `pyproject.toml` 的 runtime、extras 与 dev group；保留 `scripts/p3/requirements.txt` 仅供独立契约环境。旧分项 requirements、旧 RF/协作验证脚本和嵌套 `.github` 已退役。

## 检查分工

| 实际入口 | 执行内容 | 证明范围 |
|---|---|---|
| 根 `.github/workflows/ci.yml` / python | Ruff、严格 Mypy、Schema drift、wheel 构建 | 源码与包可检查，不宣称真实依赖业务通过 |
| 根 `p3-contracts.yml` | 独立 P3 契约与需求追溯检查 | 字段/接口/样例一致，不等于产品验收 |
| 根 `p3-azure-tests.yml` | reviewed SHA 在独有 AKS Pod 执行 pytest | 真实 PG/Redis/Milvus/Ceph、test-owned Temporal 和 BGE；依结果判定 |
| 根 ci / web、rust | Web lint/test/build；Rust fmt/test | 各提供方的实际检查结果 |
| `azure-pipelines.p3.yml` | Python 源码与契约 | 不因运行在 Azure Pipelines 就称 AKS 服务已发布 |

GitHub Azure 任务需要 `azure-tests` environment 和三项 Secret，从 [当前开发者入口](../../../README.md#快速启动) 阅读完整 AI 环境指南与配置步骤。手动任务必须指定完整 40 位提交号；不要让未审查分支自动获得后端凭据。

## 本机静态复验

在独立 Python 3.13 环境、`AgentJYS-main` 工作目录执行。所有输出指向仓库外：

```powershell
python -m pip install --upgrade pip
python -m pip install -e . --group dev
python -B scripts/generate_proto.py
python -B -m ruff check src tests scripts
python -B -m mypy src --cache-dir <外部缓存目录>
python -B scripts/p3/generate_schemas.py --check
python -B -m pip wheel --no-deps --wheel-dir <外部wheel目录> .
```

Proto 来自保留的 `engine/proto/aether_engine.proto`，检查前生成 Python 绑定，生成文件继续 Git 忽略。Mypy 必须读取本目录的 `pyproject.toml`，否则会漏掉 Pydantic 插件和 generated/第三方边界设置。

## 真实 Azure 回归

使用 `scripts/p3/prepare_aks_test_assets.py` 在外部目录准备 BGE ONNX、分词缓存和固定版本 Linux Temporal CLI，补入团队公有 Milvus CA；用 `scripts/p3/run_aks_tests.py` 传入个人 kubeconfig、私密环境 JSON 和分配的 namespace。pytest 在 AKS 内运行，启动专用 Temporal development server，连接真实 Azure 后端。

正常返回必须包含实际执行的 JUnit、源码哈希未变、退出码 0、无 failure/error、默认零 skipped。OOM、连接失败、collect-only 或缺少 JUnit 都不能算通过。重型模型和完整回归串行执行。

默认 Azure 测试明确排除 `test_current_p2.py` 与 `test_web_gateway.py`，因为它们需要独立的外部 Rust P2/Nginx 环境；保留接口测试，单独配置并记录未运行。不能以 ignore、skip 或旧 SQLite 结果填补这个范围。

崩溃恢复继续保留真实子进程和原任务回执检查，元数据改为真实 PG；原 operation/job 身份及 Temporal deployment 绑定保持稳定。取消旧数据迁移不等于取消当前任务恢复。不要用清库、换 UUID 或固定亚秒等待代替恢复证明。

## 工作流验证与结果报告

工作流改动应检查 YAML、GitHub 表达式和实际 job 结果。`actionlint` 静态检查、模板解析与线上运行是不同证据。远端报告列出准确 SHA、job 名称、通过/失败/未运行项；不得用其他提交的通过替代当前提交。

正式报告保留结论、重要失败和限制；原始安装日志、pytest/JUnit、检查 JSON 与过程脚本放仓库外。分支保护和必需检查由维护者设置，本文及 YAML 不作为规则已生效的证明。
