# CI 检查与复验

日期：2026-09-23。全仓 CI 与 P3 协作门禁检查范围不同，必须分别确认运行结果。

## 依赖与入口

所有 Python 命令从 `AgentJYS-main` 执行，使用 Python 3.13。

| 工作流 | 安装清单 | 检查内容 |
|---|---|---|
| p3-contracts / p3-foundation | requirements.txt | 契约和 RF 检查 |
| p3-native-embedding | requirements-native.txt | 原生适配契约及异步失败用例，不下载真实模型 |
| p3-flows | requirements-flows.txt | 流程、HTTP、示例及契约回归 |
| p3-collaboration | requirements-collaboration.txt | 完整 P3 协作门禁 |
| ci / python | 项目自身 + requirements-ci.txt | 全仓 Ruff、严格 Mypy、Pytest，包括既有集成测试 |

清单位于 `scripts/p3/`。分项清单必须独立安装完整，不能依赖其他 job 或开发机已经装过的包。根目录 `.github/workflows` 是完整工作区的 GitHub 入口；`AgentJYS-main/.github/workflows` 保留独立源码检出的对应入口，修改时同步两套配置。

## 全仓 Python 复验

```text
python -m pip install -e . -r scripts/p3/requirements-ci.txt
python scripts/generate_proto.py
python -m ruff check src tests scripts benchmarks
python -m mypy src
python -m pytest -q
```

Proto 以 `engine/proto/aether_engine.proto` 为来源，在检查前生成必要 Python 绑定；生成文件保持 Git 忽略。可选 CrossEncoder 模型包只有第三方类型边界单独处理，业务源码仍保持严格类型检查。

全仓 Pytest 包含 Docker Compose 集成测试。运行前需要可用 Docker daemon 与 Compose，并可通过 `COMPOSE_PROJECT_NAME` 指定独立测试项目以隔离本机其他容器。该测试会构建示例容器、运行闭环并清理自身资源。无法运行 Docker 的本机应明确记录未执行项，不能把部分测试称为全仓通过；GitHub CI 保留该项，不删除或跳过。

## Rust 与工作流

```text
cd engine
cargo fmt --all -- --check
cargo test --workspace
```

Rust 格式检查通过不等于 Cargo 测试通过。格式失败会阻止后续测试，修复后必须继续执行全部步骤。

修改 GitHub 工作流后，在仓库根目录和独立源码目录分别运行 `actionlint`。例如 `runner.temp` 不能用于 job 级 env；缓存路径通过 step 中的 `RUNNER_TEMP` 写入 `GITHUB_ENV`。本地 YAML 解析成功不能代替 GitHub 表达式上下文校验。

本地运行的环境、缓存、测试数据和原始日志保存在项目外。报告应同时列出本地结果、远端提交号和各 job 结果，不能以历史提交或其他检查的通过代替当前提交的结果。
