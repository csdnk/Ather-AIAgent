# 01 协作接口与事件目录

## 权威定义与交接方式

Python模型是字段来源；各领域`ports.py`是同进程调用契约。完整方法、提供方、消费方、签名、样例ID见 [interface-catalog.yaml](../../../contracts/p3/interface-catalog.yaml)。该目录由对实际Protocol的核对维护；签名变化未同步时自动校验失败。

HTTP适配映射见 [http-api.yaml](../../../contracts/p3/http-api.yaml)，是待实现接口说明，不表示现有FastAPI已注册。当前实际 `/p3` 路由与早期 `/api/v2` 目录应区分，Remember 的已接入接口见 [remember-live-http.yaml](../../../contracts/p3/remember-live-http.yaml)。本次冷热地址改造不新增外部 HTTP 接口或改变请求/响应字段。所有接口参数由Host验证，内部TrustedContext不能直接从客户端JSON反序列化后当作授权结论。

| Port | 交付者 → 消费者 | 调用与提交边界 |
|---|---|---|
| IdentityPort | RF → 所有流程 | authenticate在事务外校验凭证；authorize/revalidate在本地最终事务查当前授权 |
| UnitOfWork / Transaction | RF → B/A/C | get、分页、CAS写入与受控移除；创建使用expected_revision=null，更新使用当前revision |
| TaskPort / TaskHandler | RF ↔ B/C | register为启动装配；enqueue/complete同业务事务；run/recover外部I/O不占事务 |
| EventPort | RF → B/A/C | append同业务事务；consume将Inbox与效果/待办一起提交；返回false表示已去重，不表示失败 |
| DiagnosticsPort | RF → 流程/Host/部署维护 | 事实关联写入同事务；技术日志另行采集；跨scope对象不可枚举 |
| RememberPort | B → Host | 保存、查询、更正、归档/恢复归档、删除及源删除；业务ID由B确定 |
| MemoryReadPort | B → 既有读取消费者 | 保留同步读取、来源、历史及资格能力；当前 generation Recall 的候选/冲突正文不再经旧同步 load 提前回源 |
| MemoryFoundationPort.load_bodies | B → A及其他正文消费者 | 精确版本正文读取；先合法热地址后权威地址，读前/读后核验；成功返回实际 path/location，不回填缓存 |
| RecallBodyReadPort.load_recall_batch | B → A | 候选加载及冲突补读；返回正文快照、逐项资格和冲突关系，拒绝重复引用，整个批次受请求期限约束 |
| ExtractionPort | B适配 → B Worker | LangMem候选输出；不直接写正式记忆 |
| DocumentReaderPort | B适配 → B | acquire核验指定版本并持久接收；parse读取已保存原文件 |
| RecallPort | A → Host | 统一recall、状态、原结果再取；再取不隐式新建请求 |
| EmbeddingPort | A → B/A | 单Query，多Passage；输入摘要、维度、索引和空间绑定；有限配额 |
| VectorPort | A → B/A | project/inspect/delete/search；不写B的ready；删除查询允许unknown |
| SchedulingPort | C → 内部Worker | 消费、判断、执行、对账；不向终端用户公开 |
| ExecutorPort | C契约/Provider实现 → C | resources/submit/query/observe/verify_read；新状态与真实读取都必须核验 |

## 公共错误与超时

当前正文接口的完整说明见[冷热地址读取契约](../development/17_Recall冷热地址读取契约.md)。`CacheLocationReader.read_location` 是 Runtime 注入的内部只读存储能力，不是 Agent 要调用的新 HTTP 接口；它复用已配置 Redis，不从地址记录连接任意服务器。普通读取不负责 Operate 的准入、续期或地址修复。

所有服务端口的失败使用统一错误语义，HTTP层映射ErrorResponse；不把错误返回为缺省空列表或布尔成功。协议中`-> None`仅表示无需返回业务正文，不表示可以吞异常。服务实现不得直接实例化Protocol当作实际服务。

TrustedContext保存本次操作截止；计算与向量请求不得传更晚截止扩大预算。纯本地读取受外层截止控制；网络Provider以ctx.deadline_at为上限。未知结果按原operation/action查询，不能让RF、SDK和领域层各自无限重试。

读批量结果的EligibilityBatch必须与输入MemoryRef逐项对应，无重复/缺项；主体验证通过才可加载正文。跨对象列表均经过当前授权过滤。分页游标绑定授权范围、过滤条件和排序，不能由客户端更换范围继续使用。

## HTTP约定

统一前缀`/api/v2`，使用Bearer接入凭证；新接口尚未安装到Host。Remember提交、更正、生命周期、删除和Recall POST要求Idempotency-Key；键绑定当前principal、tenant、method、规范路径及请求指纹。同键异内容409，同键处理中409；完成的重复Recall返回原处理引用，通过受控result获取，不能重放失效正文。

Remember 202回执中的saved=true必须已有可靠原内容和来源；它不表示加工或检索ready。文档获取不能确认持久保存时不得返回成功回执。查询操作与删除清理分别报告业务事实，不造一个聚合绿色状态。

状态查询不默认附带敏感正文；`GET /recalls/{id}/result`重验所有原条目和冲突组，失效返回410 RESULT_INVALIDATED，不悄悄返回新的结果。history要求memory:history；被删除正文不通过history泄露。共享的授权来自服务端Grant，不接受客户端自报共享权限。

API约定中的`object:read`代表查询底层目标的对应读权限；它不是一个新产品角色。任务和操作查询应返回经过裁剪的状态数据，不暴露TaskSpec中的内部凭证或未经授权的输入。维护操作使用部署命令或内部受保护入口，不在对外API目录新增管理员/调度端点。

## 事件与关联

事件类型和载荷模型见 [events.yaml](../../../contracts/p3/events.yaml)。EventEnvelope固定p3/1；event_id永久绑定相同规范载荷指纹；投递可重复，消费效果按consumer+event_id去重。事件封套的subject.scope、payload中的MemoryRef和生产方必须一致，由事件消费者契约校验；不能只通过通用dict结构即认为合法事件。

`memory.changed`覆盖saved/corrected/archived/activated/expired/deleted/processing/projection_ready/projection_stale/artifact_ready。`recall.access`区分candidate/read/packed/delivered，单次读取事实使用稳定access_key。`operate.action_changed`推进观察视图，不无限自触发相同动作。

可执行交接校验示例见 `scripts/p3/event_contract.py`，它只校验契约，不实现投递或消费。Pydantic的frozen配置不等于嵌套容器深度不可变或数据库记录不可变；正式生产、持久化与消费边界仍须重新校验规范指纹、主体绑定及当前权限。

request_id标识一次调用，operation_id标识幂等业务处理，task_id标识持久待办，attempt标识执行尝试，action_id标识固定外部动作；trace_id/span_id遵循W3C格式，不能用于授权或业务去重。追踪跨任务可以使用Span Link，不强求一个跨小时根Span。

## 变更程序

提供方先改自有模型/Protocol，消费方补正反样例；重新生成Schema、更新方法目录、事件/HTTP映射与文档；校验通过后才合并。字段删改、语义变化或不兼容枚举扩展需要新major或明确适配；不静默接受未知字段。测试期schema_version=p3/1，旧p3-demo/1不自动视为兼容。
