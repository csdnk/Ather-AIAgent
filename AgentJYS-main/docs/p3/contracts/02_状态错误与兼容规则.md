# 02 状态错误与兼容规则

## 状态是不同对象的事实

| 对象 | 约束 |
|---|---|
| Memory | active/archived/superseded/expired/deleted；状态改变不等于类型或物理层级改变 |
| Projection | not_required/pending/building/ready/failed/stale；B唯一判定ready |
| Task | pending/running/retry_wait/recovery_wait/succeeded/failed/cancelled/attention_required |
| Recall | accepted/running/completed/failed；结果available/empty/degraded，失败走错误通道 |
| Action | generated/submitted/succeeded/failed/unknown/cancelled；Keep/Defer不生成动作 |
| Delivery | pending/sent/retry_wait/acknowledged/attention_required；sent不代表消费效果提交 |

可允许的基础状态边在各领域`contracts/rules.py`维护。允许一条边只说明转换候选合法，仍须执行以下Guard；不允许把状态图测试当作运行状态机已完成。

| 转换 | 必需证据 / Guard |
|---|---|
| pending/retry_wait → running | 当前授权、未到期、原子配额、领取新lease_token与attempt |
| running → succeeded | 同事务required_outputs和领域结果已存在、当前租约有效、当前版本仍合格 |
| running → recovery_wait | 租约失效或外部结果未知；不能同时让旧worker继续有提交权 |
| recovery_wait → retry_wait | 领域证明允许重做，副作用不是unknown，执行预算剩余 |
| recovery_wait → succeeded | 原结果及提交身份已查证，不重复生成结果 |
| unknown Action → succeeded | 原action反馈、实例、目标层级、版本、hash、可读证据一致 |
| unknown Action → failed | 原操作被确认失败且部分效果已说明；超时/404不充分 |
| active → archived | 当前版本CAS；退出默认资格，保留受控历史 |
| archived → active | 显式授权恢复归档、来源/TTL仍有效；不从deleted/expired恢复 |
| running Recall → completed | 最终事务复核、预算、完整组及Pack/packed提交 |

Task终态不可通过人工按钮擦除后重跑。需再次尝试时创建关联恢复操作及新的任务，保留原预算与错误。Action Unknown保持原ID和fence；基础阶段不提供强制释放未知fence功能。

## 重试与恢复返回

RecoveryDecision为resume/query_only/cancel/fail/attention，必须附证据引用。unknown只允许query_only或attention；query_only必须标识原操作。RunResult.committed代表Handler已经通过同一UoW提交领域结果与Task终态，RF不得随后再开事务“补写成功”。

如果旧任务授权不再允许新业务，返回cancel；若已产生未知副作用，不能cancel掩盖结果，应移交受限维护查询。有限重试耗尽时明确无效果的任务可failed，未知效果进入attention；不能按“次数到上限”判定外部失败。

## 错误映射

详细枚举和HTTP状态见http-api.yaml。401认证失败；403显式范围/操作拒绝；404对象不存在或不可见；409版本/幂等/处理中冲突；410记忆失效或原结果失效；422参数或全组超预算；429配额；503依赖/提交不明/执行中断；504截止；500契约不变量错误。

available要求选定来源完成且无语义/正文缺失，empty要求合格内容确为零；degraded须有可信完整材料和原因。来源未知、加载失败、全部超长不能包装成empty。正常预算裁剪不是来源故障；冲突组不能拆开裁剪。

## 旧接口兼容

本轮不修改已有v1路径、既有Scope类或旧状态枚举。新增契约显式位于各流程contracts子包；旧实现需由Adapter转换并完成测试后才挂到新Host，缺少身份、版本或来源不得补造合法值。

原外置基线中的p3-demo/1、仅cache的Action、无archived状态及元数据-only的结果查询，与本版并非自动兼容。原数据不就地升级；下一阶段新配置/数据库独立初始化，经授权验证后再导入必要原输入，不搬运未验证旧状态。代码回退与数据回退分开设计。
