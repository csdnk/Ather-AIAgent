## 产品边界

外部应用与Agent使用同一Remember和Recall业务接口。更正、删除、归档、查询是配套操作。Operate消费存储和召回的历史与当前状态，自动决策、执行、核验及反馈；不要求调用方调用第三个调度功能或提交模型采用回执。

P0包括FR01～FR15、FR17、FR18；FR16预测与预测预热为P1。长文本／获准文档引用、归档、稳定事实与冲突、提纯压缩、显式共享授权、历史上下文重新获取都保留。P3不生成最终答案、不建设数据库内核、不建设独立Web后台、RBAC角色平台或身份／审计平台。

## 实施批次与产品阶段分开

当前用户明确优先搭建系统，产品指标暂不考虑。下表M1/P1/Final是PRD后续目标，不是当前开工前置条件；F1不因性能、压缩比例或长稳时长未达标而阻塞，仍要证明功能边界与正确性。

| 实施批次 | 交付 | 不代表什么 |
|---|---|---|
| D0 本轮 | 总体设计、契约模型／Protocol、Schema、样例、校验、代码改造清单 | 不代表业务恢复或产品接口已运行 |
| F1 基座 | 身份、事务、任务、事件、追溯、检测、恢复和受控维护工具；样例演练 | 不代表提取质量、真实检索或实际迁移通过 |
| B1 三流程 | 真实保存、长文、提取、压缩、召回、事实维护和自动实际调度 | 不自动代表全部性能或长稳通过 |
| M1 MVP验收 | P0完整结果、指标、故障与至少24小时稳定运行 | 不代表P1预测与Final纳管完成 |
| P1 预测 | 实际预测收益和回退 | 不能用访问后准备冒充提前命中 |
| Final | 环境纳管、发布恢复、完整材料及72小时稳定运行 | 不能只拿Pod存活作为业务可用证据 |

上述批次是工作安排，不修改PRD第13章阶段日期。已有八天学习和十天Demo是内部估计，不能代替PRD的产品验收或承诺固定完成日期。

## 需要修正的历史限制

| 历史方案 | V1.2下的正式设计 |
|---|---|
| 仅处理短文本 | 同时定义长文本及获准版本文档引用，原内容可靠保存后后台加工 |
| 不支持归档和共享 | 归档退出默认召回；历史读取显式授权；同租户资源共享须有明确Grant |
| 同源内容统一失效 | 维护来源片段与事实依赖；更正定位受影响断言，不无条件丢弃无关事实 |
| Recall结果查询只返回元数据 | 元数据查询与原结果获取分开；原结果重新获取仍经过当前资格检查 |
| Operate外部evaluate／模式切换 | 内部事件和周期触发；维护配置不转成用户人工调度 |
| 模拟cache动作代表完成 | 模拟仅验证协议；真实执行且内容正确可读才算产品完成 |
| 四视图管理页面 | 服务状态、查询、日志、指标及命令行维护；可接已有监测设施 |
| 两小时负载代表交付 | 两小时只作工程预检；MVP24小时、Final72小时 |

## 不预先捏造的验收实值

PRD第14.2要求在相应验收前确定共享范围、内容质量、轨迹保留、算法负载与删除保留规则。这些是明确的发布门禁，不是可以取消的需求。本轮固定机制与保守默认：私有数据默认拒绝共享；显式同租户Grant才开放；质量未通过的候选／压缩产物不投入使用；日志默认无正文；模拟证据不能计入真实执行。数据集、保留天数和目标机器规格由对应接入／效果／部署验证产生，见验收表的阻塞条件。
