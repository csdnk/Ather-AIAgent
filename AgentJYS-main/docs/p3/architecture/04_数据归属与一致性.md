# 04 数据归属与一致性

2026-10-08 更新正文与地址边界。A = Recall / 共享向量能力，B = Remember，C = Operate，RF = Runtime 公共运行底座。原 F1 SQLite 段落保留为本地阶段设计，不表示当前 Azure 使用 SQLite。

## 当前正文与冷热地址的归属

| 数据 | Azure 中的位置 | 读写职责 |
|---|---|---|
| `MemoryRecord` | PostgreSQL 元数据 | Remember 持有版本、状态、来源及正文绑定；Operate 经既有发布流程维护热地址 |
| `body_location` 指向的记忆正文 | Ceph 权威存储 | Remember 公共正文入口读取；热副本失效后仍以此为依据 |
| `cache_location` 指向的热副本 | Redis | 只读已登记且绑定合法的地址；准入、升降温及清理走显式写入/维护流程 |
| 向量与检索引用 | Milvus | 提供候选，不能替代正文或当前授权 |

Recall 不自行绕过 Remember 查数据库：候选与冲突成员用 `RecallBodyReadPort.load_recall_batch`，正式正文用 `MemoryFoundationPort.load_bodies`。两条入口共享 BodyReads 的读前核验、热地址优先、权威回源和读后复核，详见[读取契约](../development/17_Recall冷热地址读取契约.md)。

`cache_location=null` 表示本条记忆没有可消费的热地址，此时不查询 Redis。即使同作用域、同哈希的另一条记忆已入缓存，也不能据此跳过登记。可选缓存字段损坏时允许回源；权威地址、精确版本、状态或来源等主记录校验失败时不能放行。地址中的实例、namespace、完整 scope、正文代次和哈希必须匹配服务端配置与记录，地址不是授权凭证。

普通读取不准入、不续期、不填缓存、不写回地址。Redis 过期或淘汰会造成地址暂时失效，读取安全回源；后续位置维护由管理流程负责。读取期间仅缓存位置改变且正文事实未变时，已核验正文仍可使用；版本、授权、来源或关系变化则必须重新判定。记忆正文和来源原文是不同对象，`SourceAccess.read` 的原文路径不因本次改造而改变。

## 数据所有权与持久边界

| Owner | 记录 | 关键身份与约束 |
|---|---|---|
| B | Source／MemoryVersion／当前指针／Artifact／Projection／来源依赖 | scope+memory_id+version；source_id+source_version+locator；当前指针CAS |
| A | Recall／ContextPack／计算操作／向量目标 | recall_id；model_space+memory版本+chunk；输入摘要绑定 |
| C | 输入投影／Decision／Action／观察／target fence | event水位；action_id不可换载荷；scope+memory_id+表示种类的未决目标锁跨版本稳定 |
| RF | Principal／Grant／Task／Attempt／Outbox／Delivery／Inbox／维护与诊断记录 | auth_epoch；lease_token；consumer+event_id；固定operation_id |

F1 本地阶段以同机 SQLite 作为事实、任务与交接的原子边界；当前 Azure 由 PostgreSQL 承担元数据事务。领域 Repository 通过 RF 事务访问各自命名空间，RF 不集中定义领域表模型。外置正文须先获持久存储证据再引用；Ceph/Redis 与元数据库之间不存在跨库原子事务，发布引用和后续清理需要独立核验与恢复。

## 原子提交点

1. 保存：幂等输入指纹、原内容/来源、基础记忆、加工任务、存储事件。
2. 变更：当前版本/状态、来源依赖失效、任务资格、清理待办、变更事件和必要操作记录。
3. 任务完成：领域结果、required_outputs、Task终态、新任务与事件；使用当前lease_token及revision。
4. Recall交付：当前授权及B.final_guard、最终Pack、终态、packed事件；正文仅在确认提交后发送。
5. 消费：Inbox、领域效果、水位及后续待办；成功提交后才确认Delivery。
6. 调度：不可变Action意图、跨版本target fence与执行任务；远端调用事务外，反馈与状态再次原子提交。

本地 SQLite 配置按进程分离连接，使用 WAL、FULL、busy_timeout 和短 `BEGIN IMMEDIATE` 事务；这些配置不直接套用于 PostgreSQL。RLock 不代表跨进程互斥。模型、正文网络读取、向量查询和长正文处理不得放入元数据事务。事务等待计入请求截止；提交未知时先查原 commit/operation 身份，不能无条件再写。

## 版本、归档、冲突及删除

内容version不可变；revision用于CAS；object_revision是跨版本事件水位，不能互换。相同幂等身份不同规范载荷返回冲突，摘要采用SHA256；JSON指纹统一RFC8785。内容hash不是Memory ID，文本相同也可能属于不同租户或独立来源。

显式纠错创建v+1和新来源证据，旧版本superseded。来源依赖按片段/断言建立；包含过时断言的原始Working/事件片段不能原样作为当前事实召回。存在可分离片段时仅撤销受影响片段；无法安全分离时整段退出默认交付并记录原因，原始证据保留。不得无条件使同一文档中所有无关事实失效。未明确裁决的独立有效矛盾保留ConflictGroup，A完整表达，不凭向量相似度覆盖。

active可归档，archived退出默认Recall；显式history用途且具有权限时可读取归档／被替代版本。恢复归档须复核来源、TTL、删除屏障，不复活expired/deleted，不隐式恢复已被替代的版本。删除永久阻断该对象的新交付；重复删除返回同一逻辑结果，CAS用于防止删除错版本。

来源删除沿依赖图撤销相关片段与产物资格；如果仍有其他来源支持，重新校验后形成可解释的新事实版本，不能直接沿用已经含有被删内容的旧正文。删除前后查询以最终提交事务排序；已发送给客户端的字节无法撤回。原结果再取始终重新核验。

## 投影与产物

Working、Episodic与Semantic均建立向量表示。Working先保存，再由独立remember.project任务处理；向量来源标签memory_source取working或long_term，历史缺标签记录仅按长期解释。working_only限定来源，仍须Query编码、向量查询、索引批次清单核验及交付前重新核验。Working必须限定当前会话或任务；按ID读取获准正文不授予语义召回资格。

当前版本完整索引发布前，projection_state为pending或实际失败状态。未就绪及依赖故障不能报告为正常空，也不能静默退回词法。历史Working通过显式reindex补索引，不重跑提取；更正或摘要改变后撤销旧资格，再为新正文建立索引。

Milvus不是权威正文。目标绑定scope、memory_id、version、chunk_index、model_space及原始input_hash；相同目标不同载荷拒绝覆盖。model_space包含模型权重、tokenizer、Query前缀、池化、归一化、精度与预处理/分块版本。A的verified只证明具体写入载荷和可查询；B在全块证据、正文、来源和当前版本都匹配后设置ready。

失租或删除只能阻止本地提交，不能撤销已在远端运行的调用。迟到写可留下无资格向量，A最终过滤，B继续查询/清理；未知旧写未结束时不能宣布物理清理完成。压缩Artifact另存质量与版本，不替换唯一原始证据，质量失败保留原文可用路径。

## 授权一致性

Scope包含tenant、application、user、agent以及可选session/task；null代表无该具体归属，不代表全范围通配。请求ScopeSelector只能在当前授权中选取；不含tenant字段。服务端验证外部凭证或可信上游，产生TrustedContext。对象所属scope与调用者home_scope可以因显式共享不同，但必须同tenant且存在当前Grant；不能只比较字符串就放行。

授权配置由部署流程维护，不提供成员、角色管理产品。Grant绑定grantee、精确资源、操作、到期和revision。更改凭证权限、Grant、撤权时在同一授权存储推进epoch；final_guard使用当下授权记录。禁止在SQLite事务里等待远程授权服务；将来授权外置须重评一致性边界。

新业务在主体撤权后停止；已提交副作用对账和失效清理由受限维护身份继续，只允许原scope原目标，不输出正文或创建新有效记忆。数据不可查时返回unverifiable/失败，不能把未知伪装为已删除或空结果。
