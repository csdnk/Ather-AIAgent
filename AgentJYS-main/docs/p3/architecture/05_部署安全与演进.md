# 05 部署安全与演进

本页为部署目标与准入规范，不是已上线清单。2026-09-20 当前为单机 Host/CLI、本地 Trace 和依赖探针；Azure/AKS、OTLP/跨 HTTP 传播、生产备份还原尚未验收。当前本地缓存执行为实际文件操作，模拟端仅用于故障测试。

## Azure VM基座

第一步仍为Azure Linux VM容器化单实例。API、Worker、共享计算和Provider分别配置，SQLite为同机持久磁盘；Milvus的etcd、对象存储和数据卷单独持久化并验证备份。现有Compose不是本版最终部署清单，不能照搬缺少持久卷的服务当作可靠存储。

配置和密钥分离；通过部署身份管理凭证摘要与授权范围，不建设登录／角色后台。VM可使用Managed Identity访问支持的Azure资源及Key Vault；模型供应商密钥仍按供应商方式管理。只有必要业务入口对外开放；执行、维护、指标端点走内部网络和运行环境访问控制。

基础测试阶段Provider模拟；MVP必须接真实存储与层级执行，证明目标内容确实可读。真实Provider地址、能力、版本、动作查询和读取协议在接入阶段填写，未获得证据时FR14阻塞，不自动回退为模拟成功。F1不配置公网任意文档抓取；文档源由白名单适配器绑定资源和版本。

## 探针与优雅退出

liveness仅判断进程是否还能工作；readiness反映入口所需能力；完整能力状态分别列出save、working_read、long_term、context、scheduling。一项依赖中断不能无条件关闭独立可用路径。Worker是否允许领取新任务由应用资格控制，不能靠HTTP readiness完成。

SIGTERM后停止领取、限定在途工作退出窗口、在允许时续租和提交；不能强写成功。强退后租约扫描恢复；依赖探测失败先告警、定位，不直接触发重启风暴。详细信号、关闭期限及请求截止由F1配置和测试锁定。

## 可追踪与费用

OTel/W3C关联HTTP和异步尝试，Prometheus指标与Azure Monitor/Application Insights/Log Analytics对接按环境配置。依赖导出服务的失败不影响权威结果保存；导出队列有界，记录丢弃量。请求/记忆/任务ID不作为指标标签；日志默认无正文与密钥。云规格、区域、采集保留与模型费用须以真实配置计量，本轮不填虚构价格或SLA。

## 数据恢复与发布

使用SQLite支持的一致性Backup API或停写快照，避免只复制活跃主文件遗漏WAL。备份位于与运行盘分离的受控存储，记录数据、Schema、配置、模型和授权版本。还原到隔离目录，先校验权限、来源、tombstone、任务和未决动作，再恢复接流量。恢复旧快照后可能缺少新删除或新动作证据；必须具备连续删除/操作记录或进行外部对账，不能以“备份可读”证明业务不会复活。

RPO/RTO在环境验收前明确并实测；进程恢复、磁盘数据恢复和Provider历史丢失分别演练。回滚代码需要兼容当前Schema；数据库采用expand/contract升级。不能为回滚应用随意恢复旧数据快照。

## AKS准入

多副本前迁移PostgreSQL或经过评审的外部事务存储，重新验证事务隔离、CAS、授权屏障、并发领取和目标互斥，不将SQLite文件放共享卷代替改造。Deployment/Service、requests/limits、ServiceAccount/RBAC、NetworkPolicy、探针、优雅退出及滚动升级均有测试。

AKS Workload Identity访问受支持云资源；Namespace和Entra目录不等于业务tenant。扩副本后总Query/Passage、后台资源和Provider调用配额必须受控；API高可用不代表Milvus、Provider或数据备份高可用。
