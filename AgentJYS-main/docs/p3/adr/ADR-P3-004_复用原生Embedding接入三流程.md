# ADR-P3-004：复用原生 Embedding，保持 RF 单一任务权威

状态：已实现并通过真实 ONNX CPU 联调。日期：2026-09-19。

## 问题

仓库已有原生语义推理，但新 P3 默认仍是词法向量；SQLite 投影写死 256 维，无法直接接入 512 维 BGE。旧共享计算服务还包含独立准入和持久执行队列，整套嵌入新 Task 会形成两套执行/恢复权威。

## 决策

新增 NativeP3Embedding 实现现有 EmbeddingPort，复用 NativeEmbeddingBackend 的权重加载、tokenizer、输入前缀、有限值/归一化校验和 CPU 实际占用管理。Query/Passage 独立实例，使用同一指纹化模型空间。运行默认 native，词法模式显式选择。

新适配器直接调用原生后端，RF 保持业务任务、事务和恢复权威；每次计算的尝试记录及后端证据是执行证据，不另建任务调度器。调用前后重新校验身份，计算成功不替代 Remember 返回前的版本/删除/租约核验。

SQLite 向量适配器按配置模型空间及维度执行，现有向量不自动改标。首次本地配置持久化指纹，后续不匹配时拒绝启动并要求显式重建。此绑定只表示本地配置与数据一致，不代替生产模型质量评审。

## 影响与取舍

可以在现有三流程立即运行真实模型，并保留既有日志、健康和恢复机制。仍使用 SQLite 向量检索，后续 Milvus 沿 VectorPort 替换。模型输入超过 512 token 时拒绝，本批没有新增分块策略。Working 排序和 ContextPack 预算保持原规则。

删除被替代的测试身份/存储示例，保留仍被旧入口依赖的兼容模块；新流程不引用 B1 服务，不运行旧计算队列。新增脚本在真实身份/持久化下验证模型指纹、Query/Passage、完整三流程、重启、Trace 和健康。

实施和清理清单见[真实 Embedding 接入](../development/07_真实Embedding接入与旧实现清理.md)。
