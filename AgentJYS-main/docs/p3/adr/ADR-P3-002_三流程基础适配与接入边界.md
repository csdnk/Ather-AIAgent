# ADR-P3-002 三流程基础适配与接入边界

状态：Implemented for basic_local（本地基础实现），非生产选型验收。日期：2026-09-19。承接[PRD V1.2框架采用决策](ADR-P3-001_V1.2产品基线与框架采用.md)。

当前任务是在已完成的公共底座上实现三个流程的基础闭环。正式模型、Milvus、P2资源服务和Azure部署未在这一批配置，因此交付必须既能运行验证流程，也能准确识别适配边界。

决策：B默认使用原文Episodic保存并提供受限LangMem Core候选适配；A使用显式命名的词法特征与SQLite投影实现基础检索；C使用真实本地缓存文件和独立动作证据实现控制循环。它们均消费既有契约及RF机制。真实适配失败时不自动回退为本地成功。

这使得版本、删除、权限、任务重试、事件去重和Unknown对账可以独立运行。代价是本批不能评价真实模型质量、语义检索、压缩、冲突识别或生产分层效果，且本地缓存扩展尚需适配P2准备/清理协议。这些限制不改写PRD范围。

权限接入修订：Task与Event的权限要求由可信Host注册，默认仍是WRITE；内部派生加工、读取事件及自动缓存评估使用READ，并保留业务入口的独立授权。否则只读Recall用户会因发布自身访问事件而被错误要求拥有写入记忆权限。注册策略不接收客户端字段；当前身份及对象scope仍在执行/提交时复核。

升级条件：B真实模型适配通过来源与失败实验；A真实Embedding和Milvus通过模型空间、作用域及版本过滤；C真实Provider通过意图、原ID查询、读取证据和删除竞态。之后逐项替换本地适配，继续运行同一套流程与故障测试，不新增第二套任务系统。
